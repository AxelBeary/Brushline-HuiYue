## 一句话描述
画师约稿管理平台：多画师共用一套系统，每人有独立子域名主页。客户零注册下单/查进度，画师通过后台或QQ Bot管理排期。沟通全走QQ，平台不经手钱。

## 技术栈
- 前端：Vue 3 + Element Plus + Pinia + vuedraggable
- 后端：Node.js + Fastify 5
- 数据库：SQLite (better-sqlite3, WAL 模式)
- 文件存储：本地磁盘 uploads/
- 反向代理：Caddy（泛解析 + 自动 HTTPS）
- 部署：Docker Compose（node:22-slim 基础镜像）
- QQ Bot：NapCat/LLOneBot（Phase 2，OneBot 11 协议）

## 核心设计决策

### 1. 拖拽排序逻辑（重要！）
- 被拖动的订单获得 **目标位置的优先级**（不是交换）
- 同优先级的其他订单 **顺延**
- 实现在 `orderService.reorderQueueByDrag()`
- 前端用 vuedraggable，`@end` 事件触发后端重排

### 2. 双模式（自助 + 手动）
- 客户可以自助填表下单（source='self'）
- 画师可以手动录入（source='manual'）
- 两种进同一个队列，管理方式一致
- 画师可以把状态改为"排满/休息"来关闭自助下单

### 3. 认证方案（已加固）
- 6位数字登录码，`crypto.randomInt` 生成（密码学安全）
- 5分钟有效，3次错误锁定
- `_dev_code` 仅在 `NODE_ENV !== 'production'` 时返回
- 会话 Token：HMAC-SHA256 签名（`base64url(artistId:timestamp:hmac)`），7天有效
- `timingSafeEqual` 防时序攻击
- 无密码设计
- **生产环境必须设置 `SESSION_SECRET` 环境变量**

### 4. 子域名方案
- 泛解析 DNS + Caddy 通配符
- 开发环境用 `?artist=xxx` 参数（vue-router `route.query.artist`）
- 生产环境从 hostname 提取子域名

### 5. 文件上传
- 参考图上传是 **备用接口**（用户要求先做主功能）
- 上传路由：/api/upload/image, /api/upload/reference, /api/upload/deliverable
- 格式提示：非 JPG/PNG/WebP 弹提示但不阻止
- 限制：10MB/张，最多5张
- **前端 OrderForm 有客户端校验**：超限文件直接拒绝并提示
- **后端 upload.js**：截断后 `unlinkSync` 清理残留，`statSync` 获取真实大小

### 6. 客户端零注册
- 客户不需要账号
- 凭订单号查进度
- 凭交付链接下载文件

### 7. 安全措施
- 速率限制：send-code 5次/5分钟，verify 10次/5分钟（per-IP 内存桶）
- CORS：开发环境全开，生产环境由 `CORS_ORIGIN` 环境变量控制
- 输入校验：`validate.js` 的 `clamp()` 截断 + `isValidQq()` 格式校验
- QQ号校验：5-15位数字
- 公开 API 不泄露 qq_number

## Docker 部署注意事项

- 基础镜像：`node:22-slim`（Debian，better-sqlite3 有预编译二进制）
- `.dockerignore` 排除 node_modules/dist/data/uploads，构建上下文 < 100KB
- `docker-compose.yml` 中 `DB_PATH=/app/data/commission.db` 确保数据卷路径一致
- 种子数据命令：`docker compose exec web node server/src/db/seed.js`（注意 server/ 前缀）
- Caddy 容器在本地开发时会反复重启（无域名配置），**这是正常的**，不影响 3000 端口访问
- 国内拉镜像慢时配置 `~/.docker/daemon.json` 的 `registry-mirrors`
