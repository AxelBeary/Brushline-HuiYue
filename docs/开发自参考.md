## 一句话描述
画师约稿管理平台：多画师共用一套系统，每人有独立子域名主页。客户零注册下单/查进度，画师通过后台或QQ Bot管理排期。沟通全走QQ，平台不经手钱。

---

## 技术栈
- 前端：Vue 3 + Element Plus + Pinia + vuedraggable
- 后端：Node.js + Fastify 5
- 数据库：SQLite (better-sqlite3, WAL 模式)
- 文件存储：本地磁盘 uploads/
- 反向代理：Caddy（泛解析 + 自动 HTTPS）
- 部署：Docker Compose
- QQ Bot：NapCat/LLOneBot（Phase 2，OneBot 11 协议）

## 核心设计决策

### 1. 拖拽排序逻辑（重要！）
- 被拖动的订单获得 **目标位置的优先级**（不是交换）
- 同优先级的其他订单 **顺延**
- 实现在 `orderService.reorderQueueByDrag()`
- 前端用 vuedraggable，`@end` 事件触发后端重排

### 2. 双模式（自助 + 手动）
- 客户可以自助填表下单（source='self'）
- 画师可以手动录入（source='manual'）
- 两种进同一个队列，管理方式一致
- 画师可以把状态改为"排满/休息"来关闭自助下单

### 3. 认证方案
- 6位数字登录码，5分钟有效，3次错误锁定
- MVP阶段：登录码在 API 响应中返回（_dev_code 字段）
- Phase 2：通过 QQ Bot 私聊发送，删除 _dev_code
- 会话 Token：base64url(artistId:timestamp:random)，7天有效
- 无密码设计

### 4. 子域名方案
- 泛解析 DNS + Caddy 通配符
- 后端根据 Host header 或 URL 参数识别画师
- 开发环境用 ?artist=xxx 参数
- 生产环境从 hostname 提取子域名

### 5. 文件上传
- 参考图上传是 **备用接口**（用户要求先做主功能）
- 上传路由已实现：/api/upload/image, /api/upload/reference, /api/upload/deliverable
- 格式提示：非 JPG/PNG/WebP 弹提示但不阻止
- 限制：10MB/张，最多5张

### 6. 客户端零注册
- 客户不需要账号
- 凭订单号查进度
- 凭交付链接下载文件

## 已知注意事项
1. `server/src/index.js` 中 pino-pretty 是 dev 依赖，生产环境可能需要去掉 transport 配置
2. `web/src/views/artist/OrderDetail.vue` 中 `window.open` 在 template 里直接调用，需要改为方法
3. 开发环境客户端页面用 `?artist=alice` 参数指定画师，生产环境靠子域名
4. Element Plus 的 ElMessage 在 ArtistHome.vue 中未 import（全局注册了所以能用，但最好显式导入）
5. Docker 构建时 better-sqlite3 需要编译，Alpine 镜像可能需要 `apk add python3 make g++`
