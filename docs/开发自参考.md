## 项目位置
`D:\Hermes Agent CN Desktop\workspace\artist-commission\`

## 一句话描述
画师约稿管理平台：多画师共用一套系统，每人有独立主页（路径 `/artist/:subdomain`）。客户零注册下单/查进度，画师通过后台或QQ Bot管理排期。沟通全走QQ，平台不经手钱。

---

## 技术栈
- 前端：Vue 3 + Element Plus + Pinia + vuedraggable + **vue-i18n@9**（中英双语）
- 后端：Node.js + Fastify 5
- 数据库：SQLite (better-sqlite3, WAL 模式)
- 文件存储：本地磁盘 uploads/
- 反向代理：Caddy（自动 HTTPS，泛解析 Phase 2 预留）
- 部署：Docker Compose
- 测试：Vitest（内存数据库，63 个用例）
- QQ Bot：NapCat/LLOneBot（Phase 2，OneBot 11 协议）

## 核心设计决策

### 1. Feature-based 目录（v0.2 重构）
- 每个业务域一个目录：`features/{auth,artist,order,upload,admin}/`
- 每个 feature 包含 `*.service.js`（业务逻辑）+ `*.routes.js`（HTTP 路由）
- 跨 feature 共用的放 `shared/`（validate、middleware）
- `app.js` 是应用工厂，`index.js` 只负责启动

### 2. 拖拽排序逻辑（重要！）
- 拖拽即绝对顺序，`priority` 仅作展示标签不影响排列
- 实现在 `features/order/order.service.js` 的 `reorderQueue(artistId, orderedIds)`
- 前端传入完整的排序后 ID 数组，后端按序分配 `queue_position`
- 前端用 vuedraggable，`@end` 事件触发后端重排

### 3. 双模式（自助 + 手动）
- 客户可以自助填表下单（source='self'）
- 画师可以手动录入（source='manual'）
- 两种进同一个队列，管理方式一致
- 画师可以把状态改为"排满/休息"来关闭自助下单

### 4. 认证方案
- 6位数字登录码，5分钟有效，**5次**错误锁定
- 开发模式：登录码输出到控制台（`🔑 [DEV]` 前缀）
- 生产模式：登录码不返回，需 QQ Bot 发送（Phase 2）
- 会话 Token：HMAC-SHA256 签名，`base64url(JSON{id,t}).base64url(sig)`，7天有效
- **v0.5**：生产环境未设置 `SESSION_SECRET` 时启动报错（不再静默回退）
- **v0.6.2**：开发模式验证码通过 `AUTH_DEV_MODE=true` 环境变量显式开启（不再依赖 NODE_ENV）
- 无密码设计
- 管理员 QQ 通过 `ADMIN_QQ` 环境变量首次引导，运行时从 `platform_config` 表读取（支持运行时更换）

### 5. 画师主页路由方案
- **当前实现（v0.4.1+）**：前端使用参数化路由 `/artist/:subdomain`，后端 `GET /api/artists/:subdomain` 识别画师
- **Phase 2（未实现）**：泛子域名（`alice.example.com`），需泛解析 DNS + DNS-01 证书 + 前端 hostname 路由映射
- 开发环境直接使用 `/artist/alice` 路径访问
- 管理员后台添加画师时填写 subdomain 字段即可，无需 DNS 变更

### 6. 文件上传
- 上传路由在 `features/upload/upload.routes.js`
- **v0.5**：MIME 白名单（jpg/png/webp/gif/pdf/psd/ai/zip/rar），非白名单返回 403
- 限制：10MB/张，最多5张
- 截断时自动清理残留文件

### 7. 客户端零注册
- 客户不需要账号
- **v0.5**：凭 **QQ号+订单号** 双验证查进度（`getClientQueuePosition` 比对 `client_qq`）
- 凭交付链接下载文件
- "不知道订单号"按钮：凭 QQ 号查询在该画师处的所有订单

### 8. 订单号生成（v0.5 重构）
- 格式：`{身份码}-{序号}`，如 `ALICE-001`
- 身份码（artist_code）：2-10位大写字母/数字，画师可自定义，默认子域名大写
- 序号：从该画师最后一条订单的 `order_no` 推导（`generateOrderNo`），UNIQUE 约束防碰撞
- >999 时动态位数（`ALICE-1000`），不补零
- 状态机：pending→confirmed→wip→revision→done→delivered/cancelled，禁止跳跃

### 9. 速率限制（v0.5 新增）
- `shared/middleware/rate-limit.js`：内存桶，按 IP+端点独立计数
- 登录码发送/验证：5次/分钟
- 公开下单/订单查询：10次/分钟
- 触发返回 HTTP 429，进程重启后重置

### 10. XSS 防护（v0.5 新增）
- `web/src/utils/sanitize.js`：白名单标签+属性过滤
- 所有 `v-html` 必须经过 `sanitizeHtml()` 消毒
- 后端 `validate.js` 提供 `escapeHtml()` 用于服务端转义

### 11. 多语言（i18n）
- vue-i18n@9 Composition API 模式（`legacy: false`）
- 语言包在 `web/src/locales/`，按命名空间组织（common/menu/landing/artistHome/orderForm/track/...）
- 自动检测 `navigator.language`，手动切换存 `localStorage('huiyue-locale')`
- Element Plus locale 通过 `App.vue` 的 `ElConfigProvider` 动态切换
- 日期格式化跟随 locale（`zh-CN` / `en-US`）
- 新增语言：在 `locales/` 加文件 → `i18n/index.js` 注册 → `ThemeToggle.vue` 加菜单项

### 12. 亮暗主题
- CSS 变量体系：`:root` 8 个语义变量，`html.dark` 覆盖暗色值
- Element Plus 暗色：`element-plus/theme-chalk/dark/css-vars.css` + `html.dark` 类名
- Pinia store（`stores/theme.js`）：系统偏好检测 → localStorage 持久化 → watch 自动应用
- ThemeToggle 组件嵌入 4 处：ArtistLayout 侧边栏、LandingPage、ArtistHome、Login
- 所有 scoped 样式用 CSS 变量，不硬编码颜色

## 已知注意事项
1. `server/src/app.js` 中 pino-pretty 是 dev 依赖，生产环境自动跳过（动态 import + try/catch）
2. 客户端路由使用 `/artist/:subdomain` 参数化路径（v0.4.1 起），不再使用 `?artist=` 查询参数
3. **后端 API 统一返回 camelCase**（`orderNo`、`artistName`、`tierName`、`weiboUrl`），前端模板必须匹配，不要用 snake_case
4. Docker 多阶段构建：前端在 `frontend-build` 阶段编译，生产镜像只含 `--omit=dev` 后端依赖
5. 测试中 `auth.service.js` 的 SECRET 在模块加载时固定，vitest.config.js 的 env 必须在 import 前生效
6. `entrypoint.sh` 使用绝对路径（`/app/server/src/...`），不再依赖 CWD
7. `db/init.js` import 时无副作用，CLI 执行或 `tests/setup.js` 显式调用 `initDatabase(db)` 才建表
8. 所有路由层不含裸 SQL，业务查询统一在 `*.service.js` 中
9. `upload.routes.js` 的 `UPLOAD_DIR` 由 `app.js` 通过插件选项传入，保证与静态服务路径一致
10. i18n 语言包键名按页面命名空间组织，`common.*` 为跨页面共享（状态/优先级/按钮）
11. 暗色主题依赖 `html.dark` 类名，Element Plus 组件自动适配；自定义样式必须用 CSS 变量
12. **客户端 API 分层**：公开数据用 `artistPublicApi`（getAll/getProfile），订单用 `orderApi`（create/track/delivery），画师后台用 `artistApi`（需 token）。切勿混用
13. 后端 `GET /api/artists/:subdomain` 一次返回 profile+tiers+artworks+rules，前端不需要分多次请求
14. 后端 `deliverables` 数组中 `url` 字段已含 `/uploads/` 前缀，前端 `openFile()` 直接 `window.open(url)` 即可
15. **v0.5**：`requireAuth` 中间件注入 `req.artist` 完整对象（含 id/qq_number/name/artist_code），路由层用 `req.artist.id` 做归属校验
16. **v0.5**：订单号生成从该画师最后一条订单的 `order_no` 推导序号（`generateOrderNo`），无独立计数器表
17. **v0.5**：`client_qq` 当前为明文存储（TEXT），后续可升级为 SHA-256+salt 哈希
18. **v0.5**：前端所有 `v-html` 必须经过 `sanitizeHtml()`（`web/src/utils/sanitize.js`），新增页面时注意
19. **v0.5**：`updateTier()` 同时接受 camelCase（`workDays`）和 snake_case（`work_days`），前端统一用 camelCase
20. **v0.5**：`docker-compose.yml` 默认 `NODE_ENV=production`，本地开发需手动改为 `development`
21. **v0.6.1**：SQLite `ALTER TABLE ADD COLUMN` 不支持 `UNIQUE` 约束，迁移必须先加列再 `CREATE UNIQUE INDEX`
