# 🔧 维护说明书

> 面向系统维护者（部署、运维、故障排查）。需要基本的服务器操作能力。
> 最后更新：2026-07-28（v0.8.0）

---

## 一、系统架构

```
用户浏览器
    │
    ▼
Cloudflare CDN（可选，加速静态资源）
    │
    ▼
Caddy（反向代理 + 自动 HTTPS）
    │  端口 80/443
    │  depends_on: web (service_healthy)
    ▼
Node.js 应用（Fastify 5，多阶段 Docker 构建）
    │  端口 3000
    │  healthcheck: /api/health（30s 间隔）
    ├── SQLite 数据库（data/commission.db）
    ├── 上传文件（uploads/）
    └── 前端构建产物（web/dist/，构建时嵌入镜像）
```

## 二、首次部署

### 前置条件
- 一台 Linux 服务器（1核1G 即可）
- 已安装 Docker + Docker Compose
- 一个域名，已做泛解析：`*.你的域名.com → 服务器IP`

### 步骤

```bash
# 1. 克隆项目
git clone <仓库地址> artist-commission
cd artist-commission

# 2. 配置环境变量
cp .env.example .env
# 编辑 .env，必须修改：
#   DOMAIN=你的域名.com
#   ADMIN_QQ=你的QQ号
#   SESSION_SECRET=（用下面命令生成）
#
# 生成 SESSION_SECRET：
#   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

# 3. 启动
docker compose up -d

# 4. 初始化种子数据（可选，会创建测试画师 Alice 和 Bob）
docker compose exec web node server/src/db/seed.js

# 5. 验证
curl http://localhost:3000/api/health
# 应返回 {"status":"ok",...}
```

### 添加第一个画师

方法一：通过管理员后台
1. 用 ADMIN_QQ 对应的账号登录（访问 `/login`）
2. 访问 `/admin/artists`
3. 点"添加画师"

方法二：通过种子数据
```bash
docker compose exec web node server/src/db/seed.js
```

## 五、域名与 HTTPS

### 泛解析 DNS 配置
在你的域名服务商添加：
```
类型: A
主机记录: *
记录值: 你的服务器IP
```

### Caddy 自动 HTTPS
Caddy 默认自动申请 Let's Encrypt 证书，无需手动配置。

如果使用 Cloudflare 代理（橙色云朵），需要：
1. 安装 Caddy 的 cloudflare DNS 插件
2. 在 Caddyfile 中配置 `acme_dns cloudflare <API_TOKEN>`
3. 或者将 Cloudflare SSL 模式设为 "Full (Strict)"

### 添加新画师
不需要任何 DNS 或 Caddy 配置变更！
只需在管理员后台"添加画师"并填写子域名即可，画师主页通过 `https://你的域名/artist/子域名` 访问。

> **Phase 2 规划**：未来将支持泛子域名（`alice.你的域名`），届时需配置泛解析 DNS 和 DNS-01 证书。

## 六、环境变量说明

| 变量 | 说明 | 默认值 | 生产必改？ |
|------|------|--------|-----------|
| DOMAIN | 主域名 | artgroup.com | ✅ |
| PORT | 服务端口 | 3000 | ❌ |
| UPLOAD_DIR | 上传文件路径 | ./uploads | ❌（Docker 内已设为 /app/uploads） |
| DB_PATH | 数据库路径 | ./data/commission.db | ❌ |
| ADMIN_QQ | 管理员QQ号 | 10000 | ✅ |
| SESSION_SECRET | 会话签名密钥 | ⚠️ 生产环境必须设置，否则启动报错 | ✅ 必须改！ |
| SIGN_SECRET | 文件签名 URL 密钥 | secret | ✅ 必须改！ |
| TRUST_PROXY | 信任的代理 IP 段 | 172.16.0.0/12,10.0.0.0/8,192.168.0.0/16 | 按需 |
| TZ | 容器时区 | UTC | ✅ 建议 Asia/Shanghai |
| LOGIN_CODE_TTL | 登录码有效期（秒） | 300 | ❌ |
| LOGIN_CODE_MAX_ATTEMPTS | 最大尝试次数 | 5 | ❌ |
| CORS_ORIGIN | 生产环境CORS来源 | 空（禁止跨域） | 按需 |
| AUTH_DEV_MODE | 开发模式登录码返回 | false | ✅ 生产必须关闭 |
| BOT_ENABLED | QQ Bot开关 | false | Phase 2 |
| BOT_WS_URL | Bot WebSocket地址 | 空 | Phase 2 |

## 七、QQ Bot 配置（Phase 2）

### 安装 NapCat / LLOneBot
参考其官方文档安装，确保开启 WebSocket 反向连接。

### 配置 .env
```env
BOT_ENABLED=true
BOT_WS_URL=ws://127.0.0.1:3001
```

### Bot 功能
- 发送登录码给画师
- 画师通过QQ指令控制后台（排期、接单、改状态等）
- 新订单通知画师
- 状态变更通知客户（如客户选择了接收通知）

## 八、故障排查

### 应用无法启动
```bash
# 查看详细错误
docker compose logs web --tail 50

# 常见原因：
# 1. .env 文件缺失或格式错误
# 2. data/ 目录权限不足
# 3. 端口 3000 被占用
# 4. SESSION_SECRET 未设置（启动报错，v0.5 起）
# 5. SIGN_SECRET 未设置（使用默认值 'secret'，签名 URL 不安全）
```

### 数据库锁定
```bash
# SQLite WAL 模式下极少出现
# 如果出现 "database is locked"：
docker compose stop web
rm -f data/commission.db-wal data/commission.db-shm
docker compose start web
```

### 上传文件 404
```bash
# 检查 uploads 目录权限
ls -la uploads/
# 确保 Docker 容器内的用户有读写权限
chmod -R 755 uploads/

# 确认容器内路径正确（v0.3 起 UPLOAD_DIR 由 app.js 统一传入）
docker exec commission-web ls -la /app/uploads/
# 应该有 images/ 子目录
```

### HTTPS 证书问题
```bash
# 查看 Caddy 日志
docker compose logs caddy --tail 30
# 常见原因：DNS 未生效、端口 80/443 未开放
```

### Caddy 容器反复重启（本地开发）
这是正常现象——本地没有域名配置，Caddy 无法申请证书。
不影响使用，直接通过 `http://localhost:3000` 访问即可。

### 上传的图片不显示 / 作品加载失败
```bash
# 检查上传目录是否正确挂载
docker exec commission-web ls -la /app/uploads/
# 应该有 images/ 子目录

# 如果目录为空但本地 uploads/ 有文件，检查 docker-compose.yml：
# 确保 environment 中有 UPLOAD_DIR=/app/uploads
# 确保 volumes 中有 ./uploads:/app/uploads

# v0.3 起 UPLOAD_DIR 由 app.js 统一解析并传入 upload 插件，
# 不再依赖 entrypoint.sh 的 cd 行为
```

### NODE_ENV 与登录码
```bash
# 开发模式（NODE_ENV=development）：登录码输出到控制台（🔑 [DEV] 前缀）
# 生产模式（NODE_ENV=production）：登录码不返回，需 QQ Bot 发送
# 检查当前模式：
docker compose exec web printenv NODE_ENV
```

> ⚠️ v0.5 起 docker-compose.yml 默认 `NODE_ENV=production`。本地开发请手动改为 `development`。

### 速率限制（v0.5 新增）
所有公开接口均有内存桶速率限制（按 IP + 端点独立计数）：
- 登录码发送/验证：5次/分钟
- 公开下单：10次/分钟
- 订单查询：10次/分钟

触发限制返回 HTTP 429。限制器在进程重启后重置（无需清理）。
如需调整阈值，修改 `server/src/shared/middleware/rate-limit.js`。

> 📖 开发→生产切换的完整步骤见 [开发→生产切换指南](开发→生产切换指南.md)

### Docker 拉镜像超时（国内）
配置镜像加速：
```json
// ~/.docker/daemon.json
{
  "registry-mirrors": [
    "https://docker.1ms.run",
    "https://docker.xuanyuan.me"
  ]
}
```
配置后重启 Docker Desktop。

## 十、安全注意事项

1. **不要** 把 `.env` 文件提交到 git
2. **不要** 把 `data/` 和 `uploads/` 目录暴露到公网
3. **必须** 在生产环境设置 `SESSION_SECRET`（v0.5 起未设置会启动报错）
4. **必须** 在生产环境设置 `SIGN_SECRET`（v0.7.1 起文件签名 URL 使用此密钥，默认值 `secret` 不安全）
5. **v0.6.2**：开发模式验证码通过 `AUTH_DEV_MODE=true` 显式开启（不再依赖 NODE_ENV），生产环境务必不设置或设为 `false`
6. **v0.6.2**：容器端口仅 `expose`（内部网络），不映射到宿主机，外部访问必须走 Caddy 反向代理
7. **v0.6.2**：上传文件有扩展名 + MIME 双重白名单校验，交付文件前端限制 50MB
8. **v0.6.2**：所有 API 路由有 JSON Schema 输入校验，非法字段自动剥离
9. **v0.7.1**：`/uploads/` 不再全公开，交付文件和参考图通过 HMAC 签名 URL 访问（15 分钟有效），仅 `images/` 保留公开
10. **v0.7.1**：软删除画师的 token 立即失效（`requireAuth`/`requireAdmin` 检查 `deleted_at`）
11. **v0.7.1**：管理员删除画师时递增 `token_version`，强制吊销该画师所有会话
12. **v0.7.1**：全局安全响应头（X-Content-Type-Options / X-Frame-Options / X-XSS-Protection / HSTS）
13. **v0.7.1**：500 错误不再透传内部异常信息，返回固定文案 + 服务端日志
14. 定期备份数据库
15. 保持 Docker 和系统更新
16. 认证接口有速率限制（send-code 5次/分钟，verify 5次/分钟）
17. **v0.5 新增**：客户查询进度需 QQ号+订单号双验证，防止订单号枚举
18. **v0.5 新增**：上传文件有 MIME 白名单（jpg/png/webp/gif/pdf/psd/ai/zip/rar），非白名单返回 403
19. **v0.5 新增**：前端所有 `v-html` 均经过 `sanitizeHtml()` 消毒，防止存储型 XSS
20. **v0.5 新增**：画师后台所有操作有 `artist_id` 归属校验，防止水平越权
21. **v0.8.0**：管理员代理路由（`/api/admin/artists/:id/*`）全部经过 `requireAdmin` 中间件，非管理员无法访问
22. **v0.8.0**：流程比例写入使用 `db.transaction()` 包裹，不变式校验失败自动回滚，不会产生脏数据
23. **v0.8.0**：数据库迁移 v5/v6/v7 在容器启动时自动执行（`initDatabase`），无需手动操作；老库升级时存量画师自动补充默认流程节点
