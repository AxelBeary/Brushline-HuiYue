# 🔧 维护说明书

> 面向系统维护者（部署、运维、故障排查）。需要基本的服务器操作能力。

---

## 一、系统架构

```
用户浏览器
    │
    ▼
Cloudflare CDN（可选，加速静态资源）
    │
    ▼
Caddy（反向代理 + 自动 HTTPS + 泛解析）
    │  端口 80/443
    ▼
Node.js 应用（Fastify）
    │  端口 3000
    ├── SQLite 数据库（data/commission.db）
    ├── 上传文件（uploads/）
    └── 前端构建产物（web/dist/）
```

---

## 二、首次部署

### 前置条件
- 一台 Linux 服务器（1核1G 即可）
- 已安装 Docker + Docker Compose
- 一个域名，已做泛解析：`*.你的域名.com → 服务器IP`

### 步骤

```bash
# 1. 克隆项目
git clone <仓库地址> artist-commission
cd artist-commission

# 2. 配置环境变量
cp .env.example .env
# 编辑 .env，修改：
#   DOMAIN=你的域名.com
#   ADMIN_QQ=你的QQ号

# 3. 启动
docker compose up -d

# 4. 初始化种子数据（可选，会创建测试画师）
docker compose exec web node src/db/seed.js

# 5. 验证
curl http://localhost:3000/api/health
# 应返回 {"status":"ok",...}
```

### 添加第一个画师

方法一：通过管理员后台
1. 用 ADMIN_QQ 对应的账号登录
2. 访问 `/admin/artists`
3. 点"添加画师"

方法二：通过种子数据
```bash
docker compose exec web node src/db/seed.js
```

## 四、数据备份

### 数据库备份
```bash
# SQLite 备份就是复制文件
cp data/commission.db data/commission.db.bak.$(date +%Y%m%d)
```

### 上传文件备份
```bash
tar -czf uploads-backup-$(date +%Y%m%d).tar.gz uploads/
```

### 自动备份（crontab）
```bash
# 每天凌晨3点备份
0 3 * * * cd /path/to/artist-commission && cp data/commission.db data/backups/commission-$(date +\%Y\%m\%d).db
```

### 恢复
```bash
# 停止服务
docker compose stop web
# 覆盖数据库文件
cp data/backups/commission-20250101.db data/commission.db
# 重启
docker compose start web
```

## 五、域名与 HTTPS

### 泛解析 DNS 配置
在你的域名服务商添加：
```
类型: A
主机记录: *
记录值: 你的服务器IP
```

### Caddy 自动 HTTPS
Caddy 默认自动申请 Let's Encrypt 证书，无需手动配置。

如果使用 Cloudflare 代理（橙色云朵），需要：
1. 安装 Caddy 的 cloudflare DNS 插件
2. 在 Caddyfile 中配置 `acme_dns cloudflare <API_TOKEN>`
3. 或者将 Cloudflare SSL 模式设为 "Full (Strict)"

### 添加新画师的子域名
不需要任何 DNS 或 Caddy 配置变更！泛解析已经覆盖所有子域名。
只需在管理员后台"添加画师"并填写子域名即可。

## 六、QQ Bot 配置（Phase 2）

### 安装 NapCat / LLOneBot
参考其官方文档安装，确保开启 WebSocket 反向连接。

### 配置 .env
```env
BOT_ENABLED=true
BOT_WS_URL=ws://127.0.0.1:3001
```

### Bot 功能
- 发送登录码给画师
- 画师通过QQ指令控制后台（排期、接单、改状态等）
- 新订单通知画师
- 状态变更通知客户（如客户选择了接收通知）

## 七、故障排查

### 应用无法启动
```bash
# 查看详细错误
docker compose logs web --tail 50

# 常见原因：
# 1. .env 文件缺失或格式错误
# 2. data/ 目录权限不足
# 3. 端口 3000 被占用
```

### 数据库锁定
```bash
# SQLite WAL 模式下极少出现
# 如果出现 "database is locked"：
docker compose stop web
rm -f data/commission.db-wal data/commission.db-shm
docker compose start web
```

### 上传文件 404
```bash
# 检查 uploads 目录权限
ls -la uploads/
# 确保 Docker 容器内的用户有读写权限
chmod -R 755 uploads/
```

### HTTPS 证书问题
```bash
# 查看 Caddy 日志
docker compose logs caddy --tail 30
# 常见原因：DNS 未生效、端口 80/443 未开放
```

## 九、安全注意事项

1. **不要** 把 `.env` 文件提交到 git
2. **不要** 把 `data/` 和 `uploads/` 目录暴露到公网
3. 生产环境删除 auth 路由中的 `_dev_code` 字段（登录码应只通过QQ Bot发送）
4. 定期备份数据库
5. 保持 Docker 和系统更新
