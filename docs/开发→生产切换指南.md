# 🚀 开发→生产切换指南

> 从本地开发环境切换到生产部署的完整检查清单。
> 最后更新：2026-08-09（docs 审核批：SIGN_SECRET 虚构清理 / 路径访问 / seed.ts / 迁移检查更新）

## 一、必须修改的配置

### 1. `.env` 文件

开发环境用的是默认值，生产必须全部改：

```env
# ❌ 开发默认 → ✅ 生产必改
DOMAIN=localhost              → DOMAIN=你的域名.com
ADMIN_QQ=10003                → ADMIN_QQ=你的真实QQ号（仅首次引导用，运行时从数据库读取）
SESSION_SECRET=dev-secret-... → SESSION_SECRET=（随机生成，见下方命令）
（SIGN_SECRET 为虚构变量——文件签名 URL 实际用 SESSION_SECRET，勿配置）
COOKIE_SECRET=                → COOKIE_SECRET=（随机生成，用于 httpOnly cookie 签名）
AUTH_DEV_MODE=true            → 删除此行或设为 false（生产环境必须关闭）
CORS_ORIGIN=                  → CORS_ORIGIN=https://你的域名.com（按需）
TRUST_PROXY=                  → TRUST_PROXY=172.16.0.0/12,10.0.0.0/8,192.168.0.0/16（Docker 内网段）
（SIGN_SECRET 为虚构变量——文件签名 URL 实际用 SESSION_SECRET，勿配置）
TZ=                           → TZ=Asia/Shanghai（容器时区）
```

生成安全的 SESSION_SECRET：
```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

> ⚠️ **SESSION_SECRET 是会话签名密钥**。如果不改，重启后所有画师登录失效；如果用默认值，Token 可被伪造。
> ⚠️ **AUTH_DEV_MODE=true 会在 TOTP 绑定接口响应中附带密钥明文 `_dev_secret`**（REQ-027 起）。生产环境务必删除或设为 false，否则密钥泄露，任何人可伪造动态口令登录。

### 2. `docker-compose.yml`

```yaml
environment:
  - NODE_ENV=development    # ← 改为 production
  - DB_PATH=/app/data/commission.db
  - UPLOAD_DIR=/app/uploads
  - TRUST_PROXY=172.16.0.0/12,10.0.0.0/8,192.168.0.0/16  # Docker 内网段（v0.11 起默认）
```

改为：
```yaml
environment:
  - NODE_ENV=production
  - DB_PATH=/app/data/commission.db
  - UPLOAD_DIR=/app/uploads
  - TRUST_PROXY=172.16.0.0/12,10.0.0.0/8,192.168.0.0/16
```

> ⚠️ **v0.11 变更**：`AUTH_DEV_MODE` 已从 docker-compose.yml 移至 `.env` 控制（commit e57733d），docker-compose 中不再包含此行。`TRUST_PROXY` 已改为 Docker 内网段（不再是 `true`），确保反向代理 IP 正确传递。

**`NODE_ENV=production` 的效果：**
- CORS 由 `CORS_ORIGIN` 控制（不再全开）
- 日志从 pino-pretty 降级为 JSON（Docker 里本来就没装 pino-pretty）

**`AUTH_DEV_MODE` 的效果（v0.6.2 起独立控制，v0.11 起由 .env 管理，v0.37/REQ-027 起语义变更）：**
- `true`：TOTP 绑定接口（bind-init）响应附带密钥明文 `_dev_secret`（仅开发/测试/演示用，替代旧登录码的明文辅助字段）
- 不设置 / `false`：不返回任何密钥，正常生产行为

### 3. 端口访问（v0.11 变更）

开发环境默认开放 `ports: ["3000:3000"]`，方便本地调试直连。
**生产部署时必须注释掉或删除此行**（commit a0e07bd），仅保留 `expose`：

```yaml
# 开发环境（默认）：
ports:
  - "3000:3000"    # ← 生产部署时注释掉
expose:
  - "3000"
```

- 开发调试：直接访问 `http://localhost:3000`
- 生产访问：必须通过 Caddy 反向代理（80/443），容器端口仅 `expose`（Docker 内部网络）
- 验证生产端口未暴露：`docker compose ps` 应无 `0.0.0.0:3000` 映射

## 二、域名与 HTTPS

### 域名解析（路径访问模式）

当前为**路径访问模式**（画师主页走 `https://你的域名/artist/子域名`），只需一条 A 记录指向服务器即可，**无需泛解析**：

```
类型: A
主机记录: @（或留空）
记录值: 你的服务器IP
```

### Caddy 自动 HTTPS

`Caddyfile` 为单主域配置（`{$DOMAIN}`，C48 决策放弃子域名方案），Caddy 自动申请 Let's Encrypt 证书。
确保服务器 80/443 端口开放。

如果用 Cloudflare 代理（橙色云朵），需要额外配置 DNS 验证（见维护说明书）。

### 画师识别方式（v0.4.1 起统一）

| 环境 | 访问方式 | 示例 |
|------|----------|------|
| 开发 | 参数化路由 `/artist/:subdomain` | `localhost:3000/artist/alice` |
| 生产 | 同开发（路径访问） | `你的域名.com/artist/alice` |

> **Phase 2 规划**：未来将支持泛子域名（`alice.你的域名.com`），届时需配置泛解析 DNS + DNS-01 证书 + 前端 hostname 路由映射。当前 Caddyfile 已预留泛解析配置但标注为 Phase 2。

前端路由统一使用 `/artist/:subdomain` 路径，后端 `GET /api/artists/:subdomain` 识别画师。
管理员后台添加画师时填写 subdomain 字段即可，无需 DNS 变更。

## 三、切换步骤（按顺序执行）

```bash
# 1. 编辑 .env
cp .env.example .env   # 如果还没有 .env
vim .env               # 修改 DOMAIN / ADMIN_QQ / SESSION_SECRET / 删除 AUTH_DEV_MODE

# 2. 修改 docker-compose.yml
#    NODE_ENV=development → NODE_ENV=production
#    注释掉 ports: ["3000:3000"]（生产不暴露端口）
#    确认 TRUST_PROXY 为 Docker 内网段（v0.11 默认已设置）

# 3. 重建并启动（多阶段构建，自动编译前端）
docker compose up -d --build

# 4. 验证（healthcheck 自动检测 /api/health）
docker compose ps    # 应显示 healthy
docker compose exec web curl -s localhost:3000/api/health
# 应返回 {"status":"ok",...}

# 5. 验证 AUTH_DEV_MODE 已关闭（REQ-027 TOTP）
# 登录管理后台 → 画师详情 → TOTP 绑定，点「生成绑定二维码」，
# 在 DevTools → Network 查看 /api/admin/artists/:id/totp/bind-init 响应体：
# 应只有 qrDataUrl / otpauthUri 两个字段，不含 _dev_secret
# （若 AUTH_DEV_MODE=true，该响应会附带 TOTP 密钥明文 _dev_secret，仅限开发）

# 6. 初始化种子数据（仅首次）
docker compose exec -T web npm --prefix /app/server run db:seed
```

## 四、生产环境检查清单

| # | 检查项 | 怎么验证 |
|---|--------|----------|
| 1 | `SESSION_SECRET` 已更换为随机值 | 查看 `.env` |
| 2 | `SIGN_SECRET` 虚构变量（文件签名 URL 用 SESSION_SECRET） | 代码 grep 零引用 |
| 3 | `COOKIE_SECRET` 已设置 | 查看 `.env` |
| 4 | `ADMIN_QQ` 是真实 QQ 号 | 查看 `.env` |
| 5 | `NODE_ENV=production` | `docker compose exec web printenv NODE_ENV` |
| 6 | `AUTH_DEV_MODE` 未设置或为 false | `docker compose exec web printenv AUTH_DEV_MODE` |
| 7 | `_dev_secret` 不返回（TOTP 绑定接口） | 管理员后台调 bind-init 检查响应无该字段 |
| 8 | HTTPS 正常 | 浏览器访问 `https://你的域名.com` |
| 9 | 画师主页正常 | 访问 `https://你的域名.com/artist/alice` |
| 10 | 上传文件可访问 | 上传作品后刷新页面确认图片显示 |
| 11 | 数据库持久化 | `docker compose restart web` 后数据还在 |
| 12 | `.env` 未提交到 git | `git status` 检查 |
| 13 | `data/` 和 `uploads/` 未暴露公网 | 检查 Caddy 配置 |
| 14 | 容器端口未映射到宿主机 | `docker compose ps` 无 0.0.0.0:3000 |
| 15 | httpOnly cookie 生效 | DevTools → Application → Cookies 确认 artist_token 为 HttpOnly |
| 16 | 数据库迁移到最新 | `docker compose exec -w /app/server web node -e "const db=require('better-sqlite3')('/app/data/commission.db');console.log(db.prepare('SELECT version FROM schema_migrations ORDER BY id DESC LIMIT 3').all())"`（当前最新 v48 totp_used_codes） |
| 17 | 数据备份可生成 | `docker compose exec -T web npm --prefix /app/server run backup`（应输出 BACKUP_OK） |
| 18 | `TRUST_PROXY` 为 Docker 内网段 | `docker compose exec web printenv TRUST_PROXY` 应为 `172.16.0.0/12,10.0.0.0/8,192.168.0.0/16` |

## 五、开发模式特有功能（生产自动关闭）

| 功能 | 开发行为 | 生产行为 |
|------|----------|----------|
| TOTP 绑定明文辅助（REQ-027） | `AUTH_DEV_MODE=true` 时 bind-init 响应附带密钥明文 `_dev_secret` | 不返回，密钥仅以二维码形式展示给画师 |
| CORS | 全开（`origin: true`） | 由 `CORS_ORIGIN` 控制 |
| 日志 | pino-pretty 彩色（本地有装时） | JSON 格式 |
| 速率限制 | 触发后重启容器即可清零 | 等窗口过期（5分钟） |

## 六、回滚到开发模式

如果需要临时切回开发模式调试：

```yaml
# docker-compose.yml
environment:
  - NODE_ENV=development
```

```env
# .env（v0.11 起 AUTH_DEV_MODE 由此文件控制）
AUTH_DEV_MODE=true
```

```bash
docker compose up -d web
```

> 切回后 TOTP bind-init 响应恢复附带 `_dev_secret` 明文，CORS 全开。调试完记得改回来。

## 七、QQ Bot 集成（已推迟，REQ-028 备案）

> v0.37/REQ-027 起登录改为 TOTP 动态口令，**生产登录不再依赖 QQ Bot**：管理员在管理后台生成绑定二维码，画师用验证器 App 扫码绑定，之后以 QQ号 + 动态码登录。

QQ Bot 现仅规划用于通知类场景（新单提醒/状态变更等），已推迟为备案，见 `docs/requirements/REQ-028-消息网关备案.md`。启用时需配置：

```env
BOT_ENABLED=true
BOT_WS_URL=ws://napcat容器:3001
```
