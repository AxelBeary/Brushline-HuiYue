## 任务 A：封面图指定 + 轮播（后端，~1.5h）

### 迁移 v27

```sql
ALTER TABLE artworks ADD COLUMN is_cover INTEGER DEFAULT 0;
```

### API 变更

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| PUT | /api/artist/artworks/:id/cover | requireAuth + requireOwn | 设为封面（同画师其他作品自动取消 is_cover） |
| DELETE | /api/artist/artworks/:id/cover | requireAuth + requireOwn | 取消封面 |

**业务规则**：
- 一个画师最多 1 个封面（设新封面时事务内先 `UPDATE artworks SET is_cover=0 WHERE artist_id=?`）
- 公开 API `GET /api/public/artists/:id` 返回的 artworks 列表中，封面排第一（`ORDER BY is_cover DESC, sort_order ASC`）
- 无封面时排序不变（向后兼容）

## 任务 B：多模板随机（后端，~2h）

### 需求

画师希望一个工作流节点有多个话术模板时，复制话术可以随机选一个，而不是永远用第一个。

### 迁移 v28

```sql
ALTER TABLE workflow_stages ADD COLUMN random_template INTEGER DEFAULT 0;
```

### 逻辑变更

- 现有话术获取逻辑（greeting.service.ts 或 workflow.service.ts）：当 `random_template = 1` 且该节点有多个模板时，随机选一个返回
- `random_template = 0`（默认）：保持现有行为（第一个/唯一模板）
- API：`PUT /api/artist/workflow/stages/:id` 增加 `randomTemplate` 布尔字段

### 授权文件

- `server/src/db/init.js`（迁移 v28）
- `server/src/features/artist/workflow.service.ts`（随机选择逻辑）
- `server/src/features/artist/artist.routes.ts` 或 `dashboard.routes.ts`（stage 更新路由加字段）
- `server/src/shared/errors.ts`（如需）
- `server/tests/`（随机逻辑测试）
