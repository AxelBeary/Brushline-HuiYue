## 任务

修复第三方审计剩余 P1 中的 3 项（P1-4 需用户拍板，不在本次范围）。

### P1-5：workflow 悬挂引用

**现象**：画师删除 workflow stage 后，已有订单的 `current_stage_id` 仍指向已删除的 stage，导致订单详情页渲染异常。

**修复方向**：
1. `workflow.service.js` 的 `deleteStage`（约第 207 行）删除 stage 前，检查是否有订单引用该 stage。
2. 若有引用：要么阻止删除（返回 400 + 提示），要么将引用订单的 `current_stage_id` 迁移到相邻 stage。
3. **先出方案再动手**——涉及数据完整性，方案写入 comms 报告，一号确认后再实施。

### P1-6：重复 qq/subdomain 注册返回 500

**现象**：`createArtist` 插入重复 qq_number 或 subdomain 时，SQLite UNIQUE 约束报错未被捕获，返回 500 而非 400。

**修复方向**：
- `artist.service.js` 的 `createArtist`（第 27-58 行）：INSERT 前检查 qq_number 和 subdomain 唯一性（类似已有的 artist_code 检查），抛 AppError 400。
- 或 catch SQLITE_CONSTRAINT 错误转为友好提示。

### P1-7：docker 容器内 localhost 登录失败

**现象**：容器内访问 `localhost:3000` 的登录接口超时/失败。

**修复方向**：
- 排查 `server/src/index.js` 的 HOST 绑定（是否只绑了 127.0.0.1 而非 0.0.0.0）。
- 检查 `docker-compose.yml` 网络配置。
- 若为 HOST 绑定问题，改为 `0.0.0.0` 并确保生产环境由 Caddy 反代，不直接暴露端口。
