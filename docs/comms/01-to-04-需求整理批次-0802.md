## 任务 1：REQ — 封面重设计（#9，高优先级）

**背景**：v0.25 实施的封面功能完全偏离了用户拍板方向。当前实现是"Settings 里嵌入全部作品列表 + 星标选封面"，用户要的不是这个。

**用户原话约束（四条硬规则，逐字写进 REQ）**：

1. **封面是主页门面图**——客户打开画师主页第一眼看到的视觉焦点，不是"设置页里的一个管理功能"
2. **选中的封面不在下方图格重复展示**——设了封面的作品，在作品列表/瀑布流中不再出现（避免重复）
3. **设置里放一个指向作品管理的链接**，不是把作品列表搬到设置页——画师去作品管理页操作封面，设置页只做"当前封面预览 + 跳转链接"
4. **不同模板对封面的处理逻辑不同**——4 模板各自的门面区域结构不同，封面展示必须适配：
   - Classic：单图 Hero 横幅（一张封面撑满）
   - Gallery：轮播（多张封面自动/手动切换）
   - Folio：大图展示（封面作为作品集首图）
   - Atelier：拼图/网格（封面作为入口缩略图）

**REQ 要写清**：
- 数据模型：is_cover 字段够用吗？多张封面时排序？
- 画师端交互：在作品管理页（ArtworkManage）操作封面，不在 Settings
- 客户端渲染：4 模板各自的封面区组件规格
- 去重逻辑：封面作品从瀑布流/作品列表中排除
- 迁移：现有 Settings 里的封面管理 UI 删除，改为预览+链接

**参考**：当前封面相关代码在 `web/src/views/artist/Settings.vue`（封面管理区）、`web/src/composables/useArtistData.js`（coverArtworks computed）、4 个模板的 Hero 区域。

## 任务 2：REQ — 日期交互改进（#11）

**用户反馈**：当前日期校验是"选完了报错"（选个错误日期→弹窗 INVALID_ANNOUNCEMENT_DATE），体验差。用户看到一个更好的元素（来自某产品），特征：

- **快捷预设**：近 7 天 / 近 30 天 / 本月 / 上月 / 自定义
- **双月面板**：左右两个月并排，选开始和结束
- **屏幕自适应**：窄屏时面板堆叠或缩放
- **选择器层面限制范围**：不是选完了报错，而是不可选的日期直接灰掉（disabled）

**REQ 方向**：
- 公告过期日：改为 date-picker 的 disabled-date 限制（今天之前不可选），不需要后端校验弹窗
- 订单开工日/截稿日：date-picker 层面互相限制（选了开工日后，截稿日 picker 灰掉开工日之前的日期；反之亦然）
- 排期看板时间条：考虑是否加"快捷延后 N 天"预设
- 评估 EP 的 el-date-picker 是否原生支持上述能力（disabled-date、双月面板 type="daterange"），还是需要自定义

**注意**：后端校验保留（防御性），但前端主交互不依赖报错弹窗。

## 任务 3：REQ — 时间条整体平移（#13）

**用户反馈**：当前时间条只能拖两端（改开工日/截稿日），但画师想"把这个稿子整体延后一周"——拖中间段，开工日和截稿日同时移动。

**REQ 要写清**：
- 交互：拖横条中间区域 = 整体平移（开工日和截稿日同方向同幅度移动）
- 约束：平移后开工日不早于今天（或创建日？待确认）；截稿日不早于开工日
- 视觉：拖中间时整条横条跟随鼠标，两端日期标签同时更新
- 与两端拖拽的区分：中间区域 cursor: grab；两端 cursor: col-resize
- 无截稿日的订单：只能拖左端改开工日，中间不可拖（没有截稿日就没有"整体"概念）
