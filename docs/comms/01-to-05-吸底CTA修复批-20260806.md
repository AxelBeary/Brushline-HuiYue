## 背景

四号模板体检发现 **T1（P1）：gallery/folio/atelier 三模板的吸底约稿条从不出现**。用户拍板"修"（原话"怪不得我一直感觉少了"）。根因已由四号定位 + 一号复核：

- 三模板都用 `const heroSentinel = computed(() => heroRef.value?.sentinelEl?.value)` 作为哨兵传给 `useStickyCta`（Gallery.vue:109 / Folio.vue:156 / Atelier.vue:109）
- `TplHero` 是异步组件（`defineAsyncComponent`），其 `defineExpose({ sentinelEl })` 的 ref 在父组件 computed 首次求值时**还没就绪**（`heroRef.value` 是 null → computed 求值为 `undefined`）
- **关键**：子组件 expose 的 ref 变化**不会触发父组件 computed 重新求值**——computed 只依赖 `heroRef.value`（ref 绑定本身不变），所以永远停留在 `undefined` → `useStickyCta` 里 `watch(sentinelRef, setup, { immediate: true })` 只执行一次 `setup(undefined)` 直接 return，IntersectionObserver 从未建立，之后也不再触发
- classic 无吸底条（用侧栏常驻 CTA），不受影响

## 修法（三处一致）

把三模板里的：

```js
const heroSentinel = computed(() => heroRef.value?.sentinelEl?.value)
const { visible: ctaVisible } = useStickyCta(heroSentinel)
```

改为：

```js
const { visible: ctaVisible } = useStickyCta(heroRef)
```

**原理**：`heroRef` 本身就是父组件持有的响应式 ref，异步子组件挂载完成后 `heroRef.value` 会更新（ref 绑定变化**会**触发 watch）→ `useStickyCta` 的 `watch(sentinelRef, setup)` 在 `heroRef.value` 从 null → 组件实例时触发，`setup(el)` 拿到的 `el` 是组件实例而非 DOM 元素。

所以 `useStickyCta.js` 里的 `setup` 也要兼容：组件实例上取 `sentinelEl`：

`web/src/composables/useStickyCta.js` 第 16-18 行现状：
```js
const setup = (el) => {
  observer?.disconnect()
  if (!el) return
```
改为：
```js
const setup = (el) => {
  observer?.disconnect()
  const sentinel = el?.sentinelEl?.value || el
  if (!sentinel) return
```
并把下面 `observer.observe(el)` 改为 `observer.observe(sentinel)`。
