## 一、完成清单（施工图 A/B/C 全部完成）

### A. 画师端 ArtworkManage.vue 分页（20/页 + el-pagination）
- `web/src/views/artist/ArtworkManage.vue`
  - 数据源 `loadArtworks()` 由 `getArtworks()`（全量）改为 `getArtworksPaged({ page, pageSize: 20 })`
  - 新增 `page / pageSize / total` 状态 + `onPageChange()`；作品网格后加 `el-pagination`（`v-if="total > pageSize"`，layout=prev,pager,next）
  - **封面置顶不动**：后端 `is_cover DESC, cover_order ASC, sort_order ASC` 排序保证，前端直接用返回顺序，未重排
  - 边界保护：删除/批量删除当前页最后一条后 `items 为空且 page>1` 自动回退一页，避免空白页
  - `moveCover()` 封面排序成功后由「全量数组直接赋值 artworks」改为 `await loadArtworks()`（否则会破坏分页语义）；删除/上传/编辑/封面操作后的刷新链路已统一走 `loadArtworks()`
  - 分页接口自带 `size_tag_ids`，编辑弹窗档位回显不受影响（与老接口一致）

### B. 客户端 T2 gallery 模板「加载更多」（10/页）
- `web/src/components/templates/TplGallery.vue`（共享组件，向后兼容）
  - 新增可选 props `total`（默认 0）+ `loadingMore`（默认 false）+ `defineEmits(['load-more'])`
  - 画廊末尾加「加载更多」按钮：`v-if="hasMore"`，`hasMore = total>0 && props.artworks.length < total`
  - **口径说明**：用 `props.artworks.length`（父组件累积的原始条数，含封面）与后端 `total`（含封面）比较——若用 filteredArtworks 会因封面被过滤而永远小于 total，按钮永不消失
  - **其他模板零影响**：classic/atelier/folio 不传 total → hasMore=false → 按钮不渲染，行为与现状一致
- `web/src/views/client/templates/ArtistHomeGallery.vue`（T2 gallery 模板）
  - 数据源由「props 全量数组」改为调公开分页接口 `getPublicArtworksPaged(artist.id, { page, pageSize: 10 })`，`onMounted` 首载 + `watch artist.id` 画师切换重载
  - `pagedArtworks` 累积 + `total` + `loadingMore`；`onLoadMore()` 翻页追加
  - **size_tags 合并（关键决策）**：公开分页接口 items **不带 size_tags**（后端契约如此），但 F6 档位筛选/大图标签依赖 `art.size_tags`。方案：用 F6 画廊端点全量数据（ArtistHome 已拉取的 `props.gallery.artworks`）建 `id → size_tags` Map，分页 items 到达后按 id 合并——**F6 筛选/标签功能不回归**
  - 传 TplGallery 时 `:gallery="galleryFilterOnly"`（只留 filterSizes，artworks 置空）——避免 TplGallery 优先读 gallery.artworks 全量，分页才真正生效
  - 加载中画廊区隐藏（`pageLoading` 时返回空数组），避免「全量闪一帧」；分页失败静默回退全量兜底（行为与现状一致）
- 红线检查：只改 T2 gallery 模板；classic/atelier/folio 模板文件零改动；未循环拉取（手动点按钮才拉下一页）

## 三、审计要点/遗留说明

1. **公开分页接口不带 size_tags 是契约事实**（`getPublicArtworksPaged` 直接返回裸 Artwork[]，仅画师端 paged 有 size_tag_ids）。本批前端用 F6 画廊端点做 id 索引合并保住了筛选/标签功能；**若后续其他模板照抄时注意此坑**，或建议后端公开分页接口未来也带 size_tags（可选优化，非本批范围）
2. **其他 3 模板未做分页**：施工图红线「先 T2 gallery 改通，其余模板照抄」——TplGallery 已具备分页能力（total/load-more），classic/atelier/folio 照抄时只需在各自模板加分页状态 + 传 total（父组件数据链路与 T2 相同）
3. **hasMore 口径**：基于父组件累积原始条数（含封面）对比 total，与后端 total 含封面一致；封面去重发生在 TplGallery 展示层，不影响按钮判断
4. 本地实测产生的 `server/data/commission.db`、`server/uploads/images/2/` 测试图片均在 gitignore 内，未入库；临时脚本/配置（vite.local.config.mjs、capture.mjs 等）已删除，两仓 git status 干净
5. 未推送、未合并，等待一号审核
