## 一、🔴 真实隐患（会导致 bug/安全问题，按严重度排序）

### R1（严重度：中）POST /api/anon-token 无节流 + events 限流可被新 token 绕过
- 位置：`server/src/features/tracking/tracking.routes.ts:44-46`（anon-token 签发）+ `:76`（限流 key）
- 问题：① `/api/anon-token` 无鉴权、无限流，每次调用向 `anon_tokens` 表 INSERT 一行（每次拿到一个新凭证）；② `/api/events` 限流 key = `body.token || request.ip`（tracking.routes.ts:76），攻击者可循环「签发新 token → 用新 token 发 50 条事件」完全绕过 IP 限流。
- 影响：`anon_tokens` + `events` 两张表可被无限刷大（v44 迁移 init.js:1650-1675 无任何清理 job），磁盘膨胀 + 统计口径被污染。非数据泄露/非核心数据破坏，故定「中」。
- 建议（低成本）：anon-token 签发加 per-IP 限流（如 10 次/分钟）；`events` 限流 key 改为 `${request.ip}:${token}` 双因子。
- 处置建议：记待办，下个安全批顺手做。

### R2（严重度：低）app.ts 签名 hook 对非法编码 URL 抛 500 + 同一 URL 解码两次
- 位置：`server/src/app.ts:186`（`decodeURIComponent(request.url.slice('/uploads/'.length)...)` 无 try/catch）
- 问题：`isPublicUploadPath`（file-sign.ts:72-80）内部已 decode 一次（带 try/catch，失败返回 false），此处再次 decode 且无保护。请求 `/uploads/%` 这类非法百分号编码 → `URIError` → onRequest hook 抛异常 → 500 + 错误日志刷屏（每次攻击请求都刷一条）。
- 影响：恶意请求可制造 500 错误噪音（非漏洞，无数据泄露）；同 URL 两次解码是冗余逻辑。
- 建议：复用 `isPublicUploadPath` 的解码结果（或抽公共 `safeDecode`），decode 失败按 400/403 处理而非抛错。
- 处置建议：记待办，随安全/环境批处理。

### R3（严重度：低）tracking.service 注释与实现矛盾——「滚动续期」实际是固定 30 天过期
- 位置：`server/src/features/tracking/tracking.service.ts:16`（注释声称滚动续期）vs `:70-78`（`resolveAnonToken` 查询只按 `created_at`，`UPDATE last_seen_at` 只写不读）
- 问题：注释写「30 天滚动（last_seen_at 更新即续期；查询时 created_at 30 天内有效）」——设计意图是活跃用户滚动续期，实现是「签发后固定 30 天过期」。活跃用户 30 天后凭证静默过期（前端 track.js 有静默重取兜底，用户无感，故不致命）；`last_seen_at` 列成为死列（写但从不读）。
- 建议：二选一——① 查询条件改 `COALESCE(last_seen_at, created_at) > datetime('now', ?)`（真正滚动续期）；② 保持现状但改注释 + 删除 last_seen_at 列（减少死代码）。
- 处置建议：记待办（行为无感，但注释误导会坑后人）。

### R4（严重度：低）GalleryPanel 拖拽：dragleave 无防闪烁 + 双 dragover 依赖微妙 DOM 语义
- 位置：`web/src/components/artist/order/GalleryPanel.vue:22-24`
- 问题：① `@dragleave="emit('update:isGalleryDragOver', false)"` 无 `relatedTarget` 检查——拖拽在磁贴内子元素（icon/span/input）间移动会触发 dragleave → 高亮闪烁。对比 OrderDetail.vue:243 备注区的 `onNoteDragLeave` 有 `e.currentTarget.contains(e.relatedTarget)` 防闪烁（同一页面两种写法，不一致）；② `@dragover.capture="emit('dragover', $event)"` + `@dragover.prevent="emit('update:isGalleryDragOver', true)"` 双监听，正确性依赖 useDropGuard 的 `stopImmediatePropagation`（useDropGuard.js:44-48 先于普通监听阻断）——已核实逻辑成立（系统文件拖拽时 guard 放行、页内拖拽时 stopImmediatePropagation 阻止 prevent 监听），但属微妙依赖，无注释说明。
- 影响：拖拽高亮闪烁（视觉小瑕疵）；双监听理解成本高。
- 建议：dragleave 加 `relatedTarget` 防闪烁（抄 OrderDetail 备注区写法）；双监听处加一行注释说明依赖。
- 处置建议：可忽略或随拆分后续批顺手修。
