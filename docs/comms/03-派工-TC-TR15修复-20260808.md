## 根因（一号已核实）

`server/tests/tracking.test.js` TC-TR-15（行 ~340-368）：
- 测试先插 2 条事件，再把 MIN(id) 一条 `UPDATE ... created_at = datetime('now','-1 day')`
- 断言用 `fmt(new Date(Date.now() - 86400000))` 算「昨天」——**`Date.now() - 86400000` 是本地时间昨天，但 created_at 存 UTC**，凌晨（UTC 日期还没到第二天）时本地昨天 ≠ UTC 昨天，分组错位 → `expected 2 to be 1`

## 施工图

**只改测试文件** `server/tests/tracking.test.js` TC-TR-15，**不动业务代码**（tracking.service.ts 的 byDay 口径是对的——按 localtime 分组，生产行为正确，测试断言写错了）。

修复方案（选一，推荐 A）：

**方案 A（推荐，最小改）**：断言改用与 SQL 同口径的本地日期计算：
```js
// 昨天/今天用与 SQL 一致的 localtime 口径（UTC 存储 → localtime 分组）
function localDayStr(offsetDays) {
  const d = new Date()
  d.setDate(d.getDate() + offsetDays)  // 本地日历日偏移（处理跨日/跨月）
  return `${d.getFullYear()}-${String(d.getMonth() + 1).padStart(2, '0')}-${String(d.getDate()).padStart(2, '0')}`
}
// 替换原来的 fmt(new Date(Date.now() - 86400000)) / fmt(new Date())
expect(countByDay[localDayStr(-1)]).toBe(1)
expect(countByDay[localDayStr(0)]).toBe(2)
```
> 关键：`setDate(getDate()+n)` 走本地日历日（跨月/跨年正确），而 `Date.now()-86400000` 走 UTC 偏移（跨日边界错）。断言必须匹配 SQL `strftime('%Y-%m-%d', created_at, 'localtime')` 的口径。

**方案 B**：把测试改成不依赖「今天」——用 `strftime('%Y-%m-%d','now','localtime')` 从 DB 取今天，再算昨天（SQL 侧统一）。更稳但改动大，不推荐。
