## 函数签名清单（pricing-engine.ts）

```ts
// R1：Σ 条目 delta = 订单应收总额
sumEntryDeltas(entries: PriceEntry[]): number

// R3：初始分配（与现有 recalcInstallmentAmounts 语义一致：round + 末节点吸尾差，ratioTotal = Σbp/10000）
allocateInitial(installments: EngineInstallment[], totalCents: number): number[]

// R4：锁价状态（完成 OR 付清先到先锁；prevLockedFlags 支持回退不解锁；返回 paidCents 顺序填充结果）
computeLockedState(installments, paidTotalCents, completedStageIndex = -1, prevLockedFlags?): LockedState

// R5/R6/R10：delta 分摊（未锁节点按原始 bp 归一化，floor + 尾差归最后未锁；全锁进额外应收/应退；负 delta 受 R8 下限约束）
allocateDelta(installments, lockedFlags, deltaCents): AllocateDeltaResult

// R7/R8：顺序填充 + 超付抵扣（尾款待收可为负，非尾款最低 0）
deriveInstallmentProgress(installments, paidTotalCents): ProgressRow[]

// R9/R10：退款镜像填充（从尾往头冲未锁节点待收，冲到底尾款变负；全锁进额外应退）
applyRefund(installments, lockedFlags, refundCents): RefundResult

// R11：三条守恒断言，失败抛 AppError(PRICING_CONSERVATION, 500)
assertConservation(input: ConservationInput): void
```

所有函数纯函数、无副作用、金额全为整数「分」；入参乱序时内部按 sortOrder 配对排序，lockedFlags 永不错位。

| 规则 | 实现位置 |
|------|---------|
| R1 总价条目化 | `PriceEntry` 类型（7 种 type 与迁移 v39 CHECK 一一对应）+ `sumEntryDeltas` |

## 给一号审核的备注

1. **A2 断言表述**：REQ-025 R11.2 原文「总价 − 已收总额 = Σ 节点待收」在关单后收款场景（如收齐后加 50：已收=500，待收Σ=0）不成立；实现为「总价 − 已收 = Σ待收 + 额外应收 − 额外应退」，关单前额外项为 0 时与原文等价，关单后收支场景（案例 1 末行/案例 5）守恒闭环。A1 与原文一致。
2. **applyRefund 语义**：冲的是未锁节点「待收」（等价降价），与 R9 原文「冲未锁节点，冲到底尾款变负」严格对应；不是冲已收。
3. **allocateDelta 负 delta 封顶**：非尾款未锁节点最多减掉自身待收，超出压给最后未锁节点（案例 8），避免非尾款节点价为负。
4. **setup.js 一行改动**超出授权清单（测试隔离必要），已在文件表声明。
5. 第二阶段建议：createOrder 写 base 条目 + updateFinalPrice/addExtraItem 切 allocateDelta 时，注意 computeLockedState 需要调用方维护 prevLockedFlags 持久化（DB 需加 locked 字段，属第二阶段迁移）。
