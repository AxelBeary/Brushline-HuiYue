## 一、改动概要

### H1 封禁升级为两步确认

- 举报管理页（`ReportManage.vue`）封禁流程改为：第一步填写原因并确认（沿用原 prompt）→ 提交；若后端返回 `401 STEP_UP_REQUIRED`，弹 `StepUpDialog` 动态口令升级确认 → 验证通过后自动重提交封禁请求。
- 接线方式与画师管理页「更换管理员」的既有 StepUpDialog 模式完全同款（提交遇 `STEP_UP_REQUIRED` → 弹窗 → `verified` 后自动重提交；`cancel` 不重提交并释放行级 loading）。
- 后端 `/api/admin/artists/:id/ban` 已有 step-up 守卫（`registerAdminStepUpHooks` 自动挂到所有 `/api/admin` 路由，30 分钟窗口），按任务要求直接复用，未新增后端守卫。
- 封禁原因可空语义未变（原实现与文案均为「可选」，任务边界「必填语义不变」即保持现状不变）。
- 封禁后行为（登录提示、小店 404 隐身）未触碰。

### H2 补解封入口

- 画师管理页（`ArtistManage.vue`）：被封禁画师行显示「已封禁」标签 + 「解封画师」按钮（管理员行除外，后端本就有管理员账号不可操作防护）；解封同样走「填原因 → 必要时 StepUpDialog 升级 → 调接口」的对称两步确认，成功后即时刷新列表。
- 举报管理页：`artist_home` 类举报行按目标画师当前封禁态切换按钮——未封禁显示「封禁画师」，已封禁显示「解封画师」，两步确认与封禁对称，成功后即时刷新。
  - 封禁态来源：复用现有 `GET /api/admin/artists` 返回的 `is_banned` 字段（服务端 `publicArtistDTO` 透传、`getAllArtists` 显式列包含该字段），前端维护「被封禁画师 id 集合」。画师列表拉取失败不阻塞举报列表，此时按未封禁展示（解封入口仍在画师管理页可用）。
- 解封留痕：复用现有 `POST /api/admin/artists/:id/unban` → `complianceService.setArtistBanned(false)`，写 `admin_actions.artist_unban`（现状核实确认已存在）。
