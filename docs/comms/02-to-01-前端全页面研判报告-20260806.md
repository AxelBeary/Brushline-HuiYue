# 绘约「Brushline-HuiYue」前端全页面研判报告

> 日期：2026-08-06 · 分析师：二号（客户页面前端）
> 范围：web/src/views 全部 29 个页面 + 共享/模板组件 + 样式体系（不包含 server 后端）
> 方法：代码逐页审计 + 浏览器实测（本地 Playwright + 独立测试库 3998 端口，亮/暗双主题采样）+ computed-style 量化取证
> 约束：只读分析，未改动任何代码

---

## 总体结论

**代码工程质量高、功能完备、无 JS 崩溃（实测 9 个页面 console 零错误）；但「客户可见页面」存在一条贯穿全站的主线割裂：4 模板主页（精心设计的宣纸/美术馆视觉）与下单/查单/交付/落地等流程页（Element Plus 默认后台风）是两套视觉语言。** 核心根因是样式体系分层断裂（theme.css 的 EP 主色覆写被覆盖 + palette 配色只作用于画师主页），属于「一次修一处、处处受益」的 T0 级问题。

按严重度：**P1 共 2 项（视觉一致性主线）、P2 共 6 项、P3 共 6 项**。无 P0 级功能性崩溃。

## 一、美观性（视觉）

### M1【P1】全站 EP 组件主色覆写失效——「品牌青 + EP 默认蓝」两套主色并存

**证据（浏览器实测，所有页面一致）：**
- `--color-primary`（品牌青）= `#34dbcb`（亮）/ `#4de8d9`（暗）✓ 正确
- `--el-color-primary` = **`#409eff`（Element Plus 默认蓝）** ✗ 覆写未生效
- 样式表取证：`theme.css` 的 `:root { --el-color-primary: var(--color-primary) }`（order 0）被 `element-plus base.css` 的 `--el-color-primary: #409eff`（order 1，后加载）**覆盖**

**影响：** 落地页「进入主页」按钮、下单页「下一步/提交」、查单页「查询」等所有 EP 组件是**默认蓝**；而 4 模板主页的自定义按钮（`.tpl-btn`、`.classic-cta`）是**品牌青**。客户在同一站点、甚至同一次旅程（主页→下单页）内看到两套主色。这是「视觉一致性」第一问题。

**修法（T0，纯前端）：** 把 EP 主色覆写放到所有 EP CSS 之后（单独 `ep-override.css` 后置引入，或 `:root:root` 提升优先级），一行改动全局生效。

---

### M2【P1】客户流程页不跟随画师 palette 配色——主页「宣纸感」与流程页「后台灰白」断裂

**证据（浏览器实测）：**
- Alice 主页：`data-palette="paper"`，背景 `--pal-bg` = `#faf8f5`（暖宣纸）
- 下单页/查单页/交付页：`data-palette = null`，背景 `--bg-page`（后台主题变量），卡片 `#ffffff` + 4px 圆角 + 深投影

**影响：** 客户从画师主页（LXGW 文楷、暖纸底、圆角信息卡）点「我要约稿」，瞬间进入 EP 后台灰白表单页。画师精心选的 4 配色 5 主色只作用于主页一屏，流程页完全不受控。**模板差异化没有延伸到订单旅程**——客户旅程最重要的三步（下单/查单/交付）全是默认皮肤。

**修法（T0-T1）：** 流程页挂接 `usePalette`（或读取子域画师 paletteId）+ 流程页样式从 `--bg-page` 切换到 `--pal-*` 语义变量；EP 组件在流程页的覆写（卡片圆角、主色）随 M1 一并解决。

---

### M3【P2】下单/查单/交付页 = Element Plus 组件堆砌（「管理系统穿了便装」）

**证据（代码）：**
- `TrackOrder.vue`：整页 `el-card` + `el-page-header` + `el-descriptions border` + `el-alert` + `el-steps` + `el-progress`，无任何模板化样式
- `DeliveryPage.vue`：同款 `el-card` + `el-result` + `el-empty`
- `OrderForm.vue`：主表单包在 `el-card` 内，EP 默认 input 大间距

**影响：** 客户旅程 3 个核心页面的视觉语言与 4 模板主页（自绘按钮/卡片/留言板）完全不同。功能可用，但「品牌感」在关键转化页缺失。

**修法（T0-T1）：** 为流程页做轻量模板化皮肤（沿用主页的圆角/主色/字体 token），不需要重写组件，用 CSS 覆写 + token 挂接即可。

---

### M4【P2】4 模板残留 v0.25「封面精选」死样式（约 150 行）

**证据（代码）：** 模板中已无 `.classic-covers`/`.gallery-covers`/`.folio-covers`/`.atelier-cover-polaroid` 等元素（v0.36 画廊改版后删除），但样式保留：
- `ArtistHomeClassic.vue` L133-164（`.classic-covers`/`.classic-cover-show`）
- `ArtistHomeGallery.vue` L128-169（`.gallery-covers`/`.gallery-cover-frame`）
- `ArtistHomeFolio.vue` L214-269（`.folio-covers`/`.folio-cover-show`）
- `ArtistHomeAtelier.vue` L144-195（`.atelier-covers`/`.atelier-cover-polaroid`）

**影响：** 死代码增加包体与维护噪音；若未来复用容易造成「样式存在但行为已变」的困惑。

**修法（T0）：** 删除无引用样式块（可先用 CSS 使用率扫描确认无动态引用）。

---

### M5【P3】落地页（平台门户）全 EP 组件，模板感强

**证据（代码）：** `LandingPage.vue` 全篇 `el-card` + `el-avatar` + `el-tag` + `el-button`，卡片 4px 圆角、居中布局；实测按钮为 EP 默认蓝（M1 连带）。

**影响：** 平台第一屏是「后台管理系统穿了便装」。画师主页 4 模板再精美，落地页仍是门户模板感。

**修法（T1）：** 落地页画师卡片做轻定制（圆角/字体/主色 token 对齐 4 模板），无需重设计。

---

### M6【P3】NotFound 页按钮硬编码 `#fff`

**证据：** `NotFound.vue` L96 `.not-found-home-btn { color: #fff }`——暗色/特殊配色下对比度未走 token。低风险，顺手项。

## 二、功能性

### F1【P1】下单页旧模型倍率区硬编码中文（i18n 违规，6 处）

**证据（代码）：** `OrderForm.vue` 旧档位模式倍率区：
- L72 `label="用途与加急"`（应为 `$t('orderForm.multiplierLabel')`）
- L75 `用途：`（应为 `usageLabel`）
- L77 `个人`（应为 `personal`）
- L84 `加急：`（应为 `rushLabel`）
- L86 `不加急`（应为 `noRush`）
- L127 `总价`（应为 `receiptTotal`）

**关键对比：** 同文件画风模式倍率区（L240-258）已全部走 `$t()`。**新旧代码不一致**——无画风数据的画师（旧档位模式）在下单页会看到硬编码中文；切英文界面后这 6 处仍是中文。

**修法（T0）：** 6 处替换为既有 i18n 键（键已存在，零新增）。

---

### F2【P2】vite.config.js 注释乱码（文件编码污染）

**证据：** `web/vite.config.js` L8-10 注释为 GBK 被当 UTF-8 读取的乱码（"EP 鎸夐渶寮曞叆"等）。

**影响：** 维护者读配置会看到乱码注释，且提示该文件曾被错误编码写入（同文件可能有隐性编码问题）。不影响构建。

**修法（T0）：** 重写注释为 UTF-8。

---

### F3【P2】Folio 模板锚点导航只覆盖 2 个区块

**证据（代码）：** `ArtistHomeFolio.vue` L163-166 `navItems = [gallery, pricing]`，但页面实际有 4 个内容区块（作品/价格/须知/留言板）。「约稿须知」「留言板」不在导航内，客户无法直达。

**影响：** 单页导航的「信息架构」不完整；长页客户想看须知得手动滚动。

**修法（T0）：** navItems 补 rules/guestbook（或按内容多寡决定是否纳入）。

---

### F4【P2】TplHero split 变体两张作品图叠放有遮挡风险

**证据（代码）：** `TplHero.vue` L72-81：两张图各 `width: 78%`，`rotate(-1.25deg/+1.25deg)` 对角摆放（第一张 top-left、第二张 bottom-right）。当作品图宽高比接近时，两张 78% 宽的图在中部可能重叠（未在实测数据中触发，因为 Alice 作品较少——标注为待验证观察项）。

**影响：** 视觉上可能出现「两张图糊在一起」的布局事故。

**修法（T1）：** 视真实作品集验证后，缩第二张图尺寸或改为交错百分比。

---

### F5【P2】查单页「该 QQ 无订单」强制 3 秒锁弹窗

**证据（代码）：** `TrackOrder.vue` L151-161：`close-on-press-escape=false` + `show-close` 倒计时才显示 + 确认按钮倒计时禁用。用户输错/输错 QQ 后**被强制停留 3 秒**（防滥用设计）。

**影响：** 真实客户输错一次就被锁 3 秒，体验惩罚偏重（尤其移动端）。

**修法（T1）：** 缩短倒计时（如 1-2s）或改为「提示后自动关闭」，保留防滥用下限即可。

---

### F6【P3】交付/查单下载无进度与失败反馈

**证据（代码）：** `DeliveryPage.vue` L71-73、`TrackOrder.vue` L251-253 `window.open(url, '_blank')`——直接开新标签。签名 URL 过期时客户看到 403/空白，无任何提示；下载大文件无进度。

**修法（T1）：** 改用 `<a download>` 或 fetch→blob 下载，失败时 ElMessage 提示。

## 三、实用性

### U1【P2】查单结果页缺「需求描述/参考图」回顾

**证据（代码）：** `TrackOrder.vue` 结果卡片只有：画师/档位/下单时间（el-descriptions 3 行）+ 排队位置 + 状态步骤 + 自定义时间线 + 价格。**客户看不到自己提交的需求描述和参考图**——「查单」是客户回忆约定内容的关键场景（我约了什么？），此信息缺失。

**影响：** 客户只能靠记忆核对画师是否理解需求；纠纷场景无凭据可查。

**修法（T1）：** 后端 track 响应已含 description/references 字段（SPEC-003 有回传）则纯前端展示；否则需后端补字段。

---

### U2【P2】移动端 Gallery/Atelier 公告浮层与展签可能重叠

**证据（代码）：** `ArtistHomeGallery.vue` L171-189 公告 `absolute; top:32px; left:32px; max-width:320px`；`ArtistHomeAtelier.vue` L197-218 公告 `absolute; right:40px; bottom:40px; max-width:280px`——fullscreen hero（100vh）上两处浮层在 375px 宽窄屏时可能与展签/CTA 重叠（未实测触发，观察项）。

**修法（T1）：** 窄屏断点下让公告回到文档流或收窄宽度。

---

### U3【P3】落地页画师卡片无图片懒加载/骨架屏

**证据（代码）：** `LandingPage.vue` L12-40：`el-card` 网格 + `el-avatar`（80px），无 `lazy` 无 skeleton；加载中 `v-loading` 整页遮罩。

**影响：** 平台画师多时首屏慢；体验平庸（对比主页 TplGallery 已有 aspect-ratio 占位 + lazy，落地页反而没跟上）。

**修法（T0）：** 头像加 `lazy`，卡片加骨架占位。

---

### U4【P3】查单页两套进度展示并存（el-steps + 自定义时间线）

**证据（代码）：** `TrackOrder.vue` L63-69 通用 5 步 `el-steps` + L72-88 画师自定义流程 `OrderTimeline`——两个进度组件同时渲染（自定义流程存在时）。客户看到「提交→确认→制作→完成→交付」和画师自定义节点两套进度，可能困惑哪套为准。

**修法（T1）：** 有自定义流程时隐藏通用 5 步（或反之），明确主从。

---

### U5【P3】画师后台巨型组件（已知遗留，标注观察）

`OrderDetail.vue` 1731 行 / `QueueBoard.vue` 1530 行 / `ManualOrder.vue` 1302 行——STATUS 已记录「巨型组件拆分单独排期」。本报告确认现状，不重复展开。

## 四、环境观察（非前端代码问题）

1. **3000 端口被神秘占用**：`EADDRINUSE` 但 netstat 查不到监听者（疑似 Docker 容器映射或宿主其他服务）。本次实测绕道 3998 完成。开发时如需 3000，建议先 `netstat -ano | findstr 3000` 排查宿主/容器。
2. **多 worktree 并行 dev server 端口争抢**：5173（fix1 worktree）、3999（of worktree）、3000（未知）已被并行会话占用；vite 会自动退避到 5174（本次已验证），server 不会自动退避。
3. 启动 server 时触发了宿主 `data/commission.db` 迁移 v10-v19（自动备份 `.bak.vN`）——正常开发行为，仅提示注意。
