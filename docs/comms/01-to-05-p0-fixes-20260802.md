## P0-1：resetArtistStages 禁止有活跃订单时重置

**方案**：有活跃订单（status NOT IN delivered/cancelled）时，重置接口返回 400 拒绝。

**实现**：
- `workflow.service.ts` resetArtistStages 开头加检查：
```ts
const activeCount = db.prepare(
  "SELECT COUNT(*) as c FROM orders WHERE artist_id = ? AND status NOT IN ('delivered', 'cancelled')"
).get(artistId).c
if (activeCount > 0) throw new AppError(E.STAGES_RESET_BLOCKED, 400, { count: activeCount })
```
- `errors.ts` 新增 `STAGES_RESET_BLOCKED`，消息："有 {count} 个进行中订单，请先完成或关闭流程跟踪后再重置工作流"
- 测试：有活跃订单 → 400；无活跃订单 → 正常重置

**工程量**：~30min

## P0-2：价格加减法替代 recalcFinalPrice 重算

**方案**：干掉"从头算"逻辑，改为加减法。手动改价不会被后续增项操作覆盖。

**实现**：
- `order.service.ts` 的 `recalcFinalPrice(orderId)` 改名为 `adjustFinalPrice(orderId, deltaCents)`：
  - 读当前 `final_price_cents`（null 时回退 `total_price_cents`，再 null 则 0）
  - `newFinal = currentFinal + deltaCents`
  - 写回 `final_price_cents = newFinal`
- 添加增项时（addExtraItem）：`adjustFinalPrice(orderId, +extraItem.price_cents)`
- 删除增项时（removeExtraItem）：`adjustFinalPrice(orderId, -extraItem.price_cents)`
- 手动改价（updatePrice）：直接写 `final_price_cents = newPrice`，不变
- 下单创建时：`final_price_cents = total_price_cents + Σ增项`（初始值，不变）
- **注意**：检查所有调用 recalcFinalPrice 的地方（L565, L604），全部改为 adjustFinalPrice + 对应 delta
- 测试：改价 → 加增项 → final = 手动价 + 增项（不是 total + 增项）

**工程量**：~1h
