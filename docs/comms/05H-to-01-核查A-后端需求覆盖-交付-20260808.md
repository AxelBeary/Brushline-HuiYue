1. **login_codes 表残留（R7 一刀切未彻底，低风险）**：v41 已 DROP TABLE login_codes（`db/init.js` L1556），但 schema 段 L286 `CREATE TABLE IF NOT EXISTS login_codes` 每次启动执行会**重建空表**（注释明示"此处保留仅维持迁移链完整"——v13 迁移 ALTER 依赖此表存在）。后果：运行库存在空 login_codes 表，但**全仓 0 代码引用**，无功能影响。建议后续某版把 v13 迁移改为不依赖 login_codes 后再删 schema 声明（非阻塞）。
2. **demo-data 直插 orders（切流形式与 REQ 建议有差异，但守恒兜底已就位）**：REQ-025 §8.2 建议演示订单"改走与真实订单完全相同的入口 createOrder"；现状 `scripts/demo-data.ts` L272 仍直插 INSERT orders，但已补齐新模型四要素（base 条目 + 引擎分期 + 守恒自检 + 完整性校验）。功能等价、守恒兜底生效；"完全走 createOrder"未严格兑现——属实现形式差异，非功能缺口。
3. **REQ-027 防爆破时长**：REQ 建议「5 分钟内连续错 5 次锁定」，实现为 `TOTP_LOCK_DURATION_MS = 15 * 60 * 1000`（15 分钟）。比建议更严，方向一致，非缺陷。
