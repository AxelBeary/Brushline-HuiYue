## 设计决策

### 任务 A：platform_urls 用 JSON 列（非独立表）

理由：平台链接是画师的属性，数量少（≤10），无独立查询/关联需求。JSON 列与现有 custom_links 模式一致，无需 JOIN，读写简单。

存储格式：`[{url, platform}]`，platform 为写入时识别/手动选择的最终值。读取时补充 label 显示名。

### 任务 B：inspiration_tags 用 JSON 列

存储格式：`["标签1", "标签2"]`，service 层去重 + 去空白 + 截断 20 个。

### 平台识别覆盖

pixiv / x(twitter) / weibo / lofter / bilibili / xiaohongshu / other（兜底）

## 接口变更

### PUT /api/artist/profile（新增字段，向后兼容）

```json
{
  "platformUrls": [{"url": "https://...", "platform": "pixiv"}],
  "inspirationTags": ["赛博朋克", "水墨"]
}
```

- platformUrls: 可选，≤10 条，url 必须 https?://，platform 可选（不传则自动识别）
- inspirationTags: 可选，≤20 个，每个 ≤30 字符

### GET /api/artists/:subdomain（新增字段，向后兼容）

响应新增：
```json
{
  "platformUrls": [{"url": "...", "platform": "pixiv", "label": "Pixiv"}],
  "inspirationTags": ["赛博朋克"]
}
```

未设置时返回空数组。hidden 状态不暴露（走现有最小信息逻辑）。

### GET /api/artist/profile（无变更）

展开原始 DB 行，含 platform_urls / inspiration_tags 原始 JSON 字符串。
