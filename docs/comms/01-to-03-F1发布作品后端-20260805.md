## 任务：新增 `POST /api/orders/:id/publish-artwork`（画师登录）

**请求体**（schema `additionalProperties:false`）：
```
{
  deliverableIds: number[]   // ≥1，且必须全部属于本订单
  title: string              // 非空，≤100
  description?: string       // 可选，≤500
}
```

**成功 201**：`{ artworks: [ { id, imagePath, title, description }, ... ] }`（每张图一条，camelCase）

**失败**：
- `404` 订单不存在 / 交付物不存在
- `403` 订单不属于当前登录画师（防跨画师发布）
- `400` 订单非 delivered / deliverableIds 为空 / title 为空或超长
- deliverableIds 重复：**去重后处理**（不报错），报告注明

## 后端行为要点（逐条落实）

1. 订单归属 + 状态 `delivered` 校验（参考现有订单端点的归属校验写法，别另起一套）
2. **文件复制（非移动）**：把每张选中交付物从私有目录复制到公开目录，artworks 记新路径；**原交付物保留不动**（客户交付页仍可下载）。目录约定见 `server/src/shared/file-sign.ts` 注释（deliverables/{artistId}/ 签名私有 / images/ 公开）。
   - **先 grep 现有 artwork 上传/保存链路**（artworks.image_path 是怎么生成与被静态服务的），复制后的路径必须走同一套可访问约定，别自创新目录。
   - ⚠️ **R-1a 安全点**：只复制画师勾选的那几张，绝不整单批量公开。路径防御对齐现有 `..`/前缀校验（grep `order.routes.ts` 的 H-3 模式，取现行写法）。
3. 每张图插一条 artworks：`image_path`=复制后路径、`title`/`description`=入参、`is_cover`=0、`cover_order`=NULL。
4. **标题处理**：所建每条作品都用同一 title（若用户后续要"标题+序号"区分，属下一批，本批不做，报告注明）。
