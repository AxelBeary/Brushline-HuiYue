## 做了什么

### B1（代码）压缩 + 静态资源缓存头

1. **Caddyfile 加压缩**：`encode zstd gzip`（Caddy 2 内置，无需插件）。位置在 `{$DOMAIN}` 站点块内、`reverse_proxy` 之前。
2. **缓存头（app.js 静态路由层，不经 Caddy 也生效）**：
   - `/assets/*`（vite hash 产物，含 woff2 字体）→ `Cache-Control: public, max-age=31536000, immutable`
   - `index.html` / SPA fallback → `Cache-Control: no-cache`（发版即生效）
   - 其余真实文件（favicon 等）→ `public, max-age=300`（短缓存，避免裸文件与 index.html 同策略）
   - 未动 `/api/*` 与 `/uploads/*` 缓存语义。

### B2（代码）uploads 响应头区分公开/签名

- **公开路径**（`isPublicUploadPath`，images/）：去掉强制下载头 → `Content-Disposition: inline` + `Cache-Control: public, max-age=86400`
- **签名路径**（references/deliverables/notes）：保持 `Content-Disposition: attachment` + 补 `Cache-Control: no-store`（签名 URL 不被缓存）
- **签名校验逻辑零改动**：无签名/假签名仍 403（TC-ENV-05 + 实测 ⑤⑦ 均验证）
- 实现：`setHeaders(res, filePath)` 第三参是绝对路径，用 `relative(UPLOAD_DIR, filePath)` 还原相对路径，再走 `isPublicUploadPath()` 判定——**判定逻辑与 onRequest 钩子完全一致**，不会出现"访问控制与响应头语义分叉"。

见下节「B3 方案」。

## B3 方案（等用户拍板后实施，本批未动 compose）

### 方案甲：A 测期间保留 `3000:3000`

- **做法**：docker-compose 维持现状（`ports: 3000:3000` 注释掉的生产注释仍在），A 测画师直连 `http://服务器IP:3000` 访问。
- **对 A 测剧本影响**：四号手册里的 URL 就是 `http://<IP>:3000`，**零改动**。浏览器直接访问，无需域名/证书/HTTPS。画师可先在手机/电脑浏览器验证完整流程。
- **风险**：3000 端口直接暴露公网（若服务器有公网 IP），HTTP 明文。配合 AUTH_DEV_MODE 关闭后登录靠 TOTP，可接受，但仍是明文链路。建议：A 测期间若能加简单口令/防火墙白名单更好。

### 方案乙：现在就注释掉 `3000:3000`，A 测走 Caddy + 域名

- **做法**：注释 compose 的 ports 两行（保留 expose），A 测访问 `https://<域名>/artist/:subdomain`（Caddy 自动 HTTPS，需 DOMAIN 环境变量 + DNS 指向 + 80/443 放行）。
- **对 A 测剧本影响**：手册 URL 需全部改成域名，且**前置条件多**——域名注册/解析、证书自动签发（Let's Encrypt 需公网 80/443 可达）、Caddy 容器已部署。任何一环没就绪 A 测就无法开始。
- **风险**：部署前置多，A 测启动时间可能被拖。

### 我的推荐：**方案甲（A 测保留 3000）**

理由：
1. A 测是**真实画师第一批**，重点是功能正确性与真实反馈，不是安全边界演练。3000 直连最少依赖、最快开测。
2. 方案乙的前置（域名+证书）若未就绪，会阻塞 A 测启动——与"尽快开测"冲突。
3. 过渡路径清晰：A 测期间收集反馈 → 修完 → Caddy/HTTPS 上线时**一次切换**（注释 ports + 配 DOMAIN），代码零改动（本批 B1 压缩已就位）。
4. 明文风险可控：A 测周期短、画师数量少，且登录已走 TOTP；若担心可加防火墙白名单作为临时缓解。

**注意**：选方案甲的话，A 测期间 `AUTH_DEV_MODE` 关闭时管理员/画师全部走 TOTP（已就绪）；若服务器有公网 IP，建议部署时同时配防火墙仅放行 80/443（Caddy）或临时加 IP 白名单，把 3000 暴露面收窄。
