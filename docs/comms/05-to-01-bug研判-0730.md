## BUG-1：排期看板焦点图进入后疯狂闪烁（前端·二号）

**现象**：进入排期看板，焦点图反复闪烁数次才稳定。

**根因**：`QueueBoard.vue:48` 的 `@error="refreshNow"` 级联刷新。

链路：任一焦点图加载失败 → `refreshNow()` → 调 API 批量换新 **所有** 焦点图 URL → `apply()` 改写 `queue.value` 每项的 `focusImageUrl` → Vue 响应式触发全部 `el-image` 重渲染 → 所有图片重新显示骨架屏 → 加载 → 若再有失败则循环。

与 v0.15 UI-9（图库闪烁）同类问题，但 UI-9 只修了 OrderDetail 的 `.note-thumb` 背景色，QueueBoard 漏修。

**修复建议**（二号）：
1. `.focus-large-img` / `.focus-img-wrap` 加 `background: var(--bg-card)` 防白闪（同 UI-9 手法）
2. `refreshNow` 加防抖（300ms），避免多张图同时 error 触发多轮刷新
3. 加最大重试计数（如 2 次），超限后不再刷新，避免死循环
4. 可选：`apply` 只替换失败图的 URL，不全量替换

**涉及文件**：`web/src/views/artist/QueueBoard.vue`、`web/src/composables/useSignatureRefresh.js`

## BUG-2：非图片文件拖到图库加号无反馈（前端·二号）

**现象**：拖非图片文件（PDF、文本等）到订单图库的 "+" 上传区，区域高亮但松手后无任何提示，用户以为操作失败。

**根因**：`OrderDetail.vue:531-534` 的 `handleGalleryDrop` 静默过滤非图片：

```js
const files = [...event.dataTransfer.files].filter(f => f.type.startsWith('image/'))
if (files.length) uploadGalleryFiles(files)
// 非图片被丢弃，无 else 分支提示
```

`@dragover.prevent` 对所有拖拽都显示高亮（`isGalleryDragOver = true`），误导用户以为可以放置。

QueueBoard 的焦点图拖放（`handleFocusDrop`，:295-298）同样问题。

**修复建议**（二号）：
1. `handleGalleryDrop`：过滤后若 `files.length === 0` 且原始 `dataTransfer.files.length > 0`，`ElMessage.warning(t('orderDetail.galleryNotImage'))`
2. `handleFocusDrop`：同理，非图片拖入时给提示
3. 可选：`@dragover` 中检查 `event.dataTransfer.types.includes('Files')` 再高亮（无法在 dragover 阶段获取 MIME，但至少排除非文件拖拽）

**涉及文件**：`web/src/views/artist/OrderDetail.vue`、`web/src/views/artist/QueueBoard.vue`

## BUG-3：同一图片可重复加入订单图库（后端·三号 + 前端·二号）

**现象**：同一 `file_path` 可被多次插入 `order_references`，图库出现重复条目。

**根因**：`order.service.js:544-552` 的 `addReference` 无去重校验：

```js
export function addReference(orderId, filePath, fileName, fileSize, source = 'client') {
  const count = ... // 只查总量 ≤ 20
  // 无 (order_id, file_path) 唯一性检查
  db.prepare('INSERT INTO order_references ...').run(...)
}
```

`order_references` 表也无 `UNIQUE(order_id, file_path)` 约束（`init.js:103-106`）。

**修复建议**：
- **三号（后端）**：`addReference` 插入前查 `SELECT 1 FROM order_references WHERE order_id = ? AND file_path = ?`，已存在则抛 `AppError('REFERENCE_DUPLICATE')` 或静默返回（幂等）。`errors.js` 加错误码。
- **二号（前端）**：`uploadAndAttachReference` 捕获该错误码，提示"该图片已在图库中"。

**涉及文件**：`server/src/features/order/order.service.js`、`server/src/shared/errors.js`、`web/src/views/artist/OrderDetail.vue`

## BUG-4：比例条右拖节点无法正确回弹 5%（前端·二号）

**现象**：价格管理 → 流程与比例 → 收款比例条，向右拖动节点后松手，不回弹到 5% 且报错"请求参数不正确"。

**根因**：`PaymentBar.vue:121` 右拖弹性条件与左拖不对称：

| 方向 | 弹性触发 | 脱离触发 | 150~499bp 区间 |
|------|---------|---------|---------------|
| 左拖（:114） | `< MIN_BP(500)` | `< ELASTIC_THRESHOLD(150)` | ✅ 回弹 |
| 右拖（:121） | `< ELASTIC_THRESHOLD(150)` | 同上（同时） | ❌ 无处理 |

右拖时 right 节点 bp 落入 150~499：不触发弹性也不触发脱离 → `localBp` 保留非法值（如 300）→ `emitChange()` 发给后端 → schema `minimum: 500` 拒绝 → "请求参数不正确"。

**修复**（二号，一行条件 + 一行 detach）：

```js
// PaymentBar.vue:121 改为：
else if (newRight < MIN_BP && !rightIsFinal) {
    elasticId.value = rightId
    detachId.value = newRight < ELASTIC_THRESHOLD ? rightId : null  // ← 加这行
    newRight = Math.max(0, newRight)
    newLeft = startLeftBp + startRightBp - newRight
}
```

**涉及文件**：`web/src/components/artist/PaymentBar.vue`
