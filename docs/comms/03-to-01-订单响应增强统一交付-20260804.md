# 三号交付：B1 订单响应增强统一（收款区归零根因修复）

> 分支：v036-w2-backend（worktree wt-03）
> 派工：docs/comms/01-to-03-订单响应增强统一-20260804.md

## 做了什么

把 GET /api/artist/orders/:id 的增强逻辑抽成共享函数 `enrichOrderForArtist()`（order.routes.ts 内，signOrderUrls 之后），所有返回单个订单的画师端点统一走它。语义严格照抄原 GET /:id（`paid_total_cents ?? 0`、`final ?? total`、`remaining` 不为负、`startDate ?? null`），零语义变更。

## 改了哪些文件

- `server/src/features/order/order.routes.ts` — 新增 enrichOrderForArtist；GET /:id + 17 个变更端点统一改走它
- `server/tests/order-enrich-unified.test.js` — 新增 13 个测试（TC-EN-00 ~ TC-EN-12）

**非 order.value= 直接消费、但返回订单的端点也一并统一：**

| 端点 | 消费方式 | enrich |
|------|---------|--------|
| POST /deliver、/deliver-no-file | DeliverDialog @delivered → onDelivered → order.value = updated（第 1273 行，等价于 order.value 覆盖） | ✅ |
| PUT /priority | 失败时本地回滚，不覆盖 order.value | ✅（一致性） |
| DELETE /references/:refId | 成功后 loadOrder() 刷新，响应不直接用 | ✅（**顺手修隐藏缺陷：此前连签名 URL 都没有**） |
| POST /promote | QueueBoard 成功后刷列表，不覆盖 order.value | ✅（一致性） |

**明确不改：** POST /artist/orders/manual（创建端点，非变更端点）。ManualOrder.vue 仅用返回值的 `order.id` / `order.quote_snapshot` 做后续链式调用（改价/截稿日），不覆盖 order.value。派工范围是"返回订单的变更端点"，创建不在列。

## 验证结果

- 新增测试 13/13 绿：TC-EN-01（报障场景）断言加项后 paidTotalCents=20000 不归零、remainingCents=35000、installments 2 节点数值正确；TC-EN-02 改价同理；TC-EN-11 边界（无价格订单 remainingCents=null）；TC-EN-00 以 GET /:id 为基准锚点

- `npm run lint`（server）：零错误零警告

## 语义备注

- 加项/改价触发 `recalcInstallmentAmounts`（v0.31 F4）：节点应收按 basis_points 联动重算，已收金额可能不足以覆盖重算后的定金节点 → 状态从 paid 变 partial。这是既有正确语义，测试按此断言，非本修复引入。
- 无数据库变更。
