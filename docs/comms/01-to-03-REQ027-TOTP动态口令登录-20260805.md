## 一号已钉死的设计决策（照做，不另起方案）

1. **算法零依赖**：TOTP 是标准 RFC 6238，用 Node 内置 `crypto`（HMAC-SHA1 + 时间步长）实现，约 30 行，**不装第三方依赖**（用户预算为零，且避免供应链风险）。密钥用 `crypto.randomBytes` 生成，Base32 编码给二维码。
2. **校验窗口 ±1**（R3）：前后 30 秒有效。
3. **防爆破**（R4）：沿用现有登录码的量级——5 分钟内连续错 5 次临时锁定，明确提示（具体锁定存储与现有 login_attempts 机制对齐，你定）。
4. **恢复方案**（R5）：管理员后台「重置绑定」+ 服务器本机 CLI 命令兜底（可重置含管理员的任意账号，不经网络）。
5. **R7 旧机制一刀切移除——一号批准**：TOTP 上线时同步移除旧登录码（login_codes 表 / generateLoginCode / verifyLoginCode / send-code / verify-code 接口 / AUTH_DEV_MODE 显示码逻辑）。符合用户「不留双轨」原则。AUTH_DEV_MODE 环境变量保留但语义变为「是否显示 TOTP 密钥/二维码辅助」或直接移除，你评估后定，报告说明。
6. **二维码**：用 `otpauth://` URI 生成二维码。不装第三方二维码库的话，可用纯 JS 二维码生成（若无现成，允许装**一个**轻量零依赖的 qrcode 生成库——这是唯一允许的依赖例外，报告声明选型）。
