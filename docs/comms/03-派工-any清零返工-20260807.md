- 但 strict 批在 3 个路由文件引入了 **72 处显式 `request: any / reply: any`**（admin.routes 39 / artist.routes 30 / dashboard.routes 3）——这是**假修复**，必须清零
- **红线（用户原话）**：不许任何形式的 `: any` 蒙混。修不了就列出来交一号决策，不许自己绕。

## 二、正确修法（一号已实测验证，零错误）

**方式：handler 参数标 `FastifyRequest` / `FastifyReply`，体内用 `as` 类型断言取字段。**

```ts
import type { FastifyInstance, FastifyRequest, FastifyReply } from 'fastify'

export default async function adminRoutes(fastify: FastifyInstance) {
  fastify.get('/api/admin/artists/:id', { preHandler: requireAdmin }, async (request: FastifyRequest, reply: FastifyReply) => {
    const id = Number((request.params as { id: string }).id)
    const body = request.body as { qqNumber?: string }
    ...
  })
}
```

**一号实测**：在 strict=true 下用此组合写 probe 文件，`tsc --noEmit --strict` **exit 0 零错误**。三号此前称"强标 FastifyRequest 会新增 ~100 错误（TS18046/TS2339/TS2741）"**不成立**——正确做法是标了 FastifyRequest 之后**体内字段用 as 断言**（Fastify 5 默认 body/params 是 unknown，断言后正常）。

## 三、任务步骤（精确）

### Step 1：清点
- `cd server && npx tsc --noEmit --strict` 拿当前错误清单（应为 0，strict 已过）
- 扫描 3 个文件：`admin.routes.ts` / `artist.routes.ts` / `dashboard.routes.ts` 中所有 `request: any` / `reply: any`（72 处）

### Step 2：逐个替换（3 个文件）
- 每个路由 handler：`async (request: any, reply: any)` → `async (request: FastifyRequest, reply: FastifyReply)`
- 体内字段取用加 `as` 断言：
  - `request.params` → `(request.params as { id: string; ... })`（按实际用到的键）
  - `request.query` → `(request.query as { days?: string; ... })`
  - `request.body` → `(request.body as { ... })`（按 schema 或实际使用）
  - `request.artist` / `request.targetArtist`（fastify.d.ts 已扩展，直接可用）
- preHandler 具名函数（如 `requireExistingArtist(request: any, reply: any)`）同样改
- `fastify.register(dashboardRoutes)` 相关（若 strict 批改过 `.default`，保持）
- **禁止**：`as any`、`: any`、`as unknown as any`、`@ts-ignore`、`@ts-expect-error`（除非经一号批准）
