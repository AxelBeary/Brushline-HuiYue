## 三、🟡 逐条详情

### 🟡1 Settings.vue:80 customLinks 用 index 当 key，且列表有上移/下移变序操作
- 现象：`<div v-for="(link, index) in form.customLinks" :key="index" class="link-row">`，97-98 行提供 ↑↓ 按钮（moveLink(index, -1/1)），99 行删除。
- 触发：画师在「主页展示-链接」编辑多条链接后点 ↑/↓ 调整顺序。
- 影响：列表变序 + index 当 key → Vue 按位置复用 DOM，正在输入/聚焦的输入框状态错位（典型 index-key 反模式）；行内含 el-input（link.url）+ @input detectLinkPlatform，快速连续调整时输入内容可能粘在旧行。
- 建议：customLinks 项加稳定 id（或直接以内容 hash/自增序号作 key），moveLink/removeLink 后 key 稳定不漂移。
- 验证：moveLink 定义于 457-459（splice 移出再插入）——确认变序真实存在。

### 🟡2 ManualOrder.vue:198-231 qqHistory 异步竞态（无请求序号保护）
- 现象：watch(form.clientQq) → 500ms 防抖 → setTimeout 内 `await Promise.all([getOrders, getToolsClient])`，返回后直接赋值 qqHistory/clientProfile/clientSummary（218-221 行）。无 seq 令牌校验。
- 触发：画师录单时先输入 QQ-A（查询慢，如 200 条订单全量接口）→ 未等结果改输入 QQ-B（查询快）→ B 结果先渲染，A 结果后返回覆盖 → 输入框显示 B 但历史订单/客户标记是 A 的。
- 影响：录单时客户标记/历史订单错位展示，误导画师（错误信息不写入订单——提交用当前 form.clientQq，故不产生脏数据，属展示层错乱）。
- 建议：加请求序号（watch 时 seq++，返回后 `if (mySeq !== seq) return`），与 PuzzlePage.vue:242-248 renderSeq 同款模式（库内已有正确范式可抄）。
- 验证：人工读 198-231 全文，确认无任何序号/AbortController 保护。

### 🟡3 ClientsPage.vue:26-40 客户搜索 @input 直发请求，无防抖且无竞态保护
- 现象：`<el-input @input="loadClients">` → loadClients 每次输入立即发 `getToolsClients(searchQq)`，无 debounce、无请求序号。
- 触发：搜索框每敲一个字符发一次请求；快速输入时慢请求可能后返回覆盖快请求结果。
- 影响：请求风暴（每字符一次）+ 结果错位（显示与输入不符的列表）。
- 建议：300ms 防抖 + 请求序号（或 AbortController）；同页其余逻辑（编辑校验=后端 PUT 子集）规范，仅此一处需补。
- 验证：人工读全文件确认。

### 🟡4 useOrderForm.js:162-174 / 321-335 价格预览 doCalc/doStyleCalc 无竞态保护
- 现象：scheduleCalc/scheduleStyleCalc 300ms 防抖只覆盖 pending timer；已发出的请求无序号校验，返回后直接覆盖 pricePreview/stylePricePreview。
- 触发：客户端选档位/增项切换后快速再切（网络慢时），慢请求后返回 → 价格预览显示旧档位价格。
- 影响：展示层价格错位（提交时后端重新算价，不产生错误订单金额）；同族还有 OrderList.vue:143-146 搜索（300ms 防抖但无序号，慢请求覆盖）。
- 建议：与 🟡2 同方案（seq 序号）。此三处（🟡2/🟡3/🟡4）+ OrderList 搜索可合并为一个「异步请求无竞态保护」修复批，统一补序号模式。
- 验证：人工读 155-177 / 314-341 确认。

### 🟡5 ArtistDetailDrawer.vue:175 t('settings.noChanges') i18n key 不存在
- 现象：`ElMessage.info(t('settings.noChanges') || '没有修改')`；zh-CN.js 全库无 settings.noChanges（仅 settings.saved 等）。
- 触发：管理后台编辑画师资料后点保存且无任何字段修改。
- 影响：vue-i18n 缺 key 返回 key 原文（truthy），`|| '没有修改'` 兜底不生效 → 用户看到英文 "settings.noChanges"（en 环境显示同字符串）。
- 建议：zh-CN.js/en.js 补 `settings.noChanges: '没有修改' / 'No changes'`（管理端 settings 域已有同族键如 saved）；或改用 `i18n.global.te('settings.noChanges')` 判断。
- 验证：node 脚本双向核对全库 i18n 引用，此 key 为唯一真缺失（其余 40+ 命中均为 emit/trackEvent/URL 误匹配，已逐一甄别）；Select-String 确认 zh-CN.js 无该键。
