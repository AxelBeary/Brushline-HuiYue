### 🔴-1 [views/artist/OrderDetail.vue:535 + composables/useOrderPaymentPanel.js:139-145] 节点快捷收款前端自行收紧（v0.36 教训重现）

- 现象：节点快捷收款（「按节点收款」）前端限制单笔不超过该节点剩余额度；但后端 addPayment 对带 installmentId 的支付**只校验节点存在性，不限制金额上限**（server/src/features/order/order.service.ts:1154-1217，installmentId 分支仅 SELECT 校验存在）。
- 证据：
  - 前端模板 views/artist/OrderDetail.vue:530-535：节点快捷收款弹窗 `<el-input-number v-model="nodePayForm.amountYuan" :min="0.01" :max="nodePayTarget?.remainingCents > 0 ? nodePayTarget.remainingCents / 100 : 999999.99" .../>`
  - 前端 composables/useOrderPaymentPanel.js:139-145：`submitNodePayment` 里 `if (cents > nodePayTarget.value.remainingCents) { ElMessage.warning(t('orderDetail.payAmountExceed', ...)); return }`
  - 后端 server/src/features/order/order.service.ts:1154 起：addPayment 无节点额度上限；超额部分按「纯超付」压到尾款待收（checkOrderConservation A2 注释：已收超出节点价的部分全部压到尾款待收变负，可退）。
- 触发条件：客户多付/预付超过单个节点金额时，画师在节点收款弹窗内输入超额金额 → 前端直接拦截「金额超出该节点待收」，只能退回订单级「记录收款」入口（该入口无上限，P2 注释明确正数多收合法）。
- 影响：同一收款场景两套规则——节点入口拒收超额，订单级入口允许。前端校验不是后端子集（红线 4：前端校验只能是后端规则的子集，不可自行收紧）。功能不丢失（有替代路径），但行为不一致会误导画师以为「不能多收」。
- 建议修复：删除 submitNodePayment 的 `cents > remainingCents` 拦截与模板 :max 上限（保留 `cents <= 0` 检查，与后端 amountCents 非零/负数拒绝对齐）；或经一号/用户确认「节点收款限超额」为产品设计后，在后端 addPayment 同步加节点上限校验（前后端一致，二选一，不能只留前端）。
