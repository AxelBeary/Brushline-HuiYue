## 二、解析规则（message-parser.js）

纯函数，不引 AI、不引外部 API、无副作用、可单测。

1. **QQ 号** `clientQq`：消息中第一个「独立数字串」（5-15 位，前后均非数字），对齐后端 schema `^[0-9]{5,15}$`。
   - 用逐字符扫描而非 `\b` 正则：`\b` 只认 ASCII 词边界，中文/emoji 粘连时不可靠（如「想要12345678这张」）。
   - **金额线索内的数字串不作为 QQ 候选**（预算 100000 元 不冒充 QQ；见单测「金额中的长数字不冒充 QQ」）。
   - 识别不到 → 留空，绝不用假值凑。
2. **需求描述** `description`：全文（trim），截断到 2000（对齐后端 order create maxLength=2000，前端 textarea maxlength 同）。
3. **金额线索** `hints.amount`：`预算 x 元` / `x 元`（支持 1-2 位小数）。**只提示不自动填**。
4. **日期线索** `hints.deadline`：`x号前` / `x月x日`，规范化输出（`5号前` / `8月20日`）。**只提示不自动填**。

边界：非字符串/null/空白输入 → 全空返回不抛错；4 位数字串不命中；16 位不命中（超 15 位不猜）。

## 三、预填确认交互（ManualOrder.vue）

1. 页面顶部（标题+提示下方）「粘贴消息解析」按钮（纸墨 token，主色 plain 按钮）。
2. 点击打开弹窗：textarea 粘贴客户消息 → 「解析」→ 展示结果区：
   - 客户QQ：命中显示 success tag；未命中显示「未识别（留空，请手动填写）」
   - 金额线索 / 日期线索：命中显示提示值；未命中显示「未识别」
   - 底部提示「金额与日期仅作线索提示，不会自动填入，请人工核对后填写。」
3. 「填入表单」：仅回填识别到的 clientQq / description（非空才填），**不自动提交**，关闭弹窗并 toast「已填入表单，请核对后提交」。画师检查补全（金额→右栏价格，日期→截稿日）后手动提交。
4. 解析结果仅在弹窗内展示，金额/日期绝不自动写入 form（遵循「解析不出不猜 + 人工确认」）。

## 五、风险与说明

- 解析规则是启发式（正则），MVP-1 不追求 100% 准确，核心是「不猜」：识别不到就留空 + 人工确认兜底，绝无假值入库风险。
- 手机号 13800138000 等 11 位数字串会按规则被识别为第一个独立数字串（画师手动改即可）；规则如此设计，后续 MVP 可加「QQ 前缀关键词优先」增强。
- 未做浏览器端到端验证（本批验证门禁为单测+构建；交互已按现有页面模式实现）。
