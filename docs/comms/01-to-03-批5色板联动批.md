## 三、施工图

### 改动 1：Settings.vue ACCENT_PRESETS（L376-382）

**before**：
```js
const ACCENT_PRESETS = [
  { color: '#34dbcb', name: '青' },
  { color: '#34c2db', name: '碧' },
  { color: '#3498db', name: '蓝' },

```

**after**：
```js
const ACCENT_PRESETS = [
  { color: '#356B69', name: '青' },
  { color: '#3F5E80', name: '碧' },
  { color: '#5E5494', name: '蓝' },
  { color: '#346edb', name: '靛' },
  { color: '#3445db', name: '紫' }
]
```

### 改动 2：artist.service.ts ACCENT_COLORS 白名单（L196）

**before**：
```ts
const ACCENT_COLORS = ['#34dbcb', '#34c2db', '#3498db', '#346edb', '#3445db']
```

**after**（小写归一，与后端存储格式一致——后端存的是 `String(value).toLowerCase()`）：
```ts
const ACCENT_COLORS = ['#356b69', '#3f5e80', '#5e5494', '#346edb', '#3445db']
```

### 改动 3：ArtistHome.vue ACCENT_INDEX（L90）

**before**：
```js
const ACCENT_INDEX = { '#34dbcb': '1', '#34c2db': '2', '#3498db': '3', '#346edb': '4', '#3445db': '5' }
```

**after**（key 用新 hex，注意与后端 toLowerCase 存储一致——渲染端读取时 `String(raw).toLowerCase()` 查找，所以 key 用小写）：
```js
const ACCENT_INDEX = { '#356b69': '1', '#3f5e80': '2', '#5e5494': '3', '#346edb': '4', '#3445db': '5' }
```

> ⚠️ 核对 ArtistHome.vue L93 `ACCENT_INDEX[String(raw).toLowerCase()]`——查找时已 toLowerCase，所以 key 必须小写才能命中。改动 2 的后端也是 toLowerCase 存储，两边对齐。

### 改动 4：存量数据迁移（Alice #34dbcb → #356b69）

**方案**：不改 DB（低风险优先）——**渲染兼容即可**：
- ArtistHome 的 ACCENT_INDEX 只认新 hex，Alice 存旧 `#34dbcb` 会查不到 → 返回 null → 走默认色（不报错）
- **可接受吗？** Alice 主页从"旧青"变回"默认主色"（theme.css 默认 #356B69 其实也是月白青！）——**恰好兼容**：默认色 = 1 号色新值，Alice 显示月白青（符合预期）
- **结论**：存量无需 UPDATE，渲染兼容天然兜底。但**在待修复清单记录**（说明 Alice 的 DB 值仍是旧 hex，若未来改默认色会脱节——低优先级）
- **若你判断需要 UPDATE**（让 DB 干净）：写一次性脚本 `UPDATE artists SET accent_color='#356b69' WHERE accent_color='#34dbcb'`（生产库操作，**先备份再执行**——但按一号纪律，改生产数据需用户确认，**本批不做 UPDATE，只记录**）
