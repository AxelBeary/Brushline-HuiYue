## 二、缺陷详情（每条含定位 + 复现步骤）

### T1 🔴 三模板吸底 CTA 永不触发（P1，交互完全失效）

**现象**：gallery / folio / atelier 三个模板的吸底约稿条（TplStickyCta）从不出现。实测滚到页面底部（scrollY=3555，hero 早已滚出 -3516px），`.tpl-sticky-cta` 仍不在 DOM；组件实例 `visible` prop 恒为 `false`。

**根因定位**（代码 + 运行时双重确认）：
- 三个模板均为：`const heroSentinel = computed(() => heroRef.value?.sentinelEl?.value)`（ArtistHomeGallery.vue:109 / Folio:156 / Atelier:109）
- TplHero 的 expose 正常（`exposed.sentinelEl` 是合法 HEADER 元素，已实测）
- 但父组件 `heroRef` 实际为 null → `heroSentinel` 计算为 `undefined` → `useStickyCta(undefined)` 中 `watch(sentinelRef, setup)` 首次执行 `setup(undefined)` 直接 return，**IntersectionObserver 从未建立**，此后 watch 也不再触发（computed 始终 undefined，无变化）
- 组件树确认 `AsyncComponentWrapper → ArtistHomeGallery`——模板本身经 defineAsyncComponent 加载，heroRef 未绑定到异步加载完成后的 TplHero 实例

**影响**：三模板"滚出 hero 后显示吸底约稿条"的核心转化交互完全失效。classic 不受影响（无吸底条，用侧栏常驻 CTA）。

**修复方向**（建议，未实施）：
1. 用 DOM 查询替代 ref 链：`onMounted` 后 `document.querySelector('.tpl-hero--fullscreen')` 作为哨兵，或
2. 模板内给 hero 外层 wrap 直接挂哨兵 ref（不经过异步组件），或
3. useStickyCta 支持"元素未就绪时重试"（watch 内 null 时延迟轮询/ MutationObserver 等待出现）

### T2 🔴 folio 导航锚点与页面区块错位（P1）

**现象**：
- 空数据态（bob，无作品/无画风）：导航仍显示"作品"(#gallery)、"价格"(#pricing) 两项，但 `#gallery` 锚点**不存在**（gallery section 因无作品整个 v-if 隐藏）→ 点击"作品"无任何反应；`#rules` 也不存在（无须知）→ 但页面实际有 `#guestbook`（留言板）导航却没有
- 有数据态：导航只有作品/价格两项，页面另有"约稿须知""留言板"区块未入导航

**根因定位**：ArtistHomeFolio.vue:163-166 `navItems` 硬编码 `[{id:'gallery'}, {id:'pricing'}]`，未随数据状态动态生成；`scrollTo()`（:168-171）对不存在的 id 直接 `scrollIntoView` 失败静默。

**影响**：空数据画师（新画师、未传作品的画师）主页导航有一半是死链。

**修复方向**：
1. navItems 按数据动态生成：有作品才显示"作品"，有画风/档位才显示"价格"，必要时补"留言"项
2. 或空数据时隐藏整个导航

### T3 🟠 TplTierGrid 档位按钮未随画师状态禁用（P2）

**现象**：bob status=full（已排满），hero"我要约稿"与 classic 侧栏"我要约稿"均正确 disabled（`disabled=true`），但档位展示柜的"选择此档位"按钮 `disabled=false` 可点。

**根因定位**：TplTierGrid.vue:58-64 只判断 `activeTier.visibility === 'showcase'`，未检查 `artist.status`。TplStyleGrid.vue:62 的"选择此画风约稿"同样没有 status 判断（bob 无画风走 tier 分支未实测 style 分支，但代码同构，一并标注待复核）。下单页 OrderForm 无前端 status 拦截（grep 确认），full 状态仍可进入下单流程（后端是否拦截未验证）。

**影响**：已排满/休息画师仍可从档位区进入约稿流程，与页面其他禁用逻辑不一致（观感缺陷 + 潜在流程漏洞）。

### T4 🟠 seed 幂等性差 → 主页档位重复展示（P2，数据层）

**现象**：bob 主页档位区"全身插画 ¥350"、"双人插画 ¥500"各出现 2 次（共 4 条）。alice 同样有 6 条重复 tiers（id 1-3 与 6-8）。

**根因定位**：seed.js 用 `INSERT OR IGNORE` 插入 artists（有唯一约束 subdomain 生效），但 price_tiers **无唯一约束**，第二次跑 seed 会再插入一份。公开 API `GET /api/artists/:subdomain` 原样返回全部 tiers → 主页重复展示。

**影响**：开发环境反复 seed 后主页档位重复；A 测若用 seed 数据会直接暴露。生产不受影响（无 seed 流程），但开发体验差、易误判为产品 bug。

**修复方向**：seed 前先 `DELETE FROM price_tiers WHERE artist_id IN (...)` 或给 price_tiers 加 (artist_id, name, price) 唯一索引。

### T5 🟡 TplHero 按钮动画时长超批 1 纪律（P3）

**现象**：`.tpl-btn` transition `0.25s cubic-bezier(0.22, 1, 0.36, 1)`（TplHero.vue:115），hover 位移 -2px（:124）符合规范，但**时长 0.25s ≠ 批 1 的 0.15s 纪律**。classic-cta `0.2s`、gb-submit `0.2s, transform 0.15s`、gallery-filter `0.2s` 同样混用。

**归类**：批 1（二号）只授权改 theme.css 全局 `.el-button` 规则，模板 scoped 样式里的 `.tpl-btn` 是**漏网项**——建议批 1 顺手收敛或独立小批。

### T6 🟡 atelier 硬编码字体体系外字体（P3）

**现象**：atelier 标题（.atelier-label）、公告便签、留言板正文硬编码 `'Noto Serif SC', 'STSong', 'SimSun', serif`（ArtistHomeAtelier.vue:212/233/310 等），而其他三模板与后台统一用 `var(--font-display)`（LXGW WenKai 楷体）。

**归类**：规范缺失（设计系统未规定 atelier 是否允许独立宋体体系）——需设计拍板：宋体是 atelier 的"画室纸片感"一部分（有意为之），还是应统一走 --font-display？若有意，建议至少抽成 token（如 `--font-atelier-serif`），避免散落硬编码。

### T7 ⚪ classic 同页 2 个主 CTA（记录）

classic 有数据态 hero 区 + 侧栏吸顶卡各 1 个"我要约稿"。代码注释明确"侧栏约稿按钮常驻"（ArtistHomeClassic.vue:8），判为**规范既有设计**（侧栏吸顶卡常驻提供持续转化入口），非缺陷。记录备查：若用户觉得重复可讨论，但本次不列为缺陷。

### T8 ⚪ 画册初始页为第 1 张非封面作品（记录）

gallery/atelier 画册模式初始页显示第 1 张**非封面**作品（实测为"夜色都市"）。原因：TplGallery displayArtworks 按 REQ-017 约束 2 过滤 `is_cover=1`（封面只在 hero 展示），过滤后第 1 张是夜色都市。**符合约束 2 的设计意图**（封面不重复展示），但"用户设的封面不出现在画廊"是否满足预期，建议与用户确认（若画师把所有作品设封面，画廊走兜底显示全部，实测正常）。

### T9 ⚪ fullscreen hero 无作品图时纯色底 + 黑渐变（记录）

bob（无作品）gallery/atelier hero：`background: none`（页面底色）+ 底部 `linear-gradient(rgba(0,0,0,0.55) → transparent)` 黑渐变。实测 hero 高 566px 全屏正常，文字可读，但"无图 hero + 黑渐变"的观感可能突兀（一个暗蒙层盖在空白上）。归类为**数据态观感**（无作品图的 hero 表现），非功能缺陷，是否优化由设计拍板。
