### 2.2 端点行为

**POST /api/anon-token**（无鉴权）
- 签发 32 字节随机 token，`INSERT INTO anon_tokens`，响应 `{ token: '<64位hex>' }`

**POST /api/events**（body：`{ token?, events: [{ name, ts, version?, ...payload }] }`）
1. 限流：`rateLimit('events:' + (token||ip), 100, 60_000)` → 超限 429 `RATE_LIMITED`（请求级：每分钟最多 100 次 POST）
2. 白名单：非白名单事件名 → 400 `INVALID_EVENT_NAME`，不落库
3. 鉴权（REQ-033 §2.2 拍板 B）：画师已登录（可选登录态解析，cookie/Bearer）→ 记 `artist_id`，匿名凭证不强制；未登录 → 必须带有效 anon token，否则 400 `INVALID_ANON_TOKEN`
4. 落库 `events` 表，响应 `{ ok: true, received: N }`

**白名单 23 项**（施工图 §2.2 的 18 项 + REQ-033 补充 5 项，见 §四 卡点 1）：
`theme_accent_change`、`order_form_start`、`order_form_step_view`、`order_form_step_leave`、`order_form_submit_attempt`、`order_form_submit_success`、`order_form_submit_fail`、`order_form_back`、`order_form_step_back`、`order_form_abandon`、`order_submit_success`、`dashboard_view`、`queue_view`、`orders_view`、`manual_view`、`artworks_view`、`settings_view`、`tiers_view`、`guestbook_view`、`preferences_view`、`dashboard_quick_click`、`artist_page_enter`、`artist_action`

### 2.3 迁移 v44（init.js，追加于 MIGRATIONS 数组尾部）

CREATE TABLE IF NOT EXISTS events (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,
  ts INTEGER NOT NULL,
  version INTEGER NOT NULL DEFAULT 1,
  artist_id INTEGER,
  anon_id INTEGER,
  payload_json TEXT NOT NULL DEFAULT '{}',

## 四、卡点与说明（请一号留意）

1. **白名单 23 项 vs 施工图 18 项（需确认）**：施工图 §2.2 列出 18 项白名单，但注明"完整清单以 REQ-033 §4.4 为准"；REQ-033 文档实际无 §4.4 事件清单（§4.4 为派工标注），事件定义散在 §2.1（换色）、§3.2（漏斗，命名拍板 A：沿用第三方原名 `order_form_step_view/order_form_step_back/order_form_abandon/order_submit_success`）、§4.2（后台 `artist_page_enter/artist_action`）。为防前端按 REQ-033 实现时被 400 误拒，白名单取**施工图 18 项 ∪ REQ-033 事件 5 项 = 23 项**。若一号/四号拍板严格封闭 18 项，改 `tracking.service.ts` 的 `EVENT_WHITELIST` 数组 + 删 TC-TR-04 即可。
2. **typecheck 基线 4 处错误已修（master 同错）**：`npm run typecheck` 在 master（主仓）同样报 4 处：`app.ts` L98/L148/L216、`index.ts` L18，均为 `app.log.warn('msg', err)` 第二参数 unknown 不匹配 pino 类型。为满足施工图门禁"typecheck 0 错误"，统一改为 pino 推荐 `app.log.warn({ err }, 'msg')` 对象模式（序列化行为等价，无运行时变更）。这 4 处修复夹带在本次 commit 内。
3. **限流语义**：`rateLimit()` 为请求级限流（每次 POST /api/events 计 1 次），施工图"1 分钟 100 条"实际对应"每分钟最多 100 次上报请求"（一次可带最多 50 条事件）。单请求 50 条上限由 schema `maxItems: MAX_EVENTS_PER_REQUEST` 保证。
4. **A 部分零补日志属如实判定**：未为"完成任务"而硬补日志——health.service 的 8 项检查为"错误即输出"设计、order-gallery 已 throw 传播、artist.service 为防御性解析，补日志均会制造噪音而非增益。判定依据逐条列于 §一。
