## 二、问候系统重构（用户拍板终稿，2026-08-16）

### 时段表（7 档全覆盖，无空档）
| 档位 | 时间 |
|---|---|
| 清晨 | 4:00~6:59 |
| 上午 | 7:00~11:59 |
| 午后 | 12:00~13:59 |
| 下午 | 14:00~17:59 |
| 夜晚 | 18:00~21:59 |
| 深夜 | 22:00~3:59 |
| 全天 | 任何时间（万能兜底） |

### 抽取逻辑（用户原话逐字：「节日>（时段40%、画师时段专属40%、全天20%）随机>兜底」）
1. **节日层**：特别日（生日/纪念日等）命中 → 抽该日专属文案，结束
2. **加权随机层**：掷骰子 0~99
   - 0~39 → 时段池（40%）= 系统通用文案（artist_id 为空）且 time_slot=当前时段
   - 40~79 → 画师时段专属池（40%）= artist_id=该画师 且 time_slot=当前时段
   - 80~99 → 全天池（20%）= time_slot='全天'（不分归属）
3. **兜底层**：全空 → 默认问候「你好，{name}」

### 回落规则（用户确认 ✅）
画师专属池空 → 掉入时段池；时段池空 → 掉入全天池；全天池空 → 默认问候

### 配置入口（用户确认 ✅）
- **仅管理员后台**：全局问候管理页（系统通用）+ 画师详情抽屉（画师专属，含时段下拉）
- **画师端不加自助入口**（用户原话：「不给画师自己设置 只能我设置」）
- 数据模型已支持「画师+时段」双维度（greeting_templates.artist_id + time_slot），无需改表结构

### 附带动作
- 删除「午夜/深夜」双档困惑（latenight 优先池概念消除，合并为「深夜」一档）
- 数据迁移 v67：旧 6 档按规则搬家（旧 evening→夜晚、night/latenight→深夜、morning→上午、afternoon→下午、any→全天；专属/全局归属不变）
- 全链路同步：schema CHECK、后端抽取逻辑、管理端档位下拉、i18n zh/en、测试
