## 任务理解

用户要求：收入导出页（ToolsExport.vue）也要展示收入信息——日期范围下方的「收入概览区」，包含总收入/订单收入/散单收入/收款笔数，口径与导出 CSV 一致。

## 实现内容

ToolsExport.vue 在导出面板内新增「收入概览」卡片（纸墨 token 样式，双主题自适应）：

- **数据源**：`GET /api/artist/tools/standalone-incomes?from=&to=`（带 credentials，token 在 httpOnly cookie）
- **触发**：`watch(range, immediate: true)`——页面加载即按默认本月区间加载；用户改日期范围自动刷新
- **展示**：
  - 散单收入：¥（分→元，`amountCents` 求和，`(cents/100).toFixed(2)`）
  - 散单笔数：N 笔（`items.length`）
  - 订单收入 / 总收入：显示「待后端汇总」占位（不硬造数字）
- **i18n**：zh-CN.js / en.js 同步新增 10 键（incomeOverview/incomeLoading/incomeTotal/incomeOrder/incomeStandalone/incomeCount/incomeCountUnit/incomeUnavailable/incomeNote/incomeLoadFailed）

## 后端端点核查（grep 结论）

按派工要求先 grep 后端确认区间汇总端点，**结论：没有可用的自定义区间 JSON 汇总端点**：

| 端点 | 能力 | 能否用于页面收入汇总 |
|---|---|---|
| `GET /api/artist/tools/export.csv?from=&to=` | getExportRows 合并 order_payments + standalone_incomes，含完整金额/类型 | ❌ 仅下载专用，返回 CSV 文本非 JSON |
| `GET /api/artist/tools/standalone-incomes?from=&to=` | 散单列表 JSON（amountCents/incomeDate） | ✅ 散单部分可用 |
| `GET /api/artist/dashboard/revenue?period=month|quarter|year` | 柱状图 bars + summary | ❌ 固定 period，且口径是「完成订单」（completed_at）非支付流水，与 CSV 不一致 |
| `GET /api/artist/orders`（order.routes.ts） | 订单列表（status/page 分页） | ❌ 无支付流水金额聚合，无法按支付日期区间汇总 |

**口径说明（关键）**：
- 导出 CSV 的口径 = `order_payments.created_at`（本地日期）按区间过滤的订单支付流水 + `standalone_incomes.income_date` 按区间过滤的散单
- 散单概览数据与 CSV 的散单行**完全同源同口径**（同一 SQL 过滤条件 `income_date BETWEEN from AND to`）
- 订单收入 / 总收入无法在前端准确还原：订单支付流水没有 JSON 端点，且 revenue 端点口径不同（完成订单 vs 支付流水），不可混用

## 后端缺口（需一号拍板）

页面缺失「订单收入」「总收入」两项，根因是**后端没有按自定义日期区间返回订单支付流水汇总的 JSON 端点**。

建议补端点（方案）：
`GET /api/artist/tools/income-summary?from=&to=` 返回：
```json
{
  "orderCents": 0,
  "orderCount": 0,
  "standaloneCents": 0,
  "standaloneCount": 0,
  "totalCents": 0,
  "totalCount": 0
}
```
实现可复用 `tools.service.ts getExportRows` 的 SQL（order_payments + standalone_incomes，按本地日期区间），在 service 层聚合即可。前端只需把「待后端汇总」占位替换为真实值，其余逻辑已就绪。
