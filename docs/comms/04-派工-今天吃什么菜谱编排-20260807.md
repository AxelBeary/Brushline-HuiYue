## 任务：编写「今天吃什么」菜谱数据文件（纯内容，零代码逻辑）

**产出**：`web/src/utils/food-menu.js`——四类菜谱库，每类 30~50 条，合计 ≥120 条（鼓励更多），跨类可复用同一菜品（打多个标签）。

## 数据结构（建议，按需微调）

```js
// 四大类 key：healthy（健康）/ diabetes（糖尿病）/ gout（痛风）/ takeout（外卖）
// 每菜品：{ name, tags: [分类key数组], note: 一句话点评（可选） }
// 例：{ name: '清蒸鲈鱼', tags: ['healthy', 'diabetes', 'gout'], note: '高蛋白低脂，蒸制少油' }
```

- 健康版：低卡/清淡/营养均衡家常菜（≥30）
- 糖尿病版：低 GI/控糖友好主食与菜（≥30，note 标注「低GI」等提示）
- 痛风版：低嘌呤友好，避开海鲜/内脏/浓汤（≥30，note 标注「低嘌呤」提示）
- 外卖版：直接可点的外卖品类/店型推荐（≥30，含常见外卖平台可搜品类）
- **跨类打标签**：如「清蒸鲈鱼」= healthy+diabetes+gout 都可用——避免硬凑 120 条注水
- 全部中文（菜名/点评）

## 内容要求（用户拍板）

1. 质量优先不注水——真实可吃的家常菜/外卖品类，不编造离谱菜名
2. 糖尿病版注意：标注低 GI / 控糖友好；避开高糖（含糖饮料/甜点/白粥）
3. 痛风版注意：避开高嘌呤（海鲜/动物内脏/浓肉汤/啤酒）；标注低嘌呤
4. 外卖版：真实可搜的外卖品类（黄焖鸡/麻辣烫/轻食沙拉/饺子/粥铺等）

## 红线

3. 每菜品 name 非空、tags 是合法分类 key 数组
