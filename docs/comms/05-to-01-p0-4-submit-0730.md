【Bug 标题】login_codes.expires_at 列类型声明与实际存储不一致 + 管理员订单时间未格式化

【复现路径】
1. 查看 server/src/db/init.js:135 — 列声明为 `expires_at DATETIME NOT NULL`
2. 查看 server/src/features/auth/auth.service.js:53 — 实际存入 `Date.now() + CODE_TTL_MS`（Unix 毫秒整数）
3. 用 DB Browser 打开数据库，login_codes.expires_at 列显示为 INTEGER 值（如 1753891200000），与 DATETIME 声明矛盾
4. 管理员后台 → 画师管理 → 查看订单 → 时间列显示 UTC 原始字符串（如 `2026-07-29 14:30:00`），未转本地时间

【严重程度】一般（当前功能不受影响，但 schema 不一致是维护隐患）

【影响范围】
- 后端：login_codes 表 schema 声明（新建库时生效）
- 前端：管理员后台画师订单列表时间显示

【原因分析】
- v0.11 止血批次（2a2a9ff）把 expires_at 的读写逻辑改为整数比较，但未同步修改 schema 声明
- ArtistManage.vue 的订单表格直接用 `prop="created_at"` 渲染，未经 formatDateTime() 处理（其他视图均已使用）

【责任模块】数据库 + 管理后台前端

【修复方案】
1. init.js：`expires_at DATETIME NOT NULL` → `expires_at INTEGER NOT NULL`（与实际存储一致）
2. ArtistManage.vue：created_at 列加 `<template #default>` 调用 `formatDateTime()`
3. 迁移暂不写（按一号指示，等 v12 落地后统一安排 v13 修正）
