## 检查维度（每项给「文件:行号 + 问题 + 建议」）

### A. 死代码 / 冗余
- 未使用的 import / 变量 / 函数（用 eslint/oxlint 报出的 unused 项辅助，但要区分"真死"与"lint 漏检"）
- 注释掉的代码块（git 历史里有版本，注释块=残留）
- 重复逻辑（同一 SQL/同一段校验在多个文件复制粘贴）

### B. 架构 / 结构
- 巨型组件（已知：OrderDetail.vue 1731 行 / QueueBoard.vue 1530 / ManualOrder.vue 1302——核实当前行数，标注是否还在膨胀）
- 单文件职责混杂（一个文件干多件事）
- 命名不一致（同一概念多种叫法）
- 魔法数字 / 魔法字符串（硬编码值应抽常量）
- 硬编码中文（应走 i18n——已知部分历史遗留，重点找新的）

### C. 安全 / 健壮性
- 裸 catch 吞错（`catch {}` 无日志无处理）
- 可能的空指针 / 未定义访问（strictNullChecks 已开，剩余是否还有运行时隐患）
- 无校验的输入直传 SQL（注入面——虽然 better-sqlite3 参数化，但要查字符串拼接）
- 敏感信息硬编码（token/密钥/路径）
- 过宽的错误处理（catch 全吞导致难排查）

### D. 性能
- N+1 查询（循环里查库）
- 无分页的全量拉取
- 大对象不必要的深拷贝 / 重复 JSON.stringify
- 前端无 key 的 v-for / 无节流的滚动监听

### E. 技术债（已知清单核验）
- 已记录的巨型组件拆分（前端性能池）——现状确认
- `any` 黑洞（TS 迁移批 P3 未做，核实当前 any 数量分布）
- legacy 兼容层（如有）
