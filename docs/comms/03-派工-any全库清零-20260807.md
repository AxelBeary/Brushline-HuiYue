## 三、分类修法（精确）

### 类别 A：路由 handler 参数（大头）
`async (request: any, reply: any)` → `async (request: FastifyRequest, reply: FastifyReply)` + 体内字段 `as` 断言：
```ts
import type { FastifyInstance, FastifyRequest, FastifyReply } from 'fastify'
fastify.get('/api/...', { preHandler: requireAuth }, async (request: FastifyRequest, reply: FastifyReply) => {
  const id = Number((request.params as { id: string }).id)
  const body = request.body as { qqNumber?: string }
})
```
- `request.params`/`query`/`body` 按实际用到的键写断言对象
- 一号已实测：此组合 strict=true 下 exit 0 零错误

### 类别 B：SQL 行断言（约 30 处，多数合理但可更精确）
- `(row as { c: number }).c` 这类**已合理**（SQL 结果确实无静态类型）——保留 `as { c: number }` 具体类型，**不是 any**，不算违规
- 若见到 `as any` / `as unknown as any` → 改为具体类型（如 `as Array<{ name: string; count: number }>`）

### 类别 C：`as any` 逃生舱（需要逐个判断）
- `request.body as any` → 应写具体 body 接口（按 schema 或实际字段）
- 第三方无类型库的调用 → 若确实无法类型化，**列出来交一号**（不许自己 `as any` 留底）

### 类别 D：`types/fastify.d.ts` 的 3 处
- `targetArtist: any` 等——改为具体类型（Artist 类型导入）或按 fastify 扩展规范处理；若 Fastify 泛型不允许，列出来交一号决策
