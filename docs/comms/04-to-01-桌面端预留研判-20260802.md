## 请一号研判

桌面端本身是 v1.0+ 的事，但**当前平台侧是否有需要提前预留的设计**，避免将来大改。具体：

### 1. API 层

- 桌面端登录后需要拉取：画师档案、委托列表、委托图片（20 张/委托）
- 当前 API 是否已覆盖这些读取场景？有无需要新增的端点？
- 图片缓存需要 ETag / Last-Modified 支持（免重复下载），当前静态文件服务是否已带？

### 2. 数据模型

- 桌面端本地记账（F2）的数据结构和平台订单模型是否需要兼容？
  - 如果将来"本地委托 → 关联平台订单"，字段映射现在是否清晰？
- 画师档案（profile 表）是否有桌面端需要但当前缺失的字段？

### 3. 图片上传

- 桌面端上传逻辑"和网页一样"，当前上传 API（`upload-img` / `upload-deliver`）是否对非浏览器客户端友好？（Content-Type 校验、CORS、分片等）

### 4. 认证预留

- 当前 AUTH_DEV_MODE 下无真实认证。桌面端登录体系虽远，但 token 机制（JWT / session）是否需要在 v0.25~v0.26 期间先设计好接口契约？
- 还是说等真做时再说，现在不预留？
