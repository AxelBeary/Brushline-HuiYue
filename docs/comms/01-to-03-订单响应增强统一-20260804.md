> 风险等级：中（订单展示链路，无数据库变更）

## 根因（一号已实锤，不要重新查）

GET /api/artist/orders/:id（order.routes.ts 399-418）对订单做了增强：
`paidTotalCents / remainingCents / installments / startDate` + stageInfo + speechInfo。

但**返回订单的变更端点全部没做增强**，只 signOrderUrls 或裸返回：
- PUT /price（765 行）
- POST /extra-items（944 行）← 用户报障"加项目后收款区变 0"的直接原因
- DELETE /extra-items/:itemId（956 行）
- PUT /focus-image（796 行）
- 其余返回订单的端点（deadline/start-date/priority/track-on 等）自行排查

前端 OrderDetail.vue 多处 `order.value = await artistApi.xxx()` 直接覆盖页面数据 →
`paidTotalCents` 变 undefined → `?? 0` → 收款区已收显示 0、installments 丢失节点列表消失。

## 任务

1. 把 GET /:id 的增强逻辑抽成共享函数（如 `enrichOrderForArtist(order)`，放 order.routes.ts 内或新 helper 文件均可），GET /:id 与所有返回订单的变更端点统一走它。
2. **消费者全量核对**：grep OrderDetail.vue 里所有 `order.value = await artistApi.`，逐个确认对应端点已走增强函数。这是验收硬标准，不许只修报障的那一个。
3. 注意增强逻辑对 null 字段的兜底（paid_total_cents ?? 0 等），照抄 GET /:id 现状语义，不要顺手改语义。
