## 一、结论

需求按用户拍板方案完成：

- 订单详情页新增「再来一单」按钮（终态/非终态订单均可），点击弹出回填选项对话框（需求描述 / 款式尺寸 / 备注，无参考图选项），确认后跳转手动录单页并预填草稿。
- 客户 QQ 与昵称无条件带上；描述/款式尺寸/备注按勾选回填；进入录单页后全部可改；提交为全新订单（新单号/客户令牌/幂等键均由既有后端链路全新生成，原订单零影响）。
- 备注预填为「新增备注输入框 + 创建后经既有 `POST /artist/orders/:id/notes` 写入新单」，后端零改动。
- 款式尺寸回填 `style_size_id`；**增项选择（用途/加急/普通增项/自定义增项）因画师端订单详情接口无结构化数据，如实降级不携带**（详见第三节）。
- 埋点已接：`trackEvent('artist_action', { action: 'reorder_start', fromOrderId, fill })`（项目既有口径）。

## 二、实现明细

### 1. 入口与回填选项对话框（`web/src/views/artist/OrderDetail.vue`）

- 「再来一单」按钮放在「订单信息」卡头右侧（状态标签旁），`v-if="order"` 包裹，终态/非终态均可见。
- `el-dialog` 含三个 `el-checkbox`（`desc`/`style`/`note`），默认勾选 `desc,style`（备注默认不勾——备注常含内部沟通，画师按需勾选；每次打开重置默认值）。
- 确认：`router.push({ path: '/orders/new', query: { from: <orderId>, fill: <勾选集> } })`，query 契约与任务书一致（如 `fill=desc,style,note`）。
- 埋点在确认时上报 `reorder_start`。

### 2. 预填纯函数（新增 `web/src/utils/reorderFill.js`）

- `parseReorderFill(fill)`：逗号分隔白名单解析（`desc`/`style`/`note`），未知项静默忽略。
- `buildReorderTextPrefill(sourceOrder, fill)`：QQ/昵称必带；描述/备注按勾选；**返回值不包含 deadline/startDate/priority 等任何新单字段（新单从零）**。
- `buildReorderNoteText(sourceOrder)`：只取备注时间线中**非系统备注**（`created_by !== 'system'`）且有正文的条目，按时间升序换行合并，截断到 1000 字（对齐 `addNote` 单条上限）。
- `findReorderStyleTarget(sourceOrder, styles)`：源单 `style_size_id` 在当前画师画风列表仍存在时返回 `{ styleId, sizeId }`，否则 `null`。

### 3. 手动录单页预填（`web/src/views/artist/ManualOrder.vue`）

- 挂载时读 `route.query.from`/`fill`，`init()` 加载完画风/报价/工作流后：
  - 有 `from`：拉源单 → 回填文字字段 → 勾选 `style` 且尺寸仍存在时经 `ManualOrderRight.setDraftState` 选中尺寸（自动联动价格计算）→ `clearDraft()`（预填即新草稿起点，不弹旧草稿恢复）→ `ElMessage.success(manualOrder.reorderPrefilled)` 轻提示（带源单订单号）。
  - 无 `from`：走原 F6 草稿恢复逻辑，行为不变。
- 源单读取失败：`ElMessage.error(manualOrder.reorderSourceFailed)`，页面不崩溃、不预填。

### 4. 备注字段（`ManualOrderLeft.vue` / `ManualOrderRight.vue` / `ManualOrder.vue`）

- 左栏需求描述下方新增「备注（选填）」textarea（maxlength 1000，含字数统计），纳入表单 model、草稿存取、重置与 hasDraftContent。
- 右栏提交时，备注非空则创建订单后经既有 `artistApi.addNote` 写入新单（对齐截稿日/开稿日 post-create 补写模式）；失败进 `postCreateFailed.note` 汇总提示。
- 说明：手动录单页原先没有备注字段，拍板方案的「备注」必须可预填可编辑，因此新增该字段；不涉及后端契约变更。

### 5. i18n（`zh-CN.js` / `en.js`）

- `orderDetail.reorderBtn / reorderDialogTitle / reorderDialogHint / reorderFillDesc / reorderFillStyle / reorderFillNote / reorderConfirm`
- `manualOrder.note / notePlaceholder / reorderSourceFailed / reorderPrefilled / postCreateFailed.note`
- `check:i18n` 零新增违规。

## 三、契约核实与如实降级

- 画师端订单详情实际返回字段（`server/src/features/order/order-read.ts` + `order-route-utils.ts` 增强）为 **snake_case**：`client_qq / client_name / description / style_size_id / notes / extraItems / quote_snapshot` 等，**不含 `styleAddons` 结构化选择**。
- 因此：
  - 款式尺寸只回填 `style_size_id`（含画风联动）；源单尺寸已删除/画师当前无该尺寸/自定义单（`style_size_id=null`）时**静默降级只回填描述类**，画师可在录单页重选。
  - 增项选择（普通增项/用途/加急）与自定义增项**一期不携带**：接口无结构化增项数据（`quote_snapshot` 仅为人类可读文本，解析不可靠），如实降级并在本报告写明；如需二期携带需后端只增接口。
  - 参考图按拍板范围二期再做，对话框不放参考图选项。
- deadline/开工日/优先级/收款/节点状态一律不带，新单从零（单测有断言）。
