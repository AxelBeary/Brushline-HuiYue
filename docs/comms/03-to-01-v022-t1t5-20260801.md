# 三号 → 一号：T1-T5 额度池技术确认（2026-08-01）

## T1: paid_total_cents 冗余字段 vs 每次 SUM

**结论：采用冗余字段，spec 方案正确。**

理由：
- 订单详情是高频查询（画师端每次打开订单），SUM 每次扫 order_payments 表
- 冗余字段在 POST payments 时事务原子更新（INSERT 流水 + UPDATE paid_total_cents 同一事务），一致性由事务保证
- SQLite 单写者模型，事务内更新无并发风险
- 可选：管理端加"对账"按钮（SUM vs paid_total_cents），不需要自动化

## T2: 撤销实现细节（Q3 已拍板负数流水）

实现约束：
- POST /api/artist/orders/:id/payments 接受负数 amount_cents
- **硬约束**：`paid_total_cents + amount_cents >= 0`，减到负数 → 400 拒绝
- 负数记录**必须**带 note（撤销原因），正数 note 可选
- order_payments 表永不 DELETE，只 INSERT（审计完整性）
- 不需要单独的 DELETE API

## T3: 工作流推进与 installment status 解耦

**关键发现：全局搜索 `UPDATE order_payment_installments` 只有一处（adjustInstallments 改 amount_cents），没有任何代码写 status='paid'。**

这意味着：
- installment status 永远是 DEFAULT 'pending'
- `SUM(amount_cents) WHERE status='paid'` 永远返回 0
- **{已付}/{待付} 话术变量当前永远显示 ¥0 / 全额——这是现有 BUG**

解耦方案（比 spec 预想的更简单）：
- 不需要"移除写入点"（本来就没有）
- advanceStage / rollbackStage 本来就不碰 installments，零改动
- 新增 paid_total_cents 后，话术变量改读 paid_total_cents（修 BUG）
- getOrderInstallments 的 paid 判定改为 paid_total_cents 推算

## T4: adjustInstallments 替换影响范围

调用点仅 2 处（均在 order.service.js）：
1. `addExtraItem` L545：`adjustInstallments(orderId, cents)`
2. `deleteExtraItem` L576：`adjustInstallments(orderId, -item.price_cents)`

两处都已在 adjustInstallments 之前调了 `recalcFinalPrice`。替换方案：
- 删除 adjustInstallments 调用，只保留 recalcFinalPrice
- 系统备注中 `result === 'all_paid'` 改为 `paid_total_cents >= final_price_cents`
- adjustInstallments 函数本体删除
- **影响面小，无其他调用点**

## T5: 话术变量 {已付}{待付} 改用 paid_total_cents

当前实现（order-workflow.service.js）：
- `replaceSpeechVars` L188-191：SUM(amount_cents) WHERE status='paid'
- `getSpeechInfo` L222-225：同上

改为：直接读 `order.paid_total_cents`

对已有话术模板的影响：**无**
- 变量名不变（{已付}{待付}），模板格式不变
- 含义不变（已付金额 / 待付金额），只是数据源变了
- 唯一区别：修复了 T3 发现的 BUG（之前 {已付} 永远 ¥0）

## 总结

| # | 结论 | 风险 |
|---|------|------|
| T1 | 冗余字段 ✅ | 低（事务保证） |
| T2 | 负数流水 + 非负约束 + note 必填 | 低 |
| T3 | 无需解耦（本来就没耦合），但发现现有 BUG | 🟡 BUG 修复是好事 |
| T4 | 2 个调用点，删除即可 | 低 |
| T5 | 无影响，顺带修 BUG | 低 |

spec 整体方案可行，无阻塞项。建议 v0.23 实施时优先修 T3 的 BUG（话术变量已付永远为 0）。
