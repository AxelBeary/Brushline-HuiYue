## 四、PUT profile 破坏性变更回答（一号提问）

**确认：这个设计是有意的。**

理由：

1. **项目硬规则要求**：「所有写入路由（POST/PUT/DELETE）必须有 Fastify JSON Schema（additionalProperties: false），无例外」。旧 PUT profile 是项目中唯一没有 Schema 的写入路由，属于合规债务。

2. **camelCase 是项目统一约定**：POST /api/orders 用 `clientQq`/`tierId`/`clientName`，POST /api/artist/tiers 用 `exampleImage`/`workDays`。PUT profile 之前用 snake_case 是历史遗留，不是有意设计。

3. **静默剥离是 Fastify 默认行为**：Fastify 的 AJV 配置默认 `removeAdditional: true`，即 `additionalProperties: false` 时未知字段被静默移除而非报 400。这不是我额外配置的，是框架默认。

**风险评估**：

- 当前前端（Settings.vue）如果仍发 `weibo_url`/`bilibili_url`/`artist_code`（snake_case），这些字段会被静默剥离 → 用户保存后字段不生效但不报错。
- 这确实比报错更危险（用户不知道没保存成功）。

**建议方案**（请一号决策）：

- **方案 A（推荐）**：二号同步改前端字段名为 camelCase。改动量小（Settings.vue 的 payload 字段名），且与项目其他接口一致。本 PR 先合后端，二号基于合入后的 master 改前端。
- **方案 B（兼容层）**：我在路由 handler 里加一层 snake_case → camelCase 映射（类似旧代码的 CLAMP_MAP），让旧字段名也能生效。缺点： perpetuates 不一致，且 Schema 里要同时声明两套字段名。
- **方案 C（拒绝模式）**：在 app.js 全局 AJV 配置改 `removeAdditional: false`，让未知字段直接 400。影响范围大（所有路由），不建议在 v0.12 做。

我推荐方案 A。如果一号选 B，我可以在本分支追加一个 commit。
