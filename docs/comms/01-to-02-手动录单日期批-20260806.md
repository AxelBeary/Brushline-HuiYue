## 任务清单

### B1（中）今天选不了——disabled-date 时间比较 bug

`web/src/views/artist/ManualOrder.vue` 第 73、82 行，截稿日/开稿日两个 `el-date-picker` 的禁用逻辑都是：

```html
:disabled-date="(d) => d < new Date()"
```

`d` 是面板日期的 0 点对象，`new Date()` 带当前时分秒 → **今天 0 点 < 当前时刻 = true，今天被灰掉**，加急单"今天截稿/今天开稿"录不进去。

修法：归一化到今天 0 点再比较（今天可选，昨天起灰掉）。例如：

```js
const today0 = new Date(); today0.setHours(0, 0, 0, 0)
const disablePast = (d) => d < today0
```

两处 picker 共用。注意 `today0` 在组件 setup 期构造一次即可（录单页生命周期内跨天概率忽略不计，勿过度设计）。

### B2（中）截稿日 ↔ 开稿日无互相约束

现状：可录"截稿日 8-10、开稿日 8-15"。提交时订单先创建成功，再补写开稿日被后端拒（`INVALID_START_DATE`，server 已有测试 `server/tests/date-cross-validation.test.js`）→ 弹"订单已创建，但开稿日写入失败"，产生半残订单。

修法（对齐 `OrderDetail.vue` 第 994–1005 行的成熟实现）：

1. **双向灰掉**：`form.startDate` 有值时，截稿日 picker 灰掉 startDate 之前的日期；`form.deadline` 有值时，开稿日 picker 灰掉 deadline 之后的日期。注意本文件里两个字段是 `value-format="YYYY-MM-DD"` 的字符串，构造边界用 `new Date(form.startDate + 'T00:00:00')`，与 OrderDetail 一致。
2. **提交兜底**：`submitOrder()` 开头（clientQq 校验附近）加守卫：两日期都填了且 startDate > deadline → `ElMessage.error` + return，不发请求。前端校验只做后端规则的子集，后端 `INVALID_START_DATE` 不动。

新增/修改文案走 i18n（zh-CN.js + en.js 的 `manualOrder` 块），例如 `dateConflict: '开稿日不能晚于截稿日'` / `'Start date cannot be later than deadline'`（en.js 已有同语义句子可参考 `orderDetail` 或 `INVALID_START_DATE` 的措辞，保持风格一致）。
