## 做了什么

### V1 动画纪律收敛 ✅
- `web/src/styles/theme.css`：全局 `.el-button` 三态规则——hover `-3px`→`-2px`、transition `0.25s var(--ease-bounce)`→`0.15s ease`（含 box-shadow/背景/边框/文字色全部 0.15s）。
- `web/src/views/client/NotFound.vue`：画师卡片 hover `-3px`→`-2px`、`0.2s`→`0.15s`。
- `web/src/views/client/LandingPage.vue`：画师卡片 hover `-4px`→`-2px`、`0.2s`→`0.15s`。
- **bounce 变量处置研判**：`--ease-bounce` 保留变量定义（未删）。全局按钮已彻底移除 bounce；但 OrderForm.vue（6 处：步骤点/档位选中/入场动画 `tier-stamp-in`）和 templates.css（滚动渐入/吸底 CTA）仍在用。OrderForm 属五号并行批，**本批未动**。其中 `tier-stamp-in 0.35s var(--ease-bounce)` 属"庆祝/选中"类场景，可视为保留；若一号认为 OrderForm 的选中态也应去 bounce，需另派（涉及五号批文件）。
- **发现并修复隐藏问题**：EP button.css 自带 `.el-button { transition: 0.1s }` 加载在 theme.css 之后，单类选择器同特异性后定义者胜，导致 theme.css 的 0.15s 被覆盖。用双类 `.el-button.el-button` 提升特异性压过（实测 computed transition = `0.15s` 全套生效）。

### V2 EP 蓝泄漏排查 ✅ **属实，已修复**
- **实测确认评审指控属实**：约稿页"下一步"按钮 enabled 背景 `rgb(64,158,255)` = `#409eff` EP 出厂蓝。
- **根因**：EP `theme-chalk/base.css` 由 unplugin-vue-components 按需注入，加载在 theme.css 之后；其 `:root { --el-color-primary:#409eff }` 覆盖了 theme.css 的 `:root` 覆写（文档中两个 `:root` 规则并存、后者胜出）。泄漏范围不止主色：`--el-color-primary-rgb`、`light-3/5/7/8/9`、`dark-2` 整组变量全被 EP 出厂蓝系覆盖。
- **修复**（theme.css）：
  1. EP 覆写块选择器 `:root` → `:root:root`（双伪类，特异性 0,2,0 压过 EP 单 `:root` 的 0,1,0，对加载顺序不敏感）；
  2. 新增 `--color-primary-rgb`（5 色 × 亮暗 10 组）并接入 `--el-color-primary-rgb`，补上 EP rgba 场景。
- **验证**：10 组组合全部实测——亮色 a1-a5 = `#34dbcb/#34c2db/#3498db/#346edb/#3445db`、暗色 a1-a5 = `#4de8d9/#4dd0e8/#4da8e8/#4d82e8/#4d5ce8`，rgb 同步正确；"下一步"按钮 enabled 背景 `rgb(77,232,217)` = `#4de8d9`（accent1 暗色主题青）。
- 功能色（success/warning/danger）实测保持 EP 出厂色（暗色 `#95d475/#eebe77/#f89898`），符合 theme.css:28-31"功能色固定不跟随主色"设计决策，本批未动。是否收进 token 体系请用户另拍板。
