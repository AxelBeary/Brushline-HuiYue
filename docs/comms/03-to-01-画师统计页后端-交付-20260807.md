## 二、迁移 v45 说明

- 位置：MIGRATIONS 数组末尾（紧跟 v44，version 递增无重复），`server/src/db/init.js`
- SQL：`CREATE INDEX IF NOT EXISTS idx_events_artist_ts ON events(artist_id, ts)`
- 安全性：非 DROP/RENAME 父表，事务内可执行（v38 事故教训仅针对 DROP/RENAME）；IF NOT EXISTS 幂等，重跑安全
- 性能收益：画师/管理员统计 `WHERE artist_id = ?` 从全表扫描变为索引定位（events 表此前只有 `idx_events_name_ts(name, ts)`）
- 已有库升级：schema_migrations 记录 v45，老库启动自动执行

## 三、R1 防刷修复（四号巡检 04-to-01，中危）

| 接口 | 修复前 | 修复后 |
|------|--------|--------|
| `POST /api/anon-token` | 无鉴权无限流，每次 INSERT 一行 anon_tokens | 同 IP 每分钟最多 10 次，超出 429 `RATE_LIMITED`（正常前端首次上报 1 次/会话，10 次/分宽松） |
| `POST /api/events` | 限流 key = `body.token || request.ip`，循环签发新 token 可完全绕过 | 限流 key = `body.token ? `${body.token}:${request.ip}` : request.ip` 双因子，token 维度保留 + 绑定 IP |
| `GET /api/artist/tracking/summary` | 无限流 | 同画师每分钟最多 30 次（画师正常看页不会超过） |
| `GET /api/admin/tracking/summary` | 无限制 | 同管理员每分钟最多 30 次 |

429 响应体统一：`{ "code": "RATE_LIMITED", "error": "操作过于频繁，请稍后再试" }`

> ⚠️ 说明（R1 修复的完整防线）：双因子 key 让「带 token 时也绑定 IP 维度」；而「轮换新 token」这条路被 anon-token 签发限流（10 次/分/IP）堵死——攻击者每分钟最多签 10 个 token，两张表无法无限刷大（测试 TC-TR-17 完整复现攻击循环并验证第 11 轮被 429 卡住）。

## 五、接口契约（给前端）

### GET /api/artist/tracking/summary?days=14（requireAuth）

响应（实测，2026-08-07，演示画师 4 条 dashboard_view 事件）:

```json
{
  "enabled": true,
  "total": 4,
  "byName": [
    { "name": "dashboard_view", "count": 4 }
  ],
  "byDay": [
    { "day": "2026-08-06", "count": 1 },
    { "day": "2026-08-07", "count": 3 }
  ]
}
```

- `byDay.day` = `YYYY-MM-DD`（本地时区，与管理员 summary 一致），按日升序
- `byName` 按 count DESC（原有行为不变）
- **兼容性**：本批是加字段（`byDay`），未删/改任何既有字段；已上线的前端拿旧响应形状不受影响

### 429 限流响应（四个接口统一）

```json
{ "code": "RATE_LIMITED", "error": "操作过于频繁，请稍后再试" }
```

## 六、curl 复验样例

```bash
# 1) 签发匿名凭证（同 IP 每分钟 10 次）
curl -s -X POST http://localhost:3000/api/anon-token
# → {"token":"<64位hex>"}；第 11 次同一 IP 调用 → 429

# 2) 画师 summary（需登录 cookie/Bearer）
curl -s "http://localhost:3000/api/artist/tracking/summary?days=14" -H "Authorization: Bearer <画师session>"
# → { enabled, total, byName[], byDay[] }（byDay 按日升序）

# 3) 管理员 summary
curl -s "http://localhost:3000/api/admin/tracking/summary?days=30" -H "Authorization: Bearer <管理员session>"
# → { total, byName[], byDay[], funnel }（本批不变，限流 30 次/分）

# 4) 限流触发（同画师连发 31 次第 31 次）：
curl -s -o - -w "\nHTTP %{http_code}\n" "http://localhost:3000/api/artist/tracking/summary" -H "Authorization: Bearer <画师session>"
# 第 31 次 → HTTP 429 {"code":"RATE_LIMITED","error":"操作过于频繁，请稍后再试"}
```
