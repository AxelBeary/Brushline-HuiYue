## 2. catch-all 伪装 400 → 统一 AppError 分流（后端审计 🟡-1 升 🔴）✅

**文件**：admin.routes.ts(75/725/744/755) + artist.routes.ts(220/442) + upload.routes.ts(175/210/244/278)，共 10 处

**修复方案**：两形态统一替换为
```ts
if (err instanceof AppError) return reply.code(err.statusCode).send({ code: err.code, error: err.message })
throw err
```
- 类型 A（5 处：admin:75 + upload×4）：`return reply.code(400).send({ error: (err as Error).message })`——非 AppError 伪装 400 + 泄露内部 message
- 类型 B（5 处：admin×3 + artist×2）：`const e = err as AppError; reply.code(e.statusCode || 400)`——强断言 + `|| 400` 兜底同样伪装
- **关键修复**：artist.routes.ts:5 `import type { AppError }` → `import { AppError }`（原为类型导入，运行时会被擦除，instanceof 会 ReferenceError）
- 非业务错误（DB/流/未知）上抛 → 全局 500 handler：`{ code: 'INTERNAL', error: '服务器内部错误' }`，不透传内部细节
- admin.routes.ts:183 已有正确模式（instanceof + throw），未改动

**测试**（新文件 `server/tests/catch-all-unify.test.js`，vi.mock artistService 分流）：
- TC-C2-01：非 AppError（`throw new Error('boom raw internal detail')`）→ 500 + code=INTERNAL + error=服务器内部错误，响应体不含内部细节 ✅
- TC-C2-02：AppError（QQ_TAKEN, 400）→ 400 + code=QQ_TAKEN（原状态码保留）✅

**行为变化**：未预期内部错误从「400 + 内部 message 泄露」变为「500 + 结构化安全文案」；业务 AppError 状态码/结构不变。
