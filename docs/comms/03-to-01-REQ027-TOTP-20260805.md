## 决策说明（需一号知晓）

1. **二维码库选型（唯一依赖例外，已声明）**：`qrcode@1.5.4`（server 依赖）+ `@types/qrcode`（dev）。理由：Node 端 `toDataURL` 生成 PNG data URL 开箱即用，纯 JS 无原生编译；替代方案 qrcode-generator 零依赖但 Node 端需手拼 PNG 不可靠。
2. **AUTH_DEV_MODE 保留**，语义改为「bind-init 响应附带 `_dev_secret` 密钥明文」，生产默认 false 无泄露。REQ-014 桌面端复用 TOTP 时据此文档。
3. **防爆破**：连续错 5 次锁 15 分钟（对齐旧机制 MAX_ATTEMPTS=5 量级；锁定期比需求「临时」略长，报告说明）。锁定状态存 artists 行（未建新表）。
4. **bind-confirm 失败不计数不锁定**：绑定接口仅管理员可调，管理员身份可信，防爆破集中在登录接口。
5. **transfer 语义变更**：双码从「登录码」改为「双方各自的 TOTP 动态码」，双方须已绑定（未绑定 401 提示先绑定）。
6. **schema 保留 login_codes 建表**：迁移 v13 依赖该表存在（迁移链地基），由 v41 DROP 做最终移除；schemaIndexes 已删其索引（v41 后表不存在）。
7. 旧登录码错误码（CODE_INVALID 等）保留定义不再使用（错误码契约只增不删）。
