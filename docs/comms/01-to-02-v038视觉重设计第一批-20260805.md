## 二、Token 实施策略（客户端隔离，最关键）

⚠️ **现状实测**：`web/src/styles/theme.css` 的 `--bg-page/--bg-card/--color-primary/--text-*/--border-*` 及 `--el-*` 覆写被**客户端 170+ 处引用**（views/client/ 全部 + components/templates/ 全部）。客户端 4 模板依赖这些变量的当前值。

**铁律**：
1. **不改** theme.css 中任何现有变量的值，**不改** templates.css / palettes.css。
2. 新建 `web/src/styles/artist-tokens.css`（宣纸/墨黑两套，变量名用提案的 `--paper/--ink/--hq/--zs/--sl/--th/--zhe/--buf` 家族 + 圆角/阴影/字体变量），**作用域限定画师后台**：变量声明挂在后台布局容器（如 ArtistLayout 根元素 class）而非 `:root` 全局，确保客户端页面拿不到也不受影响。
3. 后台页面逐步改用新 token；后台内对旧变量（`var(--bg-page)` 等）的引用随页面改造逐个替换为新 token，第一批四页 + 骨架内不允许旧新变量混用残留。
4. Element Plus 换肤：`--el-*` 覆写同样 scoped 到后台容器（后台容器内覆写 `--el-color-primary: var(--hq)` 等），客户端路由下 EP 保持原样。
5. 主题切换：现有 `useThemeStore`（html.dark 开关）升级为宣纸/墨黑双主题（提案用 `html[data-theme="ink"]`，实现方式二号定，但**localStorage 持久化 + 刷新保持 + 默认宣纸**三条必须满足）。注意 ThemeToggle/ThemePicker/theme store 目前仅后台使用，可安全改；改完确认客户端路由下无 dark 主题残留副作用。切换交互：右上角太阳/月亮按钮 + toast「已切换 · 宣纸/墨黑」（toast 文案走 i18n）。
6. 霞鹜文楷子集已有（`assets/fonts/wencai/`），直接复用，**不新增字体资源**。
