# 屎山/不优雅代码审计报告

> 审计分支：`audit/code-smells`  
> 审计时间：2026-08-06  
> 审计范围：`server/src/`（48 文件）+ `web/src/`（158 文件）  
> 审计方式：只读分析，零代码改动  
> 结论：**P0 共 10 项 / P1 共 13 项 / P2 共 8 项**

---

## 一、执行摘要

核心风险集中在 4 类：

1. **巨型组件持续膨胀**：OrderDetail.vue 1898 行 / QueueBoard.vue 1679 行 / ManualOrder.vue 1432 行，均比派工单记录（1731/1530/1302）又涨了 ~10%，且仍在增长。
2. **裸 catch 吞错**：server 端 20+ 处无日志吞错（app.js/index.js/file-sign/platform.service 等），生产故障无迹可寻。
3. **any 黑洞**：server 端类型 any 约 190+ 处（`: any` 140 处 + `as any` 53 处 + `any[]` 若干），主要集中在上层路由，TS 类型安全形同虚设。
4. **性能隐患**：队列全量无分页、4 处模板组件 v-for 无 key、ManualOrder 桌面/移动价格面板整块重复。

> 说明：初稿曾把 SESSION_SECRET 回退列为 P0 安全风险，核实后该处**已有生产 fail-fast 保护**（NODE_ENV=production 时抛错拒绝启动），降级为 P1；初稿的"OrderForm v-for 无 key / QueueBoard 硬编码中文 / QueueBoard 滚动无节流 / N+1 查询"经核实为**误报**，已删除。

## 二、分级清单

### P0 — 必改（影响正确性/安全/维护）

#### P0-1 [C-安全] 裸 catch 静默吞错（server 端多处）
- **位置**：`server/src/app.js:95,103,110,144,212`、`server/src/index.js:18,47,58`、`server/src/shared/file-sign.ts:52,72`、`server/src/features/platform/platform.service.ts:36,104,182`、`server/src/shared/utils/platform.ts:68,134,142`、`server/src/features/auth/auth.service.ts:209`
- **问题**：`catch { /* ignore */ }` / `catch { /* 静默 */ }` / `catch { continue }` 模式 20+ 处，错误完全吞没
- **为什么算屎山**：生产环境任何被吞的异常都不可见，故障定位靠猜；file-sign 签名校验失败静默尤为危险（校验失效但调用方不知）
- **修复建议**：统一封装 `logger.warn(ctx, err)`，至少记 `console.error` + 上下文；file-sign 失败应抛错

#### P0-2 [B-架构] OrderDetail.vue 巨型组件 1898 行
- **位置**：`web/src/views/artist/OrderDetail.vue`（派工单记录 1731 → 现 1898，+167）
- **问题**：单文件承载订单详情 + 日期卡 + 状态区 + 图库 + 时间线 + 操作日志 + 附加工作项 + 收款池 + 交付 + 发布 10+ 功能域
- **为什么算屎山**：任何改动都可能踩到无关功能；模板 500+ 行 + script 数百行混排，评审/回归成本随行数线性上涨
- **修复建议**：按功能域拆 6-8 个子组件（GalleryCard/TimelineCard/PaymentCard/DeliverCard…），页面只做编排

#### P0-3 [B-架构] QueueBoard.vue 巨型组件 1679 行
- **位置**：`web/src/views/artist/QueueBoard.vue`（派工单记录 1530 → 现 1679，+149）
- **问题**：列表看板 + 月历 + 时间条三种视图 + 拖拽 + 滑条取消 + 焦点图上传全在单文件
- **为什么算屎山**：viewMode 三分支在同一 `<script setup>` 里共享状态，改时间条拖拽可能震到月历渲染
- **修复建议**：按视图拆 `QueueBoardView.vue / QueueCalendarView.vue / QueueTimelineView.vue`，共享状态抽 composable

#### P0-4 [B-架构] ManualOrder.vue 巨型组件 1432 行
- **位置**：`web/src/views/artist/ManualOrder.vue`（派工单记录 1302 → 现 1432，+130）
- **问题**：旧档位模式 + 画风模式双路径、桌面 + 移动双渲染，条件分支爆炸；**桌面版价格明细（L272-376）与移动版（L382-434）是近乎整块的重复模板**
- **为什么算屎山**：改一次价格展示要动两处；双模式 × 双端 = 4 个组合都要回归
- **修复建议**：价格明细抽 `PricePreviewPanel.vue` 复用；双模式逻辑拆 composable（useManualOrder / useStyleMode）

#### P0-5 [E-技术债] server 端 any 黑洞 ~190 处
- **位置**：`server/src` 全仓：`: any` 140 处（upload.routes.ts / pricing.routes.ts / style.routes.ts 的 `request: any, reply: any` 几乎占满）+ `as any` 53 处（order.routes.ts 25 处、pricing.routes.ts、artist.routes.ts）+ `any[]` 若干（order-queue.service.ts:22,76 等）
- **问题**：上层路由几乎无类型；`(request.body as any).xxx` 直接解构，无 DTO 校验类型
- **为什么算屎山**：TS 类型安全名存实亡；body 字段拼错只有运行时炸，编辑器零提示
- **修复建议**：路由层改 `FastifyRequest<{ Body: XxxDto }>` 泛型 + 补 DTO 定义，`as any` 逐处消解

#### P0-6 [D-性能] 队列全量拉取无分页
- **位置**：`server/src/features/order/order-queue.service.ts:15-23`（getArtistQueue 无 LIMIT）
- **问题**：`SELECT o.* ... .all(artistId)` 一次性返回正式区全部订单（含 description 大字段），且 `o.*` 冗余（tier 已 JOIN）
- **为什么算屎山**：画师订单量数百后响应体膨胀、前端 v-for 渲染卡顿；`o.*` 把 description 等大字段全拖下来
- **修复建议**：显式列清单 + 可选 `LIMIT/OFFSET`；getCompletedQueue（L65）已有 7 天窗口缓解，可加同样模式

#### P0-7 [D-性能] 模板组件 v-for 无 key（4 处）
- **位置**：`web/src/components/templates/TplTierGrid.vue:7`（`v-for="(tier, idx) in tiers"`）、`TplStyleGrid.vue:8`（`(style, idx)`）、`TplGallery.vue:140`（`(art, index) in filteredArtworks`）、`TplHero.vue:74`（`(art, i) in artworks.slice(0,2)`）
- **问题**：客户主页模板组件渲染列表无 `:key`，用 `idx` 做隐式 key
- **为什么算屎山**：列表更新时 Vue 无法复用节点，图集筛选/切换时整列重渲染；`idx` 作 key 在插入/删除时会错位复用导致状态串
- **修复建议**：全部补稳定 `:key="art.id / tier.id / style.id"`

#### P0-8 [B-架构] init.js 巨型文件职责混杂 1898 行
- **位置**：`server/src/db/init.js`（行号至 1898）
- **问题**：表结构建表 + v11~v39 共 30+ 个迁移 + 种子数据 + 管理员账号创建全在一个文件
- **为什么算屎山**：每次 DB 变更都要翻这个巨型文件；迁移与初始化耦合，测试难隔离
- **修复建议**：迁移拆 `server/src/db/migrations/` 目录（每版本一文件），init.js 只做编排

#### P0-9 [B-架构] 硬编码中文未走 i18n（整组件级）
- **位置**：`web/src/components/artist/MultiplierManager.vue:5-49`（"用途倍率 / 确定删除？/ 编辑倍率 / 新建倍率 / 名称 / 倍率值 / 说明（客户可见）"等全部硬编码）、`web/src/views/artist/ManualOrder.vue:38`（`aria-label="上传参考图"`）、`web/src/views/artist/Login.vue:10`（`alt="绘约"`）
- **问题**：`$t()` 已全局铺开，但这些新增/边缘组件整块绕过 i18n
- **为什么算屎山**：en.js 翻译覆盖率出现真实缺口，切英文版时这些 UI 直接显示中文
- **修复建议**：按 `artist.*` 命名空间补键并替换模板字符串

#### P0-10 [A-死代码/冗余] 迁移备份逻辑复制粘贴 ×12
- **位置**：`server/src/db/init.js:754,794,915,945,988,1012,1042,1073,1093,1310,1458,1533`
- **问题**：每个迁移各自复制一份 `console.log('📦 迁移 vN: 已备份…') + console.warn('⚠️ 迁移 vN: 备份失败…')` 模板
- **为什么算屎山**：改备份策略（如加校验和/云备份）要改 12 处，漏改一处行为就不一致
- **修复建议**：抽 `backupDb(dbPath, version): void` 工具函数，迁移内一行调用

### P1 — 建议（明显不优雅）

#### P1-1 [A-冗余] ManualOrder 桌面/移动价格明细模板整块重复
- **位置**：`web/src/views/artist/ManualOrder.vue:272-376` 与 `:382-434`
- **问题**：桌面 sticky 面板与移动端展开明细渲染同一份价格数据，模板几乎逐行复制（stylePricePreview 分支 ×2、pricePreview 分支 ×2、customAddons ×2）
- **为什么算屎山**：改价格明细展示（如加字段）必须同步改两处，已见 2 组 4 分支
- **修复建议**：抽 `PricePreviewPanel` 子组件，接收 `preview/items/total` props

#### P1-2 [C-健壮性] 过宽错误处理（web 端静默 catch）
- **位置**：`web/src/views/client/ArtistHome.vue:143-164`（5 个 `.catch(() => {})`）、`web/src/components/shared/ArtworkLikeButton.vue:78`（点赞失败静默）、`web/src/views/client/OrderForm.vue:755,768`（`catch {}`）
- **问题**：失败无任何用户反馈，仅"静默失败：不打扰"
- **为什么算屎山**：点赞/提交失败用户以为成功，产生业务误解；首页数据块失败无人知晓
- **修复建议**：交互类失败给 `ElMessage.error`；数据类失败至少 `console.warn` + 局部错误态

#### P1-3 [C-安全] SESSION_SECRET 开发默认值固定字符串
- **位置**：`server/src/features/auth/auth.service.ts:20-30`
- **问题**：开发环境 `SESSION_SECRET` 未设时回退固定值 `'dev-secret-change-in-production'`（**已核实：生产环境有 fail-fast 抛错，无实际劫持风险**）
- **为什么算屎山**：固定可预测密钥是坏习惯，若未来 fail-fast 被误删即成漏洞；同仓库多人开发共用同一密钥易互相串会话
- **修复建议**：开发环境改为每次启动 `crypto.randomBytes(32)` 生成并 warn

#### P1-4 [B-命名] order 模块返回类型混乱
- **位置**：`server/src/features/order/order-gallery.service.ts:27,57,115,154`（返回 `any`）、`order-queue.service.ts:15,30,65,83`（返回 `any[]`/`any`）vs `order.service.ts` 返回具体类型
- **问题**：同一模块一半函数返回 `any` 一半返回类型，调用方被迫二次 `as any`
- **为什么算屎山**：类型信息断裂，重构无编译器护航
- **修复建议**：为队列/交付结果定义 `QueueOrder`/`DeliverResult` 接口

#### P1-5 [B-魔法值] time_slot 五元组多处重复硬编码
- **位置**：`server/src/features/artist/greeting.service.ts:7`（`SLOTS` 常量）与 `server/src/features/admin/admin.routes.ts:307,324,357,374`（4 处 inline `['morning','afternoon','evening','night','any']`）、`server/src/db/init.js:234,600`（CHECK 约束内联）
- **问题**：同一枚举值定义 3 处（service 常量 / 路由 enum / DB CHECK）
- **为什么算屎山**：加一个时段要改 3 处，漏一处即运行时校验不一致
- **修复建议**：抽 `shared/constants.ts` 导出 `TIME_SLOTS`，路由与 service 引用同一来源（DB CHECK 保留但加注释引用）

#### P1-6 [A-死代码] TODO 残留未落地
- **位置**：`web/src/utils/track.js:11`（`// TODO(埋点后端): 接入服务端收集端点后启用…`）
- **问题**：埋点实现只有 `console.debug`（L10），远程端点是 TODO
- **为什么算屎山**：半成品功能上线，后续想查行为数据发现没数据
- **修复建议**：要么按 TODO 接端点，要么移除调用点并删注释

#### P1-7 [A-冗余] admin.routes.ts 三连 catch 重复
- **位置**：`server/src/features/admin/admin.routes.ts:723,741,751`
- **问题**：三个相邻 handler 的 `catch (err: any)` 错误处理块几乎相同（复制粘贴）
- **为什么算屎山**：改错误响应格式要改三处；`err: any` 还削弱类型
- **修复建议**：抽 `wrapHandler(fn)` 或共用 `handleAdminError(err, reply)`

#### P1-8 [E-技术债] fastify.d.ts 类型定义用 any
- **位置**：`server/src/types/fastify.d.ts:14,16`（`order: any`、`multiplier: any`）
- **问题**：Fastify 装饰器注入的 `request.order` / `request.multiplier` 类型为 any
- **为什么算屎山**：这两个是鉴权中间件注入的核心对象，类型缺失让所有下游失去提示
- **修复建议**：改为 `import type { Order } from './entities'` 的强类型声明

#### P1-9 [B-架构] web 模板硬编码 `/uploads/` URL 前缀
- **位置**：`web/src/views/artist/ManualOrder.vue:132,155,181`、`web/src/views/artist/QueueBoard.vue`（focusImageUrl 等拼装处）、`web/src/views/client/OrderForm.vue` 等多处模板内联 `` `/uploads/${x}` ``
- **问题**：静态资源 URL 前缀散落各组件模板
- **为什么算屎山**：换 CDN 域名/存储路径要全局搜索替换，漏一处即图片 404
- **修复建议**：抽 `assetUrl(path)` 工具或 API 层统一拼装（存疑待核：需确认后端是否已有 baseUrl 配置项）

#### P1-10 [C-健壮性] 前端埋点/数据加载失败无上报通道
- **位置**：`web/src/views/client/TrackOrder.vue:396`、`web/src/views/client/DeliveryPage.vue:113`、`web/src/components/shared/TplGuestbook.vue:100,111`、`web/src/components/shared/ArtworkLikeButton.vue:52,61,78` 等 10+ 处 `.catch(() => {})`
- **问题**：公开页"静默失败不阻塞浏览"策略可理解，但完全无监控痕迹
- **为什么算屎山**：线上主页数据加载持续失败时无人感知（无 error 日志/无指标）
- **修复建议**：接一个轻量错误上报（现有 console.warn 至少），或统一错误边界

#### P1-11 [A-冗余] 参数数组类型 `any[]` 应改为具体元组
- **位置**：`server/src/features/guestbook/guestbook.service.ts:37,102`、`server/src/features/order/activity-log.service.ts:45` 等
- **问题**：`const params: any[] = [...]` 传参给 prepared statement
- **为什么算屎山**：SQL 参数数量/顺序错误编译期不可见
- **修复建议**：按语句参数数量定义 `[number, string]` 等元组类型

#### P1-12 [B-命名] 初始状态枚举语义重叠
- **位置**：`web/src/views/artist/ManualOrder.vue`（`initialStatus` 用 confirmed/wip/revision/done 子集）与全局 `common.orderStatus`（pending/confirmed/wip/revision/done/delivered/cancelled）
- **问题**：录单初始状态选项是全局状态枚举的子集，但前端另建 `initialStatusOptions` 数组 + disabled 逻辑（L262-264）
- **为什么算屎山**：两份状态定义需手动保持同步，新增状态时容易漏录单页
- **修复建议**：由 `common.orderStatus` 派生 + 白名单过滤，去掉独立维护的 options

#### P1-13 [D-性能] 拖拽排序事务内逐条 UPDATE
- **位置**：`server/src/features/order/order-queue.service.ts:53-56`
- **问题**：`orderedIds.forEach((id, index) => updatePos.run(index + 1, id))` 在事务里逐条 UPDATE
- **为什么算屎山**：队列 100 单 = 100 次 UPDATE + 1 次全量返回；SQLite 单写锁下高频拖拽会串行化
- **修复建议**：批量写（CASE WHEN 一条 UPDATE）或接受现状并记录为已知边界（当前规模可接受，属优化项）

### P2 — 观察（风格/偏好）

#### P2-1 [风格] Rxx/REQ-xxx 编号注释密度过高
- **位置**：`OrderDetail.vue` / `QueueBoard.vue` / `ManualOrder.vue` 模板与 script 中 `<!-- R40: … -->`、`// v0.38: …`、`<!-- REQ-013 #7: … -->` 等 100+ 处
- **问题**：注释与代码行接近 1:1，且引用外部编号（R40/REQ-013）对新人无索引意义
- **为什么算屎山**：版本号注释随时间全部过时（v0.38 已成历史），阅读噪音大
- **修复建议**：清理版本号注释，保留"为什么"类注释，需求追溯交 docs

#### P2-2 [风格] 引号风格不统一
- **位置**：`server/src/db/init.js:754,794` 等（`'📦 迁移…'` 与 `"⚠️ 迁移…"` 混用）
- **问题**：同文件单双引号混用，模板字符串拼接连字符风格不一（`${}` 与 `'…' + …` 并存）
- **修复建议**：统一 ESLint/prettier 规则并 CI 卡关

#### P2-3 [风格] 模板长行超宽
- **位置**：`web/src/views/artist/OrderDetail.vue:171-175`（status 按钮 4 连 if 单行）、`QueueBoard.vue:142-146`（dropdown-item 单行多条件）等
- **问题**：多行超 120 字符，diff 阅读困难
- **修复建议**：prettier 统一格式化

#### P2-4 [风格] 状态/优先级文案映射函数散落
- **位置**：`QueueBoard.vue`（`statusType / priorityType / bandClass` 等）、`OrderDetail.vue`（同型映射）、`ManualOrder.vue`（`statusType`）各组件各自实现
- **问题**：同一 `status → el-tag type` 映射逻辑在 3+ 组件重复
- **为什么算屎山**：改一种状态的颜色要改多个文件
- **修复建议**：抽 `useOrderStatus()` composable 或 `statusMeta.js` 共享

#### P2-5 [风格] `console.warn` 与错误处理策略不一致
- **位置**：`server/src/features/auth/auth.service.ts:26`（warn）、`web/src/api/index.js:41,62`（warn）、大量裸 catch（无日志）
- **问题**：同类失败有的 warn、有的静默，无统一规范
- **修复建议**：定错误处理规范（交互错误→提示；数据错误→warn；未知→error），代码评审把关

#### P2-6 [观察] 迁移文件内历史版本注释过多
- **位置**：`server/src/db/init.js` 迁移段（v11-v39 各版本含详细变更说明注释）
- **问题**：30+ 版本迁移挤在一个文件，即使拆目录后历史注释也应精简
- **修复建议**：随 P0-8 拆分时一并精简为一行 `// vN: 变更摘要`

#### P2-7 [风格] 私有函数命名前缀不统一
- **位置**：`server/src` 部分函数 `getXxx`（getArtistQueue/getCompletedQueue 可导出）、部分 `_xxx` 风格（web 端 composable 内）
- **问题**：导出/私有边界靠命名暗示，无 `export` 显式区分时易误用
