## 任务：LRU 化（Map 有序迭代 + delete/set 刷新顺序）

利用 **JS Map 迭代顺序 = 插入顺序** 实现 LRU，零依赖：

```ts
// 核心改动：访问即刷新顺序（delete + set 重插到末尾）+ 淘汰最旧
export function rateLimit(key: string, maxHits: number, windowMs: number): boolean {
  const now = Date.now()
  const cutoff = now - windowMs

  // LRU 刷新：取出的桶重插到 Map 末尾（最近访问）
  let timestamps = buckets.get(key)
  if (timestamps) {
    buckets.delete(key)
    buckets.set(key, timestamps)
  } else {
    timestamps = []
    buckets.set(key, timestamps)
  }

  // 清除窗口外的旧记录（行为不变）
  while (timestamps.length > 0 && timestamps[0] <= cutoff) {
    timestamps.shift()
  }

  // 判断是否超限（行为不变）
  if (timestamps.length >= maxHits) {
    return false
  }

  timestamps.push(now)
  return true
}

// LRU 淘汰：超上限时从 Map 头部（最久未访问）逐个删，直到达标
const MAX_BUCKETS = 100_000
function evictOldest() {
  while (buckets.size > MAX_BUCKETS) {
    const oldestKey = buckets.keys().next().value
    if (oldestKey === undefined) break
    buckets.delete(oldestKey)
  }
}
```

**改动要点**：
1. `rateLimit()` 内：取桶后 `delete + set` 刷新 LRU 顺序（在 `if (timestamps)` 分支）
2. **保留** 窗口内 `shift` 过期时间戳逻辑（行为完全不变——滑动日志语义）
3. `setInterval(60s)` 定时器**保留但简化**：仍做「空桶清理」防止永远不活跃的 key 堆积（或改为「过期桶清理」——**保守起见保留现有清理逻辑**，只把 `buckets.clear()` 超限分支换成 `evictOldest()` 精确淘汰）
4. ⚠️ **行为不变铁律**：放行/限流判定、滑动窗口语义、MAX_BUCKETS 上限——全部保持

> 为什么保留 60s 定时器：LRU 淘汰只处理「超上限」，但「key 不活跃但未超上限」的场景（如 10 万 IP 各打一次后不再来）仍靠定时清理空桶/过期桶——**保留现有清理逻辑是最保守方案**，LRU 只替换「超限全清」这个最粗暴的行为。
