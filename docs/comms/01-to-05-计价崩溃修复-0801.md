# 一号 → 五号：详细计价点击崩溃修复

> 日期：2026-08-01
> 优先级：P0（用户可见崩溃）
> 分支：fix/pricing-detail-crash

## 现象

用户在 `/artist/alice/order` 选档位后点"详细计价"按钮，Vue 渲染崩溃（白屏/报错）。

## 已定位上下文（一号预排查）

按钮位置：`web/src/views/client/OrderForm.vue` 第 49-56 行，`@click="pricingExpanded = !pricingExpanded"`。

展开后渲染三块内容（第 61-138 行）：
1. **增项选择**（第 62-96 行）：`el-input-number v-model="addonSelections[a.id]"`（第 79 行）——`addonSelections` 是 `reactive({})`，初始无键，`addonSelections[a.id]` 为 `undefined`。**el-input-number 收到 undefined 可能崩溃**。
2. **倍率选择**（第 100-118 行）：radio-group，风险低。
3. **价格预览**（第 123-138 行）：`pricePreview.breakdown` 遍历 + `.toFixed(2)`——若 breakdown 为 null 或 item.amount 为 null 则崩。

composable：`web/src/composables/useOrderForm.js`
- 第 87-90 行：`addonSelections = reactive({})`，`addonToggles = reactive({})`，`pricePreview = ref(null)`
- 第 168-178 行：`calculatePrice` 异步调用，失败时 `pricePreview.value = null`
- 第 184-185 行：watch addonSelections/addonToggles 触发 scheduleCalc

## 修复方向（参考，五号自行确认根因）

1. `el-input-number` 的 v-model 不能是 undefined。展开时须确保 `addonSelections[a.id]` 有初始值 0。方案：在 `onTierChange` 或展开时初始化所有 quantity 类型 addon 的键为 0。
2. 模板中 `pricePreview.breakdown` 遍历前加防御（`v-if` 已有 `pricePreview` 判断，但 breakdown 本身可能为 null）。
3. `.toFixed(2)` 调用前确认 amount 非 null。
