## 任务

### 1. 抽样核对（优先）
挑 **10-15 篇**最可能过时的核对（按价值排序）：
- API 接口文档（接口路径/请求/响应若变必过时）——对照 `server/src/features/*/routes.ts` 实际路由
- 数据库设计（表结构）——对照 `server/src/db/init.js` 实际建表
- 认证授权系统 / TOTP（若 wiki 写登录码=过时，应写 TOTP）
- 前端样式系统（若 wiki 写旧五色/旧 token=过时，应写新纸墨盘）
- 技术栈 / 架构设计（对照现状）
- 故障排除（对照实际错误处理）

### 2. 差异分级
| 级别 | 含义 |
|------|------|
| 🔴 严重过时 | 与当前代码直接矛盾（如接口路径/字段/登录方式），会误导开发者 |
| 🟡 轻微过时 | 细节数字/术语旧（如测试数、版本号、组件行数），不影响理解 |
| 🟢 正确 | 与现状一致 |
| ⚪ 缺失 | wiki 没写但当前代码有的重要功能（如 TOTP、封面上限、埋点） |

### 3. 产出
交付报告（放 w15 工作区根，不 commit）：`repowiki-核对报告.md`：
- 核对了哪些篇、每篇结论（级）
- 🔴 清单：文件 + 过时段落 + 当前正确版本（一句话）
- 🟡 清单：条目化
- ⚪ 缺失清单
- 建议：哪些值得修（交一号），哪些忽略
