## 审计清单（逐项查，每项给证据：文件:行号）

### A. 错误处理
1. 全库 `catch` 块：吞错（空 catch / catch 后不抛不记录）/ 返回假成功（200 但没落库）/ 错误码不一致
2. `reply.send` 后继续执行（已发送又 send 报错）
3. 异步错误：`await` 缺失（promise 未捕获）、路由 handler 内 `setTimeout`/`setInterval` 未清理

### B. 边界与空值
4. 除法/取模除零（金额比例、分页）
5. `parseInt/Number` 无校验（NaN 进 SQL/金额）
6. 空数组/空结果：`reduce` 空数组、`[0]` 越界、`.find` 后直接 `.id`
7. 日期边界：UTC/本地混用（对标 TC-TR-15 教训）、时区偏移、月底/闰年
8. 金额：负数、超大数（溢出）、精度（分 vs 元混用）

### C. 并发与事务
9. 读改写非原子（check-then-act 竞态：如库存/名额/额度扣减）
10. 事务缺失：多步写操作部分失败留脏数据（对照 v38 迁移事故教训）
11. better-sqlite3 同步操作在 async handler 中阻塞（大查询）

### D. 安全
12. SQL 注入：模板字符串拼 SQL（非参数化）——全库 grep `\`SELECT|INSERT|UPDATE|DELETE` + `\${`
13. 越权：端点是否按 artist_id 过滤（对照 tools.routes.ts 的正确姿势）、admin 端点 requireAdmin 全覆盖
14. 敏感信息：日志/错误响应泄露（token、secret、内部路径）
15. 文件路径：用户输入拼路径（路径穿越）

### E. 清理与死代码
16. 未使用导出/死分支（可达性明显为假）
17. `console.log` 泄漏（正式代码残留调试输出）
