## 一、结论

需求按任务书完成：

- 订单详情「再来一单」回填对话框新增第四个勾选项「参考图」，**默认勾选**（与 desc/style 默认勾选策略一致；备注仍默认不勾）。
- 勾选后，源单**客户参考图**（`order.references` 中 `source !== 'artist'` 的条目）以**路径引用**复用进手动录单页左栏参考图区，**不重复上传**；缩略图正常展示、可删除，数量受 `MAX_IMAGE_COUNT`（5）约束，超上限截断并轻提示。
- 提交时参考图走既有 `references` 字段同一提交链路，随新单正常创建；新单幂等键（`crypto.randomUUID()` 按提交意图生成）与客户令牌（后端既有生成链路）均全新，原单零影响。
- 源单无参考图：选项仍可勾选，进入录单页预填时提示「源单没有参考图」，文字类预填不受影响（任务书两个方案中选此方案，报告说明见下）。
- 埋点沿用一期口径：`trackEvent('artist_action', { action: 'reorder_start', fromOrderId, fill })`，fill 含 refs。

## 二、实现明细

### 1. 对话框（`web/src/views/artist/OrderDetail.vue`）

- 第四个 `el-checkbox value="refs"`，文案走 `orderDetail.reorderFillRefs`。
- 默认勾选集合由 `['desc', 'style']` 改为 `['desc', 'style', 'refs']`，每次打开弹窗重置为默认（防上次选择残留）。
- 确认跳转 query 不变（`from=<orderId>&fill=desc,style,note,refs`），fill 白名单含 refs。

### 2. 预填纯函数（`web/src/utils/reorderFill.js`）

- `REORDER_FILL_KEYS` 增加 `'refs'`（未知项仍静默忽略）。
- 新增 `buildReorderRefs(sourceOrder, maxCount = MAX_IMAGE_COUNT)`：
  - 只取**客户参考图**（`source !== 'artist'`）且有非空 `file_path` 的条目，按后端返回顺序截断到 maxCount；
  - 返回 `{ refs, truncated }`，`truncated=true` 表示源单超出上限已被截断；
  - 条目保留原字段（`url`/`original_name`/`source` 等），供缩略图展示与删除链路使用。
- 只复用客户参考图的理由：画师加图（`source='artist'`）是内部图库，客户追踪页（R18）刻意不展示；若把画师图当作新单参考图提交，后端会落成 `source='client'`，导致内部图泄漏给客户。此过滤有单测锁定。

### 3. 参考图灌入（`ManualOrderLeft.vue`）

- 新增并 `defineExpose` 暴露 `setReorderRefs(sourceRefs)`：
  - 防御性按 `MAX_IMAGE_COUNT` 再截断一次；
  - 用源单签名 `url` 构造 EP picture-card 文件项（uid 为 `reorder-${crypto.randomUUID()}`，name 取 `original_name` 或文件名兜底，status=success），
  - 同步写 `refUidMap`（uid → file_path）与 `uploadedRefs`（file_path 数组）。
- 缩略图展示、悬停删除（`handleRefRemove` 经 refUidMap 移除路径）、提交消费，均与**新上传同一链路**，无第二套逻辑。

### 4. 预填装配（`ManualOrder.vue`）

- `applyReorderPrefill` 在文字/款式预填后，`fillSet.has('refs')` 时：
  - 源单有参考图：`leftRef.setReorderRefs(refs)` 灌入；
  - `truncated`：`ElMessage.warning(manualOrder.reorderRefsTruncated, { count: MAX_IMAGE_COUNT })`；
  - 源单无参考图：`ElMessage.info(manualOrder.reorderNoRefs)`，不中断其余预填。
- 提交链路未改动：`uploadedRefs`（父级 ref）经左栏 emit 同步、右栏提交时随 `references` 发送；幂等键逻辑原样保留。

### 5. i18n（`zh-CN.js` / `en.js`）

- `orderDetail.reorderFillRefs`：参考图 / Reference images
- `manualOrder.reorderNoRefs`：源单没有参考图 / The source order has no reference images
- `manualOrder.reorderRefsTruncated`：参考图超过 {count} 张，仅带入前 {count} 张 / Reference images exceed {count}; only the first {count} were carried over
- `check:i18n` 零新增违规。

## 三、契约核实与如实说明

- 画师端 `GET /api/artist/orders/:id`（`enrichOrderForArtist`）返回 `references[]`：`{ id, order_id, file_path, original_name, source, url }`，其中 `url` 为签名 URL（15 分钟有效），`source` 区分 `client`/`artist`。
- 手动录单 `POST /api/artist/orders/manual` **本就接收** `references: string[]`（maxItems 5 / 单条 maxLength 2000），且已有 `assertReferenceFileExists` 校验（`references/` 前缀 + 拒绝穿越 + 文件真实存在），创建时 `order_references` 落 `source='client'`。**因此后端零改动即可支持路径复用**，无需新增字段。
- 源单参考图文件已被清理（后端路径失效）时：提交被后端 `ILLEGAL_PATH` 400 拦截，走右栏既有 `ElMessage.error(err.message)` 容错，页面不崩；缩略图为签名 URL 失效/缺失时由 EP picture-card 既有展示容错兜底（占位/裂图，不崩页）。
- 无参考图降级方案选「选项仍可勾 + 预填时提示」而非禁用该行：参考图是否存在不影响对话框契约（四选项恒定），提示发生在真正消费勾选的位置，交互更简单；报告自述该决策。
