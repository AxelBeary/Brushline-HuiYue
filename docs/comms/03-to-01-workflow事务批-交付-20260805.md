## 任务一：P0-1 workflow 多步写事务包裹

`order-workflow.service.ts`：

- **advanceStage**：原四步写（UPDATE orders → refreshInstallmentLocks → logActivity → done 时 UPDATE completed_at）改为 `db.transaction()` 包裹（`advanceStageTx`）。校验（getOrder / STAGE_NOT_FOUND / INVALID_TRANSITION / 终态检查 / mapStageToStatus）全部留在事务外（读操作），事务只包写。`stageId=null` 关闭跟踪分支是单步写，不包事务。
- **rollbackStage**：原三步写（UPDATE orders → INSERT order_notes → logActivity）改为 `db.transaction()` 包裹（`rollbackStageTx`），校验同样留在事务外。
- 事务内调用的 refreshInstallmentLocks / logActivity 均走同一 db 单例、无嵌套事务（logActivity 注释本就声明"事务内调用，随主操作一起提交/回滚"），随事务一起提交/回滚，无外部副作用遗漏。
- REQ-025 守恒语义：中间步骤抛错不再留"orders 已更新但锁/日志未写"的半态。

## 任务二：P1-4 ADMIN_QQ 启动 fail-fast

`init.js` 管理员自举段开头新增守卫：**生产环境（NODE_ENV=production）缺 ADMIN_QQ 且无管理员账号 → 抛错退出**（带 .env 指引文案）。判定 = 环境变量缺失，且 platform_config.admin_qq 为空或其对应画师账号不存在；已有管理员账号（重启场景）不抛错；开发环境保持原静默行为。`.env.example` 补充 ADMIN_QQ 必填指引（属派工明确交付物）。
