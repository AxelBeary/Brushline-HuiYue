## 事故回顾

测试上传文件写入真实 `uploads/`（vitest.config.js 只设了 `DB_PATH=:memory:` 没设 `UPLOAD_DIR`）→ 容器重启时孤儿回收在空数据库上跑 → 所有图片被永久删除。

## 任务A：测试隔离（vitest.config.js + setup.js）

1. `vitest.config.js` 的 `env` 块加 `UPLOAD_DIR`，指向 `os.tmpdir()` 下的唯一子目录（如 `join(tmpdir(), 'commission-test-uploads-' + process.pid)`）
2. `setup.js` 加 `afterAll` 钩子：测试结束后递归删除该临时目录
3. 验证：跑全量测试，确认 `uploads/` 目录无新增文件

授权文件：`server/vitest.config.js`、`server/tests/setup.js`

## 任务B：孤儿回收→回收站（app.js + admin 接口）

### B1. 安全检查（app.js gcUploads 函数）

在 gcUploads 开头加：
```js
// 安全检查：画师表为空 = 数据库异常（测试/损坏），跳过回收
const artistCount = db.prepare('SELECT COUNT(*) as c FROM artists').get().c
if (artistCount === 0) {
  app.log.warn('孤儿回收跳过：画师表为空（数据库可能异常）')
  return
}
```

### B2. 删除→移入回收站

- `unlinkSync(absPath)` 改为 `renameSync(absPath, recycleBinPath)`
- 回收站目录：`UPLOAD_ROOT/.recycle-bin/YYYY-MM-DD/`（按日期分目录，保留原始相对路径结构）
- 回收站内的文件不参与下次 GC 扫描（walk 时跳过 `.recycle-bin`）

### B3. 管理员接口（admin.routes.js + admin.service.js）

- `GET /api/admin/recycle-bin`：列出回收站内容（文件名、原始路径、大小、移入时间）
- `DELETE /api/admin/recycle-bin`：清空回收站（真正删除文件）
- 两个接口都需要管理员权限（复用现有 admin 鉴权中间件）

授权文件：`server/src/app.js`、`server/src/features/admin/admin.routes.js`、`server/src/features/admin/admin.service.js`
