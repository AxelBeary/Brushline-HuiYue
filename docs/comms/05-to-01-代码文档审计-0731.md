## 任务A：order.service.js 拆分分析

### 基本数据

- **总行数**：852 行（含空行/注释）
- **导出函数**：22 个
- **内部函数**：6 个（formatYuan, buildQuoteSnapshot, compactQueue, mapStageToStatus, getStageInfo 内部辅助, STATUS_TRANSITIONS 常量）
- **import 依赖**：db, AppError/E, calculatePrice, PRICE_FALLBACK_SQL/resolvePriceCents, ACTIVE_ORDER_SQL/COMPLETED_ORDER_SQL, toSqliteDate/localDayStartSqlite/localDayEndSqlite/localMonthStartSqlite

### 按职责分组

| 组 | 函数 | 行数(约) | 说明 |
|----|------|---------|------|
| **订单 CRUD** | createOrder, getOrder, getOrderByNo, updateOrderStatus, updatePriority, updateDeadline | ~200 | 核心，createOrder 最重（事务+价格+分期+工作流接入） |
| **队列排序** | getArtistQueue, reorderQueue, compactQueue(内部) | ~80 | 拖拽排序+位置压缩 |
| **截稿日** | updateDeadline, getUpcomingDeadlines | ~40 | v0.15 R51 |
| **统计** | getArtistStats | ~75 | 仪表盘，含今日/月收入/待办，SQL 最复杂 |
| **图库/交付** | addReference, removeReference, setFocusImage, addDeliverable, deliverOrder | ~120 | R18/R4 焦点图+交付 |
| **备注** | addNote, deleteNote | ~30 | R19/R46 |
| **价格** | updateFinalPrice, buildQuoteSnapshot(内部), formatYuan(内部) | ~60 | v0.11 R2/R3 |
| **工作流** | advanceStage, rollbackStage, enableTracking, getStageInfo, mapStageToStatus(内部) | ~150 | R30d/v0.14 |
| **客户查询** | getClientQueuePosition, getClientOrdersByQq, hasClientOrders | ~50 | 客户端 |
| **列表/配置** | getArtistOrders, getPlatformConfig, generateOrderNo | ~60 | 分页+杂项 |

### 函数间依赖关系

**高频被调用**（拆分时需注意）：
- `getOrder()` — 被 12 个函数调用（几乎所有写操作都 return getOrder）
- `compactQueue()` — 被 updateOrderStatus, deliverOrder 调用
- `getArtistQueue()` — 被 reorderQueue, getClientQueuePosition 调用

**共享 import**：
- `db` — 全部函数
- `AppError/E` — 全部函数
- `ACTIVE_ORDER_SQL` — 队列/统计/列表
- `calculatePrice` — 仅 createOrder
- 日期工具 — 仅 getArtistStats, getUpcomingDeadlines, updateDeadline

### 拆分建议

| 新文件 | 包含函数 | 理由 | 风险 |
|--------|---------|------|------|
| `order-queue.service.js` | getArtistQueue, reorderQueue, compactQueue, updatePriority | 队列逻辑独立，仅依赖 getOrder | 低：compactQueue 被 updateOrderStatus/deliverOrder 调用，需 export |
| `order-stats.service.js` | getArtistStats, getUpcomingDeadlines | 纯读，SQL 复杂，独立性强 | 低：无写操作，无交叉依赖 |
| `order-gallery.service.js` | addReference, removeReference, setFocusImage, addDeliverable, deliverOrder | 图库+交付内聚 | 中：deliverOrder 调用 compactQueue（跨组） |
| `order-workflow.service.js` | advanceStage, rollbackStage, enableTracking, getStageInfo, mapStageToStatus | R30d 完整状态机，逻辑最复杂 | 中：advanceStage 写 status+completed_at，与 updateOrderStatus 有语义重叠 |

**保留在 order.service.js**：createOrder, getOrder, getOrderByNo, updateOrderStatus, updateDeadline, addNote, deleteNote, updateFinalPrice, getArtistOrders, getClientQueuePosition, getClientOrdersByQq, hasClientOrders, getPlatformConfig, generateOrderNo（~14 个，核心 CRUD + 客户查询）

**拆分后**：order.service.js 从 852 行降至 ~400 行，4 个子模块各 80~150 行。

**注意事项**：
1. `getOrder` 是公共依赖，拆分后子模块需 `import { getOrder } from './order.service.js'`，注意循环引用（order.service 不应反向 import 子模块）
2. `compactQueue` 拆到 queue 模块后需 export，deliverOrder（gallery 模块）import 它
3. 路由层 `order.routes.js` 的 import 路径需同步更新（约 20 处）
4. 建议分两步：先拆 stats（零风险），再拆 queue → gallery → workflow
