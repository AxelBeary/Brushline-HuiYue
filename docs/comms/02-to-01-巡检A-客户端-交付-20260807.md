## 一、🔴 真实问题

### 🔴-1【中】OrderForm「复制约稿信息」在画风模式下缺档位与明细
- 页面：OrderForm（成功弹窗）
- 位置：web/src/views/client/OrderForm.vue:822-829（copyOrderSummary 函数）
- 证据：函数只读旧模型字段 `selectedTier.value?.name`（825 行）与 `pricePreview.value?.breakdown`（826 行）；画风模式（isStyleMode）下两者均为空 → 复制出的摘要缺档位名和价格明细，只剩订单号+总价（displayPrice 画风模式有值）
- 严重度：中（画风模式是主要约稿路径，复制功能对启用画风的画师不可用）
- 状态：静态分析（本地 seed 无画风数据，未浏览器复现；建议一号协调三号/五号用真实画风数据复核）
- 建议修法：copyOrderSummary 增加 isStyleMode 分支——档位名取 `selectedStyle.value?.name`，明细取 `stylePricePreview.value.addonItems`，与 summary-card 的画风模式模板保持一致

### 🔴-2【中】DeliveryPage 交付记录 deliverables 为空时双卡片矛盾同屏
- 页面：DeliveryPage（交付页）
- 位置：web/src/views/client/DeliveryPage.vue:22（卡片1 v-if="verified && delivery"）、:36（el-empty noFiles）、:40（卡片2 v-if="verified && !delivery?.deliverables?.length && delivery"）
- 证据：当 delivery 对象存在但 deliverables 为空数组（[]）时，卡片1 渲染「暂无文件」空态、卡片2 同时渲染「尚未交付」结果 → 用户看到两个互相矛盾的卡片
- 严重度：中（低概率但直接的用户困惑；取决于后端未交付时的返回形态——返回对象带空数组即触发）
- 状态：静态分析（本地无交付数据，未浏览器复现）
- 建议修法：二选一——后端未交付直接报错走错误提示；或前端合并判断：`v-if="verified && delivery && delivery.deliverables?.length"` 显示文件卡，`v-else-if="verified && delivery"` 显示未交付卡

### 🔴-3【低】LandingPage import 语句位于 script setup 中部
- 位置：web/src/views/client/LandingPage.vue:70（`import { ARTIST_STATUS_TYPE }` 在 statusType/onMounted 之间）
- 证据：ESLint import/first 规范不允许 import 位于其他语句之后；代码可运行（import 提升）但违反项目规范、可读性差
- 严重度：低（非用户可见，规范问题）
- 建议修法：把该 import 移到 script setup 顶部与其它 import 合并

### 🔴-4【低】TrackOrder `loading` ref 恒为 false，v-loading 永不触发
- 位置：web/src/views/client/TrackOrder.vue:222（`const loading = ref(false)`）+ 模板 :4（v-loading="loading"）
- 证据：loading 声明后从未被赋 true（页面实际用 searching/myOrdersLoading 各自控制）；v-loading 恒不生效
- 严重度：低（无害冗余；页面实际有查询加载态）
- 建议修法：删除无用 loading 或改为首查时置 true（顺带获得初次渲染加载态）
