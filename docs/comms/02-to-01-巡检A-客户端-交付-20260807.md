## 一、🔴 真实问题（建议修复）

### 1. [中] 画风模式（主推路径）下「复制约稿信息」缺明细
- 页面：OrderForm 成功弹窗
- 位置：`web/src/views/client/OrderForm.vue:822-831`（copyOrderSummary）
- 现象：函数只读旧模型字段 `selectedTier.value?.name` 与 `pricePreview.value?.breakdown`。画风模式（styles 数据存在时系统走 style 定价）下两者均为空，复制结果 = 订单号 + 空档位名 + 无明细行 + 总价，约稿信息不完整。画风模式正是当前主推路径（TplStyleGrid 优先渲染）。
- 建议：按 `isStyleMode` 分支，画风模式用 `selectedStyle?.name + selectedSize?.name + stylePricePreview.addonItems` 拼明细（与成功弹窗小票一致）。
- 证据：静态分析确认（seed 无画风数据，未实测复现；如需要可由三号补画风数据后复测）。

### 2. [中低] DeliveryPage 交付物为空数组时双卡片同屏
- 页面：交付页 `/artist/:subdomain/delivery/:orderNo`
- 位置：`web/src/views/client/DeliveryPage.vue:22-37`（交付卡片 + `el-empty noFiles`）与 `:41-43`（未交付 el-result）
- 现象：当后端返回 `delivery` 对象但 `deliverables` 为空数组时，两个卡片同时渲染：「暂无文件」空态 + 「尚未交付」提示，语义矛盾、页面冗余。
- 建议：二选一——若「交付记录存在但无文件」属异常态只显示 noFiles；若确未交付应后端不返回 delivery（404/400），前端只保留一个分支。需与三号确认 delivery 端点契约。
- 证据：静态分析（本地 seed 无交付数据，未实测复现）。

### 3. [低] Folio 公告定位与 Hero 布局硬编码耦合
- 位置：`web/src/views/client/templates/ArtistHomeFolio.vue:221-222`
- 现象：`.folio-announcement` 用 `left: max(32px, calc(50% - 518px))`、`width: min(420px, calc(50% - 80px))` 硬算 TplHero split 的左栏位置（max-width 1100px + padding 32px + gap 48px 的推论）。当前实测未错位（hero 无图时右栏空，公告仍对齐左栏），但 Hero 布局一改（字号/间距/断点）公告即错位，是脆弱耦合。
- 建议：TplHero split 暴露左栏 ref 或公告改为 Hero 内布局（如 Hero 开 slot），消除魔法数字。
- 证据：实测未现错位，属结构性风险提示。
