## 三、关键语义变更（A3 口径说明）

### 1. 关闭判定（R10 + R13 收敛）

- 旧：`unlockedIdx.length === 0`（全锁即关闭）→ done 未付全订单被误判关闭，负 delta 全进 `extra_refund_after_close`（TC-P2-R13a 原注释「客户已付全」与数据只收定金 3000/30000 自相矛盾）。
- 新：`全部节点锁定 且 Σ待收 = 0` 双条件。已付全+全锁 → 维持 extra 语义（R10/R13 案例 9 回归）；全锁但未付清（done 未付全）→ **未关闭**，delta 冲抵/摊入未付节点（R13）。

### 2. 未关闭时的 delta 去向（参与节点集合）

- **非全锁订单**：参与节点 = 未锁节点（R5/R9 既有规则不变）。已锁但未付清的欠款保留（案例 2/7：完成即锁不参与分摊）；负 delta 的 R8 下限（非尾款最低 0、尾差压尾款可为负）不变（案例 8 回归）。
- **全锁订单（done 半终态）**：参与节点 = 有待款的节点（**含已锁但未付清的节点**，R13 对 R4 冻结的例外）：
  - 正 delta：按 R5 原始基点比例分摊（floor + 尾差归最后未付节点），增加其待收；
  - 负 delta：按 R9 镜像从尾往头冲抵欠款（每节点最多冲掉自己的待收），冲抵完仍有剩余 → 进 `extraRefund`（R13「已付全 → 额外应退」的推广）。

### 3. 条目落账（混合去向不丢账）

- 旧逻辑按去向二选一写条目（要么原因条目、要么 extra 条目）。新语义出现「部分进节点 + 剩余进额外项」的混合去向（done 未付全 + 负 delta 超出欠款），故改为：
  - 进节点部分 → 原因条目（`refund_item`/`extra_item`/`manual_adjust`）；
  - 进额外项部分 → `extra_refund_after_close`（负）/`extra_charge_after_close`（正）；
  - 纯节点 / 纯额外场景与旧行为逐条等价（`nodeDelta = 0` 时不写原因条目），Σ 两笔 ≡ delta，不双重记账。
