# 一号→五号：REQ-013 #7 看板完成订单修复（2026-08-01）

## Bug 描述

工作流订单推到流程最后节点后 status=done，但看板无法交付、无法消失。非工作流订单正常（有交付按钮）。

## 根因（一号已确认）

`QueueBoard.vue` 中"交付"入口的条件是 `element.status === 'done' && element.currentStageId == null`，只覆盖非工作流订单。工作流订单（currentStageId != null）到达最后节点时：
- `canAdvance()` 返回 false → 无"推进"按钮
- `nextAction` 的 else-if 要求 `currentStageId == null` → 无固定状态按钮
- 下拉菜单"交付"也要求 `currentStageId == null` → 无交付入口

结果：工作流订单 done 后永远卡在看板。

## 用户拍板方案（B + 补充）

1. **修复交付入口**：工作流订单在最后节点（status=done）时，显示"交付"按钮
2. **完成区沉底**：delivered 订单灰色显示在看板最下方，不可拖拽
3. **过期隐藏**：delivered 超过 N 天（建议 7 天，你定合理值）后不再显示

## 实现要点

### 前端（QueueBoard.vue）

1. 交付按钮：工作流订单 `status === 'done' && !canAdvance(element)` 时显示"交付"主按钮（调用 `artistApi.deliver` 或 `updateStatus(id, 'delivered')`——看 OrderDetail 的交付流程是否需要上传文件，如果需要则跳转详情页交付）
   - **注意**：OrderDetail 的交付需要上传交付文件（deliverable）。看板上如果直接标 delivered 不上传文件，业务上是否合理？你判断：如果交付必须带文件，则按钮改为"去交付"跳转详情页；如果可以不带文件直接交付，则直接调 updateStatus
2. 完成区：loadQueue 后把 delivered 订单分离到 `completedQueue` 数组，渲染在正式区下方，灰色样式，不可拖拽（不在 draggable 内）
3. 后端需要返回 delivered 订单（当前 SQL 过滤了）——见下方后端改动

### 后端（order-queue.service.ts）

当前 `getArtistQueue` 过滤 `status NOT IN ('delivered', 'cancelled')`。需要：
- 新增一个查询或修改现有查询，额外返回最近 N 天的 delivered 订单（status='delivered' AND updated_at >= 7天前）
- 或者新增 `GET /api/artist/orders/completed?days=7` 端点
- 你选方案，写清楚

### 样式

完成区卡片：opacity 0.5 + 灰色边框 + 无拖拽手柄 + 无操作按钮（只保留"详情"）
