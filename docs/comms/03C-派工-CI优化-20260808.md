## 任务 1：CI 现状审计 + 优化

先读 `.github/workflows/ci.yml` + `e2e.yml` 全貌，然后：

- **覆盖面**：unit/type/lint 是否全跑？缺什么（如 check:i18n、server oxlint、web build）？

- **稳定性**：E2E 的 strict-mode 类脆弱定位器是否还有（全量扫描 `getByText` 宽泛匹配 + 响应式双布局风险）
- **失败反馈**：失败时 artifacts 是否齐全（report/trace/screenshot）
- 优化项逐条落地 + 说明收益

## 任务 2：E2E 测试定位器系统性加固

刚修的 3 个用例暴露模式：**响应式双布局（移动卡片 + 桌面表格）导致同文本 2 处 + 管理端导航与页面标题重复**。

全量扫描 `e2e/tests/*.spec.js`：
- 所有 `getByText('静态文本')` → 评估 strict 风险（是否可能多元素）
- 所有 `getByText(动态变量)` → 评估是否双布局（订单号/用户名类）
- 加固策略：
  - 桌面表格定位 → `page.locator('tbody')...`
  - 页面标题 → `getByRole('heading')`
  - 唯一场景 → `.first()` 或 `:visible` 过滤（若元素可见性互斥）
  - 作用域限定 → 组件内 `drawer.`/`dialog.` 前缀
- **不改业务逻辑**，只改测试定位
- 修复后本地能跑（若环境允许）或至少语法+逻辑审查

## 任务 3：CI 防回归（可选但推荐）

- 加一个「strict-mode 扫描」脚本或 ESLint 规则：`e2e/tests/` 里禁止未限定作用域的宽泛 `getByText`（自定义 ESLint rule 太重 → 可加一个轻量 node 脚本在 CI 跑，检查 `getByText('xx')` 不带作用域前缀的静态文本）
