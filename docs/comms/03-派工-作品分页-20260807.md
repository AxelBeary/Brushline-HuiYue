## 一、后端改动（三号）

### 1. `server/src/features/artist/artist.service.ts`：getArtworks 加分页

```ts
/** 画师端作品分页（画师自己管理用，20/页；封面置顶不动） */
export function getArtworksPaged(artistId: number, page: number, pageSize: number): {
  items: Artwork[]
  total: number
  hasMore: boolean
} {
  const offset = (page - 1) * pageSize
  const total = (db.prepare('SELECT COUNT(*) AS c FROM artworks WHERE artist_id = ?').get(artistId) as { c: number }).c
  const items = db.prepare(`
    SELECT * FROM artworks WHERE artist_id = ?
    ORDER BY is_cover DESC, cover_order ASC, sort_order ASC
    LIMIT ? OFFSET ?
  `).all(artistId, pageSize, offset) as Artwork[]
  return { items, total, hasMore: offset + items.length < total }
}

/** 公开端作品分页（访客看画师主页用，10/页 + 加载更多） */
export function getPublicArtworksPaged(artistId: number, page: number, pageSize: number): {
  items: Artwork[]
  total: number
  hasMore: boolean
} {
  // 与 getArtworksPaged 同排序；如公开端要隐藏某些（hidden 画师已由路由层过滤）
  return getArtworksPaged(artistId, page, pageSize)
}
```

- 保留原 `getArtworks`（兼容现有调用，如公开 profile 组装）——分页接口是**新增**，不破坏旧契约
- ⚠️ SQL 参数化：LIMIT/OFFSET 用 `?` 占位（page/pageSize 已在路由层 clamp 整数，双保险）

### 2. `server/src/features/artist/artist.routes.ts`：

**(a) 画师端分页接口**（改造或新增，选新增避免破坏现有调用）：
```ts
/** GET /api/artist/artworks?page=1&pageSize=20 — 画师端分页（20/页默认） */
fastify.get('/api/artist/artworks', { preHandler: requireAuth }, async (request: FastifyRequest, reply: FastifyReply) => {
  const q = request.query as { page?: string; pageSize?: string }
  const page = Math.max(parseInt(q.page ?? '1', 10) || 1, 1)
  const pageSize = Math.min(Math.max(parseInt(q.pageSize ?? '20', 10) || 20, 1), 50)
  const paged = artistService.getArtworksPaged(request.artist.id, page, pageSize)
  return paged
})
```
- ⚠️ 现有 `GET /api/artist/artworks`（L340）返回数组——**改造为返回分页对象会破坏前端**。决策：**改现有接口**（前端同步改）或**新增 `/api/artist/artworks/paged`**。**选新增**（老接口留给不需要分页的调用），前端画师端改用新接口。
