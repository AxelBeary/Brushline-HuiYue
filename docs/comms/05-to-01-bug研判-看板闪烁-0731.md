# Bug 研判：排期看板首次进入焦点图反复闪烁

> 五号 → 一号 | 2026-07-31
> 来源：画师用户反馈"排期看板首次点入后图片依旧闪烁很多次才停下"

---

## 结论：确认是 Bug，BUG-1 修复未根治

v0.16 的 BUG-1 修复（300ms 防抖 + 最大重试 2 次）只解决了"多张图同时 error 合并为一次刷新"，但根因未触及。

---

## 根因分析

### 闪烁链条（4 层缺陷叠加）

**① 一张图 error → 全部图刷新**

`QueueBoard.vue:48` 的 `@error="refreshNow"` 触发后，`useSignatureRefresh.js:34` 的 `collect()` 收集**所有**订单的 `focus_image_path`，而非仅出错的那张。

**② apply() 替换所有 URL → 全图重渲染**

`useSignatureRefresh.js:39` 的 `apply(urls)` 把新签名 URL 写回**每个**订单的 `focusImageUrl`。签名含时间戳（`file-sign.js:24`），每次生成的 URL 字符串必然不同 → Vue 检测到 `:src` 变化 → `el-image` 重置内部状态 → 所有图片重新加载 → **全部闪烁**。

**③ errorRetries 只防 API 失败，不防图片加载失败**

`useSignatureRefresh.js:40`：API 成功 → `errorRetries = 0`（重置）。刷新 API 永远成功（只是生成新签名），所以 `MAX_ERROR_RETRIES = 2` 的上限**永远不会触发**。

**④ 循环形成**

```
图片加载失败 → @error → refreshNow → 300ms → doRefresh
→ API 成功 → errorRetries=0 → apply() 替换所有 URL
→ 所有 el-image src 变化 → 重新加载 → 可能再次 error
→ @error → refreshNow → ...（无限循环）
```

每轮 ~300ms + API 往返。用户看到的就是"闪烁很多次"。最终停下是因为浏览器缓存/网络稳定后图片加载成功，但体验很差。

### 为什么"首次进入"最明显

首次进入时 `loadQueue()` 一次性返回所有订单，N 张焦点图同时发起加载。浏览器对同域并发连接有限（Chrome 6 个），排队等待的图片更容易触发超时/error。一张 error 就触发全量刷新 → 雪崩。

## 修复建议（供一号派工参考）

**方案 A（最小改动，推荐）：按图刷新 + 按图计数**

1. `refreshNow(path)` 接受出错图片的 path 参数
2. `collect` 改为只收集传入的 path（或 Set 去重后批量）
3. `errorRetries` 改为 `Map<path, count>`，按图独立计数
4. `apply` 只更新出错图片的 URL，不动其他图
5. `QueueBoard.vue` 改为 `@error="() => refreshNow(element.focus_image_path)"`

改动量：~30 行，仅 `useSignatureRefresh.js` + `QueueBoard.vue`。

**方案 B（补充）：el-image 加 loading 守卫**

在 `apply` 写回 URL 前，检查该图是否正在正常显示（无 error 状态），避免不必要的 src 替换。可作为方案 A 的补充。

**风险等级**：低（纯前端显示逻辑，不涉及数据/权限/支付）

**建议派工**：二号（前端 composable + 组件修改）
