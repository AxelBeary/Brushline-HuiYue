## 第一部分：10 条验收逐项操作

### 验收 1 — token 符合度抽查（≥5 页面）

抽查页面固定为这 6 个（覆盖骨架+核心+列表+表单）：`/dashboard`、`/queue`、`/orders/:id`（任一订单）、`/orders/new`、`/artworks`、`/settings`。

每页检查四项：底色宣纸 `#F5F4EF`（墨黑主题 `#171611`）· 卡片圆角 11px · 按钮圆角 7px · 间距为 4 的倍数（卡片内边距 18、页面边距 28）。

- [ ] 宣纸主题：6 页逐项过，无旧色值残留（重点找有没有漏改的 Element Plus 默认蓝 `#409EFF`）
- [ ] 墨黑主题：同 6 页再过一遍
- [ ] 管理后台 `/admin` 及子页抽查 2 个（只套 token，不做定制）——低频从简，看卡片/表格/按钮是否套上新 token

### 验收 2 — 主题切换与持久化

- [ ] 右上角有主题切换按钮（太阳/月亮形态）
- [ ] 点击即时切换宣纸↔墨黑，无闪烁白屏
- [ ] 切换后 toast 提示「已切换 · 宣纸」或「已切换 · 墨黑」
- [ ] F5 刷新后主题保持（localStorage 已记）
- [ ] 清 localStorage 后默认宣纸
- [ ] 两套主题下逐页过一遍第一部分抽查页，确认语义映射完全一致（颜色变亮变暗可以，**语义不能变**——花青永远是进行中，不会因为换主题变成完成色）

### 验收 3 — 朱砂克制（逾期才见朱砂）

操作：找一个已逾期的订单（截稿日 < 今天）打开 `/orders/:id`，再回 `/dashboard` 和 `/queue`。

- [ ] 逾期订单相关元素（逾期 chip / 日期卡「逾期 N 天」/ 排期色带）为朱砂 `#BC3A2B`（墨黑主题 `#E07B6B`）
- [ ] 同一屏内非逾期元素无朱砂——界面其余部分保持纸墨安静
- [ ] 危险操作按钮（如删除）仅朱砂描边，无大面积红底
- [ ] 印章（已交付/已录入）朱砂底属于允许用法，不算破例

### 验收 4 — 统计卡数字不上色

操作：`/dashboard` 统计卡区域 + 两主题。

- [ ] 大数字为文楷 + **墨色**（松烟），未上色
- [ ] 卡片顶部有 3px 状态色条（色条才是状态载体）
- [ ] hover 出现跳转箭头
- [ ] 墨黑主题下数字为浅色墨系（可读），仍非颜料色

### 验收 5 — 密集界面无文楷

操作：`/orders`（订单表格）、`/settings`（表单）、`/tiers`（价格表格）逐屏看。

- [ ] 表格/表单字体为思源黑体（Noto Sans SC），正文 ≥13px
- [ ] 无文楷出现在表格单元格、表单 label/input 中
- [ ] 文楷只出现在：H1 大标题、统计数字/金额/日期、印章——超出这三处即为越界

### 验收 6 — 日期卡（订单详情）

操作：打开任一未完订单 `/orders/:id` 找「日期」卡；再造一个截稿日已过的订单看逾期态。

- [ ] 开工日 + 截稿日在**同一张卡**内（原来是两个独立 picker 各存各的）
- [ ] 改任一日期即时保存（无需点保存按钮），toast 含「排期已同步」字样
- [ ] 保存后 `/queue` 月历/时间条数据联动变化（切页验证）
- [ ] 剩余天数 chip 正确：未来显示「剩 N 天」；逾期显示「逾期 N 天」朱砂 chip
- [ ] 开工日 > 截稿日时的校验行为与重设计前一致（现有校验逻辑不变）

### 验收 7 — 空状态统一

操作：构造三个空场景——待办为空（无进行中订单）、留言为空（测试画师无留言）、作品为空（新画师未传作品）。

- [ ] 三处均显示统一墨线空状态组件（一笔墨线，非插画）
- [ ] 结构：楷体 15px 标题 + 12px 描述（+ 可选操作按钮）
- [ ] 两主题下墨线可见（墨黑主题下墨线需换浅色，不能隐形）

### 验收 8 — 破坏性操作撤销 toast

操作：`/queue` 排期看板拖拽一个订单改期（时间条拖拽若本批未做，则用本批实际存在的任一破坏性操作替代，并在报告注明替代项）。

- [ ] 操作后 toast 出现且**带撤销按钮**
- [ ] 点撤销，数据恢复原状
- [ ] 不点撤销，toast 自动消失后变更生效

### 验收 9 — 移动端不回退

操作：浏览器开发者工具切移动视口（375px 宽），过 `/dashboard`、`/queue`、`/orders/:id`、`/settings`。

- [ ] 布局可用：无横向滚动条、侧栏可收起或有等效导航、表格可滚动不撑破
- [ ] 对照重设计前同视口截图（一号留档或 git stash 对比）——只许持平或更好，不许回退

### 验收 10 — 客户端零影响

见第三部分专项抽查。核心：theme.css 现有变量被客户端大量引用（实测 10 个客户端视图/模板共 394 行含 `var(--` 引用，其中 OrderForm.vue 121 行、4 个 ArtistHome 模板各 48~66 行）——**新 token 必须 scoped 到后台容器，不许改现有变量值**。

- [ ] 第三部分路由表全部过一遍
- [ ] `git diff` 确认 `web/src/styles/theme.css` 现有变量值零改动（只允许新增，不允许改值；新增 token 定义在后台 scoped 区域）

| 路由 | 页面 | 重点看 | ✓ |
|------|------|--------|----|
| `/` | LandingPage 落地页 | 首屏配色、按钮样式 | [ ] |
| `/artist/:subdomain` | ArtistHome 画师主页（壳） | 页头页脚、导航 | [ ] |
| `/artist/:subdomain`（4 模板各看一遍：Classic/Gallery/Folio/Atelier，通过不同测试画师的 template_id 切换） | 4 个主页模板 | 各模板自身配色体系（4 模板 × 各自配色）完整，作品卡片/档位展示不变 | [ ] |

> 注：`/login`（画师登录页）在 REQ-026 §三 改造清单内，**属于要重做的后台页，不在本零影响抽查范围**——它的验收并入第一部分验收 1 的 token 抽查。

**补充机器检查**（比肉眼可靠）：
