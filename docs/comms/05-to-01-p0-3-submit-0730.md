【Bug 编号】P0-3

【Bug 标题】转让管理员接口缺少 IP 维度限流 + 无 JSON Schema 校验

【复现路径】
1. 持有管理员 token（requireAdmin 通过）
2. 对 POST /api/admin/transfer 发起请求，轮换 newQq 参数
3. 每个新 newQq 获得 3 次独立机会（限流键为 `transfer:${newQq}`）
4. 无 IP 维度限流，同一 IP 可对无限个 newQq 各尝试 3 次
5. 无 JSON Schema，currentCode/newCode 不校验格式（可传超长字符串）

【严重程度】严重（核心权限功能防护不足）

【影响范围】仅管理员转让接口（POST /api/admin/transfer）。需已持有管理员 token 才能触发。

【原因分析】
- 限流键 `transfer:${newQq}` 只限"对同一目标 QQ 的频率"，攻击者轮换 newQq 即可绕过
- 全项目其他 POST 路由均有 JSON Schema，唯独 transfer 用手动判空（历史遗留）
- newQq 无格式校验，可传入任意字符串触发数据库查询

【责任模块】后端（管理后台路由）

【修复方案】
1. 增加 IP 维度限流 `transfer-ip:${request.ip}`（5 次/15 分钟），与 newQq 维度并存
2. 补 JSON Schema：additionalProperties: false，newQq 校验 `^[0-9]{5,15}$`，currentCode/newCode 校验 `^[0-9]{6}$`
3. 移除手动判空逻辑（schema required 已覆盖）
