> 目的：用户要求「全页面巡检，找布局/美观/操作逻辑的问题」。本路负责**全局工程面**（跨页面、非单页专属）。

## 一、巡检范围（本路专属）

1. **路由与守卫**（web/src/router/index.js）：全部路由、requiresAuth/requiresAdmin 覆盖、404 兜底、重定向链路
2. **布局框架**：ArtistLayout（画师）/ AdminLayout（管理）/ 客户端壳（client 布局）——侧边栏/顶栏/移动端导航
3. **主题系统**（web/src/styles/）：theme.css / palettes.css / artist-tokens.css / templates.css——变量一致性、五色 natural-v2、纸墨双主题切换、字号档位（--font-scale）
4. **公共组件**（components/ 下 shared/* 与通用）：OrderTimeline、DeliverDialog、InkEmpty、StatusChip、CardHead、UndoToast 等——跨页复用组件的视觉/交互一致性
5. **composables**（web/src/composables/）：usePasteUpload/useDropGuard/useOrderWorkflow 等——逻辑隐患（状态泄漏/重复请求/事件未清理）
6. **api 层**（web/src/api/index.js）：接口路径与后端路由一致性、错误处理统一、缺失接口
7. **响应式全局**：断点一致性（375/768/1440）、滚动条/溢出/固定定位

## 二、检查点

1. **一致性**：同类型组件在不同页面表现是否一致（按钮/卡片/空态/加载态）
2. **路由安全**：未登录/非管理员访问受保护页是否被正确拦截
3. **主题**：双主题切换后所有 token 是否生效（有硬编码色值绕过 token 的）
4. **性能**：明显重复请求、未清理的监听器、大列表无 key
5. **错误处理**：api 失败是否有统一提示（vs 静默失败）
6. **i18n**：全局键缺失/死键（有定义未使用，或使用未定义）

## 三、方法

1. **静态分析**（主）：读代码、跨文件比对、grep 硬编码色值/断点/键
2. **浏览器实测**（可选加分）：起本地 vite dev **端口 5177**，抽查 2-3 个代表页面（如画师 Dashboard + 客户端画师主页 + 管理后台各一）验证跨页一致性，**截图留证**
3. 产出报告，不修代码
