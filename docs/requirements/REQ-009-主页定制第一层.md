## R48：画师头像上传

### 现状（已核实）

- **后端已就绪**：`artists.avatar TEXT`（init.js:17），`PUT /api/artist/profile` 的 allowed 列表含 `avatar`（artist.service.js:62），上传后存路径字符串
- **前端缺失**：Settings.vue 的 profile tab **没有头像上传入口**。画师无法在设置页上传/更换头像
- **客户侧已消费**：LandingPage.vue:25 用 `<el-avatar :src="artist.avatar ? '/uploads/${artist.avatar}' : undefined">` 展示；`GET /api/artists/:subdomain` 返回 avatar 字段
- **画师后台**：ArtistLayout.vue 侧边栏用首字母色块（`avatarChar`），不读 avatar 字段

### 需求描述

Settings.vue profile tab 顶部加头像上传区：
- 显示当前头像（无则显示首字母色块兜底）
- 点击/拖拽上传新头像（复用 uploadApi.image）
- 上传成功后即时更新预览 + 保存
- 客户主页（4 模板）+ 平台首页列表 + 画师后台侧边栏统一消费

### 验收标准

1. 当画师在设置页上传头像后，客户访问其主页应该看到新头像
2. 当画师未上传头像时，所有展示位应该用首字母色块兜底（不显示破图）
3. 当画师更换头像后，平台首页列表应该即时更新（不需要清缓存）
4. 当画师上传非图片文件或超大文件时，应该有前端校验提示（与作品上传一致：image/*，≤10MB）

### 工作量

30 分钟（Settings.vue 加 el-upload + 调 updateProfile({ avatar }) + 4 模板消费 avatar）

## R49：自定义强调色取色器

### 用户原声

> "对于 b，我们依然要做画师头像、单独取色等一层功能。"

### 现状（已核实）

- Settings.vue 模板 tab 有 4 固定色板（paper/ink/dusk/moss），每个色板预设 light/dark 两色
- 画师只能四选一，不能自定义颜色
- 客户主页模板通过 `paletteId` 决定整体色调（CSS 变量）
- **无自定义强调色字段**：artists 表无 `accent_color` 列

### 需求描述

在色板选择器下方（或替代）加一个**强调色取色器**：
- 画师可以选一个自定义颜色作为主页强调色（按钮/链接/高亮/状态徽章）
- 取色器用 Element Plus 的 `el-color-picker`（原生支持，零依赖）
- 提供 4 个预设色板作为快捷选项 + 自定义色输入
- **v1 只改强调色**，不改背景色/文字色（背景/文字联动暗色模式逻辑复杂，容易翻车）

### 技术影响

- 迁移：`ALTER TABLE artists ADD COLUMN accent_color TEXT DEFAULT NULL`（NULL = 使用色板默认色）
- 后端：`PUT /api/artist/profile` allowed 列表加 `accent_color`；`GET /api/artists/:subdomain` 返回该字段
- 前端（客户侧）：4 模板的 CSS 变量注入——有 `accent_color` 时覆盖 `--color-primary`，无则走色板默认
- 前端（画师端）：Settings.vue 模板 tab 加 el-color-picker

### 验收标准

1. 当画师选择自定义强调色后，客户主页的按钮/链接/高亮应该使用该颜色
2. 当画师未选择自定义色时，行为与现在一致（走色板默认色）
3. 当画师切换暗色模式时，自定义强调色应该仍然可读（不需要自动调整明度——v1 不做，但取色器旁加提示"请确保颜色在深色背景上可见"）
4. 当画师切换色板时，自定义强调色不丢失（两者独立：色板管背景/文字基调，强调色管高亮）
5. 当 4 个模板渲染时，强调色覆盖应该一致（不存在某个模板不生效）

### 待确认

- [ ] **C61**：强调色是否也影响画师后台（侧边栏/按钮），还是只影响客户主页？（建议：只影响客户主页——画师后台是工具界面，统一风格更好维护）

### 工作量

1.5 小时（迁移 + 后端字段 + Settings 取色器 + 4 模板 CSS 变量注入）

## R50：主页实时预览

### 用户原声

> "预览功能好加吗 还是会变成屎山？"→ 四号研判后用户确认"计入"

### 现状（已核实）

- Settings.vue 模板选择器只有 emoji 占位（`📖 🖌` / `🖼 ☀️`），无真实预览
- 无"预览我的主页"按钮
- 画师改模板/色板后必须保存 → 手动打开主页 → 才能看到效果

### 需求描述

Settings.vue 模板/色板/强调色选择区加"预览"按钮：
- 点击后新窗口打开 `/artist/:subdomain?_tpl=gallery&_pal=dusk&_accent=%23ff6b6b`
- ArtistHome.vue 检测 `_tpl`/`_pal`/`_accent` 参数，有则覆盖已保存值渲染
- 预览页顶部显示横幅"🔍 预览模式 — 尚未保存"
- **只覆盖渲染层，不碰数据层**：作品/档位/须知走公开 API（已保存数据），预览的是"皮肤"

### 设计约束（防屎山）

1. **单点分支**：覆盖逻辑只在 ArtistHome.vue 入口处一个 if，不扩散到 4 个模板组件内部
2. **零数据风险**：参数只影响浏览器渲染，不写库、不改 API
3. **预览参数只传"选了什么"，不传"数据本身"**：将来第二层（区块排序）若需预览，再升级为组件级预览，现在不做

### 验收标准

1. 当画师在设置页选了 gallery 模板但没保存时，点预览应该看到 gallery 布局（不是已保存的 classic）
2. 当画师选了自定义强调色但没保存时，点预览应该看到新颜色生效
3. 当预览页打开时，顶部应该有明确的"预览模式"标识，画师不会误以为已保存
4. 当客户拿到预览链接时，看到的只是另一种布局渲染，数据全是公开的（无安全风险）
5. 当画师不传任何预览参数时（正常访问），行为与现在完全一致

### 工作量

1~2 小时（Settings 加按钮 + ArtistHome 读参数覆盖 + 预览横幅 + i18n）

## 占位备案：专人专页 / 变现路径

> **状态**：占位备案，细节待未来版本规划展开。
> **来源**：实际操作人（2026-07-30）："兼容专人专页，这可能是未来的变现手段？或者直接一个单独的页面去部署，可以从我们现在项目拿数据或者跳转到约稿下单？"

### 核心概念（已明确）

- 平台为特定画师提供差异化主页展示，作为付费增值服务
- 不动主代码库业务层，定制的是"展示层"
- 数据源唯一（公开 API），下单入口唯一（跳转 `/artist/:subdomain/order`）

### 三形态（四号研判，用户确认"很好"）

| 形态 | 描述 | 工程量 | 变现逻辑 |
|------|------|--------|----------|
| 智能链接页 | 独立静态页（类 Linktree），从公开 API 拉数据，部署在独立域名 | 小（独立项目） | 免费带水印，付费去水印+自定义域名 |
| 嵌入组件 | embed.js widget，画师贴到自己网站，显示约稿卡片+下单入口 | 中（embed tab 已占位） | 免费嵌入带水印，付费自定义样式 |
| 全定制主页 | 平台内解锁高级模板/自定义区块 | 大（第二套模板引擎） | 付费高级模板/月费会员 |

### 已有基础设施

- `GET /api/artists/:subdomain`（公开 API，无需登录）
- `GET /api/public/pricing/:subdomain`（公开价格）
- `/artist/:subdomain/order`（独立下单路由）
- Settings.vue embed tab（UI 占位，P0-5 后 disabled）

### 待未来规划展开

- 具体排哪个版本（建议 v0.16+，等 B 层第一层 + 后端稳定后）
- 定价模型

- 与 R36（嵌入白名单）的关系
