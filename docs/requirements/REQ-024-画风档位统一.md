## F1：档位带图 + 档位描述/工作天数（数据与后台）

**功能描述**：

- 画风下的每个尺寸（档位）增加一个**图片**，画师两条路径都可设置：
  - (a) 独立上传一张新图
  - (b) 从自己已有的作品集里挑一张挂上
- 每个尺寸还可以填**描述**和**工作天数**（画师自己重新写，不从旧模型搬）
- 后台尺寸编辑处增加这三个设置项；图片、描述、天数都是可选项，不填不阻塞保存

**验收标准**：

1. 当画师在后台编辑某个尺寸时，应该看到图片设置位，且能选择"上传新图"或"从作品集挑选"两种方式
2. 当画师给尺寸填写描述、工作天数并保存后，客户端读取该尺寸时应该拿到同样的内容
3. 当尺寸没有上传图时，应该允许保存，客户端按 F3-3 兜底显示
4. 当画师更换或删除尺寸图片时，应该立即生效（保存后客户端刷新即可见）

---

## F2：后台入口合并 + 多画风开关

**功能描述**：

- 后台现有的"档位"tab 和"画风"tab 合并为**一个"画风与价格"入口**：画风是容器，每个画风下列尺寸，尺寸带图/描述/天数（即 F1 的结构）
- 入口顶部增加**多画风开关**
- 开关行为：
  - **关**：只有"默认画风"可正常编辑；其他画风在后台灰色显示、点不进编辑；客户端只显示默认画风
  - **开**：所有画风正常显示、可编辑，客户端全部显示（受各自 is_active 控制）
  - 关→开→关往返，**数据不丢**：多出的画风只是变灰隐藏，重新打开即恢复
- **默认画风** = 固定取排序最前的、且启用的画风（动态规则：若最前的被停用，自动顺延到下一个启用的）
- 原"档位"tab 移除（旧模型入口消失）；增项、倍率、流程、折扣码、增项库等其他 tab 不动

**验收标准**：

1. 当画师进入后台时，应该只看到一个"画风与价格"入口，原"档位""画风"两个并列 tab 应该消失
2. 当多画风开关**关闭**时，后台应该只有默认画风（排序最前的启用画风）可编辑，其他画风灰色、不能点进编辑，客户端主页不显示它们（用户原话 2026-08-03："新加的画风会保留 但是灰色不能编辑 不能显示在外面"）
3. 当开关**打开**时，所有画风应该恢复正常显示、可编辑
4. 当开关再次关闭时，不应该删除任何画风数据；再次打开后所有画风应该完整恢复
5. 当画师停用当前默认画风时，默认画风应该自动切换为下一个启用的画风
6. 当开关关闭且画师只有默认画风时，后台和客户端的体验应该与现单画风模式一致（不出现"选画风"概念）
7. 当本次改造完成后，增项、倍率、流程与比例、折扣码、增项库等 tab 的功能应该不受影响

## F3：客户端主页"点档位切大图"

**功能描述**：

- 展示柜布局不变（上方大图 + 下方尺寸列表），尺寸列表每行在现有"名字+价格"基础上，选中后展示该档位的描述/工作天数（若有）
- 交互（方案 1，用户拍板）：
  - 客户**点击某个尺寸行** → 上方大图切换成该尺寸的图
  - **未点任何尺寸** → 大图显示画风封面
  - 点的尺寸**没传图** → 大图保持画风封面兜底，不留空白
- 多画风模式（左菜单+右展示）和单画风模式（纯尺寸列表）行为一致；移动端滑动切换画风不受影响

**验收标准**：

1. 当客户在展示柜点击某个尺寸行时，上方大图应该切换为该尺寸的图
2. 当客户未点击任何尺寸时，大图应该显示画风封面
3. 当客户点击的尺寸没有上传图片时，大图应该保持显示画风封面，不留空白
4. 当客户选中一个带描述/工作天数的尺寸时，展示区应该显示该尺寸的描述和工作天数；未选中尺寸时显示画风描述
5. 当画师只有一个显示画风（单画风模式）时，上述 1-4 行为应该与多画风模式一致
6. 当客户在移动端左右滑动时，切换画风的现有行为应该不受影响

## F4：下单页预选

**功能描述**：

- **入口 A（带预选）**：从主页展示柜区域下单（含"点过某个尺寸行再点下单按钮"）
  - 客户点过尺寸行 → 预选"画风 + 该尺寸"，进下单页**直接跳到第三步"勾增项"**（用户拍板 (a)）
  - 客户没点尺寸行 → 只预选画风，停在选尺寸步
- **入口 B（不带预选）**：约稿按钮（首页 CTA）、未来的嵌入式跳转、直接输 URL 进下单页 → 无预选，把画风和尺寸完整再显示一次让客户选
- 预选必须**可见、可改**：下单页明确展示已预选的画风/尺寸，客户可回上一步修改，不锁死
- 下单页旧模型分支（无画风直接选档位）随 F5 迁移后自然废弃

**验收标准**：

1. 当客户在主页展示柜点过一个尺寸行再点下单按钮时，下单页应该预选好该画风和该尺寸、直接跳到第三步"勾增项"，且页面明确显示已预选的画风名和尺寸名
2. 当客户没点任何尺寸行、直接点展示柜的下单按钮时，下单页应该预选好当前画风、停在选尺寸步骤
3. 当客户通过约稿按钮或直接输入 URL 进入下单页时，应该没有任何预选，画风和尺寸完整显示供客户从头选择
4. 当存在预选时，客户应该可以回退修改画风/尺寸，修改后价格应该随之重算
5. 当预选内容参与计价时，价格结果应该与客户手动选同样内容时完全一致
6. 未来的嵌入式跳转入口应该遵循入口 B 逻辑（不带预选）——本条为预留约定，非本次实现范围

## F5：旧模型画师迁移

**功能描述**：

- 对 art_styles 为零的旧模型画师（如 carol）执行一次性迁移：
  - 自动创建一个名为 **"默认"** 的画风
  - 旧档位（price_tiers）转为该画风下的尺寸：**只搬名字、价格、排序**
  - **不搬**：旧档位的示例图（丢弃，画师重传）、描述、工作天数（画师重写）
- **所有画师的多画风开关一律默认关**——包括已有画风的画师（如 alice）：迁移后 alice 的第二个画风（厚涂插画）客户端不可见，需她自己进后台打开开关才恢复（用户拍板，接受此影响）
- 迁移后旧 price_tiers 数据废弃；客户端 TplTierGrid 兜底路径理论上不再触发（代码去留由实施方定）
- 迁移脚本必须**幂等可复跑**（v0.33 教训：清理与种子必须区分归属）

**验收标准**：

1. 当迁移执行后，每个旧模型画师应该多出一个名为"默认"的画风，其下尺寸与旧档位一一对应（名字/价格/排序一致），旧档位的图/描述/工作天数不保留
2. 当迁移执行后，所有画师的多画风开关应该为关闭状态
3. 当 alice（已有 2 画风）迁移完成后，客户端主页应该只显示她的默认画风，第二画风不可见；当她进后台打开开关后，第二画风应该恢复显示
4. 当迁移完成后，carol 的客户端主页应该显示画风展示柜（单画风退化形态），不再是旧档位展示柜
5. 当迁移完成后，各画师的作品、订单、增项、倍率、流程、折扣码等既有数据应该不受影响
6. 当迁移脚本重复执行时，不应该产生重复画风/尺寸，不应该误删任何已有数据

## 三、范围外（本次明确不做）

- 增项库、倍率、流程与比例、折扣码等其他 tab 的功能不变
- 旧模型的档位"可见性"（展示专用/隐藏）概念**不迁移**——新模型尺寸没有这个概念；若旧档位有"展示专用"项，迁移后变为普通尺寸（见待确认 #2）
- 客户端 4 模板的页面结构、主题配色不变（只改展示柜组件内部实现，4 模板自动继承）
- 作品集的点赞、封面标记等功能不受影响

## 四、实施注意（供二号/三号参考，非需求本身）

- 订单表 `orders.tier_id` 外键引用旧 `price_tiers`：迁移删除旧档位时，历史订单的档位引用需妥善处理（待确认 #1）
- 尺寸图"从作品集挑选"的实现：引用 artworks 还是复制一份独立存储，由三号定；若引用，作品集删图时档位图要有兜底
- `style_sizes` 表需加图片/描述/工作天数字段；`artists` 表需加多画风开关字段（v37 迁移）
- 客户端 TplTierGrid 与下单页 `isStyleMode=false` 旧分支：迁移后不再触发，删除或保留由二号/三号定，记入交付说明

## 五、待确认问题

1. **历史订单的档位显示**：旧档位删除后，已有订单（含 4 个演示订单中引用旧档位的）里的档位信息如何显示？需求底线：历史订单不能报错、不能空白。技术方案由三号确认（现有 quote_snapshot/price_snapshot 是否够）。
2. **旧"展示专用"档位的迁移提示**：若旧档位设过"展示专用"（showcase），迁移后变成普通可下单尺寸，语义变化。建议：迁移说明中告知画师。**待用户确认**是否需要在后台给一次提示。
