## R46：备注删除确认

### 决策引用

- **C59 已确认（方案 C）**：单条删除用 ElMessageBox.confirm（标准弹窗），批量删除（≥3）+ 取消订单用滑块确认

### 现状（已核实）

- **后端**：order_notes 表只有 INSERT（order.service.js:329/530/696）和 SELECT（:192），**无 DELETE 接口**
- **前端**：OrderDetail.vue 备注区（178-199 行）只有添加，**无删除按钮**
- 备注一旦写入永远无法删除——画师打错字、发错图、客户信息写错，只能忍着

### 需求描述

1. 后端新增 `DELETE /api/artist/orders/:id/notes/:noteId`（requireAuth + 归属校验）
2. 前端备注条目悬停显示 ✕ 删除按钮（与参考图删除交互一致）
3. 删除确认用 ElMessageBox.confirm（C59 方案 C：单条用弹窗）
4. 系统备注（`created_by='system'`，如状态变更记录）**不可删除**——前端不显示按钮，后端拒绝

### 验收标准

1. 当画师悬停在备注条目上时，应该显示删除按钮
2. 当画师点击删除时，应该弹出确认弹窗，确认后备注消失
3. 当备注是系统自动生成（created_by='system'）时，不应该显示删除按钮
4. 当画师删除带图备注时，关联图片文件应该被 GC 清理（或标记为孤儿待 GC）
5. 当非本画师尝试删除他人订单备注时，应该返回 403/404

### 技术影响

| 层 | 改动 |
|---|---|
| 后端 | order.routes.js 新增 DELETE 路由 + order.service.js 新增 deleteNote + 归属校验 |
| 前端 | OrderDetail.vue 备注区加悬停 ✕ + ElMessageBox.confirm |
| 迁移 | 无（order_notes 表结构不变） |

### 工作量

45 分钟（后端 30 + 前端 15）

## R40：时间线合并（展示层）

### 决策引用

- **C54 已确认**：展示层合并（时间线混排），数据层不变

### 现状（已核实，v0.14 R39 方案B 后）

OrderDetail.vue 当前布局：
```
基本信息卡（7-31行）
状态卡（33-77行）：工作流进度条 / 固定状态兜底
操作条（79-119行）：推进/打回/取消
图库卡（121-176行）
备注卡（178-199行）：纯文本+附图，按时间排列
交付文件卡（201行+）
```

- 状态变更事件**没有独立记录表**——状态变更只更新 `orders.status`/`current_stage_id`，不写事件日志
- 备注在 `order_notes` 表，有 `created_at` 时间戳
- 系统备注（`created_by='system'`）在状态变更时写入（order.service.js:696），内容如"从 X 回退到 Y"

### 需求描述

将"状态卡"和"备注卡"合并为一个**活动时间线**视图：
- 系统备注（状态变更记录）和画师备注按 `created_at` 混排
- 每条时间线节点有类型标识（🔄 状态变更 / 📝 备注 / 🖼 带图备注）
- 操作条保持独立（不合并进时间线）
- 添加备注的输入框移到时间线底部

### 技术方向（供二号/三号参考）

**方案 A（纯前端合并）**：后端不变，前端把 `order.notes`（已含系统备注）按时间渲染为时间线。状态变更事件已经在写系统备注（:696），数据已有。

**方案 B（后端事件流）**：新增 `GET /api/artist/orders/:id/activity` 返回统一事件流。更干净但多一个接口。

**建议方案 A**：系统备注已经在 order_notes 里了，前端只需要改渲染方式（从平铺列表改为时间线样式），零后端改动。

### 验收标准

1. 当画师查看订单详情时，状态变更和备注应该按时间顺序混排在一条时间线上
2. 当时间线中有状态变更记录时，应该有清晰的类型标识（区别于普通备注）
3. 当画师添加新备注时，输入框应该在时间线底部，提交后即时出现在时间线末尾
4. 当订单无工作流（老订单）时，时间线仍然可用（系统备注 + 画师备注混排）
5. 当操作条（推进/打回/取消）触发状态变更后，时间线应该即时刷新（显示新的系统备注）

### 工作量

2 小时（纯前端：OrderDetail.vue 备注区重构为时间线样式 + i18n）

## R38：订单附加工作项

### 备案来源

> "快完稿了客户突然加需求，画师加钱，计入尾款。"

- **per-order 附加项**：挂在单个订单上（区别于全局增项 price_addons）
- **费用**：每项附加工作可单独计价
- **计入尾款 + 客户可见**：附加费用累加进订单尾款，客户能看到加了什么、加了多少

### 现状（已核实）

- 全局增项系统已有：`price_addons` 表（init.js:377）+ `addon_tiers` 关联表（:401）——但这是下单前的报价组件，不是下单后的追加
- 尾款计算：`order_payment_installments` 表有分期计划，尾款 = 最后一期

### 待展开（v0.15 规划需确认）

| # | 问题 | 四号初步方向 |
|---|------|-------------|
| 1 | 录入入口 | 订单详情页加"添加附加项"按钮（画师操作） |

| 3 | 与现有增项/倍率/报价快照的关系 | 附加项独立于报价快照（快照是下单时的，附加项是下单后的） |

| 5 | 客户进度页展示 | 显示"附加工作项"列表（名称+金额），尾款金额更新 |

## R36：嵌入白名单

### 现状（已核实）

- app.js:127-133：embed 路径 CSP `frame-ancestors 'self'`，注释写"未来需配合白名单机制"
- Settings.vue embed tab：el-alert "暂未开放" + 复制按钮 disabled
- P1-5 已关闭（方案 B：不做子域名）→ 嵌入白名单逻辑简化（不需要处理子域名证书问题）

### 需求描述

画师能把自己的约稿主页/价格表嵌入到个人网站/博客：
1. 设置页 embed tab 解禁：画师配置允许嵌入的域名（如 `myblog.com`）
2. 后端 CSP 动态化：`frame-ancestors 'self'` → `frame-ancestors 'self' myblog.com`（按画师配置）
3. 嵌入脚本 embed.js 实现：在外部页面渲染约稿卡片（头像+状态+档位+下单按钮）
4. 管理员全局开关：可一键关闭所有画师的嵌入功能

### 验收标准

1. 当画师配置了允许域名后，该域名应该能 iframe 嵌入画师约稿卡片
2. 当未配置的域名尝试嵌入时，应该被 CSP 拒绝
3. 当画师未配置任何域名时，行为与现在一致（仅 'self'）
4. 当管理员关闭全局嵌入开关时，所有画师的嵌入应该失效
5. 当嵌入卡片加载时，应该展示画师头像/状态/档位/下单入口，点击下单跳转到平台

### 技术方向

- CSP 动态化：onRequest hook 中根据 URL 参数（`/embed/:subdomain`）查画师白名单，拼接 frame-ancestors
- embed.js：独立静态脚本（vanilla JS，不依赖 Vue），fetch 公开 API 渲染卡片
- 数据存储：artists 表加 `embed_domains TEXT`（JSON 数组）或新表

### 工作量

中（3~4 小时：CSP 动态化 + embed.js + Settings 解禁 + 管理员开关）

## R51：仪表盘截稿日与今日待办

### 用户原声

> "仪表盘最应该加什么功能：截稿日与今日待办。"

### 一号设计判断（已确认）

- 截稿日/今日待办：独立卡片
- 不做"空间不足则隐藏"——始终显示

### 现状（已核实）

- **orders 表无 deadline/截稿日字段**（init.js:69-98，已搜索确认零匹配）
- Dashboard.vue 现有：问候区 + 默认面板入口 + 4 统计卡 + 快捷操作 + 状态切换
- 无"今日待办"概念——订单只有状态（pending/confirmed/wip/...），无时间维度的"今天该做什么"

### 需求描述

**51a. 截稿日字段**：
- orders 表新增 `deadline DATETIME DEFAULT NULL`
- 画师在订单详情页可设置/修改截稿日（日期选择器）
- 手动录单时也可填截稿日

**51b. 仪表盘截稿日卡片**：
- 显示"即将到期"订单列表（deadline 在未来 7 天内 + 状态非终态）
- 按 deadline 升序排列
- 每条显示：订单号 + 客户名 + 截稿日 + 剩余天数（≤3 天红色警示）
- 点击跳转订单详情
- 无到期订单时显示"近期无截稿 🎉"

**51c. 今日待办卡片**：
- "今日待办"定义（待确认 C62）：
  - 今天截稿的订单
  - 状态为 pending 待确认的订单（画师需要处理）
  - 状态为 revision 的订单（客户等修改）
- 显示为简洁清单，点击跳转

### 验收标准

1. 当画师在订单详情页设置截稿日后，仪表盘截稿日卡片应该显示该订单
2. 当订单截稿日在 3 天内时，应该有红色/警示色标识
3. 当订单已交付/已取消时，不应该出现在截稿日卡片中
4. 当画师打开仪表盘时，今日待办应该列出需要处理的订单（pending + revision + 今日截稿）
5. 当没有待办时，应该显示空状态提示（不是空白）
6. 当画师未设置任何截稿日时，截稿日卡片显示"近期无截稿"

### 技术影响

| 层 | 改动 |

7. 关闭标签页后草稿保留（sessionStorage 在标签页关闭后清除——若需跨标签页保留可改 localStorage，但 v1 用 sessionStorage 即可）

### 验收标准

1. 当客户填了内容后刷新页面时，浏览器应该弹出"你有未保存的更改"警告
2. 当客户选择继续刷新后，表单应该恢复到刷新前的状态（档位/描述/QQ/参考图均在）
3. 当表单完全空白时刷新，不应该弹出警告
4. 当客户成功提交订单后，草稿应该被清除（再次打开是空白表单）
5. 当客户在画师 A 的页面填了草稿，打开画师 B 的页面时，不应该看到 A 的草稿（按 subdomain 隔离）

## R58：约稿页视觉与体验改版

### 需求来源

用户反馈（2026-07-30，两轮）：
> "约稿页面太丑。"
> 1. "布局现在比较清楚，但是有种上个世纪的表单的丑陋感。"
> 2. "没有提醒这是在约谁。"
> 3. "前面价格表展示没有直接打开增项弹窗，也没有跳转约稿的功能。"
> 4. "约稿页面明明横向空间还有，但是都浪费了。"

### 现状（已核实）

- OrderForm.vue（553 行）：标准 el-form + el-card 单栏布局，Element Plus 默认样式——"上个世纪的表单感"
- 页面无画师身份信息：客户从主页点进来后，约稿页不显示画师头像/名字/状态，不知道自己在约谁
- TplTierGrid.vue（客户主页价格表）：卡片只有展示（图/名/价/描述/工期），**零交互**——无"约这个档位"按钮，增项 slot（第 28 行）存在但无入口
- 约稿页 `.form-container` 单栏窄布局，宽屏横向空间大量浪费

### 需求描述

**58a. 视觉现代化（去"上个世纪表单感"）**：
1. 约稿页整体视觉升级：不是"填政府表格"，是"向喜欢的画师下单"
2. 风格应与客户主页（4 模板）的视觉语言衔接——客户从主页点进约稿页，不应该感觉换了个网站
3. 表单元素间距、字体层次、卡片质感需现代化（具体设计由二号出方案，用户审）

**58b. 画师身份提示**：
4. 约稿页顶部显示当前画师信息：头像 + 名字 + 接单状态徽章
5. 点击可返回画师主页

**58c. 价格表交互增强（客户主页 TplTierGrid）**：
6. 每个档位卡片加"约这个"按钮，点击跳转约稿页并**自动预选该档位**
7. 档位卡片上展示该档位适用的增项摘要（利用已有 slot），或提供"查看增项"入口

**58d. 宽屏空间利用**：
8. 桌面宽屏时约稿页改为双栏/多栏布局（如：左栏档位+价格预览，右栏描述+参考图+联系方式）
9. 移动端自动回落单栏

### 验收标准

1. 当客户打开约稿页时，页面顶部应该显示画师头像、名字和接单状态
2. 当客户点击画师头像/名字时，应该返回该画师的主页
3. 当客户在主页点击某档位的"约这个"按钮时，应该跳转到约稿页且该档位已自动选中
4. 当客户在约稿页切换档位时，价格预览应该即时更新（现有功能，不回归）
5. 当桌面宽屏（≥1024px）打开约稿页时，应该使用多栏布局，横向空间被有效利用
6. 当移动端打开约稿页时，应该自动回落为单栏布局
7. 当客户从主页进入约稿页时，视觉风格应该与主页衔接（不出现"换了个网站"的割裂感）
8. 当档位有适用增项时，价格卡片应该展示增项摘要或查看入口
