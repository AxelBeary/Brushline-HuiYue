# REQ-041 管理后台二次验证（会话升级）

> 状态：方案落档（2026-08-11 用户拍板「必须要。30min窗口。更换必须再验」）
> 整理：四号（借一号窗口）
> 关联：REQ-027（TOTP）、REQ-040（Passkey/账号安全）、REQ-039（1.0 清单 M7）
> 类型：Step-up Authentication（敏感操作再认证）

---

## 一、背景与风险

- 会话有效期 7 天（httpOnly cookie + HMAC 签名 token）
- 管理后台权限最高：**更换管理员**（`admin.routes.ts:359` 改 `admin_qq`）、删画师、改平台配置、邀请码管理
- **风险**：管理员登录态被劫持（共用电脑未退出 / cookie 被偷 / 远控 / 钓鱼）→ 攻击者直接进 `/admin` → **平台沦陷**
- **用户拍板（2026-08-11）**：1.0 必须。进管理后台二次验证，30 分钟免验窗口；「更换管理员」动作必须独立再验（不受窗口影响）

---

## 二、方案设计

### 会话升级模型

```
登录（基本会话 auth_level=basic）→ 点进 /admin → 弹验证（TOTP 或 Passkey 二选一）
→ 验证通过 → 会话升级（auth_level=admin_verified + verified_at）
→ 30 分钟内进 /admin 免验（verified_at + 30min 内）
→ 超时 / 新会话 → 再验
```

### 两级验证（用户拍板）

| 级别 | 触发 | 要求 |
|------|------|------|
| 入口级 | 进 `/admin`（路由守卫） | auth_level=admin_verified 且 verified_at 在 30 分钟内，否则弹验证 |
| 动作级 | **更换管理员**（改 `admin_qq`） | **强制独立再验**（无视 30 分钟窗口）——最高危动作 |

### 验证方式

- TOTP 动态码（现有 verify 流程）或 Passkey（REQ-040 认证流程）**二选一**，画师/管理员任选
- 验证失败走现有限流（防爆破）；与登录失败同响应语义（防枚举）

### 后端

- 会话/token 增加字段：`auth_level`（basic | admin_verified）+ `admin_verified_at`
  - 现状 token 为 HMAC 签名（无服务端会话表），升级=验证通过后**重新签发 token**（带新字段），旧 cookie 覆盖
  - 若实施时发现 token 过长，考虑服务端会话表——技术选型留实施时定
- API：
  - `POST /api/auth/step-up`（登录态，验证 TOTP 或 Passkey → 重新签发升级 token）
- 中间件：
  - `requireAdminStepUp`（管理后台路由：检查 auth_level + 30 分钟窗口）
  - `requireAdminReauth`（更换管理员动作：强制最近验证，无视窗口）
- 踢下线联动：`bumpTokenVersion` 后 auth_level 自然失效（与 REQ-040 一致）

### 前端

- `/admin` 守卫：auth_level 不足 → 弹「管理员验证」对话框（动态码输入 / 「使用 Windows Hello」按钮）
- 更换管理员表单：提交前强制弹验证（动作级），失败不清表单
- i18n 键（zh/en）；纸墨设计语言

### 测试

- 后端单测：升级成功/失败/窗口过期/动作级强制/新会话未升级进 /admin 被拒
- 前端 E2E：进 /admin 弹验证 → 通过进入；30 分钟后过期；更换管理员动作级再验

---

## 三、验收标准

1. 新登录管理员直接访问 /admin → 被要求验证（TOTP 或 Passkey），通过后进入（可测）
2. 升级后 30 分钟内再进 /admin 免验证；超时后需重新验证（可测）
3. 更换管理员（改 admin_qq）动作：即使刚升级过也必须再验一次（可测）
4. 验证失败次数过多触发限流/锁定（复用现有机制）（可测）
5. 画师（非管理员）无 step-up 能力，/admin 判定不变（可测）
6. 验证方式二选一：TOTP 码与 Passkey 都可用（可测：Playwright 虚拟认证器）

## 五、边界声明

- 本 REQ 只做管理员二次验证（会话升级 + 动作级）；画师普通后台不引入 step-up（低危操作不验，避免日常烦躁）
- 不改变现有登录/会话签发机制（只在验证通过后重新签发升级 token）
- 与 REQ-040 共用 Passkey 认证能力；与 REQ-027 共用 TOTP 验证能力
