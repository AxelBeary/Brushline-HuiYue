## 一、核心概念（已明确）

- 现有**约稿须知**的结构化升级：须知现为自由文本、客户下单前勾选同意；画师协议 = 须知结构化 + 下单时自动填充本单信息（档位/价格/截稿日）+ 客户下单即确认，生成一份**可存档的凭证**
- 定位 = **画师与客户之间的约定**（版权归属/用途范围/修改次数/交付标准等，内容画师自己写），不是平台统一服务条款
- 与 REQ-031 A2（订单收据）同属"凭证渲染"类功能，未来可一批实施

## 二、明确不做（边界，用户认可的方向）

1. **不叫"合同"、不用"签署"字眼**——避免平台暗示法律效力
2. **平台不对协议内容做法律背书**——内容是画师写的，责任归画师
3. **不做电子签名**——客户下单确认 = 事实确认，不是法律签署
4. **不改变订单状态机**——协议是订单的附属凭证，不引入"已签署"等状态

## 三、待未来规划展开（占位，不预设）

1. 协议模板编辑方式（须知编辑器升级 vs 独立模板区）
2. 协议内容是否纳入内容审核（与须知同等待遇，倾向是）
3. 凭证呈现形式（与 A2 收据共用渲染组件？独立页面？）
4. 多语言（现有 i18n 体系下协议模板是否需要画师自写双语）
5. 排期：建议与 REQ-031 A2 同批考虑（凭证渲染一批做）
