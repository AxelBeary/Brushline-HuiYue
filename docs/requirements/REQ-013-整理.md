## #1 画师端留言管理独立页面

### 画师原声
> 留言相关内容应该全部放主页里

### 用户澄清（2026-08-01）
> "我问了问，他说留言这个功能的详细功能，现在只有仪表盘一个入口。（不是主页没有功能，是只有一个小板块来处理这个）"

### 代码现状（已验证）
- **客户端留言墙**：4 个主页模板全部内嵌 `TplGuestbook`，位于页面底部 → 客户端无问题
- **画师端**：仅仪表盘右栏一个小板块（`Dashboard.vue:36-85`），功能只有通过/拒绝/回复
- **后端 API 已齐**：`GET /api/artist/messages`（全量含 pending）、approve/reject/reply 三个 PUT 均已实现（`guestbook.routes.ts:70-107`）
- 无独立页面、无状态筛选、无搜索、无分页

### 验收标准
1. 当画师在侧边栏点击"留言管理"时，应打开独立的留言管理页面
2. 当留言管理页加载时，应显示全部留言列表（含待审核/已通过/已拒绝三种状态），每条显示昵称、内容、时间、状态
3. 当画师点击状态筛选标签（待审核/已通过/已拒绝/全部）时，列表应只显示对应状态的留言
4. 当画师对某条留言点击"通过"/"拒绝"/"回复"时，操作应立即生效并刷新该条状态（复用现有 API）
5. 当有待审核留言时，侧边栏"留言管理"入口应显示未处理数量角标

### 优先级：P2
后端 API 已齐，纯前端页面。与 #3 联动（留言管理是候选按钮之一）。

### 预估工程量：~3h（前端页面 + 侧边栏入口 + 角标）

## #3 快捷按钮自定义

### 画师原声
> 右边现有 6 个按钮（实际空位有 9 个），希望可以自定义或部分自定义

### 用户确认（2026-08-01）
> "我感觉他很想自定义"；对候选池 + 勾选方案回复"对！"

### 代码现状（已验证）
- 6 个按钮硬编码在 `QuickActions.vue:19-26`，3×3 网格空 3 格
- 无 DB 配置、无设置项、无排序 UI
- **附加问题（代码核实发现）**：6 个按钮中 5 个与侧边栏重复（排期看板/全部订单/图库管理/档位管理/主页设置），仅"手动录单"是侧边栏没有的；且按钮命名与侧边栏不一致（"图库管理" vs 侧边栏"作品管理"，"档位管理" vs "价格管理"）

### 方案（用户已确认）
1. **候选按钮池**（约 10 个）：手动录单、留言管理（#1 新增后）、排期看板、全部订单、作品管理、价格管理、主页设置、主页预览、收入统计（预留）、数据导出（预留）
2. 画师在设置里**勾选显示哪些**（最少 3 个，最多 9 个），网格 3 列 × 1~3 行自适应
3. **统一命名**：按钮文案与侧边栏菜单完全一致，消除"图库管理≠作品管理"的困惑
4. **默认 6 个**：手动录单、留言管理、排期看板、全部订单、作品管理、主页设置

### 验收标准
1. 当画师打开设置的快捷按钮配置区时，应看到全部候选按钮列表（图标 + 名称），每个可勾选/取消
2. 当画师勾选 N 个按钮（3≤N≤9）并保存后，仪表盘快捷区应只显示这 N 个按钮，3 列排列
3. 当画师勾选少于 3 个时，应提示"至少选择 3 个"且不允许保存
4. 当画师未做任何配置时（新画师/未设置），应显示默认 6 个按钮
5. 按钮名称应与侧边栏菜单名称完全一致（作品管理、价格管理等）
6. 当候选按钮对应的功能页面不存在时（如预留项），该候选不应出现在列表中

### 优先级：P2
个性化体验 + 解决命名混乱。依赖 #1（留言管理页面做好后才有该候选）。

### 预估工程量：~3-4h（DB 配置存储 + 设置 UI + QuickActions 读配置 + i18n）

## #4 接稿设置独立 + 名额概览改版

### 画师原声
> 稿位数字设置怎么还没上线？

### 用户确认（2026-08-01）
> "这个设置挪位置的话，我觉得你说得对，完全可以独立出去，成为一个'接稿设置'大项。主页模板暂时可以不动。"
> "正式和缓冲共用一个条来显示进度怎么样呢？这个板块没必要专门做个齿轮。画师只要想点，整个板块直接跳转接稿设置。"

### 代码现状（已验证）
- slotDisplay 功能链路完整，4 模板全部渲染，**不是 Bug**——画师没开启名额/额度所以不显示
- 名额开关埋在"基本资料"标签页第 10 项（`Settings.vue:103-157`），要滑过 9 个设置项
- 画师直觉会去"主页模板"标签页找，但那里只有视觉设置
- 仪表盘名额概览显示内部术语"正式 3/5""缓冲 0/2"（`SlotOverview.vue`），与客户主页看到的 slotDisplay（"开放中 · 剩 N 席"）是两套语言

### 方案（用户已确认）

**A. 设置页新增"接稿设置"标签页**：
- 挪入：正式名额开关、缓冲位、月度额度开关、4 个缓冲开关（自动晋升/隐藏排位/隐藏晋升通知/缓冲短表单）
- "基本资料"和"主页模板"标签页不动
- 标签页顺序：基本资料 / 接稿设置 / 主页模板 / 约稿须知 / 嵌入脚本

**B. 名额概览卡片改版**：
- 主文案复用 slotDisplay（客户看到什么，画师看到什么）
- 正式 + 缓冲共用一个进度条（总容量 = 正式 + 缓冲，已用 = 当前在队数）
- 整卡点击 → 跳转接稿设置（不加齿轮按钮）

### 验收标准
1. 当画师打开设置页时，应看到"接稿设置"标签页，点进去只显示名额/额度/缓冲相关设置（正式名额开关、缓冲位、月度额度开关、4 个缓冲开关）
2. 当画师在接稿设置里开启正式名额并保存后，客户主页应立即显示对应的 slotDisplay 文案（如"开放中 · 剩 N 席"）
3. 当画师查看仪表盘名额概览时，应看到大字主文案（与客户主页一致的 slotDisplay）+ 一个合并进度条（已接 X / 总容量 Y）
4. 当画师点击名额概览卡片任意位置时，应跳转到设置页的"接稿设置"标签页
5. 当正式名额和缓冲位都未开启时，名额概览应显示引导文案（如"未开启名额限制，去设置"），点击同样跳转接稿设置

### 优先级：P1
解决画师"找不到功能"的核心问题。纯前端改动（设置页挪组件 + SlotOverview 改版），无 DB 变更。

### 预估工程量：~2-3h（前端）

### 后续专项备案

### 验收标准
**界面改进（P2）：**
1. 当画师打开话术编辑区时，变量按钮应只显示一次（顶部公共区域），点击变量按钮应插入到当前聚焦的编辑框

### 优先级：界面改进 P2，多模板随机 P3

## #9 档位展示柜 + 图片裁切修复

### 画师原声
> 设置的图片在约稿页上被错误乱截：竖的截成横的、长的截成方的

### 用户确认（2026-08-01）
> 裁切方案："现在的乱裁切绝对是不行的"；对展示柜方案回复"很好"
> 首屏大图："首屏大图不动"
> 作品 grid："A. 自适应高度（height: auto）"
> 模板共享："之后得问问这个功能设置是不是所有模板共享的，不共享我们可以先放一个里试试水"

### 代码现状（已验证）

| 组件 | 裁切方式 | 处理 |
|------|----------|------|
| TplTierGrid（档位示例图） | 固定 180px + cover → 竖图裁成横条 | ⚠️ **改展示柜** |
| TplGallery grid 模式（classic 用） | 固定 200px + cover | ⚠️ **改 auto** |
| TplGallery editorial / masonry | height auto / 瀑布流 | ✅ 不动 |
| TplHero 三个变体 | cover（首屏设计意图） | ✅ 不动（用户拍板） |

**模板共享结论（已核实）**：TplTierGrid 是 4 个模板共享的组件（Classic/Gallery/Folio/Atelier 全部调用），改一处全部生效。**不做模板级开关，全模板统一生效**——旧裁切设计本身是坏的，无保留价值。

### 方案（用户已确认）：档位展示柜

客户看到的档位区从"一排被裁的小卡片"改为"菜单 + 展示柜"：

**桌面端**：
```
┌──────────────┬─────────────────────┐
│ 头像档  ¥50   │                     │
│ 半身档  ¥120 ◀│   [ 完整大图 ]       │
│ 全身档  ¥300  │   不裁切，原比例      │
│              │   工期 7 天           │
│  点哪个看哪个  │   [ 选择此档位 ]      │
└──────────────┴─────────────────────┘
```

**移动端**：档位标签横排在上方，大图在下方，左右滑动切换档位。

### 验收标准
1. 当客户访问画师主页的档位区时，应看到左侧档位菜单（档位名 + 价格，纵向排列）+ 右侧当前档位大图
2. 当客户点击菜单中某个档位时，右侧大图应切换为该档位的示例图，**完整显示不裁切**（原比例，宽度撑满展示区）
3. 当档位无示例图时，展示区应显示档位说明文字（不留空白框）
4. 当客户在移动端左右滑动大图区域时，应切换档位（与点击菜单等效）
5. 当某档位为"只展示"状态时（#10），菜单中该档位应灰色显示 + 标注"暂不接单"，大图正常可看
6. 当某档位为"不展示"状态时（#10），菜单中不应出现该档位
7. 4 个主页模板应同时生效（共享组件 TplTierGrid，不做模板级开关）
8. 当客户访问 classic 模板的作品展示区（grid 模式）时，作品图应完整显示不裁切（height: auto）

### 优先级：P1
客户做购买决策的最后一个界面。与 #10 三态有天然依赖（展示柜菜单需渲染三态），**建议一号安排同批实施**。

### 预估工程量：~4-6h（前端组件重做 + 响应式 + 4 模板验证）；grid auto ~30min

## #10 档位三态

### 画师原声
> 档位希望能设置：开、只展示、不展示（三态）

### 代码现状（已验证）
- DB 无可见性字段（`price_tiers` 表，`db/init.js:49-59`）
- 后端无过滤，公开 API 返回全部档位
- 管理端无可见性设置，只有新建/编辑/删除
- 当前只有两态：存在 / 删除。临时下架只能删除，数据不可恢复

### 三态定义

| 状态 | 含义 | 客户端表现 | 画师端表现 |
|------|------|-----------|-----------|
| **开**（visible） | 正常接单 | 正常显示 + 可选 | 正常编辑 |
| **只展示**（showcase） | 展示但不接单 | 显示 + 灰色"暂不接单"标注 | 正常编辑 + 状态标记 |
| **不展示**（hidden） | 完全隐藏 | 不显示 | 列表中灰色显示 + 可恢复 |

### 验收标准
1. 当画师在档位管理页将某档位设为"只展示"时，客户主页应显示该档位但不可选择（灰色 + "暂不接单"标注）
2. 当画师将某档位设为"不展示"时，客户主页应完全不显示该档位
3. 当画师将"不展示"的档位改回"开"时，客户主页应立即恢复显示
4. 档位管理页应有三态切换控件（分段按钮：开 / 只展示 / 不展示），新建档位默认为"开"
5. "不展示"的档位数据应完整保留，恢复后无需重新填写
6. 客户下单流程中，"只展示"和"不展示"的档位均不可被选择下单

画师明确需求。与 #9 展示柜同批实施效果最佳。
