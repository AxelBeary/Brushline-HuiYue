## 一、Token 体系（开发可执行清单）

### 1.1 色彩——国画颜料盘 7 色，语义严格一对一

| 颜料 | 宣纸主题色值 | 语义（唯一职责） |
|------|--------------|------------------|
| 宣纸 | `#F5F4EF` | 页面底色；卡片纯白 |
| 松烟 | `#262520` | 标题正文墨色；侧栏底色 |
| 花青 | `#33526E` | 品牌色 · **进行中** · 主操作按钮 |
| 朱砂 | `#BC3A2B` | **逾期** · 警示 · 印章（出现即重要，平时不用） |
| 石绿 | `#2F7D54` | **完成** · 交付 · 成功 |
| 藤黄 | `#A8790B` | **待确认** · 缓冲提醒 |
| 赭石 | `#8A5A33` | 暖中性 · **客户** · 优先级 |

**硬规则**：
- 颜色只说状态——平时是纸墨，有事才见颜料；画师每天看 8 小时，界面必须安静
- 统计数字一律墨色，仅用色点 + 卡片顶部 3px 色条标状态（不给数字上色）
- 危险操作仅朱砂描边，不大面积铺红
- 主操作 = 花青；最终提交 = 墨黑（仪式感）；次操作 = 白底描边

### 1.2 双主题（宣纸 / 墨黑）

- 墨黑主题：底色压暗（`#171611`）、卡片 `#22201A`、颜料统一提亮（如朱砂→`#E07B6B`）、**语义映射完全不变**
- 全部色值以 CSS 变量实现（提案 HTML L12-36 已给出两套完整变量表，直接采用）
- **切换交互**：右上角主题切换按钮（太阳/月亮形态），点击即时切换 + toast 提示（"已切换 · 宣纸/墨黑"）；选择记入 localStorage；默认宣纸
- Element Plus 组件通过 CSS 变量覆盖同步换肤（EP 主题定制常规做法，三号评估覆盖范围）

### 1.3 字体分工（严格边界）

| 用途 | 字体 | 规格 |
|------|------|------|
| 页面大标题（H1） | **霞鹜文楷** | 28px / 700 |
| 统计数字、金额、日期、印章 | **霞鹜文楷**（落款感） | 按场景，开启 tnum |
| 卡片标题（H2） | 思源黑体（Noto Sans SC） | 15px / 600 |
| 正文 | 思源黑体 | 13.5px / 400 |
| 辅助信息 | 思源黑体 | 12px / 400（底线：正文不小于 13px） |

> 口诀：**文楷是落款**——只落在标题、数字、印章上；表格表单等密集界面一律无衬线。霞鹜文楷已有子集拆分（v0.24 PERF-1 修复），直接复用。

### 1.4 间距 / 圆角 / 阴影 / 动效

- 间距刻度：4 的倍数（4 图标间距 / 8 表单项内 / 12 列表行内 / 16 卡片内区块 / 24 分区间 / 32 章节留白）；页面边距 28、卡片内边距 18、卡片间距 14
- 圆角：4px 标签 / 7px 按钮 / 11px 卡片 / 全圆 Badge
- 阴影三级：静置 4% / 悬浮 9% / 浮层 16%，克制不堆叠
- 动效：微交互 160ms、入场 450~550ms（上浮 16px + 5px 模糊，stagger 延迟）、页面切换 150ms、盖章 450ms 回弹；**不引入新动效库**（CSS transition + Vue Transition，现有 vuedraggable 之外不加）
- 装饰性元素（墨线、漂移墨晕）透明度 ≤10%

## 二、组件标准（全站统一，一次建成多处复用）

| 组件 | 标准（摘自提案 v2 第四节） |
|------|---------------------------|
| 按钮 | 主操作花青 / 提交墨黑 / 次操作白底描边 / 危险仅朱砂描边；圆角 7px |
| 状态标签 chip | 软底 + 同色文字，全圆角：进行中（花青）/逾期（朱砂）/已完成（石绿）/待确认（藤黄）/缓冲位/高优先（赭石 ⚑） |
| 排期色带 | 正式订单 = 实心色块；缓冲位 = 同色半透明 + 虚线边框；未设截稿日 = 斜纹纹理 + ⚠️（纹理编码状态，色盲友好）；今天线 = 朱砂竖线 |
| 表格 | 表头 11px 大写字距下沉底色，行 hover 纸色底，金额右对齐等宽字体，分页当前页高亮 |
| 空状态 | 一笔墨线代替插画（保持工具感），楷体 15px 标题 + 12px 描述 + 可选操作按钮 |
| Toast | 支持撤销按钮；**破坏性操作（拖拽改期/挪单）一律提供撤销** |
| 印章 | 「已交付 / 已录入」终态视觉：朱砂底 + 文楷白字，旋转 -6°，落章回弹 + 墨圈扩散（纯视觉，450ms） |
| 卡片头部 | 朱砂小方块 mark + 标题 + 右侧辅助信息（cnt/chip），统一结构 |

## 三、页面改造清单

**改造范围**：画师后台 11 个页面（仪表盘 / 排期看板 / 订单管理 / 手动录单 / 订单详情 / 开稿管理 / 价格管理 / 作品管理 / 留言管理 / 设置 / 登录）+ 侧边栏与顶栏骨架。
**管理后台**（数据总览/画师管理/欢迎语/工作流编辑器/健康检查）：低频，只套 token 与基础组件（卡片/表格/按钮/空状态），不做定制设计。
**客户端**：完全不动（4 模板 × 4 配色独立体系，用户已拍板后台独立于客户端）。

各页面内容以现有系统为准（提案 HTML 仅为视觉参考）。重点页面：

1. **骨架（侧边栏 + 顶栏）**：侧栏松烟底 / 宣纸底按主题切换、导航三组分组（工作台/经营/门面）、激活态花青软底 + 左侧 3px 竖条、留言角标；顶栏含主题切换按钮
2. **仪表盘**：统计卡（大数字文楷墨色 + 顶部 3px 色条 + hover 跳转箭头）、待办清单、快捷操作、接稿状态胶囊、留言审核卡
3. **排期看板**：月历色带 + 时间条按 §2 色带标准重绘；今天线朱砂
4. **订单详情**：日期卡定义见 §四
5. **手动录单**：双栏结构不变（功能以 REQ-015 + REQ-029 为准），只换视觉；REQ-029 的画风模式 UI 直接按本 token 实施（两需求同批或相邻批，二号协调）

## 四、开稿日/截稿日日期卡（行为定义）

**现状**（已核实 OrderDetail.vue）：订单详情里截稿日、开工日是**两个独立 el-date-picker**，各自即时保存。

**目标形态**（提案 v2"日期"卡）：合并进**一张「日期」卡**，卡内两个日期输入（开工日 + 截稿日）+ 剩余天数 chip（如"剩 3 天"，逾期变朱砂）。

**行为规则**：
1. 仍然是**两个独立日期字段**（不是区间选择器）——数据模型不变，只是视觉合并成一张卡
2. 改任一日期**即时保存**（保留现有行为），保存成功 toast："开工日/截稿日已保存，排期已同步"
3. 保存后排期（月历/时间条）数据联动刷新
4. 剩余天数实时计算：截稿日 − 今天；已逾期显示"逾期 N 天"朱砂 chip
5. 开工日 ≤ 截稿日的约束保持现状校验逻辑，不变

## 五、迁移策略

**推荐：一次性全量切换，不留双轨。**
理由：① 上线前无真实用户流量，没有灰度必要性；② token 层建成后全页面统一套用，维护两套视觉的成本远高于一次切完；③ 与用户"不留双轨"一贯原则一致。

实施顺序建议（二号排）：token + 骨架先行 → 核心页面（仪表盘/排期/订单详情/手动录单）→ 其余页面按 token 推导。提案原话："其余页面按本页规范直接推导"。

> 若一号审核认为风险需分批，可退一档：骨架+4 核心页一批、其余一批——但**任何阶段都不允许两套主题 token 并存**。

## 六、验收标准

1. 当打开画师后台任意页面时，配色/字体/间距/圆角应该符合 §1 token（抽查不少于 5 个页面）。
2. 当点击右上角主题切换时，应该即时切换宣纸/墨黑主题，刷新后选择应该保持；两套主题下 7 色语义映射应该一致。
3. 当页面出现逾期订单时，应该只有该订单相关元素出现朱砂（其他界面保持纸墨安静）。
4. 当查看统计卡时，数字应该是文楷墨色 + 顶部 3px 状态色条，数字本身不应该被上色。
5. 当表格/表单等密集界面渲染时，字体应该是思源黑体（无文楷）。
6. 当订单详情打开日期卡时，应该看到开工日+截稿日在同一张卡内，改日期即时保存并提示"排期已同步"，剩余天数 chip 正确（含逾期朱砂态）。
7. 当出现空列表（待办/留言/作品为空）时，应该显示统一墨线空状态组件。
8. 当执行破坏性操作（拖拽改期）时，toast 应该带撤销入口。
9. 当使用移动端访问后台时，布局应该可用（现有响应式不回退）。
10. 当检查客户端（画师主页/下单页）时，视觉应该与重设计前完全一致（零影响）。
