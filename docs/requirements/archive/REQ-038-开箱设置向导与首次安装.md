## 一、背景与目标

**用户原话（2026-08-11）**：「给别人装」「从买来新的服务器开始，安装我们的东西，到绑定管理员 QQ」「做个脚本让连 AI 都不会交互的笨蛋们也能轻松搞定，毕竟我们的目的就是要 **简单 易操作 宝宝都会 本能级**的」

目标：一个完全不懂技术的人，从一台新买来的服务器开始，**全程不需要 SSH 改文件、不需要懂命令**，就能完成：装环境 → 起系统 → 浏览器点完设置 → 绑定管理员 QQ → 登录使用。参考 WordPress 的「开箱设置」（first-run setup）体验。

## 三、方案设计（2026-08-11 用户拍板）

### 总览

```
买服务器 → SSH 一条命令跑 setup.sh → 终端显示访问地址+安装口令
        → 浏览器 /setup 开箱向导 4 步（语言→管理员+工作室→扫码绑 TOTP→完成）
        → QQ + 动态码登录，开张
```

### 组件 A：`setup.sh` 一键脚本（部署者唯一要碰的东西）

交互设计原则：**能自动的绝不问，必须问的给默认值，回车就是安全答案**。

| 步骤 | 行为 | 交互 |
|------|------|------|
| 1 | 检测 Docker / Compose，缺则打印安装命令并暂停 | 自动 |
| 2 | **是否生成安装口令（默认开）** | 一次提问，回车=开 |
| 3 | 自动生成 `SESSION_SECRET` / `COOKIE_SECRET`（随机） | 自动，不显示明文 |
| 4 | 问域名（`DOMAIN`） | 唯一必须人工填的信息 |
| 5 | 写 `.env`（含 `SETUP_TOKEN`，若开了口令） | 自动 |
| 6 | `docker compose up -d --build`，等 healthy | 自动 |
| 7 | 打印：访问地址 + 安装口令 + 下一步提示 | 自动 |

**验收标准**：
- 全新服务器执行一条命令后，浏览器访问域名 → 进入 `/setup`（可测）
- 口令开着时，向导第一步要求输入 `SETUP_TOKEN`，输错进不去（可测）
- 脚本幂等：已初始化（`setup_completed` 已写）的系统重复执行，不破坏现有配置（可测）

### 组件 B：开箱设置向导 `/setup`（浏览器 4 步）

| 步骤 | 内容 | 说明 |
|------|------|------|
| ① 欢迎 | 语言选择（中文/English） | 复用现有 i18n 双语言 |
| ② 创建管理员 | QQ 号 + 显示名 + **「同时创建我的画师工作室」默认勾选**（勾选后展开：工作室名 + 子域名，默认 `admin`） | 复用 `migrate.ts` 自举逻辑改 API 化 |
| ③ TOTP 绑定 | 展示二维码 → 验证器 App 扫码 → 输 6 位动态码 → 验证通过 | 复用 bind-init/bind-confirm 逻辑，但走 setup 专用接口（免登录） |
| ④ 完成 | 提示去登录页，QQ + 动态码登录 | — |

**触发与关闭**：
- 未初始化判定：`platform_config.admin_qq` 为空 **且** `artists` 无管理员账号
- 未初始化时：前端所有页面重定向 `/setup`；后端非 setup 接口返回 `503 SETUP_REQUIRED`（健康检查 `/api/health` 和静态资源除外，容器 healthcheck 不能挂）
- 向导完成 → 写 `setup_completed` → `/setup` 永久失效（重定向到登录页），防重复初始化

**验收标准**：
- 全新系统访问任意页面 → 进 `/setup`（可测）
- 向导 4 步全程浏览器完成，**无 SSH**（可测）
- 第 ② 步勾选「同时创建我的画师工作室」→ 装完 `/artist/admin` 公开主页直接可用（可测）
- 完成后刷新/重启，`/setup` 都进不去（可测）
- 未初始化时 `/api/health` 仍返回 ok（容器不因 setup 未完成而重启循环，可测）

### 组件 C：生产首装不再 seed

- 「开发→生产切换指南」第 6 步（`db:seed`）**删除**，生产首装不跑 seed
- `seed.ts` 保持开发用途不变（Alice/Bob 只出现在开发库）
- System 账号（10000）**不再创建**（无业务引用，已核实）

**验收标准**：
- 全新生产库初始化完成后，`artists` 表只有向导创建的管理员（可测）
- 开发环境 `npm run db:seed` 行为不变（可测）

### 组件 D：管理员兼画师（单人场景）

- 向导第 ② 步默认勾选「同时创建我的画师工作室」
- **管理员 status 解锁**：`ArtistManage.vue:38` 移除 `:disabled="row.isAdmin"`
  - 现状核实：status 只控制客户端主页展示（open/full/closed），管理员登录管理后台走「QQ == admin_qq」判定，与 status 无关 → 解锁无安全影响
  - 解锁后管理员可自主开/关自己的公开主页、切换接稿状态

**验收标准**：
- 管理员账号在管理后台可以改自己的状态（不再灰）（可测）
- 管理员公开主页 `/artist/<subdomain>` 随状态正常展示/隐藏（可测）
- 管理员登录后管理后台与画师工作台都能进（现有 `Login.vue:153` `isAdmin → /admin` 已支持；切换入口待技术确认）

### 组件 E：兼容与安全

- **`ADMIN_QQ` 环境变量自举：移除（2026-08-11 用户拍板）**。理由：当前无老部署用户，保留兼容路径=为不存在的东西付维护成本。边界：只移除「环境变量读入 + 启动自举」，**保留** `platform_config.admin_qq`（数据库配置）作为管理员判定唯一数据源（登录判断、管理后台「更换管理员」均靠它；现有生产库该值已持久化，升级不受影响）。
- **fail-fast 改造**：`migrate.ts:127-141` 生产「缺 ADMIN_QQ 抛错」→ 改为「进入 setup 模式」（不抛错，setup 本身是安全路径：无管理员时谁也登不进）。新判定只看数据库：有管理员 → 正常服务；无管理员 → setup 模式。
- **安装口令**：默认开（用户拍板）。`SETUP_TOKEN` 存 `.env`；未初始化时 `/setup` 第一步校验；初始化完成后即使知道口令也进不去
- 防抢注分析：口令开着时，域名解析后陌生人访问 `/setup` 也进不去（可测）

## 四、技术要点（供一号拆任务时参考，非需求）

- 后端：
  - `GET /api/setup/status` → `{ initialized: boolean }`
  - `POST /api/setup/admin`（事务：创建管理员 + 工作室）
  - `POST /api/setup/totp/bind-init` / `bind-confirm`（setup 模式免登录，或复用现有实现改造）
  - 中间件：未初始化 → 除 health/静态资源外返回 `503 SETUP_REQUIRED`
  - `migrate.ts` fail-fast 改 setup 模式
- 前端：
  - `/setup` 页面（纸墨设计语言，双主题）
  - 路由守卫：未初始化重定向 `/setup`
  - 4 步向导组件 + i18n 键
- 脚本：`setup.sh`（bash，幂等）
- 测试：后端 setup 单测、前端向导 E2E、脚本幂等实测

## 五、验收清单（用户终验）

1. 全新服务器：SSH 一条命令 → 浏览器 4 步 → 绑定 QQ → 登录成功，全程无手改文件
2. 口令默认开：不知道口令的人访问 `/setup` 进不去
3. 完成后 `/setup` 永久消失（刷新/重启均进不去）
4. 管理员能改自己的公开主页状态（不再灰）
5. 生产库无 Alice/Bob 测试画师
6. 管理员判定只走 `platform_config.admin_qq`（无环境变量残留依赖），现有生产库升级后管理员登录不受影响
7. 流程中任何一步失败有明确中文提示和重试入口
