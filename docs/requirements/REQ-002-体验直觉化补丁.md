## R9：主页设置移除重复的"流程与比例"入口

### 现状（已核实）

`WorkflowPaymentEditor` 组件同时出现在两个页面：
- **主页设置**（Settings.vue）→ tab "流程与比例"
- **价格管理**（TierManage.vue）→ tab "流程与比例"

完全相同的组件、相同的数据、两个入口。画师会困惑"到底在哪里改"。

### 需求描述

从主页设置中移除"流程与比例" tab，只保留价格管理中的入口。

理由：
- 流程节点 + 收款比例本质是"钱怎么分"，归价格管理更直觉
- R1 已确定客户端"流程只出现在价格板块"，管理端对齐同一心智模型
- 主页设置应只管"页面长什么样"（资料、模板、配色、嵌入脚本）

### 验收标准

1. 当画师打开主页设置时，应该不再看到"流程与比例" tab
2. 当画师打开价格管理时，应该仍然能看到"流程与比例" tab 并正常编辑
3. 当画师在价格管理中修改流程/比例后，客户端展示应该正常反映变更

## R10：下单页/查询页补主题控制

### 现状（已核实）

ThemePicker（主色圆点 + 亮暗自动 + 语言切换）已存在于：
- ✅ 4 个主页模板（Classic / Gallery / Folio / Atelier）
- ✅ 落地页（LandingPage）
- ✅ 画师端全部页面（ArtistLayout 内嵌）

但**缺失于**：
- ❌ 下单页（OrderForm.vue）
- ❌ 订单查询页（TrackOrder.vue）

客户从主页点"开始约稿"进入下单页后，主题控制消失。如果客户在主页切了暗色，进入下单页后主题偏好仍然生效（localStorage 持久化），但无法再调整。查进度页同理。

### 需求描述

在 OrderForm 和 TrackOrder 页面顶部增加精简版主题控制：
- 亮暗切换按钮（复用 ThemeToggle 组件）
- 语言切换按钮
- 五色主色圆点（可选，复用 ThemePicker 或精简版）

不需要完整的 popover 面板，一行小按钮即可，不干扰表单主体。

### 待确认

- [x] **C23**：~~下单页/查询页是否需要完整的五色主色选择？~~ → **按建议执行**：亮暗+语言即可，主色在主页选过一次就持久化了，下单页不需要重复选

### 验收标准

1. 当客户在下单页时，应该能看到亮暗切换和语言切换按钮
2. 当客户在订单查询页时，应该能看到亮暗切换和语言切换按钮
3. 当客户在下单页切换暗色后，页面应该即时切换为暗色主题
4. 当客户从主页（暗色）进入下单页时，下单页应该继承暗色状态，不闪白
5. 当客户在手机上访问下单页时，主题按钮不应该遮挡表单内容

## R11：客户端订单进度可视化时间线

### 现状（已核实）

客户查进度（TrackOrder.vue）当前显示的是文字状态。客户看到的是"草稿确认中""线稿绘制中"这样的文本，没有"我在哪里、还有多远"的视觉感知。

数据基础已完全具备：
- `artist_workflow_stages` 表有完整的阶段列表（含排序）
- 订单有当前阶段 ID
- 客户端 API 已返回 workflow stages 数据

### 需求描述

在订单查询页增加一条**步骤条/时间线**：
- 横向（桌面）或纵向（手机）排列所有流程阶段
- 已完成阶段：打勾 + 主色填充
- 当前阶段：高亮 + 脉冲/呼吸动画（暗示"正在进行"）
- 未开始阶段：灰色空心
- 每个阶段下方显示阶段名称

设计原则：
- **零学习成本**：类似快递物流追踪条，任何人看到就懂
- **不依赖文字理解**：即使看不懂阶段名称，通过"进度条走到哪里了"也能感知
- 当前阶段可以附带一句状态描述（如"画师正在绘制线稿，预计 3 天"）

### 待确认

- [x] **C24**：~~时间线是否显示每个阶段的完成日期？~~ → **按建议执行**：已完成的显示日期，未开始的不显示
- [x] **C25**：~~如果画师的流程只有 2-3 个阶段，时间线是否仍然显示？~~ → **按建议执行**：是，哪怕只有 2 步也显示，保持一致性

### 验收标准

1. 当客户打开订单查询页时，应该看到一条可视化的进度时间线，显示所有流程阶段
2. 当订单处于"线稿"阶段时，时间线上"线稿"之前的阶段应该显示为已完成（打勾），"线稿"应该高亮，之后的阶段应该灰色
3. 当订单完成所有阶段时，时间线应该全部显示为已完成状态
4. 当客户在手机上查看时，时间线应该自动切换为纵向排列，不出现横向滚动
5. 当画师修改了流程阶段（增删节点）后，客户查询页的时间线应该反映最新的阶段列表
6. 当订单刚创建（尚未进入任何阶段）时，时间线应该显示全部阶段为未开始状态，不报错

## R12：画师主页实时预览（v0.12 候选）

### 需求描述

画师在主页设置中切换模板/配色时，右侧或下方显示一个实时预览框架（手机/桌面模拟），选择即时反映在预览中，无需"保存→开新标签→刷新"。

### 为什么放 v0.12

- 需要将 4 个模板组件改造为可在设置页内嵌渲染（当前是路由级页面组件）
- 需要模拟数据填充（预览用的虚拟档位/作品/须知）
- 工程量较大，且不影响核心业务流程
- v0.11 的 R6（新模板）开发完成后，模板系统稳定了再做预览更安全

### 验收标准（草案）

1. 当画师在设置页点击不同模板卡片时，预览区应该即时切换布局
2. 当画师点击不同配色时，预览区应该即时切换颜色
3. 预览区应该同时提供桌面和手机两种视图切换

## R13：排期看板拖拽跨列推进阶段（v0.12 候选）

### 需求描述

排期看板（QueueBoard）支持将订单卡片从一列拖到另一列 = 推进/回退订单阶段。类似 Trello 看板的心智模型。

### 为什么放 v0.12

- 跨列拖拽涉及阶段推进的业务逻辑（收款触发、QQ 通知、阶段校验）
- 需要处理"不允许跳过阶段""回退需要确认"等边界情况
- 当前看板内排序拖拽已稳定，跨列是增量能力
- 需要与 R4（焦点图）的卡片改造协调，避免同期大改 QueueBoard

### 验收标准（草案）

1. 当画师将订单卡片从"草稿"列拖到"线稿"列时，订单阶段应该推进到线稿
2. 当画师尝试跳过中间阶段拖拽时，应该被拒绝并提示
3. 当画师将卡片向后拖（回退阶段）时，应该弹出确认对话框
4. 当阶段推进触发收款节点时，应该正常触发收款提醒
