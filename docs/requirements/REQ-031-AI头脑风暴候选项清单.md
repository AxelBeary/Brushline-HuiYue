## 二、候选项

### A1 收入明细导出（CSV）

- **来源**：林野——"报税需要『某年某日，从哪些客户收了多少钱，分几笔』的明细，目前只有柱状图，得手动反推"
- **现状核实**：收款流水（order_payments）每笔都在库，仪表盘只有月/周柱状图，**无任何导出接口**
- **方案轮廓**：画师后台新增导出功能，按时间段导出 CSV（日期 / 订单号 / 客户昵称 / 金额 / 收款类型）。数据全在库里，纯新增一个导出端点，无数据模型变更
- **刚性时间窗**：商业画师每年 3 月汇算清缴，此为该需求峰值期
- **验收标准（草稿）**：
  1. 当画师选择时间段并点击导出时，应该下载一份 CSV 文件，包含该时间段内全部收款流水（正数收款与负数退款分行列示）
  2. 当时间段内无流水时，应该提示"该时间段无收款记录"，不下载空文件

### A2 订单收据 / 对账单

- **来源**：林野——"客户付款后只有进度页看付款节点，没有正式收据，客户报销需要"
- **现状核实**：v0.37 条目账本 + 锁价引擎（pricing-engine.ts）已把每一分钱的来龙去脉结构化，但无客户可见的凭证视图
- **方案轮廓**：已完成（delivered）订单生成只读收据页——订单号、画师信息、各节点收款明细（日期/金额/类型）、最终金额。客户可自行截图存档
- **注意**：收据只呈现事实流水，不出现画师私有数据（成本/备注）
- **验收标准（草稿）**：
  1. 当订单状态为 delivered 时，客户应该能在订单页看到"收据"入口
  2. 当客户打开收据时，应该看到订单号、画师名称、各笔收款的日期与金额、合计金额，且各笔金额之和与订单总价守恒一致

### B1 完稿一键分享社交平台

- **来源**：星野明——"完稿发微博/B站是固定流程：下载图→写文案→贴主页链接，重复劳动"
- **现状核实**：REQ-022 F2 外链重做后端已交付（分支 f2-social-backend，877/877 全绿，防投毒 17 类向量全过，按门控等 v0.38 后与前端批一起合入）——**域名安全校验的轮子已造好，天然协同**
- **方案轮廓**：订单详情页（delivered 状态）加"分享"按钮——画师预设文案模板（可含占位符），拼接完稿图 + 主页链接，生成微博/B站发布页 URL，点击跳转。发布动作仍在第三方平台完成，平台不代发
- **依赖**：F2 前端批（域名白名单复用）
- **验收标准（草稿）**：
  1. 当订单状态为 delivered 且画师已配置分享文案模板时，订单详情应该显示"分享"按钮
  2. 当画师点击分享时，应该在新窗口打开对应平台的发布页，文案已按模板填充
  3. 当文案模板含主页链接时，跳转 URL 中的域名必须通过 F2 防投毒校验规则

### C4 客户端时区显示

- **来源**：Sakura——"给美国客户设截稿日 8 月 10 日，纽约客户看到的也是 8 月 10 日，但他那边实际是 8 月 9 日要确认"
- **现状核实**：全站日期按服务器时间（北京时间）存储显示，客户端无时区处理
- **方案轮廓**：纯前端——浏览器 Intl API 取客户时区换算显示。例：`截稿日：2026-08-10（北京时间）· 你的当地时间：2026-08-09 20:00（EDT）`。客户与画师同时区时只显示一行，不冗余。**存储零改动，后端零改动**
- **验收标准（草稿）**：
  1. 当客户浏览器时区与北京时间不同时，查单页的截稿日应该同时显示北京时间和客户当地时间
  2. 当客户浏览器时区与北京时间相同时，应该只显示一行日期，不显示时区说明
  3. 当夏令时切换时，当地时间换算应该自动跟随（Intl API 天然处理）
