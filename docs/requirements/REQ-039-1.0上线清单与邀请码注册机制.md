## 三、邀请码注册机制（本 REQ 主体，预计 1.5~2.5 天）

### 概念与流程

```
管理后台「画师管理」→ 生成邀请码（批量 N 个，有效期默认 3 天）
    ↓ 码发给画师（群/私聊）
登录页「没有账号？用邀请码入驻」→ 输 邀请码 + QQ + 显示名 + 子域名
    ↓ 校验（码有效/未用/未过期/QQ 未注册）
创建画师账号（status=closed，不上客户端目录）
    ↓ 自动进入 TOTP 绑定（复用 REQ-027 bind 流程）
完成 → QQ + 动态码登录 → 画师自己在设置里开接稿
```

### 邀请码属性（用户拍板 + 建议默认）

| 属性 | 值 |
|------|-----|
| 一次性 | 用一次作废（防转发复用） |
| 有效期 | **默认 3 天**（生成时可调） |
| 批量生成 | 管理后台填数量，一次生成 N 个，逐个复制 |
| 吊销 | 管理员可作废未使用的码（防泄漏兜底） |
| 入驻后初始状态 | `closed`（不上客户端目录页），画师自己开（画师侧已有状态切换，v0.40 F3） |

### 入驻模式（部署时选择，REQ-038 向导一步）

- `platform_config` 新增 `onboarding_mode`：`manual` / `invite`
- 默认 **invite**（建议；待确认）
- `manual` 模式 = 现状（管理员手动建号），登录页不显示入驻入口

### 后端

- **迁移 v56**：新表 `invite_codes`（code、status[unused/used/revoked]、expires_at、created_by、used_by_artist_id、used_at、created_at）
- API：
  - `POST /api/admin/invite-codes` 批量生成（数量 + 有效期天数）
  - `GET /api/admin/invite-codes` 列表（含状态）
  - `POST /api/admin/invite-codes/:id/revoke` 吊销
  - `POST /api/invite/register` 公开注册（校验码 + 建号），**限流**（复用 rate-limit；校验失败与码错误同响应，防枚举）
- 建号复用 `artistService.createArtist`（事务化已有），子域名保留词黑名单复用

### 前端

- 管理后台：画师管理页加「邀请码」入口 → 生成/列表/吊销 UI（纸墨设计语言）
- 登录页：入驻入口 + 入驻表单 + 校验 → 复用 TOTP 绑定衔接（绑定成功即登录态）
- i18n 键（zh/en）

### 测试

- 后端单测：生成/校验/过期/吊销/一次性/QQ 冲突/限流
- 前端：入驻 E2E（含 TOTP 绑定衔接）
