## 产品定位

**一句话**：画师的本地工作台——管稿子、记账、出图，联网后和绘约平台无缝对接。

**核心原则**：
- 本地优先：所有核心功能不依赖网络
- 登录是"升级"不是"门槛"
- 平台是加分项，不是前提

## 功能清单

### F1 本地文件管理

- 按委托/项目归档本地文件（CSP、PSD、PNG 等）
- 快速打开工程文件（调起系统关联程序）
- 文件与委托记录关联（一个委托下挂多个文件）
- **文件保持原样在磁盘**：应用只记录路径，不复制、不搬迁、不封装
- **文件丢失提醒**：应用启动时（或定时）校验所有关联路径，文件不存在时提示画师"文件找不到了，是被移动了还是删了？"，画师可重新指路或忽略
- 工程文件可被 Everything 等系统工具直接搜索（因为就是普通文件）
- 工程文件可被其他软件（CSP、PS、SAI）直接打开修改（应用不锁定、不占用）

#### F1a 工程文件模板

- **用途**：创建订单时自动准备工程文件，省去画师每次手动建文件的步骤
- **模板存放**：`我的文档\绘约\templates\`，画师上传的原始文件（CSP/PSD/SAI 等）
- **绑定关系**：
  - 全局默认模板（所有未绑定档位的订单用这个）
  - 档位级覆盖（"头像"绑 A 模板，"全身"绑 B 模板）
  - **一个档位只绑一个文件**（用户确认"画师不太会闲着没事左右横跳"）
- **创建订单时**：
  - 有模板 → 复制副本到委托文件夹，命名「客户名-档位名.扩展名」（如「张三-头像.csp」）
  - 没模板 → 只建文件夹，不建文件
  - 模板本身永远不动，每个订单拿到的是副本（"母版"和"复印件"的关系）
- **模板更换**：画师随时重新上传覆盖，已创建的订单文件不受影响
- **创建后行为**：只创建不自动打开。订单详情页关联文件旁显示蓝字链接（如「在 CSP 中打开」），点击调起系统关联程序。文件不存在时链接灰掉 + 提示
- **平台订单**：登录后同步下来的平台订单同样享受自动创建（订单不分来源）
- **格式兼容**：不需要管。画师在 CSP 里画完想换 PS 修图，自己"导出→PSD→PS 打开"即可，全程普通文件操作，与应用无关。一个委托文件夹里可以同时放 .csp、.psd、.png 多个文件
- ❌ 不做空白画布快捷创建（CSP 无公开命令行 API，伪需求）

### F2 本地委托记账

- 记录：客户名、委托类型、价格、截稿日、状态
- 纯本地，不需要网络
- 状态流转（草稿 → 进行中 → 已交付 → 已收款）由画师手动标记
- **导出**：支持导出为 Excel（.xlsx），导出范围 = 当前列表筛选结果
- 结构化数据存 SQLite，路径透明（`我的文档\绘约\data.db`）
- 不允许应用内直接编辑原始数据库；"看数据"通过导出 Excel 覆盖

### F3 约稿条生成

- **用途**：画师发社交平台（微博/小红书/米画师）招揽客户
- **排版模式**：模板填空（A 档）。预设模板，画师只做换图、改文字、选配色。不支持自由拖拽布局
- **输出**：PNG 图片 + 纯文字版（复制粘贴用）
- **模板数量**：2~3 套长条（竖版）+ 1 套横版，区别在排版风格（如简约白底 / 深色质感 / 可爱贴纸风），元素区域相同，视觉不同
- 用户原话（2026-08-02）："真有设计需要他们也都会去别的软件去做对吧，他们自己就是搞艺术"

#### F3 模板结构（五个区域）

```
┌──────────────────────────┐
│  [头像]  画师昵称         │ ← ① 头部区
│  一句话简介 / 风格标签     │
├──────────────────────────┤
│  [头像例图]  头像 ¥100   │
│  [半身例图]  半身 ¥200   │ ← ② 档位区（例图+价格一体）
│  [全身例图]  全身 ¥350   │
├──────────────────────────┤
│  [作品A]  [作品B]        │
│  [作品C]  [作品D]        │ ← ③ 额外作品展示区
├──────────────────────────┤
│  · 修改 3 次以内          │
│  · 工期 2~4 周            │ ← ④ 约稿规则区
│  · 先款后稿               │
├──────────────────────────┤
│  QQ: 123456  微博 @xxx   │ ← ⑤ 联系尾部区
│  [二维码]                 │
└──────────────────────────┘
```

- **① 头部区**：头像 + 昵称 + 简介/标签（来自 F6 画师档案）
- **② 档位区**：每个档位一行，左边例图右边价格。客户一眼看到"这个价位长这样"
  - 价格来源：登录后从平台档位拉取（可编辑），免登录纯手填
  - 例图来源：登录后从平台档位 `focus_image` 拉取，免登录画师手动拖入
- **③ 额外作品展示区**：和档位无关的"我就是想秀一下"的图。最多 6 张（2 列 × 3 行），可少放
  - 来源：登录后从平台代表作选 / 本地拖入均可
- **④ 约稿规则区**：纯文字，画师自由填写（修改次数、工期、付款方式、不接类型等）
- **⑤ 联系尾部区**：联系方式 + 可选二维码

### F4 委托小票/回执

- **用途**：发给客户确认委托详情（"你约了什么、多少钱、什么时候交"）
- **输入**：从 F2 记账数据自动填充
- **输出**：PNG 图片 + 纯文字版
- ❌ 不做 PDF（"很多单主连 PDF 是啥都不知道"——用户原话）
- **签名/印章**：
  - 主路径：上传签名图片（PNG 透明底），全局设置一次，所有小票复用
  - 辅助路径：应用内手绘签名板（优先级低于上传，可延后）
  - 不做每张小票单独选签名

### F5 平台图片缓存（登录后）

- 单个委托最多 20 张图（与平台 `REFERENCES_LIMIT` 对齐）
- 上传：拖入，逻辑与网页端一致
- 下载/缓存：首次拉取后存本地，下次打开免流量
- 不做文件同步（只缓存图片，不同步 CSP/PSD 等工程文件）
- 平台缓存图片**不纳入导出打包**（来源是平台，登录后可重新拉取）

### F6 画师档案（本地）

- 字段：昵称、头像、简介、风格标签
- 约稿条（F3）和小票（F4）复用此档案
- 免登录阶段：画师手动创建/编辑
- 登录后：首次触发对比（见 F7），之后平台为准

### F7 首次登录档案对比（登录后，一次性）

- 触发条件：本地已有档案 + 平台也有档案
- 交互：左右对比界面，逐项（昵称/头像/简介/标签）让画师选哪边赢，或手动改
- 确认后：平台为 source of truth，本地变为缓存
- 本地无档案 + 平台有：直接用平台数据
- 本地有 + 平台无（新注册）：本地推上去

## 数据迁移与备份

### 导出

- **触发方式**：纯手动。设置页"导出全部数据"按钮，不主动提醒
- **导出内容**：
  - 数据包（zip，几 MB）：SQLite 数据库 + 签名图片 + 本地设置
  - 文件清单（manifest.json）：所有关联工程文件的路径、大小、所属委托
- **不包含**：平台缓存图片（登录重新拉）、工程文件本体（画师自行搬运）
- **云备份提示**：导出目录选择器下方显示提示文字："💡 将导出目录设为坚果云 / OneDrive 同步文件夹，可实现自动云备份"。不做网盘集成

### 导入

- **策略**：替换。不做合并，不做手动逐条核对
- **冲突处理**：导入前检测本地是否已有数据。若有，弹强提醒：
  > ⚠️ 你本地已有 N 条记账记录。导入将替换它们。
  > 我们会先把当前数据自动备份为「绘约备份-替换前-{日期}.zip」，万一后悔可以恢复。
  > [取消] [确认替换]
- 确认后：自动备份当前数据 → 导入新数据
- **工程文件关联恢复**：导入数据包后，根据 manifest.json 提示"检测到 N 个委托文件夹尚未关联，请指定位置"，画师手动指向文件夹路径

### 设计原则

- 数据（记账、档案、设置）我们管——一键导出导入
- 文件（CSP、PSD）画师自己搬——12GB 的东西用画师自己的方式搬最快
- 应用只记路径，不拥有文件

## 数据可见性规则

> **一条规则管所有：数据的来源决定可见性，不是当前登录状态。**

| 数据来源 | 免登录可见？ | 登录后可见？ | 切出账号后？ |
|----------|:-----------:|:-----------:|:-----------:|
| 本地创建（手动记账、本地文件） | ✅ | ✅ | ✅ 永远在 |
| 平台同步（委托单、缓存图） | ❌ | ✅ | 界面隐藏，文件留磁盘 |

- 切出账号 ≠ 没收数据：平台来源的文件保留在磁盘，下次登录免重新下载
- 不做"已同步/未同步"标签，不做混合态 UI

## 登录与账号

- 画师账号由**管理员后台创建**，不允许自助注册
- **登录方式**：复用平台登录机制
  - 2026-08-05 决策变更：平台登录改为 **TOTP 动态口令**（REQ-027）——桌面端同样走「QQ 号 + 验证器 App 动态码」，码在画师自己手机上生成，无需任何消息通道
  - 原方案「QQ 号 + 验证码经 QQ Bot 发送」已推迟为 REQ-028 备案（QQ 机器人转为通知渠道，不再是登录渠道）
  - 与网页端流程一致，画师不需要记任何新东西
  - 不另建邀请码体系
- 当前网页端为开发模式（AUTH_DEV_MODE=true），TOTP 落地时一并移除（REQ-027 R7）
- 桌面端登录体系随 v1.0 平台认证一起落地

## 明确不做（本版本）

| 排除项 | 原因 |
|--------|------|
| 客户下单/支付 | 无登录体系，不做客户侧 |
| 云端文件同步 | 只缓存图片，不同步工程文件 |
| 多人协作 | 单画师工具 |
| 移动端 | 桌面应用 |
| PDF 输出 | 目标用户不熟悉 PDF |
| 自助注册 | 管理员建号模式不变 |
| 自由拖拽画布编辑器 | 画师有专业设计工具，约稿条只需模板填空 |
| 数据合并导入 | 冲突处理复杂度过高，替换 + 自动备份更干净 |
| 自动定时备份 | 大文件打包吃性能，手动更可控 |
| 网盘集成 | 零成本方案：提示画师自行配合网盘同步文件夹 |
| 空白画布快捷创建 | CSP 无公开命令行 API，伪需求 |
| 一个档位多模板 | 画师主力软件就一个，不需要每次选 |
