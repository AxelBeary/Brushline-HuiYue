## R22：约稿流程与收款板块视觉重做

### 用户原声

> "约稿流程与收款板块好丑。而且不收钱的都是灰色的 很反直觉"

### 现状（已核实）

流程条组件 `WorkflowOverviewStrip.vue` 在两处使用：
- 画师主页 classic 模板（`ArtistHomeClassic.vue:55`，vertical 竖排，嵌在价格板块内）
- 下单页（`OrderForm.vue:112`，horizontal 横排，"流程与收款预览"表单项）

现状样式：
- 整体 12px 字号、灰色文字（`var(--text-secondary)`），简单圆点 + 箭头连接
- **非收款节点**：圆点 `var(--text-muted)`（灰）、名字默认灰色
- **收款节点**：圆点 `var(--color-primary)`、名字加粗主色、比例数字主色
- 尾款节点：金色圆点 + 🔒 图标

### 需求描述

1. **视觉层级重做**：流程条是"客户了解约稿怎么进行、什么时候付钱"的核心信息，不是一行灰色小字。需要更清晰的视觉设计——节点有存在感、步骤关系一目了然、收款节点突出但不喧宾夺主
2. **免费节点不能是灰色**：灰色在界面语言里 = 禁用/不可用/不重要。"草稿确认""线稿"这些节点是客户约稿流程的重要环节，只是不涉及付款，不是"不重要"。所有节点都应该是正常可读的颜色，收款节点用**强调**（如主色标记、💰 图标、金额比例）而非把其他节点**弱化**成灰
3. 两处使用场景（主页竖排、下单页横排）都要覆盖

### 验收标准

1. 当客户查看约稿流程时，每个节点（含免费节点）的文字应该清晰可读，不呈现"禁用/不可用"的灰色观感
2. 当节点涉及收款时，应该有明确的强调标识（颜色/图标/金额），客户能一眼看出"这一步要付钱、付多少比例"
3. 当客户在下单页看到流程预览时，整体视觉应该与页面其他部分协调，不显得简陋突兀
4. 当画师主页（classic 模板）展示流程时，竖排布局应该层次清晰，不是一列灰点

## R23：作品展示长图/竖图不应被裁成正方形

### 用户原声

> "在alice作品展示那里画师的长条的还是啥的图都变成正方形了"

### 现状（已核实）

Alice 使用 classic 模板（数据库已验证：`template_id='classic'`）。`TplGallery.vue` 的 grid 布局：

```css
.tpl-gallery--grid { grid-template-columns: repeat(auto-fill, minmax(200px, 1fr)); }
.tpl-gallery--grid .tpl-gallery-img { width: 100%; height: 200px; }  /* + fit="cover" */
```

每格约 200×200 近正方形，`fit="cover"` 裁切。长条图（横幅）、竖图（立绘）都被裁成方形，构图破坏严重。

### 需求描述

作品展示应该尊重原图比例。画师的作品形态多样——头像、立绘、横幅、条漫——统一裁成方形等于把画师最在意的构图毁掉。

### 验收标准

1. 当画师上传竖图（如 1:2 立绘）时，作品展示应该保留竖图形态，不裁成正方形
2. 当画师上传横幅/长条图时，作品展示应该保留横幅形态，关键内容不被裁掉
3. 当多种比例的作品混排时，网格应该整齐不凌乱（瀑布流/自适应行高均可，由二号定方案）
4. 当客户点击作品时，仍然能全屏预览原图（与 UI-6 修复联动）

### 待确认

- [ ] **C36**：grid 布局改瀑布流（masonry，folio 模板已有现成实现）还是自适应行高？（建议：瀑布流——folio 的 masonry 已验证，保留原图比例最彻底，且 4 个模板中 folio 已用此布局，风格统一）

## R24：下单页校验失败弹窗提示

### 用户原声

> "希望约稿下单页面如果有没填写的或者有问题的 可以弹窗。现在只有一个红字，特别是已阅读须知功能总是忘记勾选。"

### 现状（已核实）

`OrderForm.vue` 提交逻辑（413-415 行）：

```js
const valid = await formRef.value.validate().catch(() => false)
if (!valid) return
```

校验失败时：
- 只在对应表单项下方显示红色小字（Element Plus 默认行为）
- **无弹窗、无滚动定位**——如果漏勾的"已阅读须知"在页面底部，客户在顶部点提交，红字在视口外，完全看不到，以为按钮坏了
- 须知勾选框（164 行）在表单最底部、须知全文卡片之后，是视觉上最容易被忽略的位置

### 需求描述

1. **校验失败弹窗**：提交时如有未通过项，弹出提示框列出所有问题（如"请选择档位""请填写 QQ 号""请勾选已阅读须知"），不只是红字
2. **定位到问题**：弹窗关闭后（或点击弹窗中的某一项）自动滚动到第一个出错的表单项
3. **已阅读须知强化**：这是客户最容易漏勾的项，需要额外提示手段（具体方式由二号定，如：弹窗中特别标注、勾选框加粗、未勾选时提交按钮置灰等）

### 验收标准

1. 当客户未填必填项就点提交时，应该弹出提示框，列出所有未通过的项目，而不是只有视口外的红字
2. 当弹窗显示后，客户应该能被引导到出错位置（自动滚动或点击定位）
3. 当客户漏勾"已阅读须知"时，提示信息应该明确指出"请勾选已阅读须知"，客户不会困惑为什么提交不了
4. 当所有校验通过时，提交流程应该不受影响（不新增多余步骤）

## R25：色盘/亮暗/中英切换位置调整

### 用户原声

> "页面色盘 亮暗功能以及中英功能在约稿按钮下面 不符合直觉。"

### 现状（已核实）

`ArtistHomeClassic.vue` 左栏信息卡结构（9-38 行）：

```
头像 → 名字 → 状态徽章 → 社交链接 → 【约稿按钮】→ 【ThemePicker（色盘+亮暗+中英）】
```

ThemePicker 在约稿 CTA 按钮正下方。约稿按钮是信息卡的核心行动点，主题切换是全局偏好设置，放在行动按钮下方：
- 视觉上像"约稿的附属选项"，客户可能误以为点了色盘是在给约稿选颜色
- 偏好设置属于页面级工具，不属于画师信息卡内容

对比：下单页（OrderForm.vue:3）的 ThemeToggle 放在右上角，符合"页面工具在角落"的惯例。

### 需求描述

色盘/亮暗/中英切换移到更符合直觉的位置——页面级工具区（如右上角/页脚），不占用约稿按钮下方的黄金位置。4 个模板统一处理。

### 验收标准

1. 当客户访问画师主页时，色盘/亮暗/中英切换不应该出现在约稿按钮正下方
2. 当客户需要切换主题或语言时，仍然能方便找到入口（位置符合"页面工具"惯例）
3. 当客户点击约稿按钮时，不应该误触主题切换控件
4. 当 4 个模板（classic/gallery/folio/atelier）切换时，主题切换入口位置应该一致

### 待确认

- [ ] **C37**：ThemePicker 移到哪个位置？（建议：页面右上角固定悬浮，与下单页 ThemeToggle 的右上角惯例一致——4 个模板统一，不占信息卡空间）
