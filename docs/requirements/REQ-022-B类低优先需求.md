## F1：作品绑定档位 + 完稿转作品链路（#32 + #33）

**产品链路（用户拍板方向）**：

> 完稿交付 → 一键发布为作品 → 绑定档位 → 客户端按档位展示 → 客户点开看价格 → 直接下单

> 注：原链路中的「加水印」环节已由用户拍板砍掉（2026-08-05），不做水印联动。

**功能描述**：

### 完稿转作品（#33）
- 订单完稿后，订单详情页加"发布为作品"按钮（**发布是可选动作，不转是默认状态**——2026-08-05 用户拍板"甚至可以不转"）
- 点击后：**勾选完稿图片（允许只选部分，默认全选）** → 填写作品标题/描述 → 发布（2026-08-05 用户拍板"允许 甚至可以不转"）
- 发布后作品出现在作品管理页，可进一步绑定档位

### 作品绑定档位（#32）
- 作品管理页：每个作品可绑定到一个或多个档位（按尺寸分组）
- 客户端：作品按档位分组展示（"半身像""全身像""Q 版"等）
- 客户点开作品 → 看到对应档位价格 → 直接下单

**验收标准**：
1. 当画师在完稿订单详情页点击"发布为作品"时，应该进入发布流程（选图 → 填信息 → 发布）
2. 当画师将作品绑定到"全身像"档位时，客户端应该在该档位分组下展示该作品
3. 当客户在客户端点击某作品时，应该看到对应档位的价格和"立即约稿"入口

**预估工时**：4 天（完稿转作品 2 天 + 绑定档位 2 天）

## F2：外链功能重做——统一输入区 + 平台可扩展（#41，2026-08-05 用户拍板重写）

**现状（问题）**：设置页有两个独立链接输入区——「外链」（图标下拉+名称+URL，上限 6 条，Settings.vue L77）和「平台链接」（平台下拉+URL，上限 10 条，L99）；客户端页脚分两块渲染（socialLinks + platformLinks）。画师挂社交账号要先想"这条算外链还是平台链接"，心智割裂。平台列表硬编码在前端两处且不一致（外链含 douyin，平台链接没有）。

**拍板方向（2026-08-05）**：统一为一个输入区、粘贴完整 URL、平台可扩展（管理后台可编辑）、粘贴自动识别平台、图标走 simple-icons 打包方案。

### 录入端（画师设置页，两个输入区合并为一个）

- 一条链接 = 一行：`[平台下拉] [完整URL输入框] [↑] [↓] [✕]`，上限统一 8 条，空态提示"还没有添加链接"
- 画师**粘贴完整 URL**（不做"填用户名自动生成 URL"——各平台 URL 规则不统一、自动生成脆弱）
- **粘贴自动识别平台**：粘贴后按 URL 域名自动把平台下拉切到对应平台并点亮图标；识别不出 → 留在"其他"用通用链接徽标
- **匹配必须精准（防投毒硬规则）**：
  1. 只认精确域名（`weibo.com` 与 `*.weibo.com`），`weibo.com.evil.com` 之类伪装域名一律不认，绝不做"包含关键词"的模糊匹配
  2. 未知域名强制归"其他"，不允许自动套任何平台身份
  3. URL 只允许 http/https 协议
- 排序保留 ↑↓ 上下移，删除保留 ✕

### 平台可扩展（管理后台「社交平台管理」，平台级配置所有画师共用）

- 每条平台 = 名称 + 徽标/图标 + 匹配域名列表 + 排序 + 启用开关，管理员可增删改（加新平台不发版）
- 画师下拉只显示启用的平台
- **防投毒**：平台图标不许自由上传（SVG 可内嵌脚本），图标来源只允许内置白名单（见下）

### 图标方案（simple-icons 打包，用户拍板 b）

- 接入 simple-icons 开源图标库，**构建时精选白名单打包进前端静态文件**（一次性挑约 20 个常用平台：微博/B站/小红书/LOFTER/pixiv/X/抖音等），零运行时网络请求
- 管理员加平台时从白名单选图标；白名单没有 → 单字文字徽标兜底（管理员填一个字）
- 新平台真图标要进白名单需发版（一行代码）——零投毒风险的代价
- 旧 LINK_ICON_BADGE / PLATFORM_BADGE 两套映射合并为一套

### 数据与展示

- `customLinks` + `platformUrls` 两套字段合并为一套（上线前无真实数据，不写迁移脚本，直接改结构）
- 客户端页脚两块合一，展签式横排不变（图标 + 名称，点击新窗口打开），一排放不下自动换行

**验收标准**：
1. 当画师在设置页粘贴 `https://weibo.com/xxx` 时，平台下拉应该自动切到"微博"并显示微博图标。
2. 当画师粘贴未知域名的链接时，应该归为"其他"并使用通用链接徽标，不应该自动匹配任何平台。
3. 当管理员在后台新增一个社交平台（名称+域名+图标）时，所有画师的设置页下拉应该出现该平台，且粘贴其域名链接时应该被自动识别。
4. 当客户端页脚展示链接时，应该只有一排（不分外链/平台两块），显示图标 + 名称。
5. 当粘贴 `javascript:` 或非 http(s) 协议的 URL 时，应该被拒绝。

## F3：约稿表单回显（#58）

**现状**：约稿表单右边摘要不回显客户填写的内容。

**功能描述**：
- 约稿表单右侧摘要区实时回显：昵称、需求描述、已选档位、已选增项、总价
- 客户每填一步，摘要区同步更新
- 摘要区只读，不可编辑

**验收标准**：
1. 当客户在约稿表单填写昵称后，右侧摘要应该立即显示该昵称
2. 当客户选择档位和增项后，右侧摘要应该显示已选项和总价

**预估工时**：1 天

## F4：回收站分页（#64）

**现状**：管理端回收站东西多时无分页/折叠，好长好长。

**功能描述**（2026-08-05 用户拍板：**分页**）：
- 回收站列表加分页（每页 20 条）
- 与全站列表交互一致（订单列表等均为分页）

**验收标准**：
1. 当回收站超过 20 条时，应该分页显示，不应该一次性全部加载

**预估工时**：0.5 天

## F5：留言分组/筛选（#67）

**现状**：管理端留言管理，画师多/留言多时混成一长串。

**功能描述**：
- 按画师分组（下拉选画师 / 侧边栏画师列表）
- 按状态筛选（未读/已读/已回复）
- 按时间排序（最新优先）

**验收标准**：
1. 当管理员选择某画师筛选时，应该只显示该画师的留言
2. 当管理员选择"未读"筛选时，应该只显示未读留言

**预估工时**：1 天
