## R1：流程展示整合至价格板块 + 修改次数告示

### 现状（已核实）

客户端的流程预览（WorkflowOverviewStrip 组件）目前出现在**两处**：

1. **画师主页**：3 个布局模板（Classic / Gallery / Folio）各有一个独立的"流程"区块
2. **下单页**：价格预览下方的"流程与收款预览"

客户从主页进入下单页会看到两次流程，信息重复。此外，流程节点没有修改次数的说明——客户不知道每个阶段可以要求修改几次。

### 需求描述

1. **流程只出现在价格板块**：主页的独立流程区块移除，流程预览整合进价格板块。客户在整个约稿流程中只在"价格"相关的区域看到流程与节点。
2. **修改次数告示**：流程展示处增加修改次数说明，让客户在下单前就知道每个阶段可以要求修改几次。

### 待确认

- [ ] **C1**："修改次数"是全局一个数（如"每阶段含 2 次免费修改"），还是每个节点单独设置（如"草稿确认 3 次、线稿确认 2 次"）？
- [ ] **C2**：修改次数是画师在流程管理页配置的**数值**（系统生成告示文案），还是画师自己写的一段**告示文字**？
- [ ] **C3**：主页的"价格板块"具体指哪里——价格表（档位网格）区域的内部/下方？还是下单页的价格预览区域？（建议：主页价格表区域下方展示流程+告示，下单页保持现有位置）

### 验收标准

1. 当客户打开画师主页时，应该只在价格板块看到流程预览，页面上不再有独立的流程区块
2. 当客户打开下单页时，应该在价格相关区域看到流程预览（含修改次数告示）
3. 当画师设置了修改次数后，客户看到的流程预览应该显示对应的修改次数说明
4. 当画师未设置修改次数时，流程预览应该正常显示，不显示修改次数（或显示默认提示），不报错
5. 当主页没有价格档位时，流程预览的显示行为应该与当前一致（有流程数据才显示）

## R2：报价快照字符串 + 最终价格手动设置

### 现状（已核实）

客户自助下单时，后端计算价格并保存：

| 字段/表 | 类型 | 内容 |
|---------|------|------|
| `orders.price_snapshot` | REAL | 档位基础价（不含增项/倍率） |
| `orders.total_price_cents` | INTEGER | 计算后总价（分） |
| `order_price_breakdown` | 表 | 价格明细行（档位/增项/倍率各项金额） |
| `order_payment_installments` | 表 | 分期计划（按流程收款比例拆分） |

问题：
- 画师端**订单详情页完全不显示价格信息**，画师看不到这单报了多少钱
- 画师**无法修改价格**——实际成交经常与计算器报价不同（面议、折扣、老客户优惠、聊完改需求）
- 价格明细存在表里，但没有一段**人话**描述这单的价格构成

### 需求描述

1. **报价快照字符串**：下单时将完整报价处理为一段可读的字符串后保存。例如：
   > 头像 ¥200 + 表情差分×2 ¥60，加急×1.5 → 总价 ¥390

   这段字符串是订单的价格"照片"——即使画师后来改了价格配置，已下单的订单仍然保留下单时的报价描述。

2. **最终价格**：订单增加"最终价格"字段。画师可在订单详情页手动设置/修改最终价格。最终价格是这单实际成交的金额。

3. **报价字串可修改**：画师也可以在订单详情页编辑报价快照字符串（修正描述、补充"含3次修改"等说明、改为实际谈好的价格描述）。

### 业务规则

- 最终价格初始值 = 计算器总价（自助下单有价格计算时）
- 手动录单无价格计算时，最终价格为空，画师手动填写（见 R3）
- 最终价格为空时，订单详情页显示"未设置"状态，画师可随时填写
- 最终价格修改后，报价快照字符串**不自动联动**——两者独立，画师各自编辑（建议：待确认是否需要联动）

### 待确认

- [ ] **C4**：报价快照字符串的格式——系统自动生成后画师可编辑，还是画师可以完全重写？（建议：系统生成初稿，画师可任意编辑）
- [ ] **C5**：修改最终价格时，是否需要记录修改历史（谁在什么时候从多少改到多少）？（建议：至少记一条订单备注"价格从 X 改为 Y"）
- [ ] **C6**：画师仪表盘的**收入统计**是否改用最终价格计算？当前用 `price_snapshot`（档位基础价），不含增项和倍率，本身就不准。（建议：改用最终价格，未设置最终价格的订单回退到 total_price_cents）
- [ ] **C7**：客户查询页是否显示价格信息？当前客户查进度看不到价格。（建议：本期不做，价格沟通走QQ）

### 验收标准

1. 当客户通过自助下单页提交含价格计算的订单时，订单应该保存一段可读的报价快照字符串，内容包含档位、增项、倍率和总价
2. 当画师打开订单详情页时，应该看到报价快照字符串和最终价格
3. 当画师修改最终价格并保存时，价格应该更新成功，刷新页面后仍然显示新值
4. 当画师修改报价快照字符串并保存时，字符串应该更新成功，刷新页面后仍然显示新值
5. 当最终价格为空时，订单详情页应该显示"未设置"状态，画师可以填写
6. 当画师输入非法价格（负数、非数字、超过合理上限）时，应该被拒绝并显示提示
7. 当已有订单（历史数据）打开详情页时，报价快照字符串应该显示为空或根据已有数据回填，不报错

## R3：快速录单页面补全

### 现状（已核实）

手动录单页面（ManualOrder.vue）当前只有 5 个字段：

| 字段 | 有 |
|------|:--:|
| 客户QQ | ✅ |
| 客户昵称 | ✅ |
| 档位选择 | ✅ |
| 需求描述 | ✅ |
| 优先级 | ✅ |
| 参考图上传 | ❌ 缺失 |
| 增项/倍率（价格计算器） | ❌ 缺失 |
| 客户QQ通知开关 | ❌ 缺失 |
| 报价快照/最终价格 | ❌ 缺失（R2 新增） |

客户自助下单页有参考图上传和完整价格计算器，但画师手动录单时这些全部缺失。画师在QQ上收到客户的参考图和需求后，无法在录单时一并录入。

### 需求描述

补全快速录单页面，使手动录入的订单信息完整度**不低于**客户自助下单：

1. **参考图上传**：录单时可上传客户发来的参考图（复用现有上传逻辑，含 R5 粘贴支持）
2. **价格计算器**：选择档位后联动增项/倍率选择，实时计算报价（与自助下单页一致的交互）
3. **最终价格**：计算后自动填入最终价格，画师可手动修改（R2）
4. **客户QQ通知开关**：是否允许客户接收QQ排队提醒

### 待确认

- [ ] **C8**："有缺失"具体指哪些字段？以上是根据与自助下单页对比的推断，请确认是否还有遗漏
- [ ] **C9**：手动录单是否也需要"须知确认"勾选？当前不需要。（建议：保持不需要——手动录单意味着画师已经和客户沟通过）

### 验收标准

1. 当画师在快速录单页选择档位后，应该能看到增项/倍率选择并实时计算报价
2. 当画师在快速录单页上传参考图后，生成的订单详情页应该显示这些参考图
3. 当画师在快速录单页粘贴图片时，应该能正常上传（依赖 R5）
4. 当画师提交含价格计算的手动订单时，订单应该包含报价快照字符串和最终价格
5. 当画师不选择档位时，应该可以正常提交（自定义订单，价格为空，画师后续在详情页设置）
6. 当画师切换档位时，之前的增项/倍率选择应该被清空并重新计算

## R4：订单焦点图（关-小-大）

### 现状（已核实）

- 订单详情页有参考图网格（小图排列）
- 排期看板的订单卡片只有文字：档位名 + QQ号 + 昵称 + 描述摘要（前60字）
- 画师面对一排卡片时，**无法一眼看出这个订单是画什么角色**——必须点进详情页看参考图

### 需求描述

1. **订单详情页增加焦点图设置**：画师从该订单的参考图中选一张作为"焦点图"——这张图代表这个订单要画的角色/内容
2. **三态滑块开关**：关（不显示）→ 小（小图）→ 大（大图），画师自己控制焦点图的显示尺寸
3. **排期看板可见**：设置后，画师在排期看板的订单卡片上能一眼看到焦点图，不用点进详情

### 待确认

- [ ] **C10**：焦点图是否也显示在**订单列表页**（OrderList），还是只显示在排期看板？（建议：排期看板优先，订单列表可后续加）
- [ ] **C11**："大"模式的尺寸预期？（建议：看板卡片内显示，小=48px 缩略图，大=卡片宽度自适应预览图）
- [ ] **C12**：没有参考图的订单，焦点图区域显示什么？（建议：显示占位提示"暂无参考图"，开关置灰不可用）
- [ ] **C13**：焦点图是否允许画师上传一张不在参考图列表中的新图？（建议：本期只从已有参考图中选，降低复杂度）

### 验收标准

1. 当订单有参考图时，画师在订单详情页应该能选择其中一张设为焦点图
2. 当画师将焦点图开关设为"小"时，排期看板对应卡片应该显示小尺寸焦点图
3. 当画师将焦点图开关设为"大"时，排期看板对应卡片应该显示大尺寸焦点图
4. 当画师将焦点图开关设为"关"时，排期看板对应卡片应该不显示焦点图
5. 当订单没有参考图时，焦点图设置区域应该显示"暂无参考图"提示，开关不可操作
6. 当画师设置焦点图后刷新页面，设置应该保持不丢失
7. 当画师删除了被设为焦点图的参考图时，焦点图应该自动失效（开关回到"关"），不显示破图

## R5：全平台粘贴上传图片

### 现状（已核实）

平台共有 4 处上传，全部只支持点击选择/拖拽，**不支持粘贴**：

| # | 位置 | 类型 | 粘贴支持 |
|---|------|------|:--------:|
| 1 | 客户下单页 — 参考图上传 | 图片（JPG/PNG/WebP，10MB/张，最多5张） | ❌ |
| 2 | 画师作品管理 — 作品上传 | 图片 | ❌ |
| 3 | 画师价格管理 — 档位例图上传 | 图片 | ❌ |
| 4 | 画师订单详情 — 交付文件上传 | 文件（22种格式，50MB） | ❌ |

画师/客户截图后无法直接 Ctrl+V，必须先保存截图文件再选择上传——多一步操作。

### 需求描述

1. **所有图片上传处（#1 #2 #3）支持粘贴上传**：在上传区域激活时（或页面全局监听，待确认），Ctrl+V 粘贴剪贴板中的图片即可上传
2. **安全防护**：只接受图片类型的粘贴内容。粘贴非图片内容（文字、文件路径、HTML 片段等）时拒绝并提示
3. 交付文件上传（#4）是否支持粘贴——待确认（交付文件不限于图片，粘贴场景主要是截图）

### 安全要求

- 前端第一道过滤：粘贴事件只处理 `image/*` 类型的剪贴板项，其余忽略或提示
- 后端已有 MIME 白名单校验（第二道防线），粘贴上传走与拖拽上传完全相同的校验链路
- 粘贴非图片内容时，不应该有任何数据发送到后端
- 粘贴上传同样受大小限制（图片 10MB）和数量限制（参考图最多 5 张）约束

### 待确认

- [ ] **C14**：粘贴监听范围——仅上传组件区域内粘贴，还是整个页面任意位置粘贴？（建议：下单页参考图区域全局监听，画师端上传组件区域内监听，避免干扰其他输入框操作）
- [ ] **C15**：交付文件上传（#4）是否也需要粘贴支持？

### 验收标准

1. 当用户在客户下单页复制一张截图后按 Ctrl+V 时，图片应该被上传并显示在参考图列表中
2. 当用户粘贴非图片内容（如复制的文字）时，应该被拒绝，显示"仅支持粘贴图片"提示，无数据发送到后端
3. 当用户粘贴超过 10MB 的图片时，应该被拒绝并提示大小限制
4. 当参考图已满 5 张时粘贴新图片，应该被拒绝并提示数量限制
5. 当画师在作品管理/档位例图上传处粘贴图片时，应该能正常上传
6. 当粘贴上传的图片格式不在白名单内（如 BMP/GIF 超限格式）时，后端应该拒绝并返回错误提示

## 技术影响评估（供一号审核参考）

### 数据库迁移（高风险）

R2 和 R4 需要 `orders` 表新增字段（建议合并为一次迁移 v11）：

| 字段 | 类型 | 用途 |
|------|------|------|
| 报价快照字符串 | TEXT | R2：可读报价描述 |
| 最终价格 | INTEGER（分） | R2：画师可改的成交价 |
| 焦点图路径 | TEXT | R4：选中的参考图路径 |
| 焦点图模式 | TEXT（off/small/large） | R4：显示尺寸 |

⚠️ 属于协作规则中的**高风险操作**（数据库结构变更），一号需向实际操作人说明风险、影响范围和回滚方案，获得确认后才可执行。

R1 的修改次数若为数值配置（C1/C2 待确认），可能也需要 `artist_workflow_stages` 表或画师配置新增字段。

### 收入统计影响

C6 待确认。若改用最终价格，`order.service.js` 的收入统计 SQL 需要调整（当前用 `price_snapshot`，即档位基础价，本身不含增项/倍率，统计偏低）。

### 涉及角色

| 角色 | 受影响需求 |
|------|-----------|
| 客户 | R1（流程展示变化）、R5（粘贴上传） |
| 画师 | R2（价格设置）、R3（录单补全）、R4（焦点图）、R5（粘贴上传） |
| 管理员 | 无直接影响 |

### 依赖关系与建议实施顺序

```
R2（报价快照+最终价格，含DB迁移）
  ↓
R3（录单补全，依赖R2的字段和接口）

R1（流程整合）——独立
R4（焦点图，可与R2共用迁移）——独立
R5（粘贴上传）——独立
```

建议顺序：先 R2+R4（共用一次迁移），再 R3，R1 和 R5 可并行。

## 建议（非需求，供参考）

1. **报价快照字符串格式**：建议系统按固定模板生成初稿（如"档位名 ¥X + 增项A×n ¥Y，倍率×z → 总价 ¥T"），画师可任意编辑。这样既有统一格式，又保留灵活性。
2. **价格修改留痕**：建议每次修改最终价格时自动追加一条订单备注（"最终价格从 ¥A 改为 ¥B"），利用现有备注系统，零额外开发成本，且画师可以回看。
3. **焦点图与交付**：焦点图功能未来可以和"交付预览"结合——客户查进度时看到打码的焦点图，知道画到哪了。本期不做，仅记录方向。
