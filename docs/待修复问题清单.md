### P0-1. `/uploads/` 全目录公开，零鉴权 ✅ 确认

**位置**：`server/src/app.js:69-81`

**现状**：整个上传目录通过 `@fastify/static` 以静态文件形式对全网公开，无任何 `preHandler` 鉴权。虽然设置了 `X-Content-Type-Options: nosniff` 和 `Content-Disposition: attachment`（防 MIME 嗅探和 XSS），但这**不能替代鉴权**。

**实际风险**：
- `deliverables/<artistId>/*`（客户付费成品）和 `references/*`（客户参考图）完全公开
- 唯一"保护"是文件名 `nanoid(12)` 不可猜——security by obscurity
- URL 一旦被转发/浏览器历史/Referer 泄露，永久可下载，画师无法撤回
- 订单接口返回的正是 `/uploads/xxx` 明文 URL

**修复方向**：
- 方案 A（推荐）：签名 URL — 新增 `GET /api/files/:token`，HMAC 签名 + 15 分钟有效期，仅 `/uploads/images/` 保留公开
- 方案 B：全部走鉴权路由，移除 fastifyStatic 的 /uploads/ 注册
- 方案 C（临时）：Caddy 层 forward_auth

**工作量**：半天

### P0-3. `token_version` 机制是摆设 — 无法登出/吊销 ✅ 确认

**位置**：`server/src/features/artist/artist.service.js:106-109`（deleteArtist）+ `server/src/features/auth/auth.service.js:116-119`

**现状**：
- `token_version` 在创建 token 时写入 payload，中间件也校验——机制本身实现正确
- 但**全代码库没有任何地方 UPDATE 过 `token_version`**，它永远是 1
- `deleteArtist()` 只写 `deleted_at`，不递增 `token_version`
- 前端"登出"只是 `localStorage.removeItem()`，服务端一无所知

```js
// artist.service.js
export function deleteArtist(id) {
  db.prepare(
    'UPDATE artists SET deleted_at = CURRENT_TIMESTAMP, token_version = COALESCE(token_version,1) + 1 WHERE id = ?'
  ).run(id)
}
// 新增 POST /api/auth/logout（requireAuth），调用 bumpTokenVersion
```

### P0-6. 唯一索引被同名非唯一索引"吃掉" ✅ 确认

**位置**：`server/src/db/init.js:145` vs `init.js:161`

**现状**：
- schema 第 145 行：`CREATE INDEX IF NOT EXISTS idx_artists_code`（非唯一）
- 迁移 v1 第 161 行：`CREATE UNIQUE INDEX IF NOT EXISTS idx_artists_code`（唯一）
- `IF NOT EXISTS` 只看名字——同名非唯一索引先建成后，唯一索引静默跳过

**缓解因素**：新建库的 `CREATE TABLE` 有列级 `UNIQUE` 约束（`sqlite_autoindex`），数据完整性不受影响。但走迁移路径的老库会中招。

**修复**：
```js
// 迁移里改为：
database.exec('DROP INDEX IF EXISTS idx_artists_code')
database.exec('CREATE UNIQUE INDEX IF NOT EXISTS uniq_artists_code ON artists(artist_code)')
```

### P1-10. 会话签名用非 timing-safe 比较 ✅ 确认

**位置**：`server/src/features/auth/auth.service.js:132`

**现状**：`verifySession` 用 `if (sig !== expected) return null`（普通字符串比较），而同文件的登录码验证已用 `timingSafeEqual`。安全措施不一致。

**实际风险**：HMAC 时序攻击在网络环境下不易利用，风险等级不高。但应统一标准。

**修复**：
```js
const expected = crypto.createHmac('sha256', SECRET).update(payload).digest()
const actual = Buffer.from(sig, 'base64url')
if (expected.length !== actual.length || !crypto.timingSafeEqual(expected, actual)) return null
```
