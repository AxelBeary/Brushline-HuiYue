### 1.2 API 契约草案

**新增：POST /api/orders/:id/publish-artwork**（画师登录，订单归属校验）

```
请求体：{ deliverableIds: number[], title: string, description?: string }
  - deliverableIds 必须属于该订单；至少 1 张；允许部分勾选（默认全选是前端行为）
  - title 非空、长度上限待定（建议 ≤100，待一号确认）
成功：201 { artwork: { id, imagePath, title, ... } }
失败：404 订单/交付物不存在 · 403 订单不属于该画师 · 400 订单未完稿
```

后端行为要点：
1. 校验订单状态为完稿（completed/delivered 具体哪个状态可发布——**待一号确认**，REQ 只说「订单完稿后」）
2. 交付物文件从 `deliverables/{artistId}/` **复制**（非移动）到 `images/{artistId}/`，作品记新路径；原交付物保留不动（客户交付页仍可下载）
3. 每张选中图片建一条 artworks 记录（同标题多张 = 多条作品？还是多图一作品——**待确认**，现有 artworks 表一行一图，建议沿用一行一图，标题加序号或不加由画师填）

**复用：PUT /api/artist/artworks/:id/tags**（已存在，多选替换语义，不改）

**客户端展示**：现有公开接口返回作品 + tags 即可，前端按 style_size 分组；「立即约稿」跳转 OrderForm 是否带 `?sizeId=` 预选档位——**待一号/用户确认**（建议带，体验闭环）

### 2.2 API 契约草案

**新表 social_platforms**（暂名，不复用 key-value 的 platform_config）：

```sql
CREATE TABLE social_platforms (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,              -- 显示名，如「微博」
  icon_key TEXT NOT NULL,          -- 白名单图标键（如 'weibo'）或单字兜底标记
  fallback_char TEXT,              -- 白名单无图标时的单字文字徽标
  match_domains TEXT NOT NULL,     -- JSON 数组：["weibo.com","weibo.cn"]
  sort_order INTEGER DEFAULT 0,
  enabled INTEGER DEFAULT 1
);
```

内置约 20 平台种子数据（微博/B站/小红书/LOFTER/pixiv/X/抖音等，清单以 F2-4 白名单为准）随建表插入。

**接口**：

| 方法/路径 | 鉴权 | 说明 |
|-----------|------|------|
| GET /api/platforms | 公开（或画师登录） | 返回 enabled 平台列表（下拉 + 识别用） |
| GET /api/admin/platforms | 管理员 | 全量含停用 |
| POST /api/admin/platforms | 管理员 | 新增：name/icon_key 或 fallback_char/match_domains/sort_order/enabled |
| PUT /api/admin/platforms/:id | 管理员 | 修改 |
| DELETE /api/admin/platforms/:id | 管理员 | 删除（已有画师链接引用该平台的处理——**待确认**：建议置为「其他」而非级联删链接） |

**画师链接存储**：`custom_links` + `platform_urls` 合并为单一 JSON 列（建议直接改造 `custom_links` 列结构，弃用 `platform_urls` 列——上线前无真实数据，不写迁移）：

```json
[{ "platformId": 3, "url": "https://weibo.com/xxx" }]   // platformId=null 表示「其他」
```

### 2.3 后端校验职责结论（派工点名问题）

**结论：全部硬校验放后端，前端识别只做体验层。** 具体边界：

| 规则 | 前端职责 | 后端职责（保存时强制执行） |
|------|----------|---------------------------|
| 协议白名单（仅 http/https） | 粘贴时预检提示 | **必须拒绝**非 http(s) |
| 裸链补 https:// | 粘贴时自动补 | 保存前同样做一次归一化（不信任前端已补） |
| 长度限制（域名 253/路径 1500/总长 1800） | 超限即时提示 | **必须拒绝**超限 |
| 条数上限 8 | 按钮禁用 | **必须拒绝** >8 条 |
| 平台识别（域名末尾匹配） | 粘贴时自动切下拉（体验） | **保存时后端按 URL 重新推导 platformId，不信任前端传来的识别结果**——防投毒最关键一条：前端可被绕过/篡改，识别结果必须由后端从 URL 独立推导 |
| 域名末尾匹配算法 | 前端实现一份（体验） | 后端实现一份（权威）：主机名 == 目标 或 以 `.目标` 结尾，其余一律「其他」 |

依据项目铁律「前端校验只能是后端规则的子集」（v0.36 L3 教训）。前端两份逻辑只是让画师少犯错，安全边界 100% 在后端。

### 2.4 依赖与顺序

- F2-1 → F2-2（后端串行）→ F2-5（前端下拉依赖平台接口）
- F2-4（图标打包）可与后端并行，F2-3/F2-5/F2-6 依赖 F2-4 的图标键约定
- F2-6（客户端页脚）只依赖新存储结构，可与 F2-5 并行

### 2.5 风险点

- **R-2a 域名匹配实现错误**：`endsWith` 直接用会漏「主机名精确等于」分支、或把 `.目标` 写成 `目标` 造成前缀粘连（xweibo.com）。**必须**先写测试向量再实现：weibo.com ✓ / m.weibo.com ✓ / weibo.com.evil.com ✗ / xweibo.com ✗ / 大小写 / 端口号场景（**端口算不算合法主机名的一部分——待确认**，建议按主机名处理、端口不特殊对待）
- **R-2b snake_case 映射**：新表/新字段前后端命名映射（platformId↔platform_id）走既有 camelCase 映射层，别手抄漏字段
- **R-2c 旧数据回退逻辑**：getCustomLinks 现有「custom_links=NULL 回退旧列 weibo_url」逻辑（artist.service.ts L541），重做后该回退是否保留——上线前无真实数据，**建议直接删回退分支**，待一号确认
- **R-2d i18n**：平台管理页 + 设置页新文案 zh/en 双语同步
