## R26：手动录单支持不选档位直接手填价格

### 画师原声

> "手动录单没法手动输价格，或者说手动录单功能很差劲。"

### 现状（已核实）

`ManualOrder.vue` 有最终价格输入框（94-101 行），但被 `v-if="form.tierId"` 守卫——**必须先选档位才出现**。画师接了不在档位表里的定制单（私下谈好价），不选档位就没有任何价格输入入口。提交逻辑（376-386 行）也依赖 `pricePreview`（选档位后才有），不选档位时价格无法传入。

已记入 `docs/待修复问题清单.md` UI-5。

### 需求描述

手动录单的核心场景就是"客户没走自助下单流程，画师手动补录"——这种订单经常没有对应档位（定制内容、老客优惠、打包价）。价格输入必须独立于档位存在。

### 验收标准

1. 当画师不选任何档位时，最终价格输入框应该仍然可见可用
2. 当画师不选档位直接填价格提交时，订单应该成功创建，价格正确入库
3. 当画师选了档位时，现有行为不变（计算价自动填入，可手动覆盖）
4. 当画师不选档位时，增项/倍率选择区不显示（无档位则无增项，行为合理）

## R27：排期看板拖拽后图片加载失败（BUG）

### 画师原声

> "排期看板一拖拽图片会变成加载失败。"

### 现状（已核实）

`PUT /api/artist/queue/reorder`（order.routes.js:424-426）返回裸数据，没有像 `GET /api/artist/queue` 那样补签名 URL。前端拖拽后整体替换数组 → `focusImageUrl` 全部丢失 → 图片加载失败。刷新恢复。

已记入 `docs/待修复问题清单.md` UI-4。与 UI-3 同根（签名补漏不一致）。

### 验收标准

1. 当画师拖拽排序后，所有卡片的焦点图应该仍然正常显示，不出现"加载失败"
2. 当拖拽失败回滚时，图片显示也不受影响

## R28：接单槽位/批次上限设置

### 画师原声

> "没有一个总接单数功能，他们想要设置这批开多少个。"

### 现状（已核实）

- `artists` 表无槽位/上限相关字段（已查 schema：status 只有 open/full/break 三态）
- 画师只能手动切"已满"——但"已满"是一刀切，无法表达"这批只接 5 单，接满自动关"
- 客户主页只显示状态徽章（open/full/break），不显示"还剩几个名额"

### 需求描述

画师开一批约稿时，想设定"这批接 N 单"。达到 N 单后自动停止接单（或提示已满），客户能看到"还剩 X 个名额"。

### 验收标准

1. 当画师设置"本批接单上限为 N"时，设置应该保存并在仪表盘可见
2. 当活跃订单数达到 N 时，客户应该无法再下单（或看到"已满"提示）
3. 当客户访问画师主页时，应该能看到剩余名额信息（如"还剩 3 个名额"）
4. 当画师手动调整上限（增/减）时，接单状态应该即时响应
5. 当画师不设置上限时，行为与现在一致（open 状态无限接单）

### 待确认

- [x] **C38**：达到上限后画师状态自动切 `full`，还是保持 `open` 但下单拦截？✅ **已被 SPEC-004 覆盖（2026-07-31）**：画师状态与名额解耦，外部接单只看 status，不看空位。
- [x] **C39**：pending 算不算占名额？✅ **已被 SPEC-004 覆盖（2026-07-31）**：用户拍板 pending 就占位。
- [x] **C40**：名额信息在客户主页的展示位置？✅ **已被 SPEC-004 §3 覆盖（2026-07-31）**：slotDisplay 在状态徽章旁，classic 模板已实现。

## R29：小公告功能

### 画师原声

> "还说要一个小公告功能。"

### 现状（已核实）

- 画师主页无公告区域
- 画师想通知客户的信息（"近期排期紧张""国庆放假""开新批次"）只能改简介或发社交媒体，客户不一定看到

### 需求描述

画师可以发一条短公告，显示在客户主页醒目位置。"小"是关键——不是文章系统，是一两句话的便签。

### 验收标准

1. 当画师在后台编辑公告（一两句话）时，应该能保存并即时生效
2. 当画师设置了公告时，客户访问主页应该在醒目位置看到公告内容
3. 当画师清空/关闭公告时，客户主页不应该再显示
4. 当公告存在时，应该有视觉上的"公告感"（如 📢 图标 + 底色区分），不混入普通页面文字

### 待确认

- [x] **C41**：公告是否需要过期时间？✅ **用户拍板（2026-07-30）：默认永不过期 + 可选过期时间（顶掉模式，永远一条公告）。** 实施时 artists 表加 `announcement_expires_at DATETIME DEFAULT NULL`，公开 API 判断过期。
- [x] **C42**：公告显示在 4 个模板的什么位置？✅ **用户拍板（2026-08-01）：C 二号按模板风格定，约束首屏可见。**

## R30：排期看板宽屏增强

### 画师原声

> "排期看板页面功能太少，手机看（长条屏幕）很好，但是平板和电脑时有很多空白空间没用上。"

### 实际操作人补充建议（原声，逐条记录）

> "建议计划更多看板功能可以用的按钮，比如 推进 修改等"
> "手机时还可以直接左滑这个条直接进详情（电脑要这个功能吗？）"
> "状态流转最好也用上画师之前自己设置的流程，特别是取消订单这种，加一个像是解锁屏幕一样的滑块？"

### 现状（已核实）

- 看板卡片（`QueueBoard.vue`）宽屏下：单列纵向列表，`max-width` 未利用，平板/电脑大量空白
- 卡片操作只有两个按钮：「详情」+「操作」下拉菜单（确认/开始/完成/交付/取消）
- 状态流转用的是**硬编码状态机**（`STATUS_TRANSITIONS`：pending→confirmed→wip→revision→done→delivered），与画师自定义的工作流节点（`artist_workflow_stages`）**完全脱钩**——画师在设置里配的流程只用于客户展示，自己操作时还是固定 6 态
- 取消订单用 `ElMessageBox.confirm` 普通确认弹窗

### 需求描述

**30a. 宽屏空间利用（保持一行一条）**：~~多列~~ 实际操作人确认（2026-07-30）排期看板**必须保持一行一条**，不做多列。宽屏空间利用方向改为：卡片内部横向展开更多信息（焦点图/描述/价格/进度并排），或加宽卡片让信息不截断，而非把列表拆成多列

**30b. 卡片快捷操作按钮**：把常用操作（推进到下一步、修改）直接放在卡片上，不藏在"操作"下拉里

**30c. 手机端左滑进详情**：卡片左滑露出"详情"入口（或直接滑动跳转）。电脑端是否需要等效操作待确认（C43）

**30d. 状态流转接入自定义工作流**：画师设置里配的流程节点（如"草稿→线稿→上色→尾款→交付"）应该成为看板状态推进的实际步骤，而不是只给客户看的展示条。特别是取消订单——用滑块确认（像手机解锁一样滑动"确认取消"），防误触，比点两下弹窗更有"慎重感"

### 验收标准

1. 当画师在平板/电脑（宽屏）打开看板时，卡片应该保持**一行一条**（不拆多列），同时宽屏空间被有效利用（卡片内信息横向展开、不截断），不出现大面积空白
2. 当画师在看板上操作订单时，常用操作（推进/修改）应该一键可达，不需要先打开下拉菜单
3. 当画师在手机上左滑卡片时，应该能快速进入订单详情
4. 当画师推进订单状态时，推进的应该是画师自己设置的流程节点（如"线稿→上色"），不是固定的 wip→done
5. 当画师取消订单时，应该通过滑动确认（滑块式），不是普通点击确认
6. 当画师没有自定义流程时，应该回退到现有默认状态流转（兼容）

### 待确认

- [x] **C43**：电脑端是否需要左滑等效操作？✅ **用户拍板（2026-08-01）：电脑不做左滑，通过判断宽窄修改操作逻辑（窄屏左滑，宽屏用按钮）。**
- [ ] **C44**：自定义流程接入状态机是 v0.13 大改，涉及订单状态模型重构（固定 6 态 → 动态节点），是否确认排入 v0.13？（建议：是——这是画师端体验的核心升级，但工程量大，需三号先出技术方案）
- [ ] **C45**：滑块确认只用于"取消订单"，还是所有危险操作？（建议：先只做取消——取消是不可逆操作，其他操作可回退）

### 风险提示

- 30d 是本批次最大的改动：订单状态从固定状态机变为画师自定义节点，影响订单服务、看板、客户进度页（TrackOrder）、QQ 通知文案，需三号出完整技术方案后再实施
- 30a/30b/30c 是纯前端，可先行；30d 建议独立排期

## R31：焦点图"小"模式布局优化

### 画师原声

> "焦点图大小关功能做的有点丑（小的时候直接把图和文字上下排布 硬生生加长无效空间）"

### 现状（已核实）

`QueueBoard.vue` 小模式（55-62 行）：48px 缩略图放在 `.item-body` 内部、文字描述**下方**：

```
[拖拽] [#单号 优先级 状态]        [详情][操作]
       [档位 · QQ · 昵称]
       [描述...]
       [48px 图]   ← 硬生生把卡片加高
```

卡片是横向 flex 布局，图在文字下方导致每个卡片高度增加 ~56px，10 个卡片就多占 560px 纵向空间——看板的核心是"一屏看全排期"，小模式反而拉长了列表。

### 需求描述

小模式的 48px 图应该**嵌入**卡片横向布局（如文字左侧/右侧），不额外增加卡片高度。

### 验收标准

1. 当看板开启"小"模式时，48px 缩略图应该与文字信息并排（不额外增加卡片高度）
2. 当看板开启"大"模式时，保持现有左图右文布局（160×120，UI-2 已修）
3. 当看板关闭焦点图时，行为不变
4. 当手机上使用小模式时，布局不应该溢出或挤压

## R32：默认面板存废 + 仪表盘功能增强

### 画师原声

> "现在默认面板功能不好，甚至不如排期看板。还说默认面板不如删掉，在仪表盘加别的功能。"

### 现状（已核实）

- "默认面板"（R8 功能）：设置里可选 queue/orders/manual/tiers 之一，仪表盘上显示一个快捷入口卡片（`Dashboard.vue:16-20`），点击跳转到对应页面
- 仪表盘现有内容：问候语 + 默认面板入口 + 4 个统计卡（待确认/进行中/月收入/累计完成）+ 4 个快捷按钮 + 状态切换
- 画师的抱怨本质：默认面板入口只是一个跳转链接，没有信息量；"不如排期看板"说明画师真正想要的是**仪表盘直接展示有用信息**，而不是跳来跳去

### 需求描述

两个方向（待确认 C46）：
- **方向 A（删）**：删掉默认面板入口，仪表盘空间让给更有信息量的内容（如：今日待办、最近订单摘要、排期预览 mini 版）
- **方向 B（融）**：保留默认面板概念，但把选中面板的**摘要**直接嵌入仪表盘（如选 queue 则仪表盘内嵌排期前 5 条预览）

### 验收标准

1. 当画师打开仪表盘时，首屏应该展示对当天工作有直接帮助的信息，不只是一个跳转链接
2. 当画师想使用排期看板时，仍然能一步到达（快捷入口保留或内嵌预览）
3. 当画师切换默认面板设置时（如果保留该功能），仪表盘内容应该即时响应

### 待确认

- [x] **C46**：默认面板是删除还是融合？✅ **已被仪表盘 spec 覆盖（2026-07-31）**：C50/C52 拍板快捷操作卡片网格（固定 6 项不可自定义），默认面板入口不放入 v0.18 布局（Q5 一号已定）。
- [x] **C47**：仪表盘最应该加什么功能？✅ **已被仪表盘 spec 覆盖（2026-07-31）**：C48–C58 全部拍板（收入柱状图 + 合并列表 + 活动流 + 名额概览卡 + 双栏布局）。
