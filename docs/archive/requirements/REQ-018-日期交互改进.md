## 背景

当前日期校验是"选完了报错"——选个错误日期 → 弹窗 `INVALID_ANNOUNCEMENT_DATE`，体验差。用户看到一个更好的日期选择器（来自某产品），核心特征：**不可选的日期直接灰掉，而不是选完了再告诉你错了**。

---

## 用户期望的交互特征（原话提炼）

- **快捷预设**：近 7 天 / 近 30 天 / 本月 / 上月 / 自定义
- **双月面板**：左右两个月并排，选开始和结束
- **屏幕自适应**：窄屏时面板堆叠或缩放
- **选择器层面限制范围**：不是选完了报错，而是不可选的日期直接灰掉（disabled）

---

## 功能描述

### 1. 公告过期日（画师主页设置）

- 改为 `el-date-picker` 的 `disabled-date` 限制：**今天之前不可选**（灰掉）
- 不需要后端校验弹窗作为主交互（后端校验保留为防御性兜底）
- 加快捷预设：近 7 天 / 近 30 天 / 本月 / 自定义

### 2. 订单开工日 / 截稿日（录单 + 订单详情）

- 两个日期选择器**互相限制**：
  - 选了开工日后，截稿日 picker 灰掉开工日之前的日期
  - 选了截稿日后，开工日 picker 灰掉截稿日之后的日期
- 开工日 `disabled-date`：今天之前不可选（或创建日之前？待确认）
- 截稿日 `disabled-date`：开工日之前不可选
- 加快捷预设：近 7 天 / 近 30 天 / 本月 / 自定义

### 3. 排期看板时间条

- 考虑是否加"快捷延后 N 天"预设（与 REQ-019 时间条平移联动）
- 此项为**建议**，待确认是否纳入本期

### 4. 技术评估

- EP 的 `el-date-picker` 原生支持：
  - `disabled-date` 函数 ✅
  - `type="daterange"` 双月面板 ✅
  - 快捷预设 `shortcuts` ✅
  - 屏幕自适应：需评估窄屏表现，可能需要 CSS 覆盖
- **建议**（待三号确认）：优先用 EP 原生能力，不自定义组件

### 5. 后端校验

- 后端日期校验**保留**（防御性），但前端主交互不依赖报错弹窗
- 前端 `disabled-date` 是第一道防线，后端校验是兜底

---

## 验收标准

1. 当画师设置公告过期日时，今天之前的日期应该灰掉不可选，不应该出现"选完了弹窗报错"的交互
2. 当画师选了开工日后打开截稿日选择器时，开工日之前的日期应该灰掉不可选
3. 当画师选了截稿日后打开开工日选择器时，截稿日之后的日期应该灰掉不可选
4. 当画师使用日期选择器时，应该看到快捷预设（近 7 天 / 近 30 天 / 本月 / 自定义）
5. 当画师使用日期范围选择器时，应该看到左右两个月并排的双月面板
6. 当屏幕宽度不足时，日期面板应该自适应（堆叠或缩放），不应该溢出屏幕
7. 当后端收到非法日期时，应该仍然返回校验错误（防御性兜底保留）
