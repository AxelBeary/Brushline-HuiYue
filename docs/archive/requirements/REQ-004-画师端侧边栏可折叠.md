## R21：画师端侧边栏支持折叠

### 用户原声

> "页面缩窄左边导航栏不仅没法自动折叠 也没法手动折叠"

### 现状（已核实）

画师后台所有页面共用 `ArtistLayout.vue`，侧边栏现状：

- `<el-aside width="220px">` **固定 220px 宽**，写死，不随窗口变化
- **无折叠按钮**，画师无法手动收起侧边栏
- **无响应式处理**：窗口缩窄时，侧边栏仍占 220px，挤压主内容区
- 唯一的移动端适配在 `@media (max-width: 600px)`，但只调整了个别页面内部布局（如 QueueBoard 的卡片换行），**侧边栏本身不变**

实际影响：
- 画师用笔记本/小屏幕时，主内容区被侧边栏挤掉 220px，表格/看板拥挤
- 平板/手机访问后台时，侧边栏几乎占满半屏，内容区几乎不可用
- 画师想临时收起导航看全内容，没有任何办法

### 需求描述

侧边栏支持两种折叠方式：

1. **手动折叠**：侧边栏上提供一个折叠/展开按钮（如顶部的 ☰ 或边缘的箭头），点击后侧边栏收起为**窄条**（只显示图标，约 64px），再点恢复 220px
2. **窄屏自动折叠**：窗口宽度低于某个断点（如 900px）时，侧边栏自动收起为窄条或完全隐藏（抽屉式）；画师仍可唤出
3. **折叠状态记忆**：画师手动折叠的偏好记住（localStorage），下次进来保持
4. **折叠态可用性**：窄条模式下每个菜单项只显示图标，悬停显示文字提示（tooltip），当前页高亮仍可见

设计原则：
- 导航是工具不是内容——画师工作时需要的是内容区最大化，导航应该"用时出现、不用时让位"
- 手动 + 自动结合：桌面画师手动控制，小屏设备自动适配，都不需要学习
- Element Plus 的 `el-menu` 原生支持 `collapse` 属性（图标模式），折叠态有现成方案，不用自造

### 待确认

- [x] **C34**：窄屏（如手机）时侧边栏是**收起为图标窄条**，还是**完全隐藏 + 汉堡按钮唤出抽屉**？→ **已确认（2026-07-29）**：≤900px 收起为图标窄条，≤600px 完全隐藏 + 顶部汉堡按钮唤出抽屉
- [x] **C35**：折叠偏好是否需要跨设备同步？→ **已确认（2026-07-29）**：不需要，localStorage 即可，不跨设备

### 验收标准

1. 当画师点击侧边栏折叠按钮时，侧边栏应该收起为只显示图标的窄条（约 64px），主内容区相应扩大
2. 当画师再次点击折叠按钮时，侧边栏应该恢复为 220px 完整宽度
3. 当侧边栏处于折叠态时，每个菜单项应该只显示图标，悬停时显示文字提示
4. 当侧边栏折叠时，当前所在页面的菜单项应该仍然高亮可见
5. 当画师把窗口缩窄到断点以下时，侧边栏应该自动收起（不需要手动操作）
6. 当画师手动折叠后刷新页面/重新登录，侧边栏应该保持折叠状态
7. 当画师在手机上访问后台时，侧边栏不应该占据大半屏幕，内容区应该可用
8. 当侧边栏折叠/展开切换时，应该有平滑的过渡动画，不是生硬跳变
9. 当侧边栏折叠时，底部身份区（头像/状态/登出）应该仍然可访问（图标化或收入菜单）

## 技术影响评估（供一号审核参考）

### 无需迁移（纯前端）

| 改动 | 文件 | 说明 |
|------|------|------|
| 侧边栏折叠状态 + 按钮 | ArtistLayout.vue | `el-aside` 动态宽度 + `el-menu :collapse` |
| 响应式断点 | ArtistLayout.vue | `matchMedia`/`resize` 监听 + CSS |
| 折叠偏好持久化 | ArtistLayout.vue | localStorage |
| 移动端抽屉（C34=抽屉时） | ArtistLayout.vue | `el-drawer` 或自绘 |

### 涉及角色

| 角色 | 受影响需求 |
|------|-----------|
| 画师 | R21（后台所有页面的布局） |
| 客户 | 无（客户页无此侧边栏） |

### 依赖关系

- 无依赖，独立纯前端改动
- 与 v0.12 的 R18（订单图库）等无冲突
- 建议排在 v0.11.x 补丁之后、v0.12 之前，因为它是画师每天都要用的基础体验

### 风险提示

- ArtistLayout 是画师后台**所有页面的公共骨架**，改动影响面大，需回归测试全部后台页面（仪表盘/看板/订单/录单/价格/作品/须知/设置）
- `el-menu` 的 `collapse` 模式要求菜单项结构规范（图标 + span），当前结构已符合，改造成本低
- 折叠动画涉及 `el-aside` 宽度过渡，Element Plus 对动态 width 的过渡支持需注意（可能需要 CSS transition 配合）

## 建议（非需求，供参考）

1. **与 UI-2 一起回归看板**：R21（侧边栏折叠）和 UI-2（大图模式）都影响排期看板的可用面积，建议五号修 UI-2 时顺带验证折叠态下的看板布局，两者一起验收。
2. **折叠态默认值**：建议桌面默认展开（220px），尊重画师既有习惯；只有手动折叠或窄屏才收起，避免"一进来就变了"的突兀感。
3. **这是画师端体验的地基**：侧边栏是画师每天接触最多的框架，折叠做好了，后续所有后台功能（v0.12 图库/外链/备注附图）都受益。建议优先级不低于任何单点功能。
