> **编号**：plan-health-check
> **作者**：四号（需求整理）
> **日期**：2026-07-31（提案）/ 2026-08-01（用户拍板）

## 1. 需求

管理后台加一个"系统自检"功能，点一下检查系统各部件是否正常，显示绿勾/红叉。

**核心原则**：按需触发（点一下才跑），不做定时轮询，零持续性能开销。不存数据库、不写文件，结果只显示在页面上，刷新即消失。

## 2. 入口

管理后台侧栏新增"系统"菜单项（用户拍板）。

## 3. 检查项

| 检查项 | 说明 | 状态 |
|--------|------|------|
| 数据库连接 | SQLite 能否正常读写 | ✅/❌ |
| 迁移版本 | 当前版本号，是否最新 | ✅/⚠️ |
| 上传目录 | uploads/ 是否存在、可写 | ✅/❌ |
| 磁盘空间 | 剩余空间（标注"仅供参考"，Docker 内值可能不准） | ⚠️ 参考 |
| 数据完整性 | 孤儿记录检查（订单→画师、订单→档位等外键） | ✅/❌ |
| 备份状态 | 最近一次 .bak 文件时间 | ✅/⚠️ |
| JWT_SECRET | 是否为非默认值（一号研判新增） | ✅/❌ |
| Node 版本 | 显示当前运行时版本（一号研判新增） | ℹ️ 信息 |

## 4. 结果展示（用户拍板：B 列表+折叠详情）

默认显示列表（每项一行：图标 + 名称 + 摘要）。每行可展开查看详情：

- 数据完整性展开 → 检查了哪些表、各多少条
- 磁盘空间展开 → 具体路径、总容量、已用、剩余
- 迁移版本展开 → 全部已应用迁移列表
- 其余项展开 → 具体检查参数和返回值

**性能说明**：详情不是多跑一次检查，而是同一次检查多返回几个字段，前端 CSS 控制展开/折叠。

## 5. 诊断包下载（用户拍板：v1 做）

页面上加一个"下载诊断包"按钮：
- 把检查结果 + 最近日志打包为一个文件
- 浏览器下载，服务器不留存
- 方便发给别人排查问题

## 6. 验收标准

- 当管理员进入管理后台时，侧栏应该看到"系统"菜单项
- 当管理员点击"系统"时，应该看到自检页面，点击"开始检查"后显示结果列表
- 当某项检查通过时，应该显示 ✅ + 摘要
- 当某项检查失败时，应该显示 ❌ + 摘要
- 当管理员点击某行展开时，应该看到该项的详细检查信息
- 当管理员点击"下载诊断包"时，浏览器应该下载一个包含检查结果和最近日志的文件
- 当管理员刷新页面时，之前的检查结果应该消失（不持久化）
- 磁盘空间项应该标注"仅供参考"

## 7. 排期

v0.19（用户拍板接受）。v0.18 排期：仪表盘 > 节点话术，自检不占 v0.18 时间。
