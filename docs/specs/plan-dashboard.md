当前仪表盘（Dashboard.vue）已有模块：

| 模块 | 来源 | 说明 |
|------|------|------|
| 问候区 | R7 | 时段问候语 + 点击换一句 |
| 默认面板入口 | R8 | 一键跳转画师设置的默认面板（排期/订单/手动创建/档位） |
| 今日统计行 | R52 | 今日新增订单金额 + 今日收入（紧凑一行） |
| 统计卡片 ×4 | 初版 | 待处理新单 / 进行中订单 / 本月收入 / 累计完成 |
| 截稿日卡片 | R51 | 未来 7 天截稿订单列表，≤3 天标红 |
| 今日待办卡片 | R51 | pending + revision + 今日截稿，带计数徽章 |

| 状态切换 | 初版 | open / full / break 三态单选 |

**v0.18 要解决的问题**：
- 收入只有一个"本月"数字，无趋势、无历史对比
- 排期/截稿日/待办分散在三个区域，画师需要来回对照
- 没有"最近发生了什么"的活动流
- 名额系统上线后无处展示名额状态

## 1. 收入统计（C48 ✅ 柱状图）

### 1.1 需求

**维度切换**：月 / 季 / 年三个维度，默认"月"。

**图表**（C48 拍板：柱状图）：
- 月视图：横轴 = 每日（1~31），纵轴 = 当日收入
- 季视图：横轴 = 每周（第 1~13 周），纵轴 = 当周收入
- 年视图：横轴 = 每月（1~12），纵轴 = 当月收入

**汇总数字**（图表上方）：
- 当前维度总收入（如"7 月：¥12,350"）
- 环比变化（如"↑ 23% vs 6 月"），无上一周期数据时不显示
- 当前维度完成订单数

**不做**（C49 拍板）：不加档位收入分布饼图。

### 1.2 数据来源

- 表：`orders`
- 金额字段：`COALESCE(final_price_cents, total_price_cents, price_snapshot * 100, 0)`（与现有 PRICE_FALLBACK_SQL 一致）
- 时间字段：`completed_at`（status IN ('done','delivered')）
- 时区：复用现有 `localMonthStartSqlite` 等工具函数，按画师本地时区计算

### 1.3 验收标准

- 当画师进入仪表盘时，应该看到收入统计区域，默认展示"月"维度柱状图
- 当画师切换维度为"季"时，柱状图横轴应该变为按周聚合，汇总数字变为当季总收入
- 当画师切换维度为"年"时，柱状图横轴应该变为按月聚合，汇总数字变为当年总收入
- 当某时间段无已完成订单时，柱子高度为 0（不留空白），汇总显示 ¥0
- 当画师本地时区为 UTC+8 时，月初 1 日 00:00~07:59 完成的订单应该算入本月

## 2. "现在要干什么"合并列表（C51 ✅ 合并式）

### 2.1 需求

将现有三个独立区域（排期看板入口、截稿日卡片、今日待办卡片）**合并为一个统一列表**，按紧急程度排序。

**排序规则**（从上到下）：
1. 逾期未完成（deadline < 今天，状态非终态）→ 标红
2. 今天截稿（deadline = 今天）→ 标红/橙
3. 待处理新单（status = pending）
4. 修改中（status = revision）
5. 进行中（status = confirmed / wip）→ 按 deadline 升序
6. 无 deadline 的进行中订单 → 排最后

**每条显示**：
- 标签（区分类型：逾期 / 截稿 / 新单 / 修改 / 进行中）
- 订单号 + 客户名
- 当前状态
- 截稿日（有则显示，无则不显示）

**列表伸缩**：
- v1 不设硬上限，列表随任务数量伸缩
- 如果实测单多时过长，再加折叠（如超过 15 条折叠 + "展开全部"）——做出来再定

**点击行为**：点击任意一条 → 跳转对应订单详情页

### 2.2 验收标准

- 当画师进入仪表盘时，应该看到一个统一的"现在要干什么"列表，所有在途任务按紧急程度排序
- 当有逾期订单时，该条应该标红显示在最顶部
- 当有今天截稿的订单时，该条应该标红/橙显示在逾期之后
- 当列表中有不同类型的条目时，应该靠标签区分（逾期/截稿/新单/修改/进行中）
- 当画师点击某条时，应该跳转到对应订单详情页
- 当没有在途任务时，应该显示空状态（如"当前没有待办，休息一下 🎨"）

## 3. 快捷操作区（C50 ✅ 卡片网格 / C52 ✅ 不可自定义）

### 3.1 需求

**布局**：卡片网格（2×3），每个操作一张小卡片（图标 + 名称）。

**操作项**（固定 6 个，不可自定义）：

| 操作 | 跳转 | 说明 |
|------|------|------|
| 📋 排期看板 | /queue | 完整排期视图（拖拽排序等） |
| ✍️ 手动创建 | /orders?action=manual | 画师代客下单 |
| 📦 全部订单 | /orders | 订单列表 |
| 🖼️ 图库管理 | /gallery | 作品管理 |
| 💰 档位管理 | /tiers | 价格档位 |
| ⚙️ 设置 | /settings | 画师设置 |

**不展开内容**：图库、档位只做按钮入口，不在仪表盘展开其内容。

**状态开关**：保留现有 open/full/break 三态切换（已有功能，位置调整到右栏）。

### 3.2 验收标准

- 当画师进入仪表盘时，应该看到 6 个快捷操作卡片，2×3 网格排列
- 当画师点击"图库管理"时，应该跳转到 /gallery
- 当画师点击"档位管理"时，应该跳转到 /tiers
- 当屏幕宽度 ≤768px 时，卡片应该变为 2 列或 1 列自适应

## 4. 最近活动流（C53 ✅ / C54 ✅ 10 条 / C55 ✅ 不刷新 / C56 ✅ order_notes）

### 4.1 需求

**数据源**：复用 `order_notes` 表（已有订单操作记录、状态变更等），不新建表。

**展示内容**（每条）：
- 时间（相对时间，如"2 小时前"）
- 订单号
- 事件描述（如"状态变更为 线稿确认""新增参考图""画师添加备注"）

**条目上限**：最多 10 条（C54）。

**刷新机制**：进入仪表盘时加载一次，不加刷新按钮，不做自动轮询（C55）。画师想看最新的自己刷新页面。

**点击行为**：点击某条 → 跳转对应订单详情页。

**空状态**：无记录时显示"暂无最近活动"。

### 4.2 验收标准

- 当画师进入仪表盘时，应该看到最近活动区域，展示最多 10 条操作记录
- 当活动超过 10 条时，应该只显示最近 10 条
- 当没有活动记录时，应该显示"暂无最近活动"
- 当画师点击某条活动时，应该跳转到对应订单详情页
- 当画师停留在仪表盘页面时，活动列表不应该自动刷新

## 5. 名额概览卡（C57 ✅ 进度条+文字，画师面板专用）

### 5.1 需求

仅当画师设置了 `batch_limit`（非 NULL）时显示。

**样式**（C57 拍板：进度条+文字）：
- 正式区：一条进度条 + "正式 X/N"
- 缓冲区：一条进度条 + "缓冲 Y/M"
- 下一位候补：客户名（QQ）
- 点击跳转看板缓冲区视图

**进度条颜色**（建议，待二号按设计系统定）：
- 正式区未满：主题色
- 正式区满：橙色/红色
- 缓冲区：蓝色系

**注意**：此进度条样式仅限画师面板。客户前端走 SPEC-004 §3 的文字规则（"开放中 · 剩 X 席""可候补""已接满"），不显示进度条。

### 5.2 验收标准

- 当画师未设置 batch_limit 时，仪表盘不应该显示名额概览卡
- 当画师设置了 batch_limit=3 且正式区有 2 单在途时，应该显示进度条（2/3）+ 文字"正式 2/3"
- 当正式区满（3/3）时，进度条应该变色（橙/红）
- 当画师点击名额概览卡时，应该跳转到看板缓冲区视图
- 当客户访问画师主页时，不应该看到进度条，只看到文字状态

## 6. 整体布局（C58 ✅ 双栏）

### 6.1 宽屏布局（>768px）

```
┌──────────────────────────────┬─────────────────────┐
│ 问候区                       │ 名额概览卡          │
│ 今日统计行                   │ （batch_limit 非    │
│ 收入统计（柱状图 + 汇总）    │   NULL 时显示）     │
│ 统计卡片 ×3                 │                     │
│ （待处理/进行中/累计完成）   │ 快捷操作区（2×3）   │
├──────────────────────────────┤                     │
│ "现在要干什么"合并列表       │ 状态切换            │
│ （逾期→截稿→新单→修改→     │ (open/full/break)   │
│   进行中，标红+标签）        │                     │
│                              │ 最近活动流（10 条） │
└──────────────────────────────┴─────────────────────┘
```

左栏 = 核心数据（收入 + 待办），右栏 = 操作 + 动态。

### 6.2 窄屏布局（≤768px）

回退为单列，顺序：
1. 问候区
2. 今日统计行
3. 收入统计
4. 统计卡片 ×3
5. 名额概览卡（有则显示）
6. "现在要干什么"列表
7. 快捷操作区
8. 状态切换
9. 最近活动流

### 6.3 验收标准

- 当画师在 1920×1080 屏幕上打开仪表盘时，应该看到双栏布局，无横向滚动
- 当画师在 375×667（手机）屏幕上打开仪表盘时，应该看到单列布局
- 当画师在 768px 宽度临界点时，布局应该正确切换，无错位

## 7. 用户点评提取（temp/ 设计稿）

| 用户原声（文件名） | 提取的设计点 | 本规格对应 |
|---|---|---|
| "导航分类不错 功能有开关 还有快捷操作" | 快捷操作区 | §3 |
| "动态感很强 很丝滑 截稿日功能和待办功能我们可以考虑参考吸收设计经验" | 截稿日 + 待办合并 | §2 |
| "打回清晰 日志可筛选 截稿安帕等板块……设计都很好" | 活动流（仪表盘）+ 日志筛选（订单详情页，另记） | §4 |
| "联系客户功能我们有必要加入吗，不过感觉这个页面有点重了" | ⚠️ 页面不能太重 | 设计原则 |
| "右下角加号直接跳增加订单有必要设计吗" | ⚠️ 不要悬浮按钮 | 不采用 |
| "还行吧，有点卡" | ⚠️ 性能敏感 | 不轮询 |

**设计原则**：
1. 页面不能太重——模块多但每个轻量
2. 不要悬浮按钮式入口
3. 性能优先——不做自动轮询
4. 打开即知当下最急的事（合并列表核心目标）
