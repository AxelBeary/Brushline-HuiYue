## 1. 收入统计（C47 已拍板方向）

### 1.1 现状

后端 `order-stats.service.js` 已有：
- `monthRevenue`：本月收入（completed_at ≥ 本月 1 日，金额回退链 final_price_cents → total_price_cents → price_snapshot）
- `todayRevenueCents`：今日收入
- `todayNewOrderCents`：今日新增订单金额

前端只展示 `monthRevenue` 一个数字（统计卡片第 3 个）。

### 1.2 需求

**维度切换**：月 / 季 / 年三个维度，默认"月"。

**图表**（待确认 C48）：
- 方案 A：柱状图——横轴为时间单位（月视图→每日，季视图→每周，年视图→每月），纵轴为收入金额
- 方案 B：折线图——同上，但用折线强调趋势
- 方案 C：柱状图 + 折线叠加——柱状为收入，折线为订单数（双 Y 轴）

**汇总数字**（图表上方）：
- 当前维度总收入（如"7 月：¥12,350"）
- 环比变化（如"↑ 23% vs 6 月"），无上月数据时不显示
- 当前维度完成订单数

**数据来源**：
- 表：`orders`
- 金额字段：`COALESCE(final_price_cents, total_price_cents, price_snapshot * 100, 0)`（与现有回退链一致）
- 时间字段：`completed_at`（收入确认时间，status IN ('done','delivered')）
- 时区：复用现有 `localMonthStartSqlite` 等工具函数，按画师本地时区计算

**按档位分布**（待确认 C49）：
- 是否在收入图表旁加一个饼图/环形图，展示各档位收入占比？
- 数据来源：`orders.tier_id` JOIN `price_tiers.name`
- 如果档位被删除（tier_id 指向不存在的档位），归入"其他"

### 1.3 验收标准

- 当画师进入仪表盘时，应该看到收入统计区域，默认展示"月"维度
- 当画师切换维度为"季"时，图表横轴应该变为按周聚合，汇总数字变为当季总收入
- 当画师切换维度为"年"时，图表横轴应该变为按月聚合，汇总数字变为当年总收入
- 当某时间段无已完成订单时，图表应该显示为 0（不留空白），汇总显示 ¥0
- 当画师本地时区为 UTC+8 时，月初 1 日 00:00~07:59 完成的订单应该算入本月（而非上月）

## 2. 快捷操作区（C47 已拍板方向）

### 2.1 现状

4 个平铺按钮：排期看板 / 手动创建订单 / 全部订单 / 设置。

用户点评 temp/ 设计稿时认可的点：
> "导航分类不错 功能有开关 还有快捷操作"
> "推进到的步骤 上一步 节点 可以复制的qq……都很好"

用户存疑的点：
> "右下角加号直接跳增加订单有必要设计吗"（对悬浮按钮式快捷入口存疑）
> "联系客户功能我们有必要加入吗，不过感觉这个页面有点重了"（反对页面过重）

### 2.2 需求

**布局**（待确认 C50）：
- 方案 A：卡片网格——每个操作一张小卡片（图标 + 名称 + 一句话描述），2×3 或 3×2 网格
- 方案 B：保持按钮行——在现有 4 按钮基础上扩展，最多 6 个，超出折叠
- 方案 C：分组——"常用"（排期/订单/手动创建）+ "管理"（档位/图库/设置），两组各一行

**操作项**（待确认 C51）：

| 操作 | 跳转 | 现有？ | 说明 |
|------|------|--------|------|
| 排期看板 | /queue | ✅ | 核心操作 |
| 手动创建订单 | /orders?action=manual | ✅ | 核心操作 |
| 全部订单 | /orders | ✅ | 核心操作 |
| 设置 | /settings | ✅ | 低频但必要 |
| 图库管理 | /gallery | ❌ 新增 | 用户点评中多次提到图库 |
| 档位管理 | /tiers | ❌ 新增 | 默认面板已有此选项 |

**是否可自定义**（待确认 C52）：
- 画师能否在设置页选择仪表盘显示哪些快捷操作？
- 如果可自定义，默认显示哪些？

### 2.3 验收标准

- 当画师进入仪表盘时，应该看到快捷操作区，所有操作项一行一条，纵向排列（或按确认的布局方案）
- 当画师点击"排期看板"时，应该跳转到 /queue 页面
- 当画师点击"图库管理"时，应该跳转到 /gallery 页面
- 当操作项超过 6 个时，不应该出现横向滚动（应换行或折叠）

## 3. 最近活动 / 待办（C47 已拍板方向）

### 3.1 现状

- 截稿日卡片（R51）：未来 7 天截稿订单，≤3 天标红
- 今日待办卡片（R51）：pending + revision + 今日截稿

没有"最近发生了什么"的活动流。画师想知道"我离开后有没有新订单""客户有没有留言"，目前只能去翻订单列表。

用户点评 temp/ 设计稿时认可的点：
> "动态感很强 很丝滑 截稿日功能和待办功能我们可以考虑参考吸收设计经验"
> "打回清晰 日志可筛选 截稿安帕等板块……设计都很好"

### 3.2 需求

**待办区**（保留现有 R51，增强）：
- 保留截稿日卡片 + 今日待办卡片
- 新增：缓冲区待处理提示（SPEC-004 上线后）——"缓冲区有 N 人等待递补"，点击跳转看板缓冲区
- 新增：待确认付款提示——有 pending 状态的付款分期时显示

**最近活动流**（新增，待确认 C53）：
- 数据源：`order_notes` 表（订单备注/日志）+ 订单状态变更
- 展示内容（每条）：时间 + 订单号 + 事件描述（如"#A-003 状态变更为 线稿确认""#A-005 客户新增参考图"）
- 条目上限：最近 10 条（待确认 C54）
- 刷新机制：进入仪表盘时加载一次，不自动轮询（待确认 C55）
- 点击某条活动 → 跳转到对应订单详情页

**活动类型**（待确认 C56）：
- 方案 A：仅订单状态变更（轻量，不需要新表）
- 方案 B：状态变更 + 备注 + 参考图上传 + 交付文件上传（需要 order_notes 已有数据 + 新增事件类型）
- 方案 C：独立 activity_log 表，记录所有操作（最完整，但需要新建表 + 所有写操作埋点）

### 3.3 验收标准

- 当画师进入仪表盘时，应该看到最近活动区域，展示最近 N 条操作记录
- 当没有活动记录时，应该显示空状态提示（如"暂无最近活动"）
- 当画师点击某条活动时，应该跳转到对应订单详情页
- 当缓冲区有人等待时（SPEC-004 上线后），待办区应该显示"缓冲区有 N 人等待递补"

## 4. 名额概览卡（SPEC-004 §5 已定义）

### 4.1 需求（已在 SPEC-004 中拍板，此处仅复述确认）

仅当画师设置了 `batch_limit`（非 NULL）时显示：

- 正式 X/N · 缓冲 Y/M
- 下一位候补：客户名（QQ）
- 点击跳转看板缓冲区视图

### 4.2 补充（待确认 C57）

- 是否用进度条可视化？（如正式区 3/3 显示满条，缓冲区 12/20 显示 60% 条）
- 进度条颜色：正式区满 → 红色/橙色？缓冲区 → 蓝色？
- 还是保持纯文字（SPEC-004 原文是纯文字）？

### 4.3 验收标准

## 5. 整体布局（待确认 C58）

### 5.1 现有布局（自上而下）

```
问候区
默认面板入口
今日统计行
统计卡片 ×4
截稿日 + 今日待办（两列）
快捷操作（按钮行）
状态切换
```

### 5.2 v0.18 布局方案

**方案 A：保持单列流式（现有风格扩展）**

```
问候区
默认面板入口
今日统计行
收入统计（图表 + 汇总）     ← 新增，替代原"本月收入"卡片
统计卡片 ×3（待处理/进行中/累计完成）← 原 4 卡去掉"本月收入"
名额概览卡                   ← 新增（batch_limit 非 NULL 时）
截稿日 + 今日待办（两列）
最近活动流                   ← 新增
快捷操作区                   ← 增强
状态切换
```

**方案 B：双栏布局（宽屏时）**

```
┌─────────────────────────┬──────────────────┐
│ 问候区                  │ 名额概览卡       │
│ 收入统计（图表）        │ 快捷操作区       │
│ 统计卡片 ×3            │ 状态切换         │
├─────────────────────────┤                  │
│ 截稿日 + 今日待办       │ 最近活动流       │
└─────────────────────────┴──────────────────┘
```

窄屏（≤768px）时回退为单列。

**方案 C：标签页**

仪表盘顶部加标签：概览 / 收入 / 活动。默认"概览"。

### 5.3 验收标准

- 当画师在 1920×1080 屏幕上打开仪表盘时，应该看到完整布局，无横向滚动
- 当画师在 375×667（手机）屏幕上打开仪表盘时，应该看到单列布局，所有模块纵向排列
- 当画师在 768×1024（平板）屏幕上打开仪表盘时，布局应该自适应（按确认的方案）

3. 性能敏感——不做自动轮询，进入时加载一次
4. 截稿日 + 待办是用户明确认可的，保留并增强
5. 活动流/日志用户认可，但要可筛选（v1 先不做筛选，后续迭代）
