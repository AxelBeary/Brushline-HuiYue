## 3. 排期方案

### 方案 A：仪表盘优先（推荐）

```
第一批：节点话术（5.5h）——小快灵，快速出成果
第二批：仪表盘（17h）——核心大块
第三批：技术债（5h）——集中清
```

- **总工时**：~27.5h（不含 SPEC-005）
- **风险**：仪表盘依赖 SPEC-004 前端先合入，如果二号 SPEC-004 前端延期则仪表盘推迟
- **适合**：想尽快看到仪表盘效果

### 方案 B：小快灵优先 + 全栈并行

```
第一批（并行）：
  - 三号：节点话术后端 + schema 补齐（2.5h）
  - 二号：SPEC-004 前端（v0.17 遗留）
第二批（并行）：
  - 三号：仪表盘后端（4.5h）
  - 二号：节点话术前端（3h）
第三批：
  - 二号：仪表盘前端（10.5h）
第四批：
  - 前端测试基建（4h）
```

- **总工时**：~27.5h（同上，但并行压缩日历时间）
- **风险**：并行需要三号后端先于二号前端完成，有等待
- **适合**：想压缩总日历天数

### 方案 C：加入 SPEC-005

在方案 A 或 B 基础上插入 SPEC-005：

```
第零批：三号出 SPEC-005 详细设计（2h）→ 四号整理 spec → 用户拍板
第一批起：同方案 A/B，SPEC-005 实施插在仪表盘之后
```

- **总工时**：27.5h + SPEC-005 实施（待估）
- **风险**：SPEC-005 设计未完成，工时不确定，可能挤占仪表盘时间
- **适合**：付款模型升级是刚需、等不了 v0.19
