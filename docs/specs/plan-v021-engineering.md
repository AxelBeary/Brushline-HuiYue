## 三、全局约束（适用所有三项）

### 3.1 开关式设计

每项功能必须可通过**环境变量**完全关闭：
- 关闭后对业务逻辑零影响，等同于未安装
- 未来拆分项目（如只保留画师端）时，删除环境变量 + 对应初始化代码即可，不涉及业务代码改动

### 3.2 不侵入业务代码

- 三项均为**纯附加层**，不修改现有业务逻辑的行为
- 现有单元测试（后端 469 + 前端 87）必须全部通过，不允许因引入新工具而修改已有测试

### 3.3 不碰 Docker 体系

- 不新增 Docker 容器、不修改 docker-compose.yml
- Sentry 使用 sentry.io 云服务（SaaS），不自建服务器

## 四、Sentry 错误监控

### 4.1 概述

给前端和后端各装一个"报警器"（SDK），运行时遇到报错自动上报到 sentry.io 面板，同时通过 webhook 触发 QQ 机器人推送通知。

### 4.2 需求明细

| # | 需求 | 说明 |
|---|------|------|
| S1 | 前端接入 Sentry Vue SDK | 捕获 Vue 组件渲染错误、未处理异常 |
| S2 | 后端接入 Sentry Node SDK | 捕获 Fastify 路由异常、未处理 Promise rejection |
| S3 | 环境变量开关 | `SENTRY_DSN_FRONTEND` / `SENTRY_DSN_BACKEND`，留空或不设 = 完全禁用 |
| S4 | 关闭 IP 采集 | 前端 SDK 配置 `sendDefaultPii: false`，不上传用户 IP |
| S5 | 邮件告警 | 通过 Sentry Alert Rule 触发邮件通知（QQ 机器人通知等 Phase 2 Bot 做好后再接） |
| S6 | 环境区分 | 开发环境（NODE_ENV=development）默认不上报，避免调试噪音 |
| S7 | 版本标记 | 上报时附带 release 版本号（从 package.json 读取），方便定位"哪个版本引入的" |

### 4.3 验收标准

| # | 验收标准 |
|---|----------|
| S-AC1 | 当 `SENTRY_DSN_FRONTEND` 已配置且前端发生 JS 报错时，应该在 sentry.io 面板 30 秒内出现对应错误记录 |
| S-AC2 | 当 `SENTRY_DSN_BACKEND` 已配置且后端路由抛出异常时，应该在 sentry.io 面板 30 秒内出现对应错误记录 |
| S-AC3 | 当 `SENTRY_DSN_*` 未设置或为空字符串时，应用应该正常运行且无任何 Sentry 网络请求 |
| S-AC4 | 当 Sentry 收到新错误时，配置的告警邮箱应该在 5 分钟内收到一封包含错误类型 + 触发次数的通知邮件 |
| S-AC5 | 当 NODE_ENV=development 时，即使 DSN 已配置，也不应该有任何上报请求 |
| S-AC6 | 错误记录中不应该包含用户 IP 地址 |

### 4.4 前置条件

- 用户注册 sentry.io 账号，创建 Vue + Node.js 两个项目，获取 DSN（**待用户操作**）
- QQ 机器人 webhook 地址（已有备案，需确认 webhook 端点格式）

## 五、Playwright E2E 自动化测试

### 5.1 概述

搭建 Playwright 测试框架，编写 5 条核心用户路径的自动化测试。每次代码变更后运行，确保关键流程不被改坏。

### 5.2 覆盖路线

| # | 路线 | 机器人操作 | 角色 |
|---|------|-----------|------|
| E1 | 客户下单 | 打开画师主页 → 选档位 → 填约稿表单 → 提交 → 看到"提交成功" | **客户** |
| E2 | 客户查进度 | 打开进度页 → 输入订单号 → 看到当前阶段信息 | **客户** |
| E3 | 画师改状态 | 登录 → 进入订单 → 修改阶段 → 看到更新成功 | **画师** |
| E4 | 管理员添加画师 | 登录管理后台 → 填写画师信息 → 提交 → 新画师出现在列表 | **管理员** |
| E5 | 管理员配置流程 | 登录管理后台 → 添加/编辑阶段 → 保存 → 阶段列表更新 | **管理员** |

### 5.3 需求明细

| # | 需求 | 说明 |
|---|------|------|
| P1 | 框架搭建 | Playwright 配置 + 测试目录 `e2e/` + npm scripts |
| P2 | 测试数据隔离 | E2E 使用独立测试数据库（或事务回滚），不污染开发数据 |
| P3 | 登录复用 | 管理端/画师端登录写为共享 fixture，不每条测试重复写 |
| P4 | CI 可运行 | `npm run test:e2e` 一条命令跑完全部，退出码反映通过/失败 |
| P5 | 与业务代码隔离 | 测试文件全部在 `e2e/` 目录，不修改 `server/` 或 `web/` 下任何文件 |

### 5.4 验收标准

| # | 验收标准 |
|---|----------|
| P-AC1 | 当执行 `npm run test:e2e` 时，应该依次运行 5 条测试路线并输出每条的通过/失败结果 |
| P-AC2 | 当所有路线通过时，命令退出码应该为 0；任何一条失败时退出码应该非 0 |
| P-AC3 | 当 E2E 测试运行时，不应该修改开发数据库中的任何数据 |
| P-AC4 | 当删除整个 `e2e/` 目录后，项目应该正常构建、正常运行，无任何残留依赖影响 |
| P-AC5 | 每条测试路线应该在 30 秒内完成（含页面加载），5 条总计不超过 3 分钟 |

### 5.5 前置条件

- 应用可在本地正常启动（`npm run dev` 或 Docker）
- 开发模式下有可用的登录方式（AUTH_DEV_MODE=true）

## 六、TypeScript 渐进迁移

### 6.1 概述

给项目引入 TypeScript 工具链，v0.21 只完成基础设施搭建 + 2 个核心模块迁移。不改运行逻辑，只加类型标注。

### 6.2 v0.21 范围

| # | 内容 | 说明 |
|---|------|------|
| T1 | tsconfig 配置 | 前后端各一份 tsconfig，允许 JS/TS 混存（`allowJs: true`） |
| T2 | 构建工具适配 | Vite（前端）+ 后端构建支持 .ts 文件，不改输出产物 |
| T3 | pricing 模块迁移 | 计价逻辑（**档位**基础价 × **倍率** = 最终价）加类型标注 |
| T4 | shared/ 模块迁移 | 共享工具函数加类型标注 |
| T5 | 类型定义文件 | 为核心实体（**画师**、**订单**、**档位**）建立 interface/type |

### 6.3 明确不做（v0.21）

- ❌ 不迁移路由文件、组件文件、测试文件
- ❌ 不启用 `strict: true`（先用宽松模式，后续版本逐步收紧）
- ❌ 不引入新的类型相关 ESLint 规则（避免一次性改太多）

### 6.4 验收标准

| # | 验收标准 |
|---|----------|
| T-AC1 | 当执行 `npx tsc --noEmit` 时，已迁移的 pricing 和 shared/ 模块应该零类型错误 |
| T-AC2 | 当现有 JS 文件未迁移时，构建应该正常通过（allowJs 兼容） |
| T-AC3 | 当 pricing 模块传入非法参数（如负数价格、空档位）时，TypeScript 编译器应该报错 |
| T-AC4 | 迁移后所有现有测试（后端 469 + 前端 87）应该全部通过，无行为变化 |
| T-AC5 | 当删除 tsconfig 和 .ts 文件、恢复原 .js 文件后，项目应该正常构建运行（可逆性） |

### 6.5 后续版本规划（仅记录，不在 v0.21 实施）

- v0.22+：逐步迁移路由层、服务层
- v0.23+：迁移前端组件（.vue → `<script lang="ts">`）
- 远期：启用 strict 模式

## 九、风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| sentry.io 免费版额度不够 | 错误丢失 | 当前体量远低于 5k/月，可忽略；超了再升级 |
| Playwright 在 CI 环境不稳定 | 假失败 | 配置 retry: 2 + 超时宽容；本地先跑通再上 CI |
| TS 迁移引入隐性行为变化 | 功能回归 | 迁移前后跑全量测试对比；不改逻辑只加类型 |
| 用户忘记注册 Sentry | 阻塞 S1/S2 | 不阻塞开发——先用空 DSN 开发，注册后填入即可 |
