## 1. 需求碎片汇总（已有记录）

以下均从已有文档中提取，标注来源。

### 1.1 点赞功能

**来源**：REQ-011 §7（H5 设计原型分析）

**用户原声**：
> "那个点赞功能我也是超级想要"

**原型参考**：温暖画室风 H5 的心形图标——点击变色+填充，带微动画。

**实施要点（REQ-011 已标注）**：
- 不只是前端按钮，需要后端支持（存储 + 去重）
- 需考虑：谁可以点赞（任何人 / 仅登录用户）？一个作品只能赞一次还是可取消？
- 数据模型：新表 `artwork_likes`（artwork_id, visitor_fingerprint/user_id, created_at）或简单计数字段

**状态**：用户"超级想要"，优先级高。但具体交互细节未讨论。

### 1.2 瀑布流（作品展示）

**来源**：REQ-005 R23（客户侧体验反馈）

**用户原声**：
> "当多种比例的作品混排时，网格应该整齐不凌乱（瀑布流/自适应行高均可，由二号定方案）"

**现状**：
- 4 个模板中 folio 已有 masonry（瀑布流）实现
- classic/gallery/atelier 仍用等高网格，`fit="cover"` 裁切，长条图/竖图构图被破坏
- C36 待确认：grid 改瀑布流还是自适应行高？（建议：瀑布流——folio 已验证）

**实施要点**：
- 改 TplGallery.vue（共享组件），影响 4 个模板的作品展示区
- 需回归所有模板
- 与 UI-6（全屏预览原图）联动

**状态**：C36 待用户确认方案。技术上 folio 已有现成实现，工程量不大。

### 1.3 小公告功能

**来源**：REQ-006 R29（画师侧反馈）

**用户原声**：
> "还说要一个小公告功能。"

**需求**：画师发一条短公告（一两句话的便签），显示在客户主页醒目位置。不是文章系统。

**已拍板**：
- C41（2026-07-30）：默认永不过期 + 可选过期时间。顶掉模式（永远一条公告，新的覆盖旧的）
- 实施：artists 表加 `announcement` TEXT + `announcement_expires_at` DATETIME DEFAULT NULL

**待确认**：
- C42：公告显示在 4 个模板的什么位置？（建议：Hero 区下方/信息卡内，由二号按模板风格定）

**验收标准（REQ-006 已写）**：
1. 当画师在后台编辑公告时，应该能保存并即时生效
2. 当画师设置了公告时，客户访问主页应该在醒目位置看到
3. 当画师清空/关闭公告时，客户主页不应该再显示
4. 当公告存在时，应该有视觉上的"公告感"（📢 图标 + 底色区分）

**状态**：需求清晰，C42 待二号定位置。工程量小（一个字段 + 设置页编辑入口 + 4 模板渲染）。

### 1.4 看板 UI（客户端）

**来源**：排期占位"看板 UI"，无独立需求文档。

**推测含义**：客户在画师主页能看到画师的排期/队列状态。与 SPEC-004 §3 的客户主页显示相关：
- "开放中 · 剩 X 席"
- "可候补"
- "已接满"

**可能扩展**：
- 客户看到画师当前在途订单数 / 完成数（不暴露具体订单详情）
- 客户看到大致排队情况（如"前方还有 5 位"）
- 画师可选择是否公开排期信息（`hide_queue_position` 已有字段）

**状态**：⚠️ 含义不明确，需用户确认"看板 UI"具体指什么。可能是 SPEC-004 §3 的前端实现（已排入 v0.17/v0.18），也可能是独立的公开展示板。

## 3. 与现有客户主页的关系

### 3.1 现有架构

```
ArtistHome.vue（路由容器，根据 template_id 动态加载）
├── ArtistHomeClassic.vue    ← classic 布局
├── ArtistHomeGallery.vue    ← gallery 布局
├── ArtistHomeFolio.vue      ← folio 布局（已有 masonry）
└── ArtistHomeAtelier.vue    ← atelier 布局

共享层：
├── composables/useArtistProfile.js  ← 数据获取
├── TplGallery.vue                   ← 作品展示组件（4 模板共用）
├── TplTiers.vue                     ← 档位展示
├── TplRules.vue                     ← 约稿须知
└── WorkflowOverviewStrip.vue        ← 流程预览条
```

### 3.2 共用 vs 独立判断

| 功能 | 共用组件？ | 说明 |
|------|-----------|------|
| 瀑布流 | ✅ 改 TplGallery.vue | 4 模板共用，改一处生效全部 |
| 公告 | ✅ 新增共享组件 TplAnnouncement.vue | 4 模板各自决定插入位置，组件复用 |
| 点赞 | ✅ 新增共享组件 ArtworkLikeButton.vue | 嵌入 TplGallery 的作品卡片内 |
| 看板 UI | ⚠️ 待定 | 如果是状态徽章增强，改现有 slotDisplay 渲染；如果是独立板块，新增共享组件 |

**结论**：全部走共享组件路线，不需要独立页面。4 个模板通过引入共享组件 + 各自决定位置来适配。与现有模板系统（布局 × 配色）完全兼容。
