**数据刷新策略（全局）**：进入仪表盘时加载一次，不做自动轮询，不加刷新按钮（C55 拍板）。画师想看最新数据自己刷新页面。

**设计原则**（用户原声提取）：
1. 页面不能太重——模块多但每个轻量
2. 不要悬浮按钮式入口
3. 性能优先——不做自动轮询
4. 打开即知当下最急的事

## 1. 收入统计（C48 柱状图 / C49 不做饼图）

### 1.1 验收条件

| # | 当…… | 应该…… | 验证方式 |
|---|------|--------|----------|
| 1.1 | 画师进入仪表盘 | 看到收入统计区域，默认展示"月"维度柱状图 | 目视 |
| 1.2 | 切换维度为"季" | 横轴变为按周聚合（第 1~13 周），汇总变为当季总收入 | 切换后检查横轴标签和汇总数字 |
| 1.3 | 切换维度为"年" | 横轴变为按月聚合（1~12），汇总变为当年总收入 | 同上 |
| 1.4 | 某时间段无已完成订单 | 柱子高度为 0（不留空白），汇总显示 ¥0 | 用无订单月份测试 |
| 1.5 | 画师本地时区 UTC+8，月初 1 日 00:00~07:59 完成订单 | 该订单算入本月（不算上月） | 构造边界时间订单验证 |
| 1.6 | 有上一周期数据 | 汇总区显示环比变化（如"↑ 23% vs 6 月"） | 目视 |
| 1.7 | 无上一周期数据（如首月） | 不显示环比变化 | 新画师首月验证 |
| 1.8 | 当前维度有完成订单 | 汇总区显示完成订单数 | 目视 |
| 1.9 | 任何情况下 | 不出现档位收入分布饼图 | C49 拍板不做 |

### 1.2 三态处理

| 状态 | 表现 |
|------|------|
| **加载态** | 图表区域显示骨架屏（skeleton），汇总数字显示"-" |
| **空状态** | 无任何已完成订单时：柱状图全 0，汇总显示"¥0"，完成订单数"0"。不显示"暂无数据"占位图——0 本身就是有效信息 |
| **错误态** | API 请求失败时：图表区域显示"收入数据加载失败"+ 重试按钮。不影响其他模块加载 |

### 1.3 数据规格

- 金额：后端返回分（cents），前端 /100 显示，与现有 `formatCents` 一致
- 金额回退链：`COALESCE(final_price_cents, total_price_cents, price_snapshot * 100, 0)`（复用 PRICE_FALLBACK_SQL）
- 时间：按 `completed_at`，status IN ('done','delivered')
- 时区：复用现有 `localMonthStartSqlite` 等工具函数

## 2. "现在要干什么"合并列表（C51 合并式）

### 2.1 验收条件

| # | 当…… | 应该…… | 验证方式 |
|---|------|--------|----------|
| 2.1 | 画师进入仪表盘 | 看到一个统一的"现在要干什么"列表，所有在途任务按紧急程度排序 | 目视 |
| 2.2 | 有逾期订单（deadline < 今天，非终态） | 该条标红，显示在最顶部，标签为"逾期" | 构造逾期订单验证 |
| 2.3 | 有今天截稿的订单 | 该条标红/橙，排在逾期之后，标签为"截稿" | 构造今日 deadline 验证 |
| 2.4 | 有待处理新单（pending） | 排在截稿之后，标签为"新单" | 目视 |
| 2.5 | 有修改中订单（revision） | 排在新单之后，标签为"修改" | 目视 |
| 2.6 | 有进行中订单（confirmed/wip） | 按 deadline 升序排列，标签为"进行中" | 多条不同 deadline 验证排序 |
| 2.7 | 有进行中订单无 deadline | 排在进行中有 deadline 的之后（列表最末） | 目视 |
| 2.8 | 每条条目 | 显示：标签 + 订单号 + 客户名 + 当前状态 + 截稿日（有则显示，无则不显示） | 逐字段检查 |
| 2.9 | 点击任意一条 | 跳转到对应订单详情页（/orders/:id） | 点击验证路由 |
| 2.10 | 没有在途任务 | 显示空状态："当前没有待办，休息一下 🎨" | 清空所有订单验证 |
| 2.11 | 列表条目很多（如 20+） | v1 不设硬上限，列表随任务数量伸缩。折叠上限做出来再定 | 不验收折叠（v1 不做） |

### 2.2 三态处理

| 状态 | 表现 |
|------|------|
| **加载态** | 列表区域显示 3~5 行骨架条 |
| **空状态** | "当前没有待办，休息一下 🎨"（spec 原文） |
| **错误态** | "待办列表加载失败"+ 重试按钮。不影响其他模块 |

### 2.3 排序规则（后端实现）

```
ORDER BY:
  1. 逾期未完成（deadline < today AND status NOT IN terminal） DESC
  2. 今天截稿（deadline = today） DESC
  3. pending（按 created_at DESC）
  4. revision（按 updated_at DESC）
  5. confirmed/wip 有 deadline（按 deadline ASC）
  6. confirmed/wip 无 deadline（排最后）
```

终态定义：delivered, cancelled, done（done 是否算终态待三号确认——如果 done 后还有交付流程则不算）。

## 9. 跨模块通用规则

### 9.1 模块独立性

每个模块独立加载、独立失败。一个模块的 API 失败不应该导致整个仪表盘白屏或阻塞其他模块渲染。

### 9.2 加载顺序

布局框架（双栏/单列）先渲染 → 各模块并行请求数据 → 各模块独立渲染。无依赖关系，不需要串行等待。

### 9.3 响应式断点

| 断点 | 布局 |
|------|------|
| >768px | 双栏（左 60% / 右 40%，具体比例由二号定） |
| ≤768px | 单列 |

### 9.4 国际化

所有新增文案走 i18n（`$t('dashboard.xxx')`），与现有 Dashboard.vue 一致。中英文双语。

### 9.5 性能

- 不做自动轮询（C55）
- 柱状图组件按需加载（懒加载图表库，不阻塞首屏）
- 合并列表和活动流 API 应返回有限数据量（活动流限 10 条，合并列表 v1 不限但实际在途订单不会太多）
